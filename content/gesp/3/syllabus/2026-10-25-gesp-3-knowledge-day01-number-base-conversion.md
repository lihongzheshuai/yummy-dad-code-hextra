## 🧠 一、 核心原理深度拆解（有理论）

### 1. 为什么计算机偏爱二进制？

计算机内部由数十亿个微小的晶体管（MOS 管）组成。在物理世界中，要精确区分 $10$ 种不同的电压等级（代表 $0 \sim 9$）非常困难，微小的电磁干扰或温度波动就会导致识别错误；但要区分**两种极端状态**却极其稳定可靠：

* **高电平（通电 / 导通 / 有信号）** $\longrightarrow$ 记作数字 **`1`**；
* **低电平（断电 / 截止 / 无信号）** $\longrightarrow$ 记作数字 **`0`**。

这种**抗干扰能力极强、物理实现最简单、且天然对应布尔逻辑（真 `true` / 假 `false`）**的双态机制，决定了二进制（Binary）成为计算机底层唯一通用的语言。每一个 `0` 或 `1` 被称为一个**二进制位（Bit，比特）**，而 $8$ 个比特组合在一起就构成了计算机内存最小的可寻址单元——**字节（Byte，$1\text{ Byte} = 8\text{ bits}$）**。

### 2. 进位计数制的本质：基数（Base）与位权（Weight）

无论是十进制、二进制、八进制还是十六进制，它们都属于**位置化进位计数制**，由两个核心要素决定：

1. **基数（Radix / Base，$R$）**：逢 $R$ 进一，每一位上只允许出现 $0 \sim R-1$ 共 $R$ 种数码。当 $R=16$ 时，数码 $10 \sim 15$ 分别用大写字母 $\text{A、B、C、D、E、F}$ 表示（务必熟记：$\text{A}=10\text{、B}=11\text{、C}=12\text{、D}=13\text{、E}=14\text{、F}=15$）。
2. **位权（Weight）**：同一个数码处在不同位置上，所代表的数值大小不同。规定**从右往左（从最低位/个位开始）下标从 $0$ 起算**，第 $i$ 位的位权就是 $R^i$。

由此可得任意 $R$ 进制正整数 $(d_{n-1}d_{n-2}\dots d_1d_0)_R$ 转十进制的**按权展开通用公式**：

$$\text{Value}_{10} = \sum_{i=0}^{n-1} d_i \times R^i = d_{n-1}\cdot R^{n-1} + d_{n-2}\cdot R^{n-2} + \dots + d_1\cdot R^1 + d_0\cdot R^0$$

以十进制数 $45$ 对应的二进制 $(101101)_2$ 为例，其底层的二进制位图与位权对应关系如下：

```text
二进制位置下标 i :    5       4       3       2       1       0   （注意：最右侧个位下标为 0！）
对应位权     2^i :   2^5     2^4     2^3     2^2     2^1     2^0
十进制权值       :   32      16       8       4       2       1
-----------------------------------------------------------------
二进制数码   d_i :    1       0       1       1       0       1
-----------------------------------------------------------------
按权相乘累加     :  1×32  +  0×16  + 1×8   + 1×4   + 0×2   + 1×1  = 32 + 8 + 4 + 1 = 45
```

### 3. 十进制转 $R$ 进制：除基取余，倒序排列

反过来，为什么把十进制数 $N$ 不断除以 $R$ 取余数，就能得到它的 $R$ 进制表示？
我们把按权展开式两边同时除以 $R$：

$$N = d_{n-1}R^{n-1} + \dots + d_1R^1 + d_0 = R \times \underbrace{(d_{n-1}R^{n-2} + \dots + d_1)}_{\text{第一次除以 } R \text{ 的商 } Q_1} + \underbrace{d_0}_{\text{第一次的余数}}$$

可以看到：**第一次除以 $R$ 得到的余数，恰好就是最低位 $d_0$**！接着对商 $Q_1$ 继续除以 $R$，得到的余数就是次低位 $d_1$……直到商变为 $0$ 为止。由于先算出来的是最低位（最右边），最后算出来的是最高位（最左边），因此将所有余数**从下往上倒序排列**，即得完整的 $R$ 进制数。

### 4. 二进制与八、十六进制的“分组秒算”原理

因为 $8 = 2^3$，$16 = 2^4$，所以：
* **$1$ 位八进制数** 恰好等价于 **$3$ 位二进制数**（权值为 **`4-2-1`**）；
* **$1$ 位十六进制数** 恰好等价于 **$4$ 位二进制数**（权值为 **`8-4-2-1`**）。

> 💡 **考场黄金法则（背诵直接套用）**：
> 1. **【8421 凑数秒算法】**：做十进制与二进制互转时，无需列竖式死除！熟记 $2^0 \sim 2^{10}$ 的权值表（`1、2、4、8、16、32、64、128、256、512、1024`），像凑人民币面额一样从大到小拆解，有用到的权值位写 `1`，没用到的写 `0`。例如 $45 = 32 + 8 + 4 + 1 \longrightarrow (101101)_2$。
> 2. **【三四分组桥梁法】**：凡是遇到八进制与十六进制互转，或者大数字进制加减，**严禁绕道十进制**！一律以二进制为桥梁——从右往左（低位向高位），**每 $3$ 位二进制按 `4-2-1` 合成 $1$ 位八进制，每 $4$ 位二进制按 `8-4-2-1` 合成 $1$ 位十六进制**（高位不足补前导 `0`）。

## 🔍 二、 具象代码与数据推演（有举例）

在 C++11 中，编译器原生支持在源码里直接书写不同进制的整数字面量（Literal），并且我们可以通过简单的 `while` 循环模拟“除基取余”的全过程。请仔细阅读以下示例程序：

```cpp
#include <iostream>
using namespace std;

int main() {
    int a = 45;     // 普通数字：十进制 45
    int b = 055;    // 前缀 0 表示八进制：5 * 8^1 + 5 * 8^0 = 40 + 5 = 45
    int c = 0x2D;   // 前缀 0x 表示十六进制：2 * 16^1 + 13 * 16^0 = 32 + 13 = 45
    cout << a << " " << b << " " << c << endl;

    int x = 13;
    int weight = 1, ans = 0;
    while (x > 0) {
        int bit = x % 2;       // 取出当前最低位余数
        ans += bit * weight;   // 乘以十进制位权拼入结果
        weight *= 10;          // 下一位的显示位置左移一位
        x /= 2;                // 整数除法，消去已处理的最低位
    }
    cout << ans << endl;
    return 0;
}
```

### 分步内存与变量推演表

* **第一部分输出**：无论代码中用十进制 `45`、八进制 `055` 还是十六进制 `0x2D` 赋值，它们在计算机内存中存储的二进制比特完全一模一样，而 `cout` 默认以十进制输出，因此第一行输出为：`45 45 45`。
* **第二部分 `while` 循环逐轮推演（初始 `x = 13`）**：

| 循环轮次 | 进入循环前 `x` | `bit = x % 2`（当前余数） | `weight`（十进制位置权） | `ans += bit * weight`（累计拼数） | 循环末尾 `x /= 2` |
| :---: | :---: | :---: | :---: | :---: | :---: |
| **初始态** | `13` | - | `1` | `0` | - |
| **第 1 轮** | `13` | `13 % 2 = 1`（对应 $d_0$） | `1` | `0 + 1 * 1 = 1` | `13 / 2 = 6` |
| **第 2 轮** | `6` | `6 % 2 = 0`（对应 $d_1$） | `10` | `1 + 0 * 10 = 1` | `6 / 2 = 3` |
| **第 3 轮** | `3` | `3 % 2 = 1`（对应 $d_2$） | `100` | `1 + 1 * 100 = 101` | `3 / 2 = 1` |
| **第 4 轮** | `1` | `1 % 2 = 1`（对应 $d_3$） | `1000` | `101 + 1 * 1000 = 1101` | `1 / 2 = 0`（退出循环） |

最终第二行输出 `1101`，即 $(13)_{10} = (1101)_2$。

## ⚡ 三、 考场高频避坑指南（正误辨析）

在 GESP 三级判断题与 CSP-J 阅读程序题中，命题人最喜欢在以下几个细节设下陷阱：

### ❌ 易错点 1：在 C++ 代码中给整数乱加前导 `0` 对齐
* **错误认知**：“为了代码排版好看，把数组里的十进制数写成 `012`、`015`、`020`，反正数值跟 `12`、`15`、`20` 一样。”
* **正确原理**：**大错特错！** 在 C/C++ 语法规范中，**以数字 `0` 开头的整数字面量会被编译器强制解析为八进制（Octal）**！因此 `012` 的真实值是 $1 \times 8 + 2 = 10$；更致命的是，如果你写下 `int x = 018;`，由于八进制里根本不存在数码 `8`（最大只能到 `7`），程序会直接报编译错误（Compilation Error）！

### ❌ 易错点 2：按权展开时把最右边（个位）的次幂当成 $R^1$
* **错误认知**：“计算 $(1010)_2$ 时，最后一位是 $0 \times 2^1$，倒数第二位是 $1 \times 2^2 = 4$……”
* **正确原理**：任何非零数的 $0$ 次幂都等于 $1$（即 $R^0 = 1$）。**整数部分最右侧个位的位权永远是 $R^0 = 1$，而不是 $R^1$**！如果一个二进制数有 $n$ 位，它的最高位位权是 $2^{n-1}$ 而不是 $2^n$。此外，还可顺手记住一条奇偶性秒判铁律：**由于 $2^1, 2^2, \dots$ 全是偶数，只有最低位 $2^0 = 1$ 是奇数，因此二进制最低位为 `1` 必为奇数，最低位为 `0` 必为偶数**。

### ❌ 易错点 3：认为用 `int` 乘以 $10$ 累加就能转换任意大小的二进制数
* **错误认知**：“像上面演示代码那样用 `ans += bit * weight; weight *= 10;` 就能把任意 `int` 正整数转成二进制输出。”
* **正确原理**：十进制的 `int` 最大只能存到约 $2.1 \times 10^9$（最多 $10$ 位十进制数字）。如果输入 $x = 1024$，它的二进制是 $11$ 位的 `10000000000`，用十进制 `int` 去装这个“看起来像二进制”的十进制数就会直接爆 `int` 溢出！因此，当 $N$ 较大或目标进制 $K > 10$（含字母 $\text{A}\sim\text{F}$）时，**必须使用字符串 `std::string` 或数组来保存余数序列**。

## 📝 四、 真题实战演练与精析（有例题：3 道）

### 【例题 1 · 单选题】（GESP 三级 / CSP-J 初赛高频题型）

**题目**：下列四个不同进制的无符号整数中，数值**最大**的是（ ）。
* **A.** $(11010110)_2$
* **B.** $(325)_8$
* **C.** $(215)_{10}$
* **D.** $(\text{D8})_{16}$

**🔍 答案与逐项排除解析**：
* **正确答案**：**D**
* **解析过程**：切忌把四个选项全部硬算成十进制！直接用**“三四分组桥梁法”**统一成**十六进制**或**十进制**快速比大小：
  * **选项 A**：将 $(11010110)_2$ 从右往左每 $4$ 位一组拆开：`1101` 和 `0110`。按 `8-4-2-1` 口算：$1101 \to 8+4+0+1 = 13 (\text{D})$，$0110 \to 0+4+2+0 = 6$。所以 $(11010110)_2 = (\text{D6})_{16} = 13 \times 16 + 6 = 214$。
  * **选项 B**：将八进制 $(325)_8$ 每 $1$ 位拆成 $3$ 位二进制（`4-2-1`）：`3` $\to$ `011`，`2` $\to$ `010`，`5` $\to$ `101`，合起来是 $(011010101)_2 = (11010101)_2 = (\text{D5})_{16} = 213$（或者直接按权展开：$3 \times 64 + 2 \times 8 + 5 = 192 + 16 + 5 = 213$）。
  * **选项 C**：十进制 $215$。因为 $(\text{D6})_{16} = 214$，所以 $215 = (\text{D7})_{16}$。
  * **选项 D**：$(\text{D8})_{16} = 13 \times 16 + 8 = 208 + 8 = 216$。
  * **结论对比**：$\text{B }(213) < \text{A }(214) < \text{C }(215) < \text{D }(216)$，故选 **D**。

### 【例题 2 · 判断题】（概念与边界辨析）

**题目**：在二进制表示下，任何一个正整数只要在末尾（最右侧）直接添上两个 `0`，其表示的十进制数值就会扩大为原来的 $2$ 倍。（ ）

**🔍 答案与反例证明**：
* **结论**：**错误（$\times$）**
* **反例证明**：在 $R$ 进制数末尾添上 $1$ 个 `0`，相当于原来的每一位都向左移动了 $1$ 位，每一位的位权都乘以了基数 $R$，数值扩大为原来的 $R$ 倍；添上 $k$ 个 `0`，数值会扩大为原来的 $R^k$ 倍。
  * 在十进制下末尾添两个 `0`，数值扩大为 $10^2 = 100$ 倍；
  * 在**二进制**下末尾添两个 `0`，数值会扩大为 **$2^2 = 4$ 倍**，而不是 $2$ 倍！
  * **具体反例**：取十进制数 $3 = (11)_2$。在其二进制末尾添两个 `0` 变成 $(1100)_2 = 1 \times 8 + 1 \times 4 = 12$，显然 $12$ 是 $3$ 的 **$4$ 倍**而非 $2$ 倍。

### 【例题 3 · 微代码实战】（十进制正整数转任意 $K$ 进制）

**题目描述**：给定一个十进制非负整数 $n$（$0 \le n \le 10^9$）和目标进制 $k$（$2 \le k \le 16$），请编写 C++11 程序，输出 $n$ 转换为 $k$ 进制后的字符串（若数码大于 $9$，依次用大写字母 `A`~`F` 表示）。

**💡 建模思路**：
1. **特判边界 $n = 0$**：如果输入 $n = 0$，直接进入 `while (n > 0)` 循环会导致一次都不执行、输出空串！这是考场代码题最常见的失分点，必须先特判输出 `0`。
2. **查表映射法**：定义一个常量字符串 `string digits = "0123456789ABCDEF";`，当算出余数 `r = n % k`（范围必在 $0 \sim 15$ 之间）时，`digits[r]` 就能直接以 $O(1)$ 时间取出对应的字符，彻底省去繁琐的 `if-else` 分支！

```cpp
#include <iostream>
#include <string>
using namespace std;

int main() {
    int n, k;
    cin >> n >> k;
    if (n == 0) {
        cout << 0 << endl;
        return 0;
    }
    string digits = "0123456789ABCDEF";
    string res = "";
    while (n > 0) {
        res = digits[n % k] + res; // 余数对应的数码直接拼接到结果最前面（实现倒序）
        n /= k;
    }
    cout << res << endl;
    return 0;
}
```

* **输入样例**：`2026 16`
* **输出样例**：`7EA`（验证：$7 \times 16^2 + 14 \times 16^1 + 10 \times 16^0 = 1792 + 224 + 10 = 2026$）
