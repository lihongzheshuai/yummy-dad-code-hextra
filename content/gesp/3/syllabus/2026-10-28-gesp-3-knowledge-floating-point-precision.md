## 🎯 考纲锚点与核心痛点

> 📍 **对应考点**：掌握十进制小数与二进制小数的相互转换方法（乘 2 取整法与按权展开法），理解浮点数（`float`、`double`）在计算机中的近似存储本质与精度误差来源，熟练运用 `eps` 精度控制方法进行浮点数判等与比较。

1. **“进制转换顺手把顺序抄反”**：整数转二进制是“除 $2$ 取余、**逆序**排列”，很多同学在计算小数转二进制时，习惯性地把“乘 $2$ 取整”得到的整数位也倒过来写，导致整道单选题算错；
2. **“用 `==` 直接比较两个浮点数”**：在复赛写判断直角三角形、斜率相等或折扣金额匹配时，直接写出 `if (a + b == c)`，结果本地简单样例能过，提交评测却因为 $10^{-17}$ 级别的尾数舍入误差大面积 `WA`（答案错误）。

## 🧠 一、 核心原理深度拆解（有理论）

### 1. 二进制小数的位权与“乘 2 取整、顺序排列”法则

在十进制小数中，小数点后第 $1, 2, 3$ 位的位权分别是 $10^{-1}(0.1)$、$10^{-2}(0.01)$、$10^{-3}(0.001)$。同理，在**二进制小数**中，小数点（`.`）右侧第 $1, 2, 3, 4 \dots$ 位的位权依次是 $2$ 的负整数次幂：

| 二进制小数位 | 小数点后第 1 位 | 小数点后第 2 位 | 小数点后第 3 位 | 小数点后第 4 位 | 小数点后第 $k$ 位 |
| :---: | :---: | :---: | :---: | :---: | :---: |
| **指数形式** | $2^{-1}$ | $2^{-2}$ | $2^{-3}$ | $2^{-4}$ | $2^{-k}$ |
| **分数值** | $\dfrac{1}{2}$ | $\dfrac{1}{4}$ | $\dfrac{1}{8}$ | $\dfrac{1}{16}$ | $\dfrac{1}{2^k}$ |
| **精确十进制值** | **`0.5`** | **`0.25`** | **`0.125`** | **`0.0625`** | $0.5^k$ |

要将一个十进制纯小数 $D \in (0, 1)$ 转换为二进制小数 $(0.b_1 b_2 b_3 \dots)_2$，我们使用**“乘 2 取整，顺序排列”**法：
1. 将当前纯小数部分乘以 $2$；
2. 取出乘积的**整数部分**（必然是 `0` 或 `1`），作为二进制小数的下一位；
3. 将乘积的**小数部分**保留下来，继续乘以 $2$，直到小数部分变为 `0.0`（有限小数）或出现循环节（无限循环小数）；
4. 将每次取出的整数位**按从上到下的先后顺序**依次排列在 `0.` 后面。

例如，将十进制 **`0.625`** 转换为二进制：
* 第 1 步：$0.625 \times 2 = \mathbf{1}.25 \longrightarrow$ 取出整数 **`1`**（对应最高位 $2^{-1}=0.5$），剩余小数 `0.25`；
* 第 2 步：$0.25 \times 2 = \mathbf{0}.50 \longrightarrow$ 取出整数 **`0`**（对应第 2 位 $2^{-2}=0.25$），剩余小数 `0.50`；
* 第 3 步：$0.50 \times 2 = \mathbf{1}.00 \longrightarrow$ 取出整数 **`1`**（对应第 3 位 $2^{-3}=0.125$），剩余小数 `0.00`（结束）。
* **顺序排列结果**：$(0.625)_{10} = (0.101)_2$（验算：$0.5 + 0 + 0.125 = 0.625$）。

---

### 2. 为什么 $(0.1)_{10}$ 是二进制无限循环小数？

现在，让我们用同样的方法对十进制 **`0.1`** 执行“乘 2 取整”推演：

```text
  当前小数       × 2 后的结果     取出的整数位     剩余纯小数部分
─────────────────────────────────────────────────────────────────
    0.1       × 2 = 0.2         ──►   0            0.2   ◄── 【循环起点】
    0.2       × 2 = 0.4         ──►   0            0.4        │
    0.4       × 2 = 0.8         ──►   0            0.8        │ 循环节 "0011"
    0.8       × 2 = 1.6         ──►   1            0.6        │ 无限往复！
    0.6       × 2 = 1.2         ──►   1            0.2   ─────┘
    0.2       × 2 = 0.4         ──►   0            0.4
    ...
```

我们震惊地发现：从第 2 步开始，剩余小数陷入了 `0.2 -> 0.4 -> 0.8 -> 0.6 -> 0.2` 的**死循环**！因此，十进制里极其简单的 $0.1$，写成二进制竟然是一个无穷无尽的循环小数：
$$(0.1)_{10} = (0.0\dot{0}01\dot{1})_2 = (0.00011001100110011\dots)_2$$

**【数学本质判定定理】**：
为什么 $0.625$ 能转成有限二进制小数，而 $0.1$ 却不能？因为任何有限位二进制小数都是 $2^{-k} = \frac{1}{2^k}$ 的有限求和，通分后的最简分数分母**只能含有质因子 $2$**！
* $0.625 = \dfrac{5}{8} = \dfrac{5}{2^3}$，分母只有质因子 $2$ $\longrightarrow$ **二进制有限小数**；
* $0.1 = \dfrac{1}{10} = \dfrac{1}{2 \times 5}$，最简分母中含有奇质因子 **$5$** $\longrightarrow$ **必定是二进制无限循环小数**！

### 3. IEEE 754 尾数截断与 `eps` 判等法则

既然 $(0.1)_{10}$ 和 $(0.2)_{10}$ 在二进制下都是无限循环小数，而计算机内存中：
* 单精度 `float`（4 字节，32 位）仅有 **23 位尾数**（约 6~7 位十进制有效数字）；
* 双精度 `double`（8 字节，64 位）仅有 **52 位尾数**（约 15~17 位十进制有效数字）。

CPU 只能在有限的第 52 位尾数处对无限循环比特流进行“四舍五入（向偶数舍入）”截断。当截断后的 `0.1` 与截断后的 `0.2` 相加时，尾数末位的舍入误差叠加，得到了 `0.3000000000000000444...`，与截断后的 `0.3`（实际存储为 `0.2999999999999999888...`）在最低比特位上并不相同！

因此，在 C++ 中判断两个浮点数 `x` 和 `y` 是否相等，**严禁使用 `x == y`**，必须引入极小精度阈值 $\text{eps} = 10^{-8}$（即 `1e-8`），检查两数之差的绝对值是否小于 $\text{eps}$：
$$\text{判等规范：}\quad \texttt{fabs(x - y) < 1e-8}$$

> 💡 **考场黄金法则（背诵直接套用）**：
> 1. **【有限二进制小数秒判口诀】**：把十进制小数化为**最简分数** $\dfrac{p}{q}$（$\gcd(p,q)=1$），只要分母 $q$ 是 **$2$ 的整数次幂**（如 $2, 4, 8, 16, 32$），就一定能精确表示为有限二进制小数；只要分母含 $3, 5, 7$ 等非 $2$ 质因子（如 $0.1, 0.2, 0.3, 0.6$），在 `double` 中必有精度误差！
> 2. **【实数选型与判等铁律】**：考场编程凡涉及小数，**一律无脑用 `double`（禁用 `float`）**；凡涉及两个 `double` 判等，一律写 **`fabs(a - b) < 1e-8`**（需包含 `<cmath>` 头文件）。

## 🔍 二、 具象代码与数据推演（有举例）

下面这段标准的 C++11 程序直观展示了 `0.1 + 0.2 == 0.3` 的翻车现场、小数点后 17 位的真实内存面貌，以及 `fabs(c - 0.3) < eps` 的标准修正写法（可在本地使用 `g++ -O2 -std=c++11` 直接编译运行）：

```cpp
#include <iostream>
#include <iomanip>
#include <cmath>
using namespace std;

int main() {
    double a = 0.1;
    double b = 0.2;
    double c = a + b;

    cout << (c == 0.3) << endl;
    cout << fixed << setprecision(17) << c << endl;

    const double eps = 1e-8;
    cout << (fabs(c - 0.3) < eps) << endl;
    return 0;
}
```

### 分步内存与变量推演表

| 代码语句与表达式 | 底层存储 / 运算状态 | 实际输出结果与原因解析 |
| :---: | :---: | :--- |
| `double c = a + b;` | 两个 52 位尾数近似值相加并产生进位舍入 | `c` 在内存中存储的精确值比数学上的 $0.3$ 略微大了约 $4.44 \times 10^{-17}$ |
| `cout << (c == 0.3)` | 逐比特比对 64 位二进制编码是否完全一致 | 第一行输出：**`0`**（即 `false`，因为最低有效位存在比特差异，直接判等失败！） |
| `setprecision(17) << c` | 打印 `c` 的十进制高精度展开值 | 第二行输出：**`0.30000000000000004`**（末尾多出的 `4` 暴露了二进制截断误差） |
| `fabs(c - 0.3) < eps` | $|c - 0.3| \approx 4.44 \times 10^{-17} < 10^{-8}$ | 第三行输出：**`1`**（即 `true`，差值远在 $10^{-8}$ 容差范围内，正确识别两数相等） |

## ⚡ 三、 考场高频避坑指南（正误辨析）

在 GESP 三级客观题与 CSP-J 复赛编程中，以下三个浮点数陷阱最容易让人丢分：

### ❌ 易错点 1：误用整数绝对值函数 `abs()` 代替浮点绝对值 `fabs()`
* **错误认知**：“求绝对值用 `<cstdlib>` 里的 `abs(x - y)` 就行了。”
* **潜在风险**：在部分老旧 C 标准库头文件环境（如只包含了 `<stdlib.h>` 而未发生 `<cmath>` 重载）下，`abs()` 的参数类型是 `int`！传入 `double` 类型的 `0.0000001` 会被先强制截断成整数 `0`，导致任何差值不到 $1$ 的两个小数都被误判为相等！
* **正确规范**：处理 `double` 浮点数的绝对值时，永远包含 `<cmath>` 并显式调用 **`fabs(x - y)`**。

### ❌ 易错点 2：把本来能用整数算的金额/倍率硬转成浮点数再强转回 `int`
* **错误写法**：题目说“商品打 8 折后取整”，写成 `int pay = (int)(price * 0.8);`
* **为什么错**：因为 `0.8` 在二进制下是无限循环小数（实际存储略小于 $0.8$ 或在乘法中产生微小负误差）。当 `price = 5` 时，数学上 $5 \times 0.8 = 4$，但浮点计算结果可能变成 `3.9999999999999996`，一旦强转 `(int)` 直接向零截断砍掉小数部分，瞬间变成 **`3`**（少算了 1 块钱）！
* **正确规范**：
  1. 能用整数运算绝不用小数：改写为 **`int pay = price * 8 / 10;`**；
  2. 如果必须从浮点转整数，先使用 `round()` 四舍五入或加上 `1e-8` 修正误差：`int pay = (int)(price * 0.8 + 1e-8);`。

### ❌ 易错点 3：在 GESP / CSP 考场上习惯性定义单精度 `float`
* **错误写法**：`float r, area; cin >> r; area = 3.1415926 * r * r;`
* **为什么错**：`float` 只有约 $6 \sim 7$ 位十进制有效数字。当半径 $r = 10000$ 时，$r^2 = 10^8$，乘上圆周率后整数部分就已经占满 8 位，`float` 的小数位甚至个位都会完全失真！
* **正确规范**：信息学竞赛内存充裕，**在任何情况下都用 64 位双精度 `double` 替代 `float`**。

## 📝 四、 真题实战演练与精析（有例题：3 道）

### 【例题 1 · 单选题】（GESP 三级 / CSP-J 初赛进制转换必考题）

**题目**：下列四个十进制小数中，能够被**精确地**转换为有限位二进制小数（即在 IEEE 754 `double` 类型中不会产生无限循环截断误差）的是（ ）。
* **A.** `0.2`
* **B.** `0.45`
* **C.** `0.6875`
* **D.** `0.8`

**🔍 答案与逐项排除解析**：
* **正确答案**：**C**
* **解析过程**：
  1. 根据**【有限二进制小数秒判口诀】**，我们将四个选项化为最简分数，检查分母是否仅为 $2$ 的幂次：
     * **A 项**：$0.2 = \dfrac{2}{10} = \dfrac{1}{5}$，分母含有质因子 $5$，二进制为 $(0.\dot{0}01\dot{1})_2$ 无限循环，排除；
     * **B 项**：$0.45 = \dfrac{45}{100} = \dfrac{9}{20} = \dfrac{9}{2^2 \times 5}$，分母含有质因子 $5$，无限循环，排除；
     * **C 项**：$0.6875 = 0.5 + 0.125 + 0.0625 = \dfrac{1}{2} + \dfrac{1}{8} + \dfrac{1}{16} = \dfrac{11}{16} = \dfrac{11}{2^4}$，分母 $16 = 2^4$ 仅含质因子 $2$，对应的精确四位二进制小数为 **$(0.1011)_2$**，毫无精度损失！
     * **D 项**：$0.8 = \dfrac{4}{5}$，分母含有质因子 $5$，二进制为 $(0.\dot{1}10\dot{0})_2$ 无限循环，排除。
  2. 故选 **C**。

---

### 【例题 2 · 判断题】（边界特例与概念辨析）

**题目**：在 C++ 语言中，执行代码 `double x = 0.5 + 0.25; if (x == 0.75) cout << "YES";` 时，由于浮点数存在精度误差，`x == 0.75` 的判断结果一定为 `false`，不会输出 `"YES"`。（ ）

**🔍 答案与反例证明**：
* **结论**：**错误（$\times$）**
* **反例证明**：并非所有小数相加都会产生精度误差！
  1. $0.5 = 2^{-1} = (0.1)_2$，$0.25 = 2^{-2} = (0.01)_2$，$0.75 = 2^{-1} + 2^{-2} = (0.11)_2$；
  2. 这三个数的最简分数分母分别是 $2, 4, 4$，全部是 $2$ 的整数次幂，在 IEEE 754 `double` 的 52 位尾数中均能做到 **100% 零误差精确表示**；
  3. 因此 `0.5 + 0.25` 在二进制下的加法结果分毫不差就是 `(0.11)_2`，即 `0.75`，此时 `x == 0.75` 为 `true`，程序一定会输出 `"YES"`。命题人常借此考察考生是否真正理解误差产生的根源在于“分母能否被 $2^k$ 整除”。

### 【例题 3 · 微代码实战】（带 `eps` 容差的实数和比较器）

**题目描述**：给定三个双精度浮点数 $a, b, c$（$-10^6 \le a, b, c \le 10^6$）。请编写 C++11 程序，在考虑浮点数二进制精度误差（取 $\text{eps} = 10^{-8}$）的前提下，判断 $a + b$ 与 $c$ 的大小关系：
* 若 $|(a + b) - c| < 10^{-8}$，认为两者相等，输出 `Equal`；
* 若 $(a + b) - c \ge 10^{-8}$，认为 $a + b > c$，输出 `Greater`；
* 否则认为 $a + b < c$，输出 `Less`。

**💡 建模思路**：
1. 严格使用 `double` 类型接收输入的三个实数 $a, b, c$；
2. 定义常量 `const double eps = 1e-8;`，优先使用 `<cmath>` 中的 `fabs((a + b) - c) < eps` 拦截相等情况（即使输入为 `0.1 0.2 0.3`，也能克服 $4.44 \times 10^{-17}$ 的截断误差精准输出 `Equal`）；
3. 若不相等，再根据差值符号分支输出 `Greater` 或 `Less`。

```cpp
#include <iostream>
#include <cmath>
using namespace std;

int main() {
    double a, b, c;
    cin >> a >> b >> c;
    const double eps = 1e-8;
    if (fabs((a + b) - c) < eps) {
        cout << "Equal" << endl;
    } else if ((a + b) - c >= eps) {
        cout << "Greater" << endl;
    } else {
        cout << "Less" << endl;
    }
    return 0;
}
```

* **输入样例 1（经典 `0.1 + 0.2` 精度陷阱测试）**：`0.1 0.2 0.3`
* **输出样例 1**：`Equal`
* **输入样例 2**：`0.15 0.25 0.39`
* **输出样例 2**：`Greater`
