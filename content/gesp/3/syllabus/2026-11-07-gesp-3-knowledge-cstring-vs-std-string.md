为什么在 C++ 中写下 `char a[] = "GESP";` 和 `char b[] = {'G', 'E', 'S', 'P'};`，明明看起来都是 4 个字母，用 `sizeof(a)` 测出来是 `5`，而 `sizeof(b)` 却是 `4`？更可怕的是，如果对 `b` 调用 `strlen(b)` 或直接 `cout << b;`，屏幕上竟然会打印出一串乱码甚至直接触发内存越界崩溃？而在复赛考场上，为什么无数同学明明写出了逻辑完全正确的单层遍历 `for (int i = 0; i < strlen(s); i++)`，面对长度 $n = 10^5$ 的字符串时，原本以为稳拿满分的 $O(n)$ 代码却全部变成了 **TLE（运行超时）**？当我们改用现代 C++ 的 `std::string` 时，为什么 `s += ch` 飞快无比，而 `s = ch + s` 却又会重蹈 $O(n^2)$ 超时的覆辙？在 GESP 三级与四级认证以及 CSP-J 初赛阅读程序与复赛工程实践中，**C 风格字符串的空字符结束符 `'\0'`（ASCII 码为 `0`）底层哨兵机制、`sizeof` 编译期物理容量与 `strlen` 运行期线性扫描的本质区别、`strlen(s)` 写入循环条件引发的 $O(n^2)$ 复杂度退化，以及 `std::string` 常用操作的时间复杂度边界** 是逢考必出的核心重难点。本文将带你透视内存字节格子，彻底扫清两大字符串体系的所有暗礁。

## 🎯 考纲锚点与核心痛点

> 📍 **对应考点**：深入掌握 C 风格字符数组（`char[]` / `<cstring>`）的 `'\0'` 结尾哨兵机制，精准辨析 `sizeof(s)` 与 `strlen(s)` 的计算结果与时间复杂度，理解 `std::string` 对象的长度维护机制与高频操作（`size()`、`+=`、`+`、`substr()`、`find()`）的时间复杂度。
> 🎯 **适用等级**：`GESP 三级/四级考点 | CSP-J 初赛/复赛必考`

在考场做客观题、阅读程序和编写复赛代码时，同学们最容易在以下三个地方栽跟头：
1. **“混淆编译期运算符 `sizeof(s)` 与运行期库函数 `strlen(s)`，忽略隐式结尾符 `'\0'`”**：误以为 `sizeof("ABC")` 等于 `3`（实际包含了末尾自动补上的 `'\0'`，占 **`4`** 个字节），或者对声明了容量 `char s[100] = "ABC";` 的数组误以为 `sizeof(s)` 也是 `3` 或 `4`（实际是整个数组分配的物理字节数 **`100`**）；
2. **“把 `strlen(s)` 直接写进 `for` 循环条件中，导致 $O(n)$ 遍历瞬间退化为 $O(n^2)$ 超时”**：不知道 `strlen(s)` 并不是直接读取某个现成的长度属性，而是每次调用都要从数组下标 `0` 开始逐个字节往后数，直到撞见第一个 `'\0'` 为止！在循环条件 `i < strlen(s)` 中每走一步都重数一遍全串，当 $n = 10^5$ 时累计运算量高达 $\frac{n(n+1)}{2} \approx 5 \times 10^9$ 次，必挂 TLE；
3. **“误以为 `std::string` 也靠 `'\0'` 判断长度，或滥用 `s = s + ch` 引发内存拷贝爆炸”**：在 `std::string` 中间手动赋了一个 `s[2] = '\0'`，误以为 `s.size()` 会像 `strlen` 一样被腰斩截断；或者在循环里写 `s = s + ch`（每次新建整串副本 $O(n)$），不知道与原地追加 `s += ch`（均摊 $O(1)$）有着天壤之别。

## 🧠 一、 核心原理深度拆解（有理论）

### 1. C 风格字符串（`char[]`）的灵魂哨兵：空字符 `'\0'`

在 C 语言和 C++ 的底层数组模型中，一块普通的 `char` 数组本身**并没有任何额外的隐藏变量去记录“我里面到底存了几个有效字符”**。那么，当执行 `cout << s;` 或者调用 `strlen(s)` 时，计算机怎么知道字符串在哪里结束呢？

答案就是：**靠“哨兵字符”——空字符 `'\0'`（Null Character，其底层 ASCII 码数值严格等于整数 `0`，注意绝不是字符 `'0'` 的 `48`）**！
* **双引号字符串字面量自动补 `'\0'`**：当你用双引号初始化 `char s1[10] = "GESP";` 或 `char s2[] = "GESP";` 时，编译器会在 `'G', 'E', 'S', 'P'` 后面**自动追加一个看不见的 `'\0'`**。因此 `"GESP"` 在物理内存中实际占用 **$4 + 1 = 5$ 个字节**！
* **花括号单字符列表不自动补 `'\0'`（除非数组留有剩余空位）**：
  * 如果写 `char b[] = {'G', 'E', 'S', 'P'};`（未指定长度且未写 `'\0'`），编译器只分配**恰好 `4` 个字节**，末尾**没有 `'\0'` 哨兵**！一旦对 `b` 调用 `strlen(b)` 或 `cout << b;`，CPU 就会冲出数组 `b` 的边界，在相邻的未知内存里一路狂奔乱读，直到偶然碰到一个字节的值为 `0` 才停下（即经典的**内存越界与乱码 Bug**）！
  * 但如果写 `char c[10] = {'G', 'E', 'S', 'P'};`（显式指定长度 `10` 大于初始化元素个数 `4`），根据 C++ 数组部分初始化规则，**剩余未初始化的元素 `c[4] ~ c[9]` 会被编译器自动填 `0`（而整数 `0` 恰好就是 `'\0'`）**，因此 `c` 就变成了一个合法的 C 风格字符串！

### 2. 一表辨清：`sizeof(s)` vs `strlen(s)` vs `str.size()`

在 GESP 三级/四级与 CSP-J 初赛单选题中，命题人最喜欢把 `sizeof`、`strlen` 和 `std::string::size()`（或 `length()`）混在一起考察：

| 对比维度 | `sizeof(s)` | `strlen(s)`（需 `#include <cstring>`） | `str.size()` / `str.length()`（`std::string`） |
| :---: | :--- | :--- | :--- |
| **本质身份** | C++ **编译期运算符**（不是函数！） | C 标准库 **运行期函数** | `std::string` 类的 **成员函数** |
| **统计目标** | 整个变量/数组在内存中分配的 **总物理字节容量** | 从首地址出发到 **第一个 `'\0'` 之前** 的有效字符个数 | `string` 对象内部维护的 **当前实际字符个数** |
| **是否计入 `'\0'`** | ✅ **计入**（包含 `'\0'` 及数组所有空闲槽位） | ❌ **绝不计入**（一碰到 `'\0'` 立刻停下，不含 `'\0'` 本身） | ❌ 不以 `'\0'` 为截断标志（即使串中含 `'\0'` 也照常计入总长） |
| **时间复杂度** | **$O(1)$**（编译阶段直接算出常数，运行零耗时） | **$O(n)$**（运行期必须从头逐字节遍历寻找 `'\0'`！） | **$O(1)$**（内部用独立整型成员变量 `_M_string_length` 实时记录，直接返回！） |

### 3. 为什么 `for (int i = 0; i < strlen(s); i++)` 是复赛头号超时杀手？

看看 C 标准库中 `strlen` 函数的底层等价实现，你就能瞬间明白为什么它不能放进循环条件里：

```cpp
// strlen 的底层逻辑：老老实实从头往后一步步数！
size_t my_strlen(const char *s) {
    size_t cnt = 0;
    while (s[cnt] != '\0') {
        cnt++; // 必须走过每一个非 '\0' 字符才能算出长度，单次耗时 O(n)！
    }
    return cnt;
}
```

假设字符数组 `s` 的有效长度为 $n = 10^5$：
* **❌ 致命错误写法**：
  ```cpp
  for (int i = 0; i < strlen(s); i++) {
      // 循环体每执行 1 次，判断条件 i < strlen(s) 就要从 s[0] 到 s[n] 重数一遍（耗时 n 次）！
      // 总执行次数 = n (i=0时) + n (i=1时) + ... + n (i=n) ≈ n^2 = 10^10 次运算！直接 TLE！
  }
  ```
* **✅ 满分标准写法（提外预存 / 哨兵直判）**：
  ```cpp
  // 写法 A：在循环外部只调用 1 次 strlen(s)，用变量 len 存起来！总耗时严格 O(n)！
  int len = strlen(s);
  for (int i = 0; i < len; i++) { ... }

  // 写法 B：直接利用 s[i] != '\0' 作为终止条件，连 strlen 都不用调！总耗时严格 O(n)！
  for (int i = 0; s[i] != '\0'; i++) { ... }
  ```

### 4. `std::string` 的底层优势与拼接陷阱（`+=` vs `+`）

进入 GESP 三级/四级与 CSP-J 复赛后，我们经常使用 `<string>` 头文件中的 `std::string`。它内部封装了一个动态字符数组和一个**专门记录当前长度的成员变量 `size`**。因此：
1. **查长度永远是 $O(1)$**：写 `for (int i = 0; i < s.size(); i++)`（或 `(int)s.length()`）**完全不会超时**，因为 `s.size()` 只是读取一个现成的整数变量！
2. **最致命的 `std::string` 超时陷阱——循环内写 `s = s + ch` 或 `s = ch + s`**：
   * **`s += ch` 或 `s.push_back(ch)`（原地尾部追加）**：直接在原有动态数组末尾填入字符，仅在容量满时倍增扩容，单次**均摊时间复杂度为 $O(1)$**，$n$ 次循环总耗时 **$O(n)$**！
   * **`s = s + ch` 或 `s = ch + s`（先创建临时副本再赋值）**：运算符 `+` 必须先在内存中开辟一个新的临时字符串，把原串 `s` 的所有字符**完整复印一遍（单次耗时 $O(|s|)$）**，拼上 `ch` 后再赋回给 `s`。在长度为 $n$ 的循环里这样写，总时间复杂度会再次退化为 **$1 + 2 + \dots + n = O(n^2)$**，当 $n = 10^5$ 时必挂 TLE！

| `std::string` 常用操作 | 语法示例 | 单次时间复杂度 | 复赛避坑说明 |
| :---: | :---: | :---: | :--- |
| **获取长度** | `s.size()` / `s.length()` | **$O(1)$** | 返回类型为无符号 `size_t`，做减法 `s.size() - 1` 前务必强转为 `(int)s.size()`！ |
| **尾部原地追加** | `s += ch;` / `s += "abc";` | **均摊 $O(1)$** | **循环拼接字符串的唯一正确姿势**（若需逆序拼接，先 `s += ch` 最后再 `reverse`） |
| **加法生成新串** | `s = s + ch;` / `s = ch + s;` | **$O(n)$** | 每次拷贝整串！**严禁在高频循环内使用**，否则 $O(n^2)$ 超时 |
| **截取子串** | `s.substr(pos, len)` | **$O(\text{len})$** | 从下标 `pos` 开始截取最多 `len` 个字符（注意第 2 个参数是**长度**，不是结束下标！） |
| **查找子串** | `s.find(sub)` | **$O(n \cdot m)$** | 找到返回首次出现的首下标；**未找到返回 `string::npos`**（强转为 `int` 是 `-1`） |

> 💡 **考场黄金法则（背诵直接套用）**：
> 1. **【`sizeof` 与 `strlen` 铁律】**：**“`sizeof` 看声明容量连 `'\0'` 一起算（编译期 $O(1)$），`strlen` 从头数到第一个 `'\0'` 前停步（运行期 $O(n)$）；中途塞个 `'\0'`，`sizeof` 纹丝不动，`strlen` 当场腰斩！”**
> 2. **【复赛防 TLE 铁律】**：**“`char` 数组循环前必先 `int len = strlen(s);`；`string` 循环拼接必用 `s += ch`，严禁 `s = s + ch` 与 `s = ch + s`！”**

## 🔍 二、 具象代码与数据推演（有举例）

下面这段标准的 C++11 示例程序直观展示了字符数组 `cstr`、花括号字符数组 `arr` 与 `std::string` 在初始化及中途写入 `'\0'` 后的长度变化对比：

```cpp
#include <iostream>
#include <cstring>
#include <string>
using namespace std;

int main() {
    char cstr[10] = "GESP";
    char arr[] = {'G', 'E', 'S', 'P', '\0'};
    cout << sizeof(cstr) << " " << strlen(cstr) << " " << sizeof(arr) << endl;
    cstr[2] = '\0';
    cout << cstr << " " << sizeof(cstr) << " " << strlen(cstr) << " " << cstr[3] << endl;
    string s = "GESP";
    s[2] = '\0';
    cout << s.size() << " " << strlen(s.c_str()) << endl;
    return 0;
}
```

### 分步内存与变量状态推演表

| 执行步骤 | 内存字节状态拆解 | 核心表达式求值过程 | 输出结果 |
| :---: | :--- | :--- | :---: |
| `char cstr[10] = "GESP";`<br>`char arr[] = {'G','E','S','P','\0'};` | `cstr` 固定分配 `10` 字节，前 5 格为 `'G','E','S','P','\0'`；`arr` 根据初始化列表恰好分配 `5` 字节 | `sizeof(cstr)` 为数组总字节数 **`10`**；`strlen(cstr)` 数到 `cstr[4]` 的 `'\0'` 前共 **`4`** 个字符；`sizeof(arr)` 为 **`5`** | 第一行输出：<br>**`10 4 5`** |
| `cstr[2] = '\0';`<br>`cout << cstr << ...` | 将下标 `2`（原 `'S'`）覆盖为结束符 `'\0'`，此时内存变为：`['G', 'E', '\0', 'P', '\0', ...]` | `cout << cstr` 和 `strlen(cstr)` 扫描到 `cstr[2]` 的 `'\0'` 就立即终止，故打印 **`GE`**，长度为 **`2`**；但物理数组大小 `sizeof(cstr)` 仍是 **`10`**，且 `cstr[3]` 里的 `'P'` 依然健在！ | 第二行输出：<br>**`GE 10 2 P`** |
| `string s = "GESP";`<br>`s[2] = '\0';` | `std::string` 内部长度变量固定记录为 `4`，把 `s[2]` 改为 `'\0'` 只改变了第 3 个字符的内容，不会改变 `s` 的长度属性 | `s.size()` 直接返回内部记录的长度 **`4`**；而 `s.c_str()` 转成 C 风格指针后交给 `strlen`，遇到 `s[2]` 的 `'\0'` 停下，返回 **`2`**！ | 第三行输出：<br>**`4 2`** |

## ⚡ 三、 考场高频避坑指南（正误辨析）

在 GESP 三级/四级客观题与 CSP-J 初赛阅读程序中，以下三个经典陷阱每年都会让大批考生丢分：

### ❌ 易错点 1：定义字符数组时“恰好卡着字符个数开空间”，忘记给 `'\0'` 留座位
* **错误写法**：为了存储长度为 `4` 的单词 `"GESP"`，写下 `char s[4] = "GESP";`；或者题目说明输入字符串长度不超过 $1000$，就紧巴巴地开 `char s[1000];`。
* **为什么错**：双引号字符串 `"GESP"` 包含 4 个可见字母 **外加 1 个隐式结尾符 `'\0'`**，一共需要 **`5` 个字节**！在 C++ 中写 `char s[4] = "GESP";` 会直接报 **编译错误（Compile Error：initializer-string for array of chars is too long）**！而在复赛中如果输入刚好达到最大长度 $1000$，`cin >> s;` 会在 `s[1000]` 处写入结尾的 `'\0'`，直接触发**数组下标越界**！因此，存储最大长度为 $N$ 的字符串，数组大小必须至少开到 **`N + 1`**（习惯上开 `N + 5` 或 `N + 10`）。

### ❌ 易错点 2：把 `char` 数组名当指针传给子函数后，在函数内对形参用 `sizeof` 求数组大小
* **经典陷阱代码**：
  ```cpp
  void check(char s[100]) {
      cout << sizeof(s) << endl; // 以为会输出 100，实际上在 64 位系统输出 8（32 位系统输出 4）！
  }
  ```
* **为什么错**：在 C/C++ 中，**数组作为函数参数传递时，会自动退化（Decay）为指向首元素的指针 `char *s`**！函数形参列表里写的 `char s[100]` 完全等价于 `char *s`（方括号里的 `100` 会被编译器直接忽略）。因此在函数内部调用 `sizeof(s)`，测量的根本不是原数组的字节数 `100`，而是**一个 `char*` 指针变量本身的字节大小（64 位机器固定为 `8` 字节，32 位机器固定为 `4` 字节）**！

### ❌ 易错点 3：`s.size()` 返回无符号整数 `size_t`，空串时写 `i <= s.size() - 1` 引发死循环与越界
* **错误写法**：
  ```cpp
  string s = "";
  for (int i = 0; i <= s.size() - 1; i++) { // 当 s 为空串时当场崩溃！
      cout << s[i];
  }
  ```
* **为什么错**：`s.size()` 和 `strlen(s)` 的返回值类型都是**无符号整数 `size_t`（即 `unsigned long` / `unsigned int`）**！当 `s` 为空串（长度为 `0`）时，无符号数 `0 - 1` **绝不会等于 `-1`**，而是发生无符号下溢回绕，变成一个天文数字（如 $2^{64}-1 = 18446744073709551615$）！导致 `i <= s.size() - 1` 恒成立，引发疯狂的内存越界与死循环！**安全规范**：要么严格写 `< s.size()`，要么先存为有符号整型 `int n = s.size();`。

## 📝 四、 真题实战演练与精析（有例题：3 道）

### 【例题 1 · 单选题】（GESP 三级/四级 & CSP-J 初赛阅读程序：字符串中间含 `'\0'` 的修改与测量）

**题目**：阅读以下 C++ 程序，其运行后的输出结果是（ ）。
```cpp
#include <iostream>
#include <cstring>
using namespace std;

int main() {
    char s[20] = "Hello\0World";
    int a = sizeof(s);
    int b = strlen(s);
    s[5] = '!';
    int c = strlen(s);
    s[8] = '\0';
    cout << a << " " << b << " " << c << " " << s << endl;
    return 0;
}
```
* **A.** `12 5 11 Hello!Wo`
* **B.** `20 5 11 Hello!Wo`
* **C.** `20 11 11 Hello!World`
* **D.** `20 5 6 Hello!`

**🔍 答案与逐项排除解析**：
* **正确答案**：**B**
* **解析过程**：
  1. **求 `a = sizeof(s)`**：数组 `s` 在声明时显式指定了容量 `char s[20]`，无论里面存了什么字符串，`sizeof(s)` 永远等于整个数组在内存中占用的总字节数 **`20`**（直接排除 A 项）。
  2. **求初始 `b = strlen(s)`**：字符串字面量 `"Hello\0World"` 在内存下标 `0~11` 中依次存放了：
     * `s[0..4]` 为 `'H', 'e', 'l', 'l', 'o'`（共 5 个字符）；
     * **`s[5]` 为显式写入的 `'\0'`**；
     * `s[6..10]` 为 `'W', 'o', 'r', 'l', 'd'`；
     * `s[11]` 为双引号末尾自动补上的 `'\0'`。
     第一次调用 `strlen(s)` 时，从 `s[0]` 数到 `s[5]` 的第一个 `'\0'` 就立即停止，因此 `b = 5`（排除 C 项）。
  3. **执行 `s[5] = '!';` 后求 `c = strlen(s)`**：原本挡在下标 `5` 处的哨兵 `'\0'` 被替换成了感叹号 `'!'`！此时后续的 `'W', 'o', 'r', 'l', 'd'` 被彻底“打通复活”，再次调用 `strlen(s)` 会一路数到 `s[11]` 的末尾 `'\0'` 才停下，共 `5 + 1 + 5 = 11` 个字符，故 `c = 11`（排除 D 项）。
  4. **执行 `s[8] = '\0';` 后打印 `s`**：下标 `6, 7, 8` 原本分别是 `'W', 'o', 'r'`，将 `s[8]` 改为 `'\0'` 后，字符串在 `'o'` 后面被截断，因此输出 `s` 的结果为 **`Hello!Wo`**。综上，完整输出为 `20 5 11 Hello!Wo`，故选 **B**。

### 【例题 2 · 判断题】（GESP 三级/四级官方考纲真题辨析：`strlen` 循环复杂度与字符串字面量大小）

**题目**：在 C++ 语言中，假设 `char s[100005];` 存储了一个长度为 $n$（$n = 10^5$）的合法字符串。由于 `strlen(s)` 是 C++ 标准库自带的底层函数，能够直接读取字符数组的长度属性，因此循环语句 `for (int i = 0; s[i] != '\0'; i++)` 与 `for (int i = 0; i < strlen(s); i++)` 的总时间复杂度完全相同，均为 $O(n)$。（ ）

**🔍 答案与反例证明**：
* **结论**：**错误（$\times$）**
* **反例证明**：
  1. C 风格字符数组 `char s[]` **没有任何记录长度的隐藏属性**。标准库函数 `strlen(s)` 的唯一工作方式是从首地址 `s[0]` 开始逐个字节向后扫描，直到遇到第一个空字符 `'\0'` 为止，因此**单次调用 `strlen(s)` 的时间复杂度就是 $O(n)$**；
  2. 第一种写法 `for (int i = 0; s[i] != '\0'; i++)` 每次循环只需花 $O(1)$ 时间检查当前字符 `s[i]` 是否为 `'\0'`，整个循环的总时间复杂度为 **$O(n)$**；
  3. 第二种写法 `for (int i = 0; i < strlen(s); i++)` 在每次判断循环条件时都会重新调用一次 $O(n)$ 的 `strlen(s)`，一共调用 $n + 1$ 次，总时间复杂度退化为 **$O(n^2)$**（当 $n = 10^5$ 时运算量达 $10^{10}$ 级别，必定运行超时）。因此两者时间复杂度截然不同，原命题判定为错误。

### 【例题 3 · 微代码实战】（经典复赛模型：$O(n)$ 游程编码压缩——预存 `strlen` 与 `string +=` 原地追加规范）

**题目描述**：在信奥复赛处理十万级长度的字符串时，必须严格遵守**“循环外预存 `int len = strlen(s);`”**与**“使用 `ans += ...` 原地尾部追加”**两大 $O(n)$ 铁律。
给定一个触发阈值整数 $k$（$2 \le k \le 10$）和一个仅由小写英文字母组成的字符串 `raw_str`（长度 $1 \le n \le 10^5$）。请你对该字符串执行**阈值游程压缩（Run-Length Encoding）**：
* 将字符串中连续相同的字符合并为一段，假设某一段字符为 `ch`，连续出现的次数为 `cnt`：
  * 若 $\text{cnt} \ge k$，则在结果串 `ans` 末尾依次追加字符 `ch` 以及十进制数字字符串 `cnt`（例如当 $k=2$ 时，`"aaaa"` 压缩为 `"a4"`）；
  * 若 $\text{cnt} < k$，则仅在结果串 `ans` 末尾追加 **1 个** 字符 `ch`，不追加次数（用于过滤短重复噪点，例如当 $k=2$ 时，单个 `"b"` 保持为 `"b"`；当 $k=3$ 时，连续两个 `"ee"` 也折叠为单个 `"e"`）。
* 请在第一行输出原始字符串长度与压缩后字符串的长度（以单个空格分隔），第二行输出压缩后的结果字符串。

**💡 建模思路**：
1. **防范 `strlen` 退化**：先在循环外执行一次 `int len = strlen(raw_str);`，将总长度锁定在整型变量 `len` 中；
2. **单遍扫描统计连续段**：维护当前连续相同字符的计数器 `cnt`。遍历下标 $i = 0 \sim \text{len}-1$，每步先令 `cnt++`；当到达字符串末尾（`i + 1 == len`）或下一个字符与当前字符不同（`raw_str[i + 1] != raw_str[i]`）时，说明当前连续段结束；
3. **高效尾部追加**：使用 `ans += raw_str[i];`（均摊 $O(1)$），若 `cnt >= k` 则进一步使用 C++11 标准函数 `ans += to_string(cnt);` 追加次数，最后将 `cnt` 清零开启下一段统计。全程时间复杂度严格为 **$O(n)$**。

```cpp
#include <iostream>
#include <cstring>
#include <string>
using namespace std;

const int MAXN = 100005;
char raw_str[MAXN];

int main() {
    int k;
    cin >> k >> raw_str;
    int len = strlen(raw_str);
    string ans = "";
    int cnt = 0;
    for (int i = 0; i < len; i++) {
        cnt++;
        if (i + 1 == len || raw_str[i + 1] != raw_str[i]) {
            ans += raw_str[i];
            if (cnt >= k) {
                ans += to_string(cnt);
            }
            cnt = 0;
        }
    }
    cout << len << " " << ans.size() << endl;
    cout << ans << endl;
    return 0;
}
```

* **输入样例 1**：
  ```text
  2
  aaabccccddde
  ```
* **输出样例 1**：
  ```text
  12 8
  a3bc4d3e
  ```
  *（样例 1 解释：原始串共 12 个字符，阈值 $k = 2$。连续段依次为：`'a'` 出现 3 次（$\ge 2 \to$ `"a3"`）、`'b'` 出现 1 次（$< 2 \to$ `"b"`）、`'c'` 出现 4 次（$\ge 2 \to$ `"c4"`）、`'d'` 出现 3 次（$\ge 2 \to$ `"d3"`）、`'e'` 出现 1 次（$< 2 \to$ `"e"`）。拼接后得到长度为 8 的 `"a3bc4d3e"`。）*
* **输入样例 2**：
  ```text
  3
  gggeespcccsp
  ```
* **输出样例 2**：
  ```text
  12 9
  g3espc3sp
  ```
