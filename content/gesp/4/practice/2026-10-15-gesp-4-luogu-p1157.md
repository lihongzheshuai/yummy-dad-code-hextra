当从 $n$ 个元素中抽取固定数量（如 $3$ 个）元素时，初学者往往习惯直接编写三层嵌套的 `for` 循环完成暴力枚举；然而一旦抽取个数 $r$ 是由输入动态决定的变量（$0 \le r \le n < 21$），静态层数的循环便彻底失效。洛谷 P1157「组合的输出」正是引导选手从“静态多重循环”迈向“动态递归枚举（DFS 搜索树）”的标志性分水岭试题，高度契合 CCF GESP 四级（递归函数设计与枚举回溯初探）与 CSP-J 普及组的核心要求。本题的破局关键在于深刻理解“组合不分顺序”的数学本质：通过在递归状态中维护“当前位置所选数字严格大于前一个位置数字”的单调递增不变量，无需任何 `visited` 标记数组即可天然实现去重与字典序输出；同时结合“剩余可用数字不少于待填位置数”的可行性剪枝，以及 `<iomanip>` 库中 `setw(3)` 的场宽对齐控制，能够以零冗余的搜索路径高效生成全部 $\binom{n}{r}$ 种组合。题目在洛谷的官方难度评级为`普及−`。

## luogu-P1157 组合的输出

> 🔗 **洛谷原题传送门**：[luogu-P1157 组合的输出](https://www.luogu.com.cn/problem/P1157)

### 题目描述

排列与组合是常用的数学方法，其中组合就是从 $n$ 个元素中抽出 $r$ 个元素（不分顺序且 $r \le n$），我们可以简单地将 $n$ 个元素理解为自然数 $1,2,\dots,n$，从中任取 $r$ 个数。

现要求你输出所有组合。

例如 $n=5,r=3$，所有组合为：

$123,124,125,134,135,145,234,235,245,345$。

### 输入格式

一行两个自然数 $n,r(1<n<21,0 \le r \le n)$。

### 输出格式

所有的组合，每一个组合占一行且其中的元素按由小到大的顺序排列，每个元素占三个字符的位置，所有的组合也按字典顺序。

**注意哦！输出时，每个数字需要 $3$ 个场宽。以 C++ 为例，你可以使用下列代码：**

```text
cout << setw(3) << x;
```

输出占 $3$ 个场宽的数 $x$。注意你需要头文件 `iomanip`。

### 输入输出样例

#### 样例输入 #1
```text
5 3
```

#### 样例输出 #1
```text
  1  2  3
  1  2  4
  1  2  5
  1  3  4
  1  3  5
  1  4  5
  2  3  4
  2  3  5
  2  4  5
  3  4  5
```

### 题目深度剖析与核心解题模型

#### 1. 核心矛盾：为什么需要用递归代替多重循环？

如果题目固定要求从 $n$ 个数中选出 $3$ 个数，我们可以直接写出如下三层循环：
- 第一层枚举第一个数 $i \in [1, n]$；
- 第二层枚举第二个数 $j \in [i + 1, n]$；
- 第三层枚举第三个数 $k \in [j + 1, n]$。

但在本题中，抽取的元素个数 $r$ 是在程序运行时才读入的变量。在编译期无法确定需要写几层 `for` 循环，因此必须借助**递归（Recursion）**：让每一层递归函数承担“一层 `for` 循环”的职责，第 `step` 层递归专门负责挑选组合中的第 `step` 个数字，直到选满 $r$ 个数字为止。

---

#### 2. 状态定义与严格递增去重原理

在组合数学中，集合 $\{1, 2, 3\}$ 与 $\{1, 3, 2\}$、$\{3, 2, 1\}$ 代表的是**同一个组合**。题目要求：
1. 每个组合内部的元素按**由小到大**的顺序排列；
2. 所有的组合按**字典序（Lexicographical Order）**从小到大输出。

这两个要求实际上指向同一个黄金法则——**单调递增枚举**：
- 设数组 `chosen[1..r]` 存储当前选出的 $r$ 个数字，其中满足 $1 \le \text{chosen}[1] < \text{chosen}[2] < \dots < \text{chosen}[r] \le n$。
- 在递归函数 `dfs(int step, int start)` 中：
  - `step` 表示当前正在确定第 `step` 个位置（$1 \le \text{step} \le r$）的数字；
  - `start` 表示当前第 `step` 个位置允许选择的**最小起始数字**。
- 当我们在第 `step` 个位置选定数字 `i`（其中 `i >= start`）后，进入下一层递归 `dfs(step + 1, i + 1)`。由于下一层的起始数字被强制设为 `i + 1`，后续选出的数字必然严格大于 `i`。
- **优势**：这种设计不仅省去了排列问题中常见的 `bool vis[]` 判重数组，而且因为每一层都从最小合法数字开始从小到大尝试，生成的组合序列天然严格遵循字典序！

---

#### 3. 可行性剪枝优化（Pruning）

在枚举第 `step` 个位置的数字 `i` 时，`i` 最大能取到多少？
- 如果不加思考地写 `for (int i = start; i <= n; ++i)`，当 `i` 取值过大时，后面剩下的数字根本不够填满剩余的位置，导致大量注定失败的无效递归分支。
- **数学推导**：
  - 确定当前第 `step` 个位置后，还需要继续挑选 $r - \text{step}$ 个数字；
  - 若当前位置选择了 `i`，那么区间 $[i + 1, n]$ 中剩余可选的数字共有 $n - i$ 个；
  - 要保证剩余数字足够填满后续位置，必须满足：
    $$n - i \ge r - \text{step} \implies i \le n - (r - \text{step})$$
- **直观验证**：以样例 $n = 5, r = 3$ 为例：
  - 第 $1$ 个位置（$\text{step} = 1$）：上界为 $5 - (3 - 1) = 3$，即第一个数字最多只能选到 $3$（对应最后一个组合 `3 4 5`），完全不必尝试 $4$ 或 $5$；
  - 第 $2$ 个位置（$\text{step} = 2$）：上界为 $5 - (3 - 2) = 4$；
  - 第 $3$ 个位置（$\text{step} = 3$）：上界为 $5 - (3 - 3) = 5$。
- 加上这一上界剪枝后，递归搜索树上的每一个分支都必然能抵达合法叶子节点，没有任何一步无效回溯。

---

#### 4. 场宽控制与时空复杂度分析

1. **`setw(3)` 格式化输出细节**：
   - C++ 标准库 `<iomanip>` 提供的 `setw(3)` 操作符用于将**紧随其后的那一个输出项**的场宽设为 $3$ 个字符（默认右对齐，不足部分在左侧补空格）。
   - 注意 `setw` 是**一次性生效**的：每次输出一个元素 `chosen[i]` 前，都必须写一次 `cout << setw(3) << chosen[i];`。
2. **复杂度评估**：
   - **时间复杂度**：开启可行性剪枝后，递归树叶子节点数精确等于组合数 $\binom{n}{r}$，每个叶子节点输出耗时 $\mathcal{O}(r)$，总时间复杂度为 $\mathcal{O}\left(r \cdot \binom{n}{r}\right)$。在 $n = 20, r = 10$ 的最坏情况下，$\binom{20}{10} = 184756$，总操作次数约 $1.8 \times 10^6$，仅需约 $15\text{ms}$ 即可跑完，远低于 $1.00\text{s}$ 时限。
   - **空间复杂度**：递归调用栈的最大深度为 $r + 1$（不超过 $22$ 层），辅助数组 `chosen` 长度仅为 $25$，空间复杂度为 $\mathcal{O}(r)$，内存开销几乎可以忽略不计。

### 完整参考代码 (C++11)

```cpp
/**
 * Problem: luogu-P1157 组合的输出
 * Algorithm: 递归枚举与可行性剪枝 (Recursive Combination Enumeration)
 * Standard: C++11 (CCF GESP 四级 / CSP-J 官方规范)
 * Author: OneCoder
 */

#include <iostream>
#include <iomanip>

using namespace std;

int n, r;
int chosen[25]; // chosen[step] 用于记录当前组合中第 step 个位置选定的数字

/**
 * 递归枚举所有组合
 * @param step  当前正在确定组合中的第几个位置（从 1 到 r）
 * @param start 当前位置允许选择的最小起始数字（保证组合内元素严格递增）
 */
void dfs(int step, int start) {
    // 递归边界：当 step > r 时，说明前 r 个位置已全部选定，按场宽格式输出
    if (step > r) {
        for (int i = 1; i <= r; ++i) {
            cout << setw(3) << chosen[i];
        }
        cout << "\n";
        return;
    }

    // 枚举当前第 step 个位置填入的数字 i
    // 可行性剪枝：剩余可选数字个数 (n - i) 必须不少于后续还需填满的位置数 (r - step)
    // 因此 i 的最大合法取值为 n - (r - step)
    for (int i = start; i <= n - (r - step); ++i) {
        chosen[step] = i;       // 在第 step 个位置放入数字 i
        dfs(step + 1, i + 1);   // 递归确定第 step + 1 个位置，下界从 i + 1 开始
    }
}

int main() {
    // 读取元素总数 n 和抽取个数 r
    cin >> n >> r;

    // 从第 1 个位置开始搜索，初始可选最小数字为 1
    dfs(1, 1);

    return 0;
}
```

### 常见失分点与避坑指南

1. **误加额外空格导致格式错误（Presentation Error）**：
   - 题目要求“每个元素占三个字符的位置”，使用 `cout << setw(3) << chosen[i]` 已经自带了前导空格（例如数字 `1` 会输出为 `  1`，数字 `12` 会输出为 ` 12`）。**切忌**在两个数字之间再额外输出空格（如写成 `cout << setw(3) << chosen[i] << " ";`），否则每个数字实际占用了 $4$ 个字符宽度，会导致全盘 WA。
2. **把“组合”写成“全排列”**：
   - 许多刚学完深搜的同学习惯开一个 `bool vis[25]` 数组，每次从 `1` 循环到 `n`。那样求出的是 $A_n^r$（排列），不仅输出行数多出 $r!$ 倍，且破坏了组合内部从小到大的单调性。组合问题只需传递递增下界 `i + 1`，无需 `vis` 数组。
3. **遗漏 `<iomanip>` 头文件**：
   - `setw()` 操纵符定义在标准头文件 `<iomanip>` 中，仅包含 `<iostream>` 在标准 C++11 编译器下会报编译错误（CE）。
