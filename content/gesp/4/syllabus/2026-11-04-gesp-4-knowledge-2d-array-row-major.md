为什么我们在纸上画二维数组 `int a[3][4];` 时，它明明是一张 $3$ 行 $4$ 列的二维网格表，但在计算机物理内存（RAM）中，它却被压扁成了一条头尾相接的一维直线？更让人困惑的是，为什么在声明或传参二维数组时，C++ 编译器允许省略第一维行数（如 `int a[][4]`），却绝对不允许省略第二维列数（写 `int a[3][]` 会当场报编译错误）？而在复赛写双重循环遍历矩阵时，仅仅把内层和外层循环的 `i`、`j` 顺序颠倒一下（变成“按列遍历”），在处理千万级元素时运行耗时竟然会暴涨数倍？在 GESP 四级认证以及 CSP-J 初赛单项选择与复赛矩阵模拟题中，**二维数组的“行优先（Row-Major）”线性存储原理、已知首地址求任意元素 `a[i][j]` 内存地址的通用秒算公式、声明时列数不可省略的底层逻辑，以及按行遍历 vs 按列遍历的 CPU 高速缓存（Cache）命中率差异** 是必考的核心重难点。本文将带你彻底看清二维数组在物理内存中的真实排布，拿稳初赛地址计算与复赛矩阵遍历的每一分。

## 🎯 考纲锚点与核心痛点

> 📍 **对应考点**：深入理解二维数组在计算机内存中的“行优先（Row-Major Order）”连续存储机制，熟练掌握 `Addr(a[i][j])` 内存地址通用计算公式、二维数组初始化与声明省略规则，以及行优先遍历对 CPU 缓存局部性（Cache Locality）的性能影响。
> 🎯 **适用等级**：`GESP 四级考点 | CSP-J 初赛/复赛必考`

在考场做客观题与复赛写代码时，同学们最容易在以下三个地方栽跟头：
1. **“初赛地址计算时把行数 $R$ 和列数 $C$ 乘反”**：在求 `a[i][j]` 距离首地址跳过多少个元素时，误写成 $i \times R + j$（乘了总行数），或者在题目规定下标从 $1$ 开始（`1-based`）时忘记对行列下标同时减 $1$；
2. **“混淆 `int a[2][3] = {{1, 2}, {3}};` 与 `int a[2][3] = {1, 2, 3};` 的填充位置”**：在阅读程序题中，分不清按行分组花括号初始化与平铺顺序初始化在元素补 `0` 位置上的本质区别；
3. **“无脑交换内外层循环顺序引发 Cache 抖动超时”**：在复赛大矩阵遍历中，外层循环枚举列 `j`、内层循环枚举行 `i`（写出 `a[i][j]` 的跳跃式按列访问），导致 CPU 高速缓存频繁失效（Cache Miss），白白丢掉常数优化分甚至触发 `TLE`。

## 🧠 一、 核心原理深度拆解（有理论）

### 1. 二维数组的本质：“数组的数组”与行优先（Row-Major）存储

计算机的物理内存（RAM）就像一条无限延伸的单行街道，每个字节都有唯一的线性门牌号（内存地址），硬件层面根本不存在所谓的“二维平面空间”。

那么，C++ 是如何把一个 $R$ 行 $C$ 列的二维数组 `T a[R][C];` 塞进一维线性内存里的呢？
C/C++ 标准采用的是**“行优先存储（Row-Major Order）”**策略——即**先完整存放第 `0` 行的所有 $C$ 个元素，紧接着存放第 `1` 行的所有 $C$ 个元素，依此类推，直到第 `R - 1` 行**。

从语法底层来看，`int a[2][3];` 本质上是一个**长度为 $2$ 的一维数组**，只不过它的每一个元素 `a[0]`、`a[1]` 本身又是一个**长度为 $3$ 的一维整型数组（即“数组的数组”）**！

假设定义 `int a[2][3] = {{10, 20, 30}, {40, 50, 60}};`，且首元素 `a[0][0]` 的起始地址为十进制 `1000`（每个 `int` 占 $4$ 字节），其逻辑二维视图与物理一维内存的映射关系如下：

```text
【逻辑二维视图 (2 行 × 3 列)】
         第 0 列     第 1 列     第 2 列
第 0 行 [ a[0][0]=10  a[0][1]=20  a[0][2]=30 ]  ──► 对应一维子数组 a[0]，占 3×4 = 12 字节
第 1 行 [ a[1][0]=40  a[1][1]=50  a[1][2]=60 ]  ──► 对应一维子数组 a[1]，占 3×4 = 12 字节

【物理一维连续内存布局 (Row-Major 行优先拉平)】
 字节地址    1000~1003   1004~1007   1008~1011   1012~1015   1016~1019   1020~1023
           ┌───────────┬───────────┬───────────╦───────────┬───────────┬───────────┐
 数组元素  │  a[0][0]  │  a[0][1]  │  a[0][2]  ║  a[1][0]  │  a[1][1]  │  a[1][2]  │
           ├───────────┼───────────┼───────────╫───────────┼───────────┼───────────┤
 存储数值  │    10     │    20     │    30     ║    40     │    50     │    60     │
           └───────────┴───────────┴───────────╩───────────┴───────────┴───────────┘
 线性序号 k     k = 0       k = 1       k = 2       k = 3       k = 4       k = 5
           └──────────── 第 0 行 (a[0]) ───────┘└──────────── 第 1 行 (a[1]) ───────┘
```

### 2. 初赛必考：二维数组内存地址通用秒算公式

在 GESP 四级和 CSP-J 初赛中，最经典的题型就是：“已知二维数组规模与某个元素的内存地址，求另一个元素 `a[i][j]` 的内存地址”。

假设二维数组共 $R$ 行 $C$ 列，每个元素占用字节数为 $L = \text{sizeof}(T)$：

#### （1）标准 `0-based` 下标（行号 $0 \sim R-1$，列号 $0 \sim C-1$）
要从首元素 `a[0][0]` 走到目标元素 `a[i][j]`：
1. 首先需要**完整跨过前面的 $i$ 整行**，每行有 **$C$ 个元素**（注意是乘列数 $C$，绝不是乘行数 $R$！），共跳过 $i \times C$ 个元素；
2. 然后在当前第 $i$ 行内部，再往右**跨过前面的 $j$ 个元素**；
3. 因此，`a[i][j]` 距离首地址一共偏移了 **$k = i \times C + j$** 个元素！

由此得到 **C++ 二维数组寻址核心公式**：
$$\text{Addr}(a[i][j]) = \text{Addr}(a[0][0]) + (i \times C + j) \times \text{sizeof}(T)$$

反之，如果已知一维线性偏移序号 $k$（$0 \le k < R \times C$），利用整除与取模运算即可瞬间还原出它的二维行列坐标：
$$i = k \mathbin{/} C, \qquad j = k \bmod C$$

#### （2）初赛数学题变体：`1-based` 下标（题目声明行号从 $1 \sim R$，列号从 $1 \sim C$）
如果初赛选择题明确说明“数组下标从 $1$ 开始，首元素为 $A[1][1]$”，则站在 $A[i][j]$ 前面的完整行数是 $(i - 1)$ 行，当前行前面有 $(j - 1)$ 个元素：
$$\text{Addr}(A[i][j]) = \text{Addr}(A[1][1]) + \big[(i - 1) \times C + (j - 1)\big] \times \text{sizeof}(T)$$

#### （3）降维打击：任意两元素 $a[i_1][j_1]$ 与 $a[i_2][j_2]$ 之间的地址换算
无论下标从 $0$ 还是从 $1$ 开始，都不需要先倒推首地址，直接用**“行差乘列数，加上列差”**：
$$\text{Addr}(a[i_2][j_2]) - \text{Addr}(a[i_1][j_1]) = \big[(i_2 - i_1) \times C + (j_2 - j_1)\big] \times \text{sizeof}(T)$$

### 3. 为什么声明/传参二维数组时，“行数可省，列数必写”？

观察上面的寻址公式 $\text{Addr}(a[i][j]) = \text{BaseAddr} + (i \times \mathbf{C} + j) \times \text{sizeof}(T)$，你会立刻恍然大悟：
* 公式里**根本没有出现总行数 $R$**！编译器生成计算 `a[i][j]` 地址的机器指令时，完全不需要知道这个数组一共有多少行；
* 但是公式里**必须用到每行的列数 $C$**！如果不知道每行有几个元素（即列数 $C$），编译器连 `a[1][0]` 应该从首地址往后跳过多少个字节都算不出来！

因此，在初始化二维数组或编写接收二维数组的函数形参时：

| 声明 / 形参写法 | 编译是否合法？ | 底层原因解析 |
| :---: | :---: | :--- |
| `int a[][4] = {1, 2, 3, 4, 5};` | ✅ **合法** | 编译器已知每行固定 $C = 4$ 列，$5$ 个元素自动推断出需要 $\lceil 5 / 4 \rceil = 2$ 行（即 `a[2][4]`） |
| `void func(int a[][100], int n)` | ✅ **合法** | 函数形参已知列数 $C = 100$，可执行 `+ (i * 100 + j) * 4` 寻址 |
| `int a[2][] = {1, 2, 3, 4, 5, 6};` | ❌ **编译错误** | 缺失第二维列数 $C$，编译器无法确定行跨度（Stride），寻址公式瘫痪 |
| `void func(int a[][], int n, int m)` | ❌ **编译错误** | 缺失第二维列数 $C$，C++ 静态数组不支持未知列数的二维下标寻址 |

### 4. 按行遍历 vs 按列遍历：CPU 高速缓存（Cache Line）的性能玄机

在复赛中处理 $N \times N$（如 $2000 \times 2000$）的二维网格时，下面两段总运算次数完全相同（都是 $N^2$ 次加法）的代码，运行速度却天差地别：

| 遍历方式 | 循环结构代码 | 内存访问轨迹与 CPU 缓存（Cache）命中分析 | 实测效率对比 |
| :---: | :--- | :--- | :---: |
| **按行遍历**<br>（外层行 `i`，内层列 `j`） | `for (int i = 0; i < n; i++)`<br>&nbsp;&nbsp;`for (int j = 0; j < n; j++)`<br>&nbsp;&nbsp;&nbsp;&nbsp;`sum += a[i][j];` | 顺着物理内存连续读取 `a[0][0] -> a[0][1] -> a[0][2]...`。CPU 从内存读取数据时，每次会顺带把相邻的 $64\text{ Bytes}$（约 $16$ 个 `int`，称为一条 **Cache Line**）整块预取进超高速 L1 Cache。后续 $15$ 次读取**全部直接命中 L1 缓存（Cache Hit）**！ | ⚡ **极快**<br>（基准耗时 $1\times$） |
| **按列遍历**<br>（外层列 `j`，内层行 `i`） | `for (int j = 0; j < n; j++)`<br>&nbsp;&nbsp;`for (int i = 0; i < n; i++)`<br>&nbsp;&nbsp;&nbsp;&nbsp;`sum += a[i][j];` | 跳跃式读取 `a[0][0] -> a[1][0] -> a[2][0]...`。每次访问在内存中都要跨越整整一行（$N \times 4\text{ Bytes}$），导致 CPU 预取进缓存的相邻元素全部作废，几乎每次访问都触发**缓存未命中（Cache Miss）**，被迫去慢速主存拉取数据！ | 🐢 **极慢**<br>（耗时慢 **$3 \sim 8$ 倍**） |

> 💡 **考场黄金法则（背诵直接套用）**：
> 1. **【初赛寻址秒算口诀】**：**“行差乘列数，加上列之差，再乘元素字节数，转成十六进制加！”** 切记公式 $(i \times C + j)$ 中乘的永远是**每行的列数 $C$（第二维大小）**，绝不是行数 $R$！
> 2. **【声明与遍历铁律】**：**“二维声明行可省，列数缺失必报错；双重循环行在外、列在内，顺着内存跑得快！”**

## 🔍 二、 具象代码与数据推演（有举例）

下面这段标准的 C++11 示例程序直观展示了二维数组 `sizeof` 字节容量计算（总字节数 vs 单行字节数），以及为什么二维数组在底层内存中就是一维连续排列（通过一维指针偏移 `*(p + 4)`、行内跨界下标 `a[0][4]` 与标准二维下标 `a[1][1]` 访问到同一个内存单元）：

```cpp
#include <iostream>
using namespace std;

int main() {
    int a[2][3] = {{10, 20, 30}, {40, 50, 60}};
    int *p = &a[0][0];
    int row_bytes = sizeof(a[0]);
    int total_bytes = sizeof(a);
    cout << total_bytes << " " << row_bytes << endl;
    cout << *(p + 4) << " " << a[0][4] << " " << a[1][1] << endl;
    return 0;
}
```

### 分步内存与变量状态推演表

| 执行阶段 / 表达式 | 底层寻址计算过程（设 `&a[0][0]` 为 `Base`） | 命中物理内存单元 | 核心机制拆解与输出 |
| :---: | :--- | :--- | :--- |
| **`sizeof(a)` 与 `sizeof(a[0])`** | `total_bytes = 2 * 3 * 4 = 24`<br>`row_bytes = 3 * 4 = 12` | 整个矩阵与第 `0` 行 | `a` 是 $2 \times 3$ 整型矩阵，共占 $24$ 字节；`a[0]` 代表第 `0` 行的一维数组 `int[3]`，占 $12$ 字节。<br>第一行输出：**`24 12`** |
| **指针偏移 `*(p + 4)`** | `Base + 4 * sizeof(int)`<br>`= Base + 16 Bytes` | 线性第 $5$ 个元素<br>（序号 $k = 4$） | 将二维矩阵视为一维连续内存，从 `a[0][0]` 往后跨过 $4$ 个 `int`（第 `0` 行的 $3$ 个 + 第 `1` 行的第 $1$ 个），读出数值 **`50`** |
| **行内越界寻址 `a[0][4]`** | `Base + (0 * 3 + 4) * 4`<br>`= Base + 16 Bytes` | 实际落入下一行的 **`a[1][1]`** | 编译器按公式算出偏移 $0 \times 3 + 4 = 4$ 个元素，由于行优先紧挨存放，第 `0` 行下标越界到 `4` 时，正好无缝落入第 `1` 行的 `a[1][1]`（值为 **`50`**）！ |
| **标准二维寻址 `a[1][1]`** | `Base + (1 * 3 + 1) * 4`<br>`= Base + 16 Bytes` | 标准定位 **`a[1][1]`** | 跨过第 `0` 行的 $3$ 个元素，再跨过第 `1` 行的第 $0$ 列，精准命中 `a[1][1]`。<br>第二行输出：**`50 50 50`** |

## ⚡ 三、 考场高频避坑指南（正误辨析）

在 GESP 四级客观题与 CSP-J 初赛阅读程序中，以下三个关于二维数组的陷阱几乎每年必考：

### ❌ 易错点 1：分不清“分组花括号初始化”与“平铺顺序初始化”的落位差异
* **错误认知**：以为 `int a[2][3] = {{1, 2}, {3}};` 和 `int a[2][3] = {1, 2, 3};` 初始化出来的二维数组完全一样。
* **为什么错**：
  1. **带内层花括号 `int a[2][3] = {{1, 2}, {3}};`（按行分组初始化）**：第一个内层花括号 `{1, 2}` 专门负责喂给**第 `0` 行**，因此 `a[0][0] = 1, a[0][1] = 2`，而第 `0` 行没写出的 `a[0][2]` 立即被自动补为 **`0`**；第二个内层花括号 `{3}` 专门负责喂给**第 `1` 行**，因此 **`a[1][0] = 3`**，`a[1][1] = 0, a[1][2] = 0`！
  2. **不带内层花括号 `int a[2][3] = {1, 2, 3};`（按行优先平铺初始化）**：编译器按照行优先线性顺序依次填入前 $3$ 个位置，即第 `0` 行的 `a[0][0] = 1, a[0][1] = 2, a[0][2] = 3`，而第 `1` 行的 **`a[1][0]` 则是 `0`**！
* **对比速查**：在前者中 `a[0][2]` 是 `0`、`a[1][0]` 是 `3`；在后者中 `a[0][2]` 是 `3`、`a[1][0]` 是 `0`，千万不能混为一谈！

### ❌ 易错点 2：把数学坐标 $(x, y)$ 直接当成二维数组下标 `a[x][y]` 导致行列颠倒
* **错误写法**：题目描述“平面直角坐标系中横向为 $x$ 轴（共 $W$ 列），纵向为 $y$ 轴（共 $H$ 行）”，选手习惯性地开数组 `int a[H][W];`，却在访问时写成 `a[x][y]`。
* **为什么错**：在二维数组 `a[i][j]` 中，第一个下标 `i` 代表的是**行号（对应纵向的垂直高度 $y$）**，第二个下标 `j` 代表的是**列号（对应横向的水平宽度 $x$）**！如果混用就会在非正方形矩阵（$H \neq W$）中引发严重的下标越界。
* **正确规范**：在网格图模拟、迷宫 BFS/DFS 中，强烈建议统一使用 **`r`（Row，行）和 `c`（Col，列）** 或严格约定“`x` 表示第几行（向下为正），`y` 表示第几列（向右为正）”，彻底告别平面几何坐标系与矩阵行列的混淆。

### ❌ 易错点 3：在函数内部对二维数组形参使用 `sizeof(a)` 求矩阵总字节数
* **错误写法**：编写函数 `void clear_matrix(int a[10][20]) { memset(a, 0, sizeof(a)); }`，以为 `sizeof(a)` 会算出 $10 \times 20 \times 4 = 800$ 字节。
* **为什么错**：在 C++ 中，当数组（无论是几维数组）作为函数参数传递时，第一维都会自动**退化（Decay）为指向首行的指针**（即 `int a[10][20]` 在形参中实质等同于行指针 `int (*a)[20]`）！在 64 位系统下对指针求 `sizeof(a)` 只会固定得到 **$8$ 字节**（32 位系统下为 $4$ 字节），导致只清空了前两个整数！

## 📝 四、 真题实战演练与精析（有例题：3 道）

### 【例题 1 · 单选题】（GESP 四级 / CSP-J 初赛二维数组内存寻址真题）

**题目**：在 C++ 语言中，定义一个 $5$ 行 $6$ 列的二维整型数组 `int a[5][6];`（已知每个 `int` 型元素占 $4$ 个字节，数组按行优先顺序连续存储）。若测得首元素 `a[0][0]` 的内存起始地址为十六进制 `0x1000`，则元素 `a[3][4]` 的内存起始地址为（ ）。
* **A.** `0x1058`
* **B.** `0x104C`
* **C.** `0x1068`
* **D.** `0x1088`

**🔍 答案与逐项排除解析**：
* **正确答案**：**A**
* **解析过程**：
  1. **提取矩阵维度参数**：总行数 $R = 5$，**每行元素个数（列数）$C = 6$**，单个元素字节数 $\text{sizeof}(\text{int}) = 4\text{ Bytes}$。
  2. **计算线性偏移元素个数 $k$**：从 `a[0][0]` 到 `a[3][4]`，需要先完整跨过第 `0`、`1`、`2` 共 **$3$ 整行**（每行 $6$ 个元素），再在第 `3` 行内跨过第 `0`、`1`、`2`、`3` 共 **$4$ 个元素**：
     $$k = i \times C + j = 3 \times 6 + 4 = 22\text{ 个元素}$$
  3. **计算字节偏移量并转换为十六进制**：
     $$\Delta\text{Bytes} = 22 \times 4 = 88\text{ Bytes}_{(10)}$$
     将十进制的 $88$ 转换为十六进制：$88 \div 16 = 5 \cdots 8$，即 $88_{(10)} = 5 \times 16^1 + 8 \times 16^0 = \mathbf{\text{0x58}}$。
  4. **相加得出目标地址**：
     $$\text{Addr}(a[3][4]) = \text{0x1000} + \text{0x58} = \mathbf{\text{0x1058}}$$
  5. **排除干扰项**：
     * **B 项（`0x104C`）**：犯了“乘错维度”的经典错误，把公式写成了 $i \times R + j = 3 \times 5 + 4 = 19$ 个元素，$19 \times 4 = 76_{(10)} = \text{0x4C}$；
     * **C 项（`0x1068`）**：把 `a[3][4]` 误当成跨过了 $4$ 整行加 $2$ 列（或算错十六进制进位）；
     * **D 项（`0x1088`）**：算出十进制偏移 $88$ 字节后，忘了转十六进制，直接把十进制 `88` 拼接到 `0x1000` 后面写成了 `0x1088`。故正确选项为 **A**。

### 【例题 2 · 判断题】（GESP 四级官方考纲真题辨析：二维数组声明与初始化）

**题目**：在 C++ 语言中，定义二维数组并赋初值时，语句 `int a[2][3] = {{1, 2}, {3, 4}};` 与语句 `int b[2][] = {1, 2, 0, 3, 4, 0};` 均能正常通过编译，且元素 `a[1][0]` 的值为 `3`。（ ）

**🔍 答案与反例证明**：
* **结论**：**错误（$\times$）**
* **反例证明**：
  1. 前半句中的 `int a[2][3] = {{1, 2}, {3, 4}};` 完全合法：第 `0` 行被初始化为 `{1, 2, 0}`，第 `1` 行被初始化为 `{3, 4, 0}`，因此 **`a[1][0]` 的值确实等于 `3`**；
  2. 但是后半句中的 **`int b[2][] = {1, 2, 0, 3, 4, 0};` 会直接导致编译错误（Compile Error）**！根据 C++ 多维数组语法规范，在声明二维数组时，**只允许省略第一维（行数），绝对不允许省略第二维（列数）**（若写成 `int b[][3] = {1, 2, 0, 3, 4, 0};` 才能通过编译）。因为缺失列数会导致编译器无法确定每一行占用的内存字节跨度，故原命题错误。

### 【例题 3 · 微代码实战】（经典复赛模型：行优先高能扫描与一维线性偏移反查）

**题目描述**：某光学遥感卫星拍摄了一幅 $n$ 行 $m$ 列的辐射强度矩阵 `g`（行下标为 `0 ~ n-1`，列下标为 `0 ~ m-1`，满足 $1 \le n, m \le 500$）。矩阵按标准的行优先（Row-Major）方式存储在连续内存中，每个 `int` 元素占 $4$ 个字节。
请你编写一个 C++11 程序完成两项任务：
1. **按行优先高效扫描**：计算每一行的辐射强度总和，找出**行总和最大**的那一行行号 `best_row` 及对应的最大行总和 `max_row_sum`（若有多行总和并列最大，取行号最小的那一行）；
2. **一维线性偏移反查**：给定一个一维线性偏移元素序号 $k$（$0 \le k < n \times m$，表示从 `g[0][0]` 开始往后数跳过 $k$ 个元素的位置），请利用行优先地址逆运算公式，直接算出该位置对应的二维行号 `r`、列号 `c`、该位置存储的元素值 `g[r][c]`，以及它相对于首地址 `&g[0][0]` 的**十进制字节偏移量 `byte_offset`**。
第一行输出 `best_row` 和 `max_row_sum`；第二行输出 `r`、`c`、`g[r][c]` 和 `byte_offset`（同行数字以单个空格分隔）。

**💡 建模思路**：
1. **全局矩阵与 Cache 友好遍历**：将二维数组 `int g[505][505];` 定义在全局区，既防止爆栈又自动清零。采用外层循环枚举行 `i`、内层循环枚举列 `j` 的标准行优先顺序累加每行元素，完全顺应物理内存连续布局，CPU 缓存命中率最高；
2. **一维偏移量 $k$ 逆向还原二维坐标**：因为每行固定有 $m$ 列，根据行优先公式 $k = r \times m + c$（其中 $0 \le c < m$），直接利用整除 **`r = k / m`** 算出所在行号，利用取模 **`c = k % m`** 算出所在列号，字节偏移量即为 **`k * 4`**，无需用双重循环去数第 $k$ 个元素，时间复杂度 $O(1)$！

```cpp
#include <iostream>
using namespace std;

const int MAXR = 505;
const int MAXC = 505;
int g[MAXR][MAXC];

int main() {
    int n, m, k;
    cin >> n >> m >> k;
    for (int i = 0; i < n; i++) {
        for (int j = 0; j < m; j++) {
            cin >> g[i][j];
        }
    }
    int max_row_sum = -1000000000;
    int best_row = 0;
    for (int i = 0; i < n; i++) {
        int cur_sum = 0;
        for (int j = 0; j < m; j++) {
            cur_sum += g[i][j];
        }
        if (cur_sum > max_row_sum) {
            max_row_sum = cur_sum;
            best_row = i;
        }
    }
    int r = k / m;
    int c = k % m;
    int byte_offset = k * 4;
    cout << best_row << " " << max_row_sum << endl;
    cout << r << " " << c << " " << g[r][c] << " " << byte_offset << endl;
    return 0;
}
```

* **输入样例 1**：
  ```text
  3 4 7
  1 2 3 4
  10 20 30 40
  5 6 7 8
  ```
* **输出样例 1**：
  ```text
  1 100
  1 3 40 28
  ```
  *（样例 1 解释：矩阵为 $3$ 行 $4$ 列。第 `0` 行和为 $10$，第 `1` 行和为 $10+20+30+40 = 100$，第 `2` 行和为 $26$，故最大行号为 **1**，总和为 **100**。线性偏移序号 $k = 7$ 时，行号 $r = 7 / 4 = 1$，列号 $c = 7 \bmod 4 = 3$，对应元素 `g[1][3]` 的值为 **40**，距离首地址偏移了 $7 \times 4 = \mathbf{28}$ 字节。）*
* **输入样例 2**：
  ```text
  2 3 4
  9 8 7
  6 5 4
  ```
* **输出样例 2**：
  ```text
  0 24
  1 1 5 16
  ```
