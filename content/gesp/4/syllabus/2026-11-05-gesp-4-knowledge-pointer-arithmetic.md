为什么在 C++ 中定义一个整型指针 `int *p = &a[0];`（假设起始地址为 `0x1000`），当我们对它执行看似最简单的加法 `p = p + 1;` 时，指针里存放的内存地址并没有变成 `0x1001`，而是直接跳到了 `0x1004`？更让人不可思议的是，如果另一个指针 `q` 指向 `a[3]`（地址为 `0x100C`），两个地址明明相差了 $12$ 个字节，为什么表达式 `q - p` 算出来的结果却是 `3` 而不是 `12`？而在 64 位操作系统下，无论指针指向的是占 $1$ 字节的 `char` 还是占 $8$ 字节的 `double`，为什么 `sizeof(char*)` 和 `sizeof(double*)` 算出来的大小永远一模一样？在 GESP 四级认证以及 CSP-J 初赛单项选择与阅读程序题中，**取址符 `&` 与解引用符 `*` 的互逆本质、指针算术运算的“基类型步长（Stride）”缩放机制、数组名退化与 `*(a + i) == a[i]` 恒等式，以及空指针 `nullptr` 与野指针（Wild Pointer）的识别防范** 是必考的核心重难点。本文将带你穿透语法表象，从物理内存门牌号的视角彻底搞懂指针的底层运作法则。

## 🎯 考纲锚点与核心痛点

> 📍 **对应考点**：深入理解指针变量的底层内存模型，熟练掌握取址符 `&` 与解引用符 `*`、指针加减整数的步长换算（`sizeof` 基类型）与两指针相减的元素距离计算、一维数组名与指针的等价寻址公式 `*(a + i) == a[i]`，以及空指针 `nullptr` 与野指针的安全规范。
> 🎯 **适用等级**：`GESP 四级考点 | CSP-J 初赛/复赛必考`

在考场做客观题与阅读程序时，同学们最容易在以下三个地方栽跟头：
1. **“把指针算术运算当成普通十进制整数加减”**：看到 `int *p`（初值 `0x2000`）执行 `p + 2` 就脱口而出 `0x2002`，完全忽略了指针加减 $k$ 的本质是跳过 $k$ 个完整的基类型元素（即 `k * sizeof(T)` 字节）；或者在算 `q - p` 时直接用十六进制地址相减，忘了再除以 `sizeof(T)`；
2. **“混淆指针变量自身的大小 `sizeof(p)` 与它所指目标的大小 `sizeof(*p)`”**：误以为 `double *p;` 占 $8$ 字节是因为 `double` 占 $8$ 字节，进而在 32 位系统考题中把 `sizeof(double*)` 错选成 $8$（32 位系统下任何指针自身均只占 $4$ 字节）；
3. **“分不清 `*p + 1` 与 `*(p + 1)` 的天壤之别，或对未初始化的野指针直接解引用”**：在阅读程序时看漏括号优先级，把“取出当前元素值再加 $1$”和“指向下一个相邻元素并取值”混为一谈；或者写出 `int *p; *p = 10;` 这种直接往随机内存地址写数据的致命野指针代码，引发 `Segmentation fault`（段错误 RE）。

## 🧠 一、 核心原理深度拆解（有理论）

### 1. 指针到底是什么？内存房间号与“寻宝纸条”模型

计算机的物理内存（RAM）被划分为一个个连续的**字节（Byte）单元**，操作系统为每一个字节都编上了唯一的十六进制编号（如 `0x1000`、`0x1001`……），这就是**内存地址（Memory Address）**。

* **普通变量（如 `int x = 25;`）**：就像一间由 $4$ 个连续字节（`0x1000 ~ 0x1003`）打通组成的“储物间”，房间里面直接存放着整数数值 `25`；
* **指针变量（如 `int *p = &x;`）**：它自己也是一间独立的内存房间（如位于 `0x2000 ~ 0x2007`），但**它里面不存普通数值，而是专门用来抄写另一个变量的“门牌号（首字节地址 `0x1000`）”**！

围绕这张“写着门牌号的寻宝纸条”，C++ 提供了两个互为逆运算的核心操作符：
1. **取地址运算符 `&`（Address-of）**：`&x` 表示“查出变量 `x` 占据的第一个字节的内存门牌号”（即得到地址 `0x1000`）；
2. **解引用运算符 `*`（Dereference / Indirection）**：`*p` 表示“顺着指针 `p` 纸条上写的门牌号 `0x1000` 找过去，打开那间房门，直接读写里面的变量 `x`”！因此，**`*p` 在语法和内存效果上完全等价于变量 `x` 本身（即 `*&x == x`）**——读 `*p` 就是读 `x`，修改 `*p = 99;` 就是直接把 `x` 的值改成 `99`！

```text
【普通变量 x 的内存房间】                   【指针变量 p 的内存房间】
 起始地址：0x1000 (占 4 字节)                起始地址：0x2000 (64位下占 8 字节)
┌───────────────────────────┐              ┌───────────────────────────┐
│        数值：25            │ ◄─────────── │     保存的地址：0x1000     │
└───────────────────────────┘   *p 顺藤摸瓜  └───────────────────────────┘
       ▲                                                  ▲
       └────────────────── &x 提取首字节门牌号 ─────────────┘
```

#### ⚠️ 考场高频铁律：`sizeof(指针)` vs `sizeof(*指针)`
因为指针变量里装的仅仅是一个“内存门牌号”，而门牌号有多长，**只取决于操作系统地址总线的位数（即 CPU 是 32 位还是 64 位），与那个房间里装的是 `char`、`int` 还是巨大的结构体 `struct` 毫无关系**！

| 表达式 | 32 位编译环境 | 64 位编译环境（NOI Linux 2.0 标准） | 核心原理剖析 |
| :---: | :---: | :---: | :--- |
| `sizeof(char*)` / `sizeof(int*)` / `sizeof(double*)` | 固定 **$4$ 字节** | 固定 **$8$ 字节** | 测量的是“门牌号纸条”本身的尺寸（$32\text{ bits} = 4\text{ Bytes}$，$64\text{ bits} = 8\text{ Bytes}$），**所有类型的指针大小完全相同**！ |
| `sizeof(*p)`（设 `char *p`） | $1$ 字节 | $1$ 字节 | 解引用后等价于目标变量 `char`，测量的是目标房间的大小 |
| `sizeof(*q)`（设 `double *q`） | $8$ 字节 | $8$ 字节 | 解引用后等价于目标变量 `double`，测量的是目标房间的大小 |

### 2. 为什么 `int *p` 执行 `p + 1` 地址加了 $4$ 而不是 $1$？

既然所有指针的尺寸都一样，那为什么声明指针时不能只写一个通用的 `pointer p;`，而必须严格指明基类型 `int *p`、`char *p` 或 `double *p` 呢？

答案主要有两点：
1. **解引用 `*p` 时需要知道读取几个字节**：如果只知道起始地址是 `0x1000`，CPU 怎么知道该从 `0x1000` 开始连读 $1$ 个字节（`char`）、$4$ 个字节（`int`）还是 $8$ 个字节（`double`）？正是指针的**基类型 $T$** 决定了 `*p` 一次性吞吐的字节宽度；
2. **指针算术运算时决定“步长（Stride）”**：在数组中，一个 `int` 占据 $4$ 个字节（`0x1000 ~ 0x1003`）。如果 `p + 1` 真的只把地址加 $1$ 变成 `0x1001`，那指针岂不是一头扎进了第一个整数 `a[0]` 的“肚子正中间”，读出半截错乱的二进制位？

为了保证 `p + 1` 永远精准地指向**下一个完整的同类型元素**，C++ 编译器在底层为指针加减法设计了自动缩放公式——**指针每加减 $1$，物理内存地址自动加减 $1$ 个基类型字节数 $\text{sizeof}(T)$**：

$$\text{Addr}(p \pm k) = \text{Addr}(p) \pm k \times \text{sizeof}(T)$$

同理，当两个指向同一个数组的同类型指针 `q` 和 `p` 相减（`q - p`）时，它的含义**绝不是两个十六进制地址相差多少字节，而是两个指针之间隔了多少个完整的基类型元素**：

$$q - p = \frac{\text{Addr}(q) - \text{Addr}(p)}{\text{sizeof}(T)}$$

请看 `int a[4] = {10, 20, 30, 40};` 中 `char*`、`int*`、`double*` 指针步长的直观对比：

```text
【int a[4] 物理内存布局（每个 int 占 4 字节，首地址 0x1000）】
 字节地址    0x1000~0x1003     0x1004~0x1007     0x1008~0x100B     0x100C~0x100F
           ┌─────────────────┬─────────────────┬─────────────────┬─────────────────┐
 数组元素  │    a[0] = 10    │    a[1] = 20    │    a[2] = 30    │    a[3] = 40    │
           └─────────────────┴─────────────────┴─────────────────┴─────────────────┘
 指针定位    ▲                 ▲                 ▲                 ▲
            p = &a[0]         p + 1             p + 2             q = p + 3
           (0x1000)          (0x1004)          (0x1008)          (0x100C)
              │                                                     │
              └────────── 字节差 = 0x100C - 0x1000 = 12 Bytes ──────┘
              └────────── 元素差 (q - p) = 12 / sizeof(int) = 3 ────┘
```

### 3. 数组名退化与黄金恒等式 `*(a + i) == a[i]`

在 C++ 中，一维数组名 `a` 在绝大多数表达式中都会自动**退化（Decay）为指向数组首元素 `a[0]` 的指针常量**（即 `a` 的值就等于 `&a[0]`）。

当我们在代码里写下熟悉的下标访问 `a[i]` 时，C++ 编译器在底层实际上会无条件将它翻译为**“首地址 `a` 往后偏移 $i$ 个元素步长，然后解引用”**！由此诞生了贯穿 C/C++ 指针与数组的**四大等价寻址恒等式**（设 `int *p = a;`）：

| 访问形式 | 表达式写法 | 底层等价含义 |
| :---: | :---: | :--- |
| **数组下标法** | `a[i]` | 最直观的日常写法，底层自动转为 `*(a + i)` |
| **数组名偏移解引用** | `*(a + i)` | 从数组首地址 `a` 跨越 $i$ 个元素步长后解引用取值 |
| **指针偏移解引用** | `*(p + i)` | 从指针 `p` 跨越 $i$ 个元素步长后解引用取值 |
| **指针下标法** | `p[i]` | 指针同样可以直接带方括号下标，等价于 `*(p + i)` |

> ⚠️ **注意唯一区别**：指针变量 `p` 是一个真正的**变量**，你可以随时执行 `p++` 或 `p = p + 1` 让它改指别处；但**数组名 `a` 是一个“地址常量”**，它的门牌号在数组诞生时就被焊死了，如果在代码中写 `a++` 或 `a = a + 1`，会当场触发 **编译错误（Compile Error）**！

### 4. 空指针 `nullptr` 与夺命“野指针”防范

在考场与工程实践中，指针最危险的状态莫过于成为失控的**野指针（Wild Pointer）**或**悬垂指针（Dangling Pointer）**：

1. **野指针（Wild Pointer）**：在函数内部声明了一个局部指针变量 `int *p;`，但**没有给它赋任何初值**。此时 `p` 存储在栈区，里面装着一串完全随机的垃圾地址（比如 `0x7fff3a9b...`）。一旦执行 `*p = 100;`，就相当于拿着一张乱写的假门牌号去强拆别人的受保护内存，程序会立即崩溃（`Segmentation fault`）！
2. **空指针（`nullptr` / `NULL`）**：如果暂时不知道让指针指向谁，必须显式将它初始化为 **`int *p = nullptr;`**（C++11 推荐标准，等价于指向特殊零地址 `0x0` 的 `NULL`）。操作系统的 `0x0` 号地址区域是严禁读写的“禁区”，虽然对空指针解引用 `*p` 也会崩溃，但我们可以随时用 `if (p != nullptr)` 安全地检查它是否有效，而野指针里装的是非零随机值，根本无法通过 `if` 判断检查出来！
3. **悬垂指针（Dangling Pointer）**：函数返回了内部普通局部变量的栈地址（如 `int x = 5; return &x;`），当函数结束栈帧销毁后，指针虽然还握着旧门牌号，但那间房子已经被操作系统回收挪作他用了。

> 💡 **考场黄金法则（背诵直接套用）**：
> 1. **【指针算术缩放铁律】**：**“指针加 $k$ 跳 $k$ 格，字节偏移乘 `sizeof`；两针相减算格数，地址之差除 `sizeof`！”**
> 2. **【寻址与括号优先级口诀】**：**“`a[i]` 就是 `*(a + i)`，数组名字禁自增（`a++` 报错）；`*(p + 1)` 移位取下格，`*p + 1` 原地值加一！”**

## 🔍 二、 具象代码与数据推演（有举例）

下面这段标准的 C++11 示例程序完整演示了指针初始化、偏移读取 `*(p + 2)`、指针下标访问 `p[3]`、通过解引用修改原数组元素 `*p = *p + 5`，以及两指针相减 `q - p` 的全过程：

```cpp
#include <iostream>
using namespace std;

int main() {
    int a[4] = {10, 20, 30, 40};
    int *p = a;
    cout << *p << " " << *(p + 2) << " " << p[3] << endl;
    p = p + 1;
    *p = *p + 5;
    int *q = &a[3];
    cout << a[1] << " " << (q - p) << endl;
    return 0;
}
```

### 分步内存与变量状态推演表

假设数组 `a[4]` 的首地址 `&a[0]` 为 `0x1000`（每个 `int` 占 $4$ 字节）：

| 执行语句 | 指针 `p` 的地址与指向 | 数组 `a[0..3]` 内存实时状态 | 核心机制拆解与输出 |
| :---: | :---: | :---: | :--- |
| `int *p = a;` | `0x1000`（指向 `a[0]`） | `{10, 20, 30, 40}` | 数组名 `a` 退化为 `&a[0]`，指针 `p` 对准第 `0` 号元素 |
| `cout << *p << " " << *(p + 2) << " " << p[3]` | `0x1000`（`p` 自身未变） | `{10, 20, 30, 40}` | `*p` 取 `a[0]=10`；`*(p+2)` 临时往后跳 $2 \times 4 = 8$ 字节取 `a[2]=30`；`p[3]` 等价于 `*(p+3)` 取 `a[3]=40`。<br>第一行输出：**`10 30 40`** |
| `p = p + 1;` | **`0x1004`**（移向 `a[1]`） | `{10, 20, 30, 40}` | 指针 `p` 向前推进 $1$ 个 `int` 步长（地址 $+4$ 字节），正式指向 `a[1]` |
| `*p = *p + 5;` | `0x1004`（指向 `a[1]`） | `{10, `**`25`**`, 30, 40}` | 此时 `*p` 就是 `a[1]` 的本体！取出 `20` 加 `5` 后写回，`a[1]` 永久变为 **`25`** |
| `int *q = &a[3];`<br>`cout << a[1] << " " << (q - p)` | `p` 为 `0x1004` (`&a[1]`)<br>`q` 为 `0x100C` (`&a[3]`) | `{10, 25, 30, 40}` | `a[1]` 已变成 `25`；两指针相减 `q - p` 等于下标差 $3 - 1 = \mathbf{2}$（字节差 $8 \div 4 = 2$）。<br>第二行输出：**`25 2`** |

## ⚡ 三、 考场高频避坑指南（正误辨析）

在 GESP 四级客观题与 CSP-J 初赛阅读程序中，以下三个关于指针语法的陷阱几乎逢考必出：

### ❌ 易错点 1：混淆 `*(p + 1)` 与 `*p + 1` 的运算符优先级
* **错误认知**：以为 `*p + 1` 也是先让指针往后移一格再取值。
* **为什么错**：在 C++ 运算符优先级表中，**单目解引用运算符 `*` 的优先级远高于双目加法运算符 `+`**！
  1. **`*p + 1`（等价于 `(*p) + 1`）**：先执行 `*p` 把当前指向房间里的整数取出来，然后再把**这个整数值加 $1$**（指针 `p` 根本没动，也没看下一个房间）；
  2. **`*(p + 1)`**：因为有括号，先执行指针算术 `p + 1` 得到**下一个相邻元素的地址**，然后再解引用取出下一个房间里的元素值（等价于 `p[1]`）。

### ❌ 易错点 2：一行声明多个指针时漏写星号 `int* p, q;`
* **错误写法**：想同时定义两个整型指针 `p` 和 `q`，随手写成 `int* p, q;`。
* **为什么错**：在 C/C++ 的声明语法中，星号 `*` 是紧跟着**变量名**走的，而不是跟着左边的 `int` 走的！`int* p, q;` 在编译器眼里等价于 `int *p; int q;`——即**只有 `p` 是整型指针，而 `q` 只是一个普通的 `int` 整型变量**！
* **正确规范**：如果要在同一行声明多个指针变量，必须在每一个变量名前面都单独加上星号：**`int *p, *q;`**。

### ❌ 易错点 3：误以为两个指针不仅可以相减 `q - p`，还可以相加 `q + p`
* **错误认知**：既然 `q - p` 是合法的，那么把两个指针加起来 `q + p`、乘起来 `q * p` 肯定也能通过编译。
* **为什么错**：
  * 两个同类型指针**相减 `q - p` 具有明确的物理意义**——就像用“11 月 5 日”减去“11 月 2 日”可以得到“相差 $3$ 天”（两地址之间相隔的元素个数）；
  * 但是把两个内存地址**相加 `q + p` 没有任何物理意义**（就像把“11 月 5 日”加上“11 月 2 日”等于什么？而且两个很大的门牌号一加还会直接越出程序合法内存边界）。因此，**C++ 严禁指针与指针相加、相乘或相除**，写出 `p + q` 会直接导致 **编译错误（Compile Error）**！

## 📝 四、 真题实战演练与精析（有例题：3 道）

### 【例题 1 · 单选题】（GESP 四级 / CSP-J 初赛指针算术与地址计算真题）

**题目**：在 64 位 C++ 编译环境下（已知 `sizeof(long long) = 8`），定义一个长整型数组 `long long arr[10];` 并令指针 `long long *p = &arr[2];`。若测得指针 `p` 中当前存储的内存地址值为十六进制 `0x2010`，且另一个指针 `long long *q = &arr[7];`，则表达式 `p + 3` 的内存地址值以及表达式 `q - p` 的计算结果分别是（ ）。
* **A.** `0x2013` 和 `5`
* **B.** `0x2028` 和 `40`
* **C.** `0x2028` 和 `5`
* **D.** `0x201C` 和 `5`

**🔍 答案与逐项排除解析**：
* **正确答案**：**C**
* **解析过程**：
  1. **计算 `p + 3` 的十六进制内存地址**：指针 `p` 的基类型为 `long long`，每个元素占用步长 $\text{sizeof}(\text{long long}) = 8\text{ Bytes}$。因此 `p + 3` 在物理内存上向后偏移的字节数为：
     $$\Delta\text{Bytes} = 3 \times 8 = 24\text{ Bytes}_{(10)}$$
     将十进制的 $24$ 转换为十六进制：$24 = 1 \times 16^1 + 8 \times 16^0 = \mathbf{\text{0x18}}$。
     将其与 `p` 的起始地址 `0x2010` 相加：
     $$\text{Addr}(p + 3) = \text{0x2010} + \text{0x18} = \mathbf{\text{0x2028}}$$
  2. **计算两指针之差 `q - p`**：`q` 指向 `arr[7]`，`p` 指向 `arr[2]`。两同类型指针相减得到的是它们之间相隔的**元素个数**（即下标之差）：
     $$q - p = 7 - 2 = \mathbf{5}$$
  3. **排除干扰项**：
     * **A 项（`0x2013` 和 `5`）**：忘了乘基类型字节数 $8$，直接把地址加了 $3$；
     * **B 项（`0x2028` 和 `40`）**：地址算对了，但把 `q - p` 误算成了相差的字节数 $(7 - 2) \times 8 = 40$；
     * **D 项（`0x201C` 和 `5`）**：误把 `long long` 当成 $4$ 字节的 `int` 来算（$3 \times 4 = 12_{(10)} = \text{0xC}$，$\text{0x2010} + \text{0xC} = \text{0x201C}$）。故正确选项为 **C**。

### 【例题 2 · 判断题】（GESP 四级官方考纲真题辨析：指针大小与数组名常量性）

**题目**：在 64 位操作系统的 C++ 环境下，定义 `char c = 'A'; char *pc = &c;` 与 `double d = 3.14; double *pd = &d;`，因为 `double` 类型占用的字节数大于 `char` 类型，所以 `sizeof(pd)` 的值严格大于 `sizeof(pc)` 的值；同时，对于数组 `int a[5] = {1, 2, 3, 4, 5};`，执行语句 `a++;` 可以让 `a` 指向 `a[1]`。（ ）

**🔍 答案与反例证明**：
* **结论**：**错误（$\times$）**
* **反例证明**：本题前后两句话全部错误，精准命中了 GESP 四级最爱考的两个核心概念陷阱：
  1. **前半句错误**：`sizeof(pd)` 和 `sizeof(pc)` 测量的都是**指针变量自身（即存储内存地址的容器）**占用的字节数，而不是它们所指目标的大小（`sizeof(*pd)` 才是 $8$，`sizeof(*pc)` 才是 $1$）。在 64 位系统下，任何类型的指针变量固定占用 **$8$ 个字节**，因此 `sizeof(pd) == sizeof(pc) == 8`，两者完全相等！
  2. **后半句错误**：一维数组名 `a` 代表数组首元素的地址常量（相当于 `int * const`），**数组名不能作为左值被修改**。执行 `a++;`（等价于 `a = a + 1;`）会直接触发编译错误，只有定义独立的指针变量 `int *p = a; p++;` 才是合法的。故原命题错误。

### 【例题 3 · 微代码实战】（经典复赛模型：双指针原地翻转数组与指针算术指令模拟）

**题目描述**：给定一个长度为 $n$（$1 \le n \le 1000$）的整型数组 `a`（下标为 `0 ~ n-1`，每个 `int` 占 $4$ 个字节）以及 $m$ 条指针操作指令。请你全程使用指针算术与解引用操作完成以下两阶段任务：
1. **阶段一（双指针原地翻转）**：定义头指针 `int *left = a;` 和尾指针 `int *right = a + n - 1;`，当 `left < right` 时，不断通过解引用交换 `*left` 与 `*right` 的值，并将 `left` 向右移动一格、`right` 向左移动一格，完成整个数组的原地逆序翻转；
2. **阶段二（指针偏移修改与距离测算）**：依次处理 $m$ 条指令，每条指令输入三个整数 `idx1`、`idx2` 和 `delta`（保证 $0 \le \text{idx1}, \text{idx2} < n$）。令指针 `p1 = a + idx1`，指针 `p2 = a + idx2`：
   * 首先通过指针解引用将 `p1` 所指向的元素值增加 `delta`（即 `*p1 = *p1 + delta;`）；
   * 然后单行输出三个整数：修改后 `*p1` 的当前值、两指针的元素距离 `p2 - p1`，以及 `p2` 相对于 `p1` 的有符号字节偏移量 `(p2 - p1) * sizeof(int)`（以单个空格分隔）。
所有指令执行完毕后，在最后一行使用指针偏移形式 `*(a + i)` 依次输出数组 `a` 的全部 $n$ 个最终元素（以单个空格分隔）。

**💡 建模思路**：
1. **双指针碰撞法（Two Pointers）**：利用指针比较运算 `left < right` 控制循环边界，每次交换 `*left` 与 `*right` 后执行 `left = left + 1;` 和 `right = right - 1;`，只需 $O(n)$ 时间、$O(1)$ 额外空间即可原地翻转数组；
2. **指针差值与字节跨度**：利用 `p2 - p1` 直接得出有符号元素间距 `elem_diff`（若 `p2` 在 `p1` 左侧，结果自然为负数），再乘上 `sizeof(int)` 即可精准还原物理内存中的字节偏移差。

```cpp
#include <iostream>
using namespace std;

const int MAXN = 1005;
int a[MAXN];

int main() {
    int n, m;
    cin >> n >> m;
    for (int i = 0; i < n; i++) {
        cin >> a[i];
    }
    int *left = a;
    int *right = a + n - 1;
    while (left < right) {
        int tmp = *left;
        *left = *right;
        *right = tmp;
        left = left + 1;
        right = right - 1;
    }
    for (int i = 0; i < m; i++) {
        int idx1, idx2, delta;
        cin >> idx1 >> idx2 >> delta;
        int *p1 = a + idx1;
        int *p2 = a + idx2;
        *p1 = *p1 + delta;
        int elem_diff = p2 - p1;
        int byte_diff = elem_diff * sizeof(int);
        cout << *p1 << " " << elem_diff << " " << byte_diff << endl;
    }
    for (int i = 0; i < n; i++) {
        cout << *(a + i) << (i == n - 1 ? "" : " ");
    }
    cout << endl;
    return 0;
}
```

* **输入样例 1**：
  ```text
  5 2
  10 20 30 40 50
  1 4 5
  3 0 -2
  ```
* **输出样例 1**：
  ```text
  45 3 12
  18 -3 -12
  50 45 30 18 10
  ```
  *（样例 1 解释：初始数组 `{10, 20, 30, 40, 50}` 经阶段一双指针翻转后变为 `{50, 40, 30, 20, 10}`。第 1 条指令：`p1 = a + 1`（指向 `40`），`p2 = a + 4`（指向 `10`），`*p1` 加 `5` 后变为 **45**，`p2 - p1 = 4 - 1 =` **3**，字节偏移为 $3 \times 4 =$ **12**；第 2 条指令：`p1 = a + 3`（指向 `20`），`p2 = a + 0`（指向 `50`），`*p1` 加 `-2` 后变为 **18**，`p2 - p1 = 0 - 3 =` **-3**，字节偏移为 $-3 \times 4 =$ **-12**。最终数组为 `50 45 30 18 10`。）*
* **输入样例 2**：
  ```text
  4 1
  2 4 6 8
  0 3 10
  ```
* **输出样例 2**：
  ```text
  18 3 12
  18 6 4 2
  ```
