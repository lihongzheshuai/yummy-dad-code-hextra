为什么刚学函数的同学写下 `void my_swap(int x, int y) { int t = x; x = y; y = t; }`，在 `my_swap` 函数内部明明看到 `x` 和 `y` 的值已经互换成功，可一旦退回 `main` 函数打印实参 `a` 和 `b`，它们却纹丝不动？为什么改写成 `void my_swap(int &x, int &y)` 仅仅多了两个 `&` 符号，连一行函数体代码都不用改，就能瞬间跨栈帧修改 `main` 函数里的原变量？而在符号 `&` 的背后，为什么 `int &r = a;` 叫作“声明引用”，`int *p = &a;` 里的 `&a` 却叫作“取内存地址”？当我们在复赛中把一个包含 $10^5$ 个元素的 `vector<int>` 或巨型结构体传给自定义函数时，为什么漏写一个 `&` 就会导致时间复杂度从 $O(1)$ 暴增到 $O(N)$ 当场超时（TLE）？在 GESP 四级认证以及 CSP-J 初赛阅读程序与复赛工程实践中，**值传递（Pass by Value）的形参栈帧副本隔离机制、指针传递（Pass by Pointer）的地址拷贝与解引用跨栈修改、引用传递（Pass by Reference）作为变量“底层别名（Alias）”的零拷贝本质，以及 `const T&` 常量引用的大对象高效只读传参规范** 是贯穿始终的核心基石。本文将用一张直观的调用栈内存对照图，帮你彻底打通 C++ 三大传参机制的任督二脉。

## 🎯 考纲锚点与核心痛点

> 📍 **对应考点**：深入理解 C++ 函数调用时的栈帧传参机制，熟练辨析值传递（`void f(int x)`）、指针传递（`void f(int *p)`）与引用传递（`void f(int &r)`）在物理内存分布、实参修改能力、空间开销上的本质区别，掌握引用（Reference）的初始化约束与 `const T&` 常量引用规范。
> 🎯 **适用等级**：`GESP 四级考点 | CSP-J 初赛/复赛必考`

在考场做客观题、阅读程序和编写复赛代码时，同学们最容易在以下三个地方栽跟头：
1. **“误以为形参和实参同名就是同一个变量，掉进值传递‘假修改’陷阱”**：在 `main` 中定义了 `int a = 10;`，调用 `void add(int a) { a += 5; }`，因为两个变量都叫 `a`，就误以为 `main` 里的 `a` 也会变成 `15`，完全忽略了值传递会在被调函数栈帧中开辟一块**完全独立的形参副本内存**；
2. **“分不清同一个符号 `&` 在不同位置的双重身份，或搞混指针传参与引用传参的语法要求”**：看到 `&` 就条件反射以为是“取地址”，分不清类型后面的 `int &r = a`（引用声明：给变量起外号）与表达式里的 `&a`（取址运算：获取门牌号）；或者在指针传递函数里只改了指针形参本身的指向 `p = q;`，却没有加星号解引用 `*p = *q;`，导致实参根本没变；
3. **“复赛传 `string`、`vector` 或大型 `struct` 时习惯性按值传参，引发隐式深拷贝 TLE”**：在 DFS 递归或高频调用的辅助函数中写成 `void check(string s)` 或 `bool cmp(Student a, Student b)`，每次调用都把整块大内存完整复印一份，导致原本 $O(N)$ 的算法退化成 $O(N^2)$ 超时。

## 🧠 一、 核心原理深度拆解（有理论）

### 1. 什么是 C++ 的“引用（Reference）”？为什么它被称为变量的“合法外号”？

在拆解三种传参方式之前，我们必须先攻克 C++ 独有的核心概念——**引用（Reference）**。

在日常生活中，一个人有户口本上的大名（比如“张伟”），家里人又给他起了一个小名或外号（比如“小伟”）。当你给“小伟”塞一个苹果时，其实就是直接塞到了“张伟”手里——**因为“小伟”并不是克隆出来的另一个人，它只是“张伟”这个实体本尊的另一个名字（别名 / Alias）**！

在 C++ 中，当我们在**变量声明语句的类型名后面**加上 `&` 符号时，就是为已有变量创建一个**引用（别名）**：

```cpp
int a = 5;       // 在栈区开辟 4 字节内存房间（假设地址为 0x1000），存入 5
int &r = a;      // 声明引用：r 成为变量 a 的“别名”，与 a 共享同一个内存房间 0x1000！
r = 99;          // 操作 r 就是直接操作 a 本尊，此时 a 的值立刻变成 99！
```

#### ⚠️ 引用的三大底层铁律（GESP 判断题高频考点）
1. **零独立内存（地址完全相同）**：在逻辑语义上，引用 `r` **不额外开辟新的数据存储空间**，它直接绑定在原变量 `a` 的物理内存块上。因此对引用取地址 `&r` 与对原变量取地址 `&a` 的结果 **100% 完全相同（`&r == &a` 恒为真）**！
2. **出生必须绑定（强制初始化，且不可绑定字面量常量）**：普通引用在声明的同时**必须立刻初始化绑定到一个合法左值变量上**。写成 `int &r;`（未初始化）或 `int &r = 10;`（试图给数字常量 `10` 起可变外号）都会直接触发 **编译错误（Compile Error）**！
3. **终身一夫一妻（一旦绑定，绝不可改嫁）**：引用一旦在声明时绑定了变量 `a`，终其一生都只能做 `a` 的外号。如果后续再写 `r = b;`，它的含义**绝不是让 `r` 改做 `b` 的外号，而是把变量 `b` 的数值赋给 `r`（也就是赋给 `a`）**！

#### 🔍 一表秒懂：`&` 与 `*` 在“声明左值”和“表达式右值”中的双重面孔
很多同学看到 `&` 和 `*` 就头晕，其实只要看它**前面有没有数据类型名（如 `int`）**，就能一秒识破它的真实身份：

| 出现位置 | 语法示例 | 符号名称 | 底层物理含义 |
| :---: | :---: | :---: | :--- |
| **紧跟类型名后**（声明中） | `int &r = a;` | **引用声明符** | 给变量 `a` 起一个别名 `r`，两者共享同一间内存房（`&r == &a`） |
| **紧跟变量名前**（表达式中） | `p = &a;` | **取地址运算符** | 查出变量 `a` 所在内存房间的门牌号（如 `0x1000`） |
| **紧跟类型名后**（声明中） | `int *p;` | **指针声明符** | 声明一个专门用来存放“内存门牌号”的指针变量 `p` |
| **紧跟指针名前**（表达式中） | `*p = 20;` | **解引用运算符** | 顺着指针 `p` 里存的门牌号找过去，直接读写目标房间里的变量 |

### 2. 一张内存图看懂：值传递 vs 指针传递 vs 引用传递

现在假设 `main()` 函数中有三个整型变量 `a = 5, b = 5, c = 5`（分别位于栈地址 `0x1000`、`0x1004`、`0x1008`），我们分别用三种传参方式调用函数试图将它们加上一个数。请看底层**函数调用栈帧（Stack Frame）**的物理内存全景对比图：

```text
================================================================================
                    【 main() 函数栈帧（调用方实参区） 】
   变量 a (0x1000)                变量 b (0x1004)             变量 c (0x1008)
 ┌─────────────────┐            ┌─────────────────┐         ┌─────────────────┐
 │   原值: 5       │            │  原值: 5 ──► 25 │         │  原值: 5 ──► 35 │
 └─────────────────┘            └─────────────────┘         └─────────────────┘
         │                              ▲                           ▲
         │ 1. 值传递复印数值             │ *p 顺着门牌号跨栈修改      │ r 就是 c 的外号！
         ▼                              │ 2. 指针传递拷贝门牌号      │ 3. 引用传递零拷贝直连
 ┌─────────────────┐            ┌───────┴─────────┐                 │
 │ 形参 x (0x2000) │            │ 形参 p (0x2008) │         (无新数据房间！形参 r
 │ 副本: 5 ──► 15  │            │ 存地址: 0x1004  │          直接贴在 0x1008 门上)
 └─────────────────┘            └─────────────────┘
  【pass_val 栈帧】               【pass_ptr 栈帧】           【pass_ref 栈帧】
 (下课销毁，a 仍是 5)            (通过 *p 改掉 b 本尊)        (操作 r 就是操作 c 本尊)
================================================================================
```

#### ① 值传递（Pass by Value）：`void pass_val(int x)` —— “复印件涂改，原件毫发无损”
* **底层过程**：调用 `pass_val(a)` 时，CPU 在 `pass_val` 的新栈帧里**重新开辟了一间独立的内存房 `x`（地址 `0x2000`）**，然后把实参 `a` 的数值 `5` **复印（拷贝）** 一份放进 `x` 里。
* **修改结果**：函数内执行 `x = x + 10;` 只是把 `0x2000` 房间里的复印件改成了 `15`。当函数执行完毕返回时，`pass_val` 栈帧连同复印件 `x` 一起被销毁，而 `main` 栈帧 `0x1000` 里的原件 `a` 自始至终都是 **`5`**！

#### ② 指针传递（Pass by Pointer）：`void pass_ptr(int *p)` —— “拿着钥匙上门装修”
* **底层过程**：调用 `pass_ptr(&b)` 时，实参传入的是变量 `b` 的**门牌号 `0x1004`**。函数在自己的栈帧里开辟了一个 $8$ 字节（64位系统）的指针形参 `p`（地址 `0x2008`），把门牌号 `0x1004` 抄在 `p` 里面（注意：**指针传递本质上是“地址的值传递”**）。
* **修改结果**：函数内执行 **`*p = *p + 20;`** 时，解引用符 `*p` 顺着门牌号 `0x1004` 跨栈找到了 `main` 函数里的 `b` 本尊，直接把 `0x1004` 房间里的值改成了 **`25`**！

#### ③ 引用传递（Pass by Reference）：`void pass_ref(int &r)` —— “给原件贴上新外号，直达本体”
* **底层过程**：调用 `pass_ref(c)` 时，调用处连 `&` 符号都不用写！形参 `int &r` 直接作为实参 `c` 的**别名（外号）**，死死绑定在 `main` 函数的 `0x1008` 房间上，**没有任何数据拷贝开销**。
* **修改结果**：函数内执行 `r = r + 30;` 时，因为 `r` 就是 `c` 本尊，所以 `0x1008` 房间里的 `c` 瞬间变成了 **`35`**！既拥有指针跨栈修改实参的超能力，又省去了写 `&b` 和 `*p` 的繁琐语法。

### 3. 复赛提速核武器：为什么大对象传参必须写 `const T&`？

既然引用传递 `void f(vector<int> &v)` 可以实现 **$O(1)$ 零拷贝传参**，避免了按值传递把几十万个元素完整复印一遍的性能灾难，但如果我们只是想在函数里**读取**这个大数组或结构体（比如比较函数 `cmp` 或打印函数），万一在函数内部手滑把原数据改坏了怎么办？

为此，C++ 提供了兼具**“引用传递的 $O(1)$ 极致速度”**与**“值传递的只读安全保护”**的黄金写法——**常量引用（`const T&`）**！

| 传参方式（以占 $1000$ 字节的 `struct BigNode` 为例） | 是否拷贝原数据 | 传参时间/空间开销 | 函数内能否修改实参 | 能否接收字面量/临时表达式（如 `f(10)`） | 考场推荐场景 |
| :---: | :---: | :---: | :---: | :---: | :--- |
| **值传递**<br>`void f(BigNode x)` | ✅ 完整深拷贝 | 极慢（拷贝 $1000$ 字节） | ❌ 不能（只改副本） | ✅ 可以 | 仅适用于 `int`、`char`、`double` 等基础小类型 |
| **指针传递**<br>`void f(BigNode *p)` | ❌ 仅拷贝地址 | 极快（固定 $4/8$ 字节） | ✅ 可以（通过 `*p` 或 `p->`） | ❌ 必须传左值地址 `&a`（可传 `nullptr`） | 需要兼容 C 语言或允许传入空指针 `nullptr` 时 |
| **普通引用传递**<br>`void f(BigNode &r)` | ❌ 零数据拷贝 | 极快（$O(1)$ 别名绑定） | ✅ 可以（直接改 `r`） | ❌ 严禁传常量或表达式（`f(a+1)` 报错） | `swap(a, b)` 等明确需要修改实参的函数 |
| **常量引用传递**<br>`void f(const BigNode &r)` | ❌ 零数据拷贝 | **极快（$O(1)$ 别名绑定）** | **🔒 编译器强制只读保护** | **✅ 可以（编译器自动延长临时量寿命）** | **`sort` 自定义 `cmp`、大结构体/字符串只读传参首选！** |

> 💡 **考场黄金法则（背诵直接套用）**：
> 1. **【三大传参辨析口诀】**：**“值传递改副本，实参原件不掉粉；指针传址要解引，只改 `p` 不加 `*` 白费劲；引用 `&` 是真外号，零拷贝直改原件最省心！”**
> 2. **【工程与复赛传参铁律】**：**“基础类型随手传值，需改实参必上引用 `T&`，大对象只读无脑锁死 `const T&`！”**

## 🔍 二、 具象代码与数据推演（有举例）

下面这段标准的 C++11 示例程序同台对比了 `pass_val`（值传递）、`pass_ptr`（指针传递）和 `pass_ref`（引用传递）对实参 `a, b, c` 的影响，并验证了局部引用 `alias_c` 与原变量 `c` 的内存地址恒等性：

```cpp
#include <iostream>
using namespace std;

void pass_val(int x) { x = x + 10; }
void pass_ptr(int *p) { *p = *p + 20; }
void pass_ref(int &r) { r = r + 30; }

int main() {
    int a = 5, b = 5, c = 5;
    pass_val(a);
    pass_ptr(&b);
    pass_ref(c);
    cout << a << " " << b << " " << c << endl;
    int &alias_c = c;
    alias_c = alias_c * 2;
    cout << c << " " << (&alias_c == &c) << endl;
    return 0;
}
```

### 分步内存与变量状态推演表

假设 `main` 函数中 `a, b, c` 的栈内存地址分别为 `0x1000`、`0x1004`、`0x1008`：

| 执行步骤 | 实参 `(a, b, c)` 实时状态 | 形参/别名底层动作拆解 | 输出结果 |
| :---: | :---: | :--- | :---: |
| `int a = 5, b = 5, c = 5;` | `(5, 5, 5)` | 在 `main` 栈帧分配三间 `int` 房，初值均为 `5` | — |
| `pass_val(a);` | `(5, 5, 5)` | 新建形参副本 `x = 5`（地址 `0x2000`），将 `x` 改为 `15` 后销毁，**`a` 保持 `5` 不变** | — |
| `pass_ptr(&b);` | `(5, `**`25`**`, 5)` | 指针形参 `p` 接收地址 `&b` (`0x1004`)，执行 `*p = *p + 20` 直接跨栈把 **`b` 改为 `25`** | — |
| `pass_ref(c);`<br>`cout << a << " " << b << " " << c` | `(5, 25, `**`35`**`)` | 引用形参 `r` 直接成为 `c` (`0x1008`) 的别名，执行 `r = r + 30` 直接把 **`c` 改为 `35`** | 第一行输出：<br>**`5 25 35`** |
| `int &alias_c = c;`<br>`alias_c = alias_c * 2;`<br>`cout << c << " " << (&alias_c == &c)` | `(5, 25, `**`70`**`)` | `alias_c` 绑定为 `c` 的别名，乘 $2$ 后 `c` 变为 $35 \times 2 = \mathbf{70}$；由于共享同一块物理内存，`&alias_c == &c` 为真（输出 `1`） | 第二行输出：<br>**`70 1`** |

## ⚡ 三、 考场高频避坑指南（正误辨析）

在 GESP 四级客观题与 CSP-J 初赛阅读程序中，命题人最喜欢用下面这三个“障眼法”来诱导考生跳坑：

### ❌ 易错点 1：指针传参时“只换钥匙不换家具”——`void bad_swap(int *p, int *q)`
* **经典陷阱代码**：
  ```cpp
  void bad_swap(int *p, int *q) {
      int *tmp = p;
      p = q;
      q = tmp; // 注意：全程没有写星号 * 解引用！
  }
  ```
* **错误认知**：既然传了指针 `&a` 和 `&b` 进去，函数里也交换了 `p` 和 `q`，那 `a` 和 `b` 肯定交换成功了！
* **为什么错**：记住！**指针变量 `p` 和 `q` 本身也是按值传递的局部形参副本**！`p = q;` 只是在函数内部把 `p` 和 `q` 手里握着的两张“门牌号纸条”互换了一下，全程根本没有用 `*p` 打开房门去搬动里面的家具！函数一结束，两张纸条被销毁，`main` 函数里的 `a` 和 `b` **纹丝未动**！要真正交换，必须写成 `*tmp_val = *p; *p = *q; *q = *tmp_val;`。

### ❌ 易错点 2：对非 `const` 引用传入常量或算术表达式 `pass_ref(a + 1)`
* **错误写法**：定义了引用传参函数 `void add_one(int &x) { x++; }`，然后在调用时写成 `add_one(5);` 或 `add_one(a + 1);`。
* **为什么错**：普通引用 `int &x` 承诺“我对 `x` 的任何修改都会同步反映到调用方的原变量上”。但数字 `5` 或表达式 `a + 1` 计算出的结果是一个没有持久内存门牌号的**右值（临时值）**——你总不能把数学常数 `5` 的值改成 `6` 吧？因此 C++ 严禁非 `const` 引用绑定右值，上述调用会直接触发 **编译错误（Compile Error）**！（注：如果改为常量引用 `void print_val(const int &x)`，则合法，因为编译器确信你不会修改它）。

### ❌ 易错点 3：在函数中返回局部变量的引用 `int& bad_return()`（致命悬垂引用）
* **错误写法**：
  ```cpp
  int& create_num() {
      int local_x = 42;
      return local_x; // 致命错误：返回栈区局部变量的引用！
  }
  ```
* **为什么错**：`local_x` 是存储在 `create_num()` 栈帧里的局部变量。当函数 `return` 退栈的瞬间，`local_x` 的内存房间就已经被操作系统强制回收了！此时返回的引用沦为了指向废墟的**悬垂引用（Dangling Reference）**，一旦外部读取或写入该引用，将触发不可预测的未定义行为（UB）甚至程序崩溃！

## 📝 四、 真题实战演练与精析（有例题：3 道）

### 【例题 1 · 单选题】（GESP 四级 / CSP-J 初赛阅读程序：三种传参混合陷阱题）

**题目**：阅读以下 C++ 程序，其运行后的输出结果是（ ）。
```cpp
#include <iostream>
using namespace std;

void mystery(int a, int &b, int *c, int *d) {
    a = a + 10;
    b = b + a;
    *c = *c + b;
    d = c;
    *d = *d + 5;
}

int main() {
    int x = 1, y = 2, z = 3, w = 4;
    mystery(x, y, &z, &w);
    cout << x << " " << y << " " << z << " " << w << endl;
    return 0;
}
```
* **A.** `11 13 16 9`
* **B.** `1 13 21 4`
* **C.** `1 13 16 9`
* **D.** `1 3 6 4`

**🔍 答案与逐项排除解析**：
* **正确答案**：**B**
* **解析过程**：
  1. **审视四个形参的传参性质**：
     * `int a`：**值传递**，初始复印了实参 `x` 的值 `1`，对 `a` 的任何修改**绝不会影响 `x`**，因此 `main` 中的 `x` 永远保持 **`1`**（直接排除 A 项）；
     * `int &b`：**引用传递**，`b` 就是实参 `y` 的别名（初值 `2`）；
     * `int *c`：**指针传递**，`c` 指向实参 `z`（初值 `3`）；
     * `int *d`：**指针传递**，`d` 初始指向实参 `w`（初值 `4`）。
  2. **逐行推演函数体**：
     * `a = a + 10;`：局部形参副本 `a` 变为 $1 + 10 = 11$（实参 `x` 仍为 **`1`**）；
     * `b = b + a;`：`b` 是 `y` 的引用，将此时的局部 `a`（`11`）加到 `b` 上，实参 `y` 变为 $2 + 11 = \mathbf{13}$；
     * `*c = *c + b;`：`*c` 解引用访问实参 `z`，加上此时的 `b`（`13`），实参 `z` 变为 $3 + 13 = 16$；
     * `d = c;`：**核心障眼法**！这里没有加星号 `*`，而是把指针变量 `d` 的指向从 `&w` 改成了 `c` 所指向的 **`&z`**！从此以后 `d` 和 `c` 共同指向实参 `z`，而实参 `w` 彻底逃过一劫，永远保持初始值 **`4`**！
     * `*d = *d + 5;`：因为此时 `d` 指向的是 `z`，所以解引用 `*d` 把实参 `z` 的值从 `16` 再次加上 `5`，变为 $16 + 5 = \mathbf{21}$！
  3. **汇总最终输出**：`x = 1, y = 13, z = 21, w = 4`，对应输出 **`1 13 21 4`**。C 项错在没看出 `d = c` 改变了指针指向，误把 `+5` 加到了 `w` 上；D 项错在算 `b = b + a` 时用了 `x` 的原值 `1` 而不是修改后的副本 `a = 11`。故正确选项为 **B**。

### 【例题 2 · 判断题】（GESP 四级官方考纲真题辨析：引用绑定规则与二次赋值）

**题目**：在 C++ 语言中，执行以下代码段：`int a = 10, b = 20; int &r = a; r = b; r = 30;` 后，因为语句 `r = b;` 将引用 `r` 重新绑定到了变量 `b` 上，所以最终变量 `a` 的值保持 `10` 不变，而变量 `b` 的值变成了 `30`。（ ）

**🔍 答案与反例证明**：
* **结论**：**错误（$\times$）**
* **反例证明**：本题直接考察引用的**“终身绑定不可改嫁”**铁律：
  1. 在 `int &r = a;` 声明时，引用 `r` 就已经与变量 `a` 的内存地址永久绑定，**C++ 中没有任何语法能让一个已经存在的引用改绑到另一个变量上**；
  2. 随后的语句 `r = b;` 并不是把 `r` 改绑到 `b`，而是**普通的数值赋值操作**——将 `b` 的值（`20`）赋给 `r` 所绑定的变量 `a`（此时 `a` 变为 `20`）；
  3. 紧接着执行 `r = 30;`，依然是修改 `r` 所绑定的变量 `a`，使 `a` 变为 **`30`**，而变量 `b` 自始至终没有被修改过，依然是 **`20`**！故原命题结论完全颠倒，判定为错误。

### 【例题 3 · 微代码实战】（经典复赛模型：结合引用交换 `T&`、指针修改 `T*` 与常量引用计算 `const T&` 的战队管理系统）

**题目描述**：在信奥复赛开发结构体程序时，合理运用三种传参方式能让代码既快又稳。现有一个包含 $n$（$1 \le n \le 1000$）名英雄的战队，编号为 $1 \sim n$，每名英雄用结构体 `Hero` 表示，包含生命值 `hp` 和攻击力 `atk` 两个整型属性。请你编写三个标准规范的自定义函数并处理 $m$ 条操作指令：
1. **`void swap_by_ref(Hero &a, Hero &b)`**：使用**引用传递**，在 $O(1)$ 时间内直接交换两个英雄结构体 `a` 和 `b` 的全部数据（对应指令 `1 x y`：交换位置 $x$ 和位置 $y$ 上的英雄）；
2. **`void upgrade_by_ptr(Hero *p, int dh, int da)`**：使用**指针传递**，若指针 `p` 不为空（`p != nullptr`），则通过指针箭头运算符 `p->hp` 和 `p->atk` 将该英雄的生命值增加 `dh`、攻击力增加 `da`（对应指令 `2 x dh da`：传入第 $x$ 号英雄的地址 `&team[x]` 进行属性强化）；
3. **`int calc_power(const Hero &h)`**：使用**常量引用传递（零拷贝只读）**，计算并返回单名英雄的综合战力值 $\text{Power} = \text{hp} + \text{atk} \times 3$。
所有 $m$ 条指令执行完毕后，依次调用 `calc_power` 在一行内输出第 $1 \sim n$ 号位置上英雄的最终综合战力值（以单个空格分隔）。

**💡 建模思路**：
1. **结构体引用交换**：直接声明 `Hero &a, Hero &b`，函数内通过局部临时结构体 `Hero tmp = a; a = b; b = tmp;` 即可一步完成实参结构体的原地互换；
2. **结构体指针成员访问**：指针指向结构体时，既可以写 `(*p).hp`，更推荐使用直观的箭头操作符 **`p->hp`**（等价于 `(*p).hp`）；
3. **`const Hero &h` 零拷贝读取**：避免按值传递复制整个结构体，同时由编译器保障 `calc_power` 内部绝不会意外篡改英雄属性。

```cpp
#include <iostream>
using namespace std;

struct Hero {
    int hp;
    int atk;
};

void swap_by_ref(Hero &a, Hero &b) {
    Hero tmp = a;
    a = b;
    b = tmp;
}

void upgrade_by_ptr(Hero *p, int dh, int da) {
    if (p != nullptr) {
        p->hp = p->hp + dh;
        p->atk = p->atk + da;
    }
}

int calc_power(const Hero &h) {
    return h.hp + h.atk * 3;
}

const int MAXN = 1005;
Hero team[MAXN];

int main() {
    int n, m;
    cin >> n >> m;
    for (int i = 1; i <= n; i++) {
        cin >> team[i].hp >> team[i].atk;
    }
    for (int i = 0; i < m; i++) {
        int op;
        cin >> op;
        if (op == 1) {
            int x, y;
            cin >> x >> y;
            swap_by_ref(team[x], team[y]);
        } else if (op == 2) {
            int x, dh, da;
            cin >> x >> dh >> da;
            upgrade_by_ptr(&team[x], dh, da);
        }
    }
    for (int i = 1; i <= n; i++) {
        cout << calc_power(team[i]) << (i == n ? "" : " ");
    }
    cout << endl;
    return 0;
}
```

* **输入样例 1**：
  ```text
  3 3
  100 10
  200 20
  300 30
  1 1 3
  2 1 50 5
  2 2 -20 10
  ```
* **输出样例 1**：
  ```text
  455 270 130
  ```
  *（样例 1 解释：初始 1~3 号英雄分别为 `(100,10)`、`(200,20)`、`(300,30)`。第 1 条指令 `1 1 3` 通过 `swap_by_ref` 交换 1 号与 3 号，阵容变为 `(300,30)`、`(200,20)`、`(100,10)`；第 2 条指令 `2 1 50 5` 通过指针 `&team[1]` 将 1 号强化为 `(350,35)`；第 3 条指令 `2 2 -20 10` 将 2 号强化为 `(180,30)`。最终通过 `calc_power` 计算三名英雄战力：$350 + 35 \times 3 = \mathbf{455}$，$180 + 30 \times 3 = \mathbf{270}$，$100 + 10 \times 3 = \mathbf{130}$。）*
* **输入样例 2**：
  ```text
  2 2
  50 10
  80 20
  2 1 30 5
  1 1 2
  ```
* **输出样例 2**：
  ```text
  140 125
  ```
