## 🎯 考纲锚点与核心痛点

> 📍 **对应考点**：掌握排序算法“稳定性（Stability）”的严格定义与多级排序实际意义；透彻掌握冒泡排序、插入排序、选择排序三大 $O(n^2)$ 排序的核心逻辑、最好/最坏/平均时间复杂度、原地空间复杂度 $O(1)$，以及跨距交换破坏稳定性的底层原因。
> 🎯 **适用等级**：`GESP 四级考点 | CSP-J/S 初赛/复赛必考`

在考场解答客观题、阅读程序和编写复赛排序代码时，同学们最容易在以下三个痛点上栽跟头：
1. **“死记硬背稳定性结论，遇到变形代码或反例推演就懵”**：背熟了“冒泡、插入稳定，选择不稳定”，却说不清选择排序究竟在哪一步破坏了相对顺序，或者在自己手写冒泡排序时顺手把 `if (a[j] > a[j + 1])` 写成了 `>=`，亲手把稳定算法写成了不稳定算法；
2. **“把三大基础排序的时间复杂度一锅炖成 $O(n^2)$”**：忽略了输入数据“初始基本有序”这一高频考察场景——不知道插入排序天然具备 $O(n)$ 的最好时间复杂度，也不知道选择排序无论数据多么有序都必须死跑 $\frac{n(n-1)}{2}$ 次比较；
3. **“不会用‘逆序对’秒算冒泡与插入排序的操作次数”**：初赛单选题给出一个具体序列问“冒泡排序共发生几次交换”或“插入排序共发生几次元素后移”，还在草稿纸上一轮轮硬画，殊不知利用逆序对定理 10 秒钟就能精准口算。

## 🧠 一、 核心原理深度拆解（有理论）

### 1. 排序“稳定性”的严格定义：它到底有什么用？

* **严格数学定义**：设待排序序列中存在两个排序关键字相等的元素 $R_i$ 和 $R_j$（即 $\text{key}(R_i) == \text{key}(R_j)$），且在排序前 $R_i$ 位于 $R_j$ 之前（下标 $i < j$）。如果排序完成后，**$R_i$ 依然严格排在 $R_j$ 之前**（相等元素的相对先后次序保持不变），则称该排序算法是**稳定的（Stable）**；反之，只要**存在哪怕一组特定输入**会导致相等元素的相对次序发生颠倒，该算法就是**不稳定的（Unstable）**。
* **为什么稳定性至关重要？（多级排序的“记忆继承”效应）**：
  如果排序对象只是孤立的整数，两个 `5` 谁前谁后确实毫无区别；但在工程与竞赛中，排序对象往往是携带多个属性的**结构体（记录）**。例如：电商订单最初已经按**下单时间戳从小到大**排好，现在运营需要按**会员等级从高到低**重排，且要求同等级会员“先下单的优先发货”。
  * 若使用**稳定排序**：按会员等级重排时，同等级订单**不会互相跨越**，它们天然保留了此前排好的时间戳升序，无需额外修改比较规则！这也是基数排序（Radix Sort）能按“个位 $\to$ 十位 $\to$ 百位”逐轮桶排成立的数学根基，更是 C++ STL 在 `std::sort` 之外专门提供 `std::stable_sort` 的根本原因。

### 2. 三大 $O(n^2)$ 排序底层机制与稳定性解剖

假设我们要将数组按**升序（从小到大）**排列，三大基础排序的底层动作截然不同：

#### ① 冒泡排序（Bubble Sort）—— 相邻两两比，相等绝不换（稳定 ✅）
* **核心动作**：每一轮从头到尾扫描未排序区间，比较**相邻元素** `a[j]` 与 `a[j + 1]`。只有当严格逆序（`a[j] > a[j + 1]`）时才交换两者，使当前区间的最大值像水底气泡一样一步步“浮”到区间最右端。
* **为什么稳定？** 因为元素只能通过**相邻位置一步步交换**移动，当两个相等元素相遇时（`a[j] == a[j + 1]`），条件 `>` 不成立，绝不交换，后面的相等元素永远跨不过前面的相等元素。
* **最好情况优化**：加入布尔标记 `bool swapped = false;`。若某一轮扫描全程未发生任何交换，说明数组已彻底有序，立即 `break` 提前结束，最好时间复杂度降为 **$O(n)$**（若不加该标记，最好时间复杂度仍为 $O(n^2)$）。

#### ② 直接插入排序（Insertion Sort）—— 抓扑克牌顺移插空，近乎有序之王（稳定 ✅）
* **核心动作**：就像打扑克牌整理手牌——左侧 `a[0..i-1]` 是已经排好序的手牌，第 $i$ 轮摸起新牌 `key = a[i]`，从右往左扫描已排序手牌：只要手牌严格大于新牌（`a[j] > key`），就把手牌向右平移一格（`a[j + 1] = a[j]`），直到撞见小于或等于 `key` 的牌立即停手，把 `key` 插进空位 `a[j + 1]`。
* **为什么稳定？** 新摸的牌是从右侧出发向左找位置，一旦遇到相等的老牌（`a[j] == key`），循环条件 `a[j] > key` 立即终止，新牌稳稳落在相等老牌的**右手边**，先后次序丝毫不乱。
* **天然自适应优势**：当输入数组**原本已基本有序**时，每次新摸的牌只需与左邻 `a[i - 1]` 比较 $1$ 次就立刻停下，内层 `while` 循环几乎不执行，最好时间复杂度天然达到 **$O(n)$**！正因如此，C++ `std::sort` 底层的内省排序（Introsort）在递归子区间长度缩减到 $16$ 以内时，会专门切换为插入排序来收尾提速。

#### ③ 简单选择排序（Selection Sort）—— 跨距盲目对调，破坏稳定性的罪魁祸首（不稳定 ❌）
* **核心动作**：第 $i$ 轮完整扫描未排序区间 `a[i..n-1]`，找出全局最小元素的下标 `min_idx`，然后直接执行一次**远距离对调 `swap(a[i], a[min_idx])`**，一步到位把最小值钉死在下标 $i$。
* **为什么不稳定？（一张图看懂跨距飞跃反例）**：

```text
================================================================================
【选择排序破坏稳定性的最小反例】：初始序列 [ 5A,  3B,  5C,  2D ]（其中 5A 在 5C 之前）

  下标位置：      [0]     [1]     [2]     [3]
  排序前状态：     5A      3B      5C      2D
                   │                       ▲
                   └───── 跨距直接对调 ─────┘
             （第 1 轮找到最小值下标 min_idx = 3 即 2D，直接与 a[0] 的 5A 交换！）

  第 1 轮后：      2D      3B     [5C]    [5A]   ⚡ 惨案发生！
  第 2~3 轮后：    2D      3B     [5C]    [5A]   （后续元素已全部有序，不再交换）

  ★ 结论诊断：5A 在第 1 轮被一脚跨过中间的 5C 踢到了队尾，最终 5C 排在了 5A 前面！
             这种“隔山打牛”式的非相邻跨距交换，正是选择排序不稳定的根本原因！
================================================================================
```

* **独特优缺点**：无论初始数组是有序、逆序还是乱序，选择排序每一轮为了确认谁是最小值，都必须把剩余元素老老实实扫完，因此**最好、最坏、平均时间复杂度全都是死板的 $O(n^2)$**（固定比较 $\frac{n(n-1)}{2}$ 次）；但它的**总交换次数极少**，最多只需交换 **$n - 1$ 次**（$O(n)$ 级），适合元素体积巨大、移动成本极高但比较成本很低的特殊场景。

### 3. 三大 $O(n^2)$ 排序考场全景对比表与逆序对定理

| 核心对比维度 | 冒泡排序（带标志优化） | 直接插入排序 | 简单选择排序 |
| :---: | :---: | :---: | :---: |
| **最好时间复杂度（完全升序）** | **$O(n)$**（比较 $n-1$ 次，0 交换） | **$O(n)$**（比较 $n-1$ 次，0 平移） | **$O(n^2)$**（仍需比较 $\frac{n(n-1)}{2}$ 次！） |
| **最坏时间复杂度（完全降序）** | $O(n^2)$ | $O(n^2)$ | $O(n^2)$ |
| **平均时间复杂度** | $O(n^2)$ | $O(n^2)$ | $O(n^2)$ |
| **额外空间复杂度** | $O(1)$（原地排序） | $O(1)$（原地排序） | $O(1)$（原地排序） |
| **排序稳定性** | ✅ **稳定** | ✅ **稳定** | ❌ **不稳定**（跨距交换所致） |
| **交换 / 平移次数特征** | 交换次数 $=$ **逆序对个数** | 右移次数 $=$ **逆序对个数** | 交换次数极少，恒 $\le n - 1$ 次 |

> 💡 **考场黄金法则（背诵直接套用）**：
> 1. **【相邻保稳，跨距失稳铁律】**：只在相邻元素间严格按 `>` / `<` 移动的排序（冒泡、插入）**必稳定**；存在远距离跳跃交换的排序（选择排序、快速排序、希尔排序、堆排序）**全都不稳定**！
> 2. **【逆序对秒算操作次数铁律】**：在升序排列中，若满足下标 $i < j$ 且 $a[i] > a[j]$，则称 $(a[i], a[j])$ 为一个**逆序对**。每交换一对相邻逆序元素恰好消去 $1$ 个逆序对，故**标准冒泡排序的总交换次数**与**直接插入排序的内层元素总右移次数**，均**严格等于原序列的逆序对总数**！

## 🔍 二、 具象代码与数据推演（有举例）

### 示例：用同一组带标签序列 `[5A, 3B, 5C, 2D]` 实测三大排序轨迹

请阅读以下标准 C++11 验证程序，我们将数值相等的两个 `5` 分别打上标签 `'A'` 和 `'B'`/`'C'`，直观对比三种算法的最终顺序与操作计数：

```cpp
#include <iostream>
#include <utility>
using namespace std;

struct Item {
    int val;
    char tag;
};

int main() {
    // 1. 冒泡排序：[5A, 3B, 5C, 2D]
    Item b[4] = {{5, 'A'}, {3, 'B'}, {5, 'C'}, {2, 'D'}};
    int b_swaps = 0;
    for (int i = 0; i < 3; i++) {
        bool swapped = false;
        for (int j = 0; j < 3 - i; j++) {
            if (b[j].val > b[j + 1].val) { // 严格大于才交换
                swap(b[j], b[j + 1]);
                b_swaps++;
                swapped = true;
            }
        }
        if (!swapped) break;
    }

    // 2. 直接插入排序：[5A, 3B, 5C, 2D]
    Item ins[4] = {{5, 'A'}, {3, 'B'}, {5, 'C'}, {2, 'D'}};
    int ins_shifts = 0;
    for (int i = 1; i < 4; i++) {
        Item key = ins[i];
        int j = i - 1;
        while (j >= 0 && ins[j].val > key.val) { // 严格大于才右移
            ins[j + 1] = ins[j];
            ins_shifts++;
            j--;
        }
        ins[j + 1] = key;
    }

    // 3. 简单选择排序：[5A, 3B, 5C, 2D]
    Item s[4] = {{5, 'A'}, {3, 'B'}, {5, 'C'}, {2, 'D'}};
    int s_swaps = 0;
    for (int i = 0; i < 3; i++) {
        int min_idx = i;
        for (int j = i + 1; j < 4; j++) {
            if (s[j].val < s[min_idx].val) {
                min_idx = j;
            }
        }
        if (min_idx != i) {
            swap(s[i], s[min_idx]); // 跨距交换
            s_swaps++;
        }
    }

    cout << "Bubble   : " << b[2].val << b[2].tag << " " << b[3].val << b[3].tag << " | swaps=" << b_swaps << endl;
    cout << "Insertion: " << ins[2].val << ins[2].tag << " " << ins[3].val << ins[3].tag << " | shifts=" << ins_shifts << endl;
    cout << "Selection: " << s[2].val << s[2].tag << " " << s[3].val << s[3].tag << " | swaps=" << s_swaps << endl;
    return 0;
}
```

#### 三种排序逐轮内存状态对比推演表（初始均为 `[5A, 3B, 5C, 2D]`）

先数原序列 `[5, 3, 5, 2]` 的**逆序对**：`(5,3)`、`(5,2)`、`(3,2)`、`(5,2)`，共计 **$4$ 个逆序对**。

| 轮次进度 | 冒泡排序数组快照（本轮交换数） | 直接插入排序数组快照（本轮右移数） | 简单选择排序数组快照（本轮交换数） |
| :---: | :--- | :--- | :--- |
| **第 1 轮结束** | `[3B, 5A, 2D, 5C]`（交换 2 次：`5A↔3B`, `5C↔2D`） | `[3B, 5A, 5C, 2D]`（摸 `3B`，`5A` 右移 1 次） | **`[2D, 3B, 5C, 5A]`**（`5A↔2D` 跨距交换 1 次） |
| **第 2 轮结束** | `[3B, 2D, 5A, 5C]`（交换 1 次：`5A↔2D`） | `[3B, 5A, 5C, 2D]`（摸 `5C` 遇 `5A` 停，右移 0 次） | `[2D, 3B, 5C, 5A]`（`min_idx=1` 原位，交换 0 次） |
| **第 3 轮结束** | **`[2D, 3B, 5A, 5C]`**（交换 1 次：`3B↔2D`） | **`[2D, 3B, 5A, 5C]`**（摸 `2D`，前三项各右移 1 次共 3 次） | **`[2D, 3B, 5C, 5A]`**（`min_idx=2` 原位，交换 0 次） |
| **程序最终输出** | `Bubble   : 5A 5C | swaps=4`（**稳定 ✅**） | `Insertion: 5A 5C | shifts=4`（**稳定 ✅**） | `Selection: 5C 5A | swaps=1`（**失稳 ❌**） |

## ⚡ 三、 考场高频避坑指南（正误辨析）

在 GESP 四级客观题与 CSP-J 初赛阅读程序中，命题人最爱在以下三个边界细节上设套：

### ❌ 易错点 1：手滑把 `>` 写成 `>=`，亲手毁掉冒泡与插入排序的稳定性！
* **错误写法**：
  ```cpp
  // 冒泡排序中误加等号：
  if (a[j].score >= a[j + 1].score) swap(a[j], a[j + 1]);
  // 插入排序中误加等号：
  while (j >= 0 && a[j].score >= key.score) { a[j + 1] = a[j]; j--; }
  ```
* **为什么错**：当遇到两个相等分数时，`>=` 会强行让相邻元素交换，或者让后摸到的新牌一路越过前面所有同分老牌插到最前面，原本稳定的算法当场退化为**不稳定实现**！而且还会平白无故增加大量无效交换与移动。
* **正确规范**：排序比较条件中**严禁带等号**（升序一律用严格 `>` 触发交换/平移，降序一律用严格 `<` 触发交换/平移）。

### ❌ 易错点 2：漏看“朴素冒泡排序没有加 `swapped` 标志”，误判最好时间复杂度为 $O(n)$！
* **初赛经典坑题**：给出如下**未加提前终止标志**的朴素冒泡代码，问输入 `1, 2, 3, ..., n` 时的时间复杂度：
  ```cpp
  for (int i = 0; i < n - 1; i++) {
      for (int j = 0; j < n - 1 - i; j++) {
          if (a[j] > a[j + 1]) swap(a[j], a[j + 1]);
      }
  }
  ```
* **为什么错**：虽然 `swap` 一次都不会执行（交换次数为 `0`），但由于没有任何 `break` 退出机制，内外两层循环依然会机械地跑满 $\frac{n(n-1)}{2}$ 次 `if` 比较！因此**上述无标志朴素代码的最好时间复杂度依然是 $O(n^2)$**；只有显式加上 `bool swapped` 提前 `break` 的优化版冒泡排序，最好时间复杂度才是 $O(n)$！

### ❌ 易错点 3：在复赛要求“同分按原输入顺序输出”时，直接裸调 `std::sort` 导致 WA！
* **典型误区**：题目要求按成绩降序排列，成绩相同时**保持输入时的先后顺序**。选手写了个只比成绩的 `bool cmp(Student x, Student y) { return x.score > y.score; }`，然后直接调用 `sort(a, a + n, cmp);`。
* **为什么错**：C++ `<algorithm>` 中的 **`std::sort` 是不稳定排序**（底层包含快速排序与堆排序的跨距交换）！当数据量较大（通常超过 16 个元素触发快排分区）时，同分选手的先后顺序会被彻底打乱导致 WA！
* **正确解法（二选一）**：
  1. 在结构体中额外记录输入序号 `id`，在 `cmp` 中显式写出双关键字：`if (x.score != y.score) return x.score > y.score; return x.id < y.id;`；
  2. 直接改调 `<algorithm>` 自带的稳定排序函数：**`stable_sort(a, a + n, cmp);`**！

## 📝 四、 真题实战演练与精析（有例题：3 道）

### 【例题 1 · 单选题】（GESP 四级 / CSP-J 初赛真题演练：选择排序失稳轨迹与冒泡交换次数）

**题目**：现有一组包含 5 个带字母标签的待排序元素序列：`[(6, A), (4, B), (6, C), (5, D), (2, E)]`（括号内第一项为整型排序关键字，第二项为区分元素的唯一标签）。若按关键字**从小到大（升序）**排序：
1. 采用标准**简单选择排序**（每轮找出最小关键字首次出现的下标 `min_idx`，若 `min_idx != i` 则交换 `a[i]` 与 `a[min_idx]`），排序结束后的元素标签顺序是什么？
2. 若改用标准**冒泡排序**，整个排序过程中总共会发生多少次元素交换？

* **A.** `E B D A C`，7 次
* **B.** `E B D C A`，7 次
* **C.** `E B D C A`，6 次
* **D.** `E B D A C`，6 次

**🔍 答案与逐项排除解析**：
* **正确答案**：**B**
* **解析过程**：
  1. **第一步：手推简单选择排序的跨距交换轨迹**：
     * 初始状态：`[(6, A), (4, B), (6, C), (5, D), (2, E)]`
     * **第 1 轮（`i = 0`）**：在 `[0..4]` 中找到最小值为下标 `4` 的 `(2, E)`，与下标 `0` 的 `(6, A)` 跨距对调 $\implies$ `[(2, E), (4, B), (6, C), (5, D), (6, A)]`（此时 `A` 已被甩到 `C` 后面！）；
     * **第 2 轮（`i = 1`）**：在 `[1..4]` 中最小值为下标 `1` 的 `(4, B)`，已在原位不交换；
     * **第 3 轮（`i = 2`）**：在 `[2..4]` 中找到最小值为下标 `3` 的 `(5, D)`，与下标 `2` 的 `(6, C)` 交换 $\implies$ `[(2, E), (4, B), (5, D), (6, C), (6, A)]`；
     * **第 4 轮（`i = 3`）**：在 `[3..4]` 中 `(6, C)` 与 `(6, A)` 关键字相等，扫描时 `6 < 6` 不成立，`min_idx` 保持为 `3` 不交换。
     * 最终标签顺序为 **`E B D C A`**（排除 A、D）。
  2. **第二步：用“逆序对铁律”秒算冒泡排序交换次数**：
     * 提取关键字序列 `[6, 4, 6, 5, 2]`，逐个统计每个数右侧严格比它小的元素个数：
       * 第一个 `6` 右侧比它小的有：`4, 5, 2`（**3 个**）；
       * `4` 右侧比它小的有：`2`（**1 个**）；
       * 第二个 `6` 右侧比它小的有：`5, 2`（**2 个**）；
       * `5` 右侧比它小的有：`2`（**1 个**）。
     * 逆序对总数 $= 3 + 1 + 2 + 1 = 7$，故标准冒泡排序恰好发生 **7 次**交换（排除 C，锁定 **B**）。

### 【例题 2 · 判断题】（GESP 四级考纲概念辨析：近乎有序序列下的算法表现）

**题目**：对包含 $n$ 个整数的数组进行升序排序。当原始数组已经处于完全升序状态（如 `1, 2, 3, ..., n`）时，直接插入排序和简单选择排序都只需要执行 $O(n)$ 次元素比较即可完成排序。（ ）

**🔍 答案与反例证明**：
* **结论**：**错误（×）**
* **反例证明**：
  1. **直接插入排序**在原数组完全升序时，外层循环从 `i = 1` 到 `n - 1`，每次新元素 `key = a[i]` 与前一个元素 `a[i - 1]` 比较 **1 次**即发现 `a[i - 1] <= key`，内层 `while` 循环当场终止，总共仅执行 $n - 1$ 次比较，时间复杂度确实为 **$O(n)$**；
  2. 但**简单选择排序**完全不具备自适应提前终止能力！在第 $i$ 轮（$0 \le i \le n - 2$）中，即便 `a[i]` 已经是最小值，算法为了**确认**后面没有比 `a[i]` 更小的数，内层循环 `for (int j = i + 1; j < n; j++)` 依然必须雷打不动地执行 $n - 1 - i$ 次比较。总比较次数恒为 $(n - 1) + (n - 2) + \dots + 1 = \frac{n(n - 1)}{2}$ 次，时间复杂度恒为 **$O(n^2)$**。故原命题错误。

### 【例题 3 · 微代码实战】（GESP 四级编程实战：保序选拔成绩单与插入排序平移计数）

**题目描述**：学校举办信奥队选拔赛，共有 $n$ 名选手（$1 \le n \le 1000$），教务系统已按**报名时间从早到晚**的顺序依次导出了每位选手的参赛编号 `id` 与初赛成绩 `score`。现请你编写程序，使用**稳定的直接插入排序**将所有选手按成绩**从高到低（降序）**排列；若多名选手成绩相同，必须严格保留他们原本的报名先后顺序（报名早的排在前面）。请输出排好序后前 $k$ 名（$1 \le k \le n$）选手的参赛编号，并在第二行输出整个插入排序过程中元素向右平移（即内层循环执行 `a[j + 1] = a[j]`）的总次数。

**输入格式**：
第一行包含两个正整数 $n$ 和 $k$，分别表示选手总数和需要输出的前 $k$ 名人数。
接下来 $n$ 行，每行包含两个整数 `id` 和 `score`（$1 \le \text{id} \le 10000$，$0 \le \text{score} \le 100$），按报名先后顺序给出。

**输出格式**：
第一行输出 $k$ 个整数，以单个空格分隔，表示排名前 $k$ 的选手编号。
第二行输出一个整数，表示直接插入排序过程中元素向右平移的总次数。

**💡 算法建模与稳定性细节剖析**：
1. **为什么无需额外给结构体加序号字段？** 因为输入本身就是按报名早晚顺序读入数组 `a[0..n-1]` 的，而直接插入排序是**严格稳定**的排序算法！
2. **降序排列的保稳边界条件**：在将新选手 `key = a[i]` 向前插入时，只有当前面的选手成绩**严格小于** `key.score`（即 `a[j].score < key.score`）时才将其右移；一旦遇到同分前辈（`a[j].score == key.score`）立刻停止前移，把 `key` 放在同分前辈的后面，天然实现“同分报名早者优先”！
3. **计数器的类型防范**：当 $n = 1000$ 且成绩完全升序（对降序排序而言的最坏逆序）时，最大平移次数为 $\frac{1000 \times 999}{2} = 499500$；养成用 `long long` 统计逆序对/移动次数的好习惯，即使未来扩展到更大规模也绝不溢出。

```cpp
#include <iostream>
using namespace std;

struct Student {
    int id;
    int score;
};

Student a[1005];

int main() {
    int n, k;
    cin >> n >> k;
    for (int i = 0; i < n; i++) {
        cin >> a[i].id >> a[i].score;
    }

    long long shift_cnt = 0;
    for (int i = 1; i < n; i++) {
        Student key = a[i];
        int j = i - 1;
        // 降序排列：仅当前面选手的成绩严格小于 key.score 时才右移
        // 遇到成绩相等者立即停下，天然保持原报名先后顺序（稳定排序）
        while (j >= 0 && a[j].score < key.score) {
            a[j + 1] = a[j];
            shift_cnt++;
            j--;
        }
        a[j + 1] = key;
    }

    for (int i = 0; i < k; i++) {
        if (i > 0) {
            cout << " ";
        }
        cout << a[i].id;
    }
    cout << endl;
    cout << shift_cnt << endl;
    return 0;
}
```

* **输入样例 1**：
  ```text
  5 3
  101 85
  102 92
  103 85
  104 92
  105 90
  ```
* **输出样例 1**：
  ```text
  102 104 105
  5
  ```
  *（样例 1 解释：初始序列为 `[(101,85), (102,92), (103,85), (104,92), (105,90)]`。`102` 与 `104` 同为 92 分，因插入排序稳定，先报名的 `102` 稳居第一、`104` 居第二，`105`（90 分）居第三；各轮右移次数依次为 `1 + 0 + 2 + 2 = 5` 次。）*
* **输入样例 2**：
  ```text
  4 4
  1 95
  2 95
  3 90
  4 80
  ```
* **输出样例 2**：
  ```text
  1 2 3 4
  0
  ```
  *（样例 2 解释：输入成绩本身已满足非递增有序，且同为 95 分的 `1` 号与 `2` 号触发稳定边界 `95 < 95` 为假，内层平移 `0` 次，仅比较 $3$ 次即光速收工！）*
