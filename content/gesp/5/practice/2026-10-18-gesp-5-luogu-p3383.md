当质数筛查的范围推升至 $n = 10^8$，且需要在极短时限内连续响应多达 $q = 10^6$ 次“第 $k$ 小素数”的随机询问时，单点 $\mathcal{O}(\sqrt{x})$ 试除法早已无力招架，甚至连经典的埃拉托斯特尼筛法（埃氏筛）也会因为像 $30 = 2 \times 15 = 3 \times 10 = 5 \times 6$ 这样的合数被不同质因子反复标记，而在 $\mathcal{O}(n \log \log n)$ 的冗余内存写操作与缓存缺失中触及耗时瓶颈。洛谷 P3383「【模板】线性筛素数」正是 CCF GESP 五级（初等数论·埃氏筛与线性筛）与 CSP-J 普及组算法体系中的数论基石模板题。本题的破局核心在于利用算术基本定理导出**欧拉线性筛（Euler's Sieve）**的唯一筛除准则：让每一个合数**有且仅有一次**被其自身的“最小质因数”划去。代码中看似不起眼的一句 `if (i % primes[j] == 0) break;` 构成了整个算法的灵魂防线——一旦当前枚举的质数整除了倍数基底 $i$，即刻熔断内层循环，从而彻底消灭一切重复标记，将预处理时间严格收敛至纯粹线性的 $\mathcal{O}(n)$，再配合紧凑的全局静态质数表实现每次询问 $\mathcal{O}(1)$ 瞬时查表响应。题目在洛谷的官方难度评级为`普及/提高−`。

## luogu-P3383 【模板】线性筛素数

> 🔗 **洛谷原题传送门**：[luogu-P3383 【模板】线性筛素数](https://www.luogu.com.cn/problem/P3383)

### 题目背景

本题已更新，从判断素数改为了查询第 $k$ 小的素数。

提示：本题输入输出、运算数据量较大。

- 对于 C++ 语言，如果你使用 `cin` 来输入输出，建议使用 `std::ios::sync_with_stdio(0)` 来加速，同时使用 `'\n'` 换行输出。
- 对于 Java 语言，使用线性筛并且优化输入输出，也可以在规定时限内通过本题，但是时限可能较紧张。
- 对于 Python 语言，语言性能差异较大，需要使用到 `numpy` 库的数组以替代列表，且使用埃氏筛法，依然可以在合适的时间和内存消耗下通过本题。

### 题目描述

如题，给定一个范围 $n$，有 $q$ 个询问，每次输出第 $k$ 小的素数。

### 输入格式

第一行包含两个正整数 $n,q$，分别表示查询的范围和查询的个数。

接下来 $q$ 行每行一个正整数 $k$，表示查询第 $k$ 小的素数。

### 输出格式

输出 $q$ 行，每行一个正整数表示答案。

### 输入输出样例

#### 样例输入 #1
```text
100 5
1
2
3
4
5
```

#### 样例输出 #1
```text
2
3
5
7
11
```

### 题目深度剖析与核心解题模型

#### 1. 三代质数筛查算法的演进：为什么埃氏筛在 $10^8$ 下依然不够快？

在 GESP 三级与四级阶段，判断单个正整数 $x$ 是否为素数通常使用**试除法**，时间复杂度为 $\mathcal{O}(\sqrt{x})$。然而本题需要求出 $[1, n]$（$n = 10^8$）内的所有素数并按序编号。如果对每个数逐一试除，总计算量高达 $\sum_{i=2}^{n} \sqrt{i} = \mathcal{O}(n \sqrt{n}) \approx 10^{12}$，毫无疑问会严重超时（TLE）。

进入 GESP 五级，我们学习了两种批量筛法：

1. **埃拉托斯特尼筛法（埃氏筛，Sieve of Eratosthenes）**：
   - **思路**：每找到一个质数 $p$，就将它的所有倍数 $2p, 3p, 4p, \dots$（优化后从 $p^2$ 开始）全部标记为合数。
   - **缺陷（重复标记）**：一个含有多个不同质因数的合数会被反复标记多次。例如合数 $30 = 2 \times 3 \times 5$：
     - 当 $p = 2$ 时，$30$ 作为 $2 \times 15$ 被标记一次；
     - 当 $p = 3$ 时，$30$ 作为 $3 \times 10$ 又被标记一次；
     - 当 $p = 5$ 时，$30$ 作为 $5 \times 6$ 第三次被标记。
   - **复杂度**：根据梅滕斯定理（Mertens' theorem），调和级数在质数集上的求和渐近于 $\sum_{p \le n} \frac{n}{p} = \mathcal{O}(n \log \log n)$。在 $n = 10^8$ 时，大量随机跨步的内存写入不仅带来数倍冗余计算，还会频繁触发 CPU 高速缓存未命中（Cache Miss）。

2. **欧拉线性筛法（Euler's Linear Sieve）**：
   - **核心目标**：能不能规定一条铁律，让区间 $[2, n]$ 内的**每一个合数，自始至终只被它自己的“最小质因数”筛除唯一一次**？
   - 一旦做到这一点，由于每个数最多只会被标记一次，整个筛法的总步数就必然与 $n$ 严格成正比，时间复杂度达到理论下界 $\mathcal{O}(n)$！

---

#### 2. 欧拉筛的数学原理与 `i % primes[j] == 0` 破局证明

根据**算术基本定理（唯一分解定理）**，任何一个合数 $M$ 都可以唯一地拆分为：**它的最小质因数 $p_{\min}$** 与 **另一个大于等于 $p_{\min}$ 的正整数 $i$** 的乘积：
$$M = i \times p_{\min} \quad \left(\text{其中 } p_{\min} \text{ 是 } M \text{ 的最小质因数，且 } i = \frac{M}{p_{\min}} \ge p_{\min}\right)$$

在欧拉筛的双层循环中：
- **外层循环**依次从小到大枚举整数 $i \in [2, n]$（注意：无论 $i$ 是质数还是合数，都要参与筛除后续更大的合数）；
- 若当前 $i$ 未被标记为合数，则将其加入有序质数表 `primes[++cnt] = i`；
- **内层循环**从小到大枚举当前已筛出的质数 `primes[j]`（$j = 1, 2, \dots, cnt$），将乘积 $M = i \times \text{primes}[j]$ 标记为合数。

此时，最关键的语句出现了：
```text
if (i % primes[j] == 0) {
    break;
}
```
为什么要在这个条件满足时立刻 `break` 跳出内层循环？我们从**不重**与**不漏**两个维度给出严格证明：

##### （1）证明“不重”：为什么继续往后枚举会导致重复筛除？
- 假设当前内层循环枚举到某个质数 $p_j = \text{primes}[j]$，恰好满足 $p_j \mid i$（即 `i % primes[j] == 0`）。
- 因为我们是从小到大枚举质数的，第一个能整除 $i$ 的质数 $p_j$，**必然就是 $i$ 本身的最小质因数**！也就是说，我们可以把 $i$ 写成 $i = k \times p_j$（其中 $k \ge 1$）。
- 如果此时我们**不 `break`**，而是继续枚举下一个更大的质数 $p_{j+1} > p_j$，并试图筛掉合数 $M' = i \times p_{j+1}$：
  $$M' = i \times p_{j+1} = (k \times p_j) \times p_{j+1} = (k \times p_{j+1}) \times p_j$$
- 请看上式右侧：因为 $p_j < p_{j+1}$，合数 $M'$ 的最小质因数明明是更小的 $p_j$，而不是 $p_{j+1}$！
- 当外层循环将来增长到 $i' = k \times p_{j+1}$ 时，在内层枚举到 $p_j$ 的那一刻，$M' = i' \times p_j$ 自然会被它的真正最小质因数 $p_j$ 筛掉。如果现在用 $p_{j+1}$ 提前筛了一次，将来又被 $p_j$ 筛一次，就破坏了“每个合数只被最小质因数筛一次”的唯一性。因此，遇到 `i % primes[j] == 0` 必须果断 `break`！

##### （2）证明“不漏”：为什么每个合数都一定会被筛到？
- 对于任意合数 $M$，设其最小质因数为 $p_{\min}$，令 $i = M / p_{\min}$。
- 因为 $p_{\min}$ 是 $M$ 的最小质因数，所以 $i$ 的所有质因数都必然**大于或等于** $p_{\min}$。
- 这意味着：
  1. 当外层循环推进到 $i$ 时，所有不超过 $p_{\min}$ 的质数（显然都 $\le i$）早已全部被收入了 `primes` 数组；
  2. 在内层循环从小到大遍历质数、尚未到达 $p_{\min}$ 之前，对于任何严格小于 $p_{\min}$ 的质数 $p$，由于 $i$ 不含小于 $p_{\min}$ 的质因子，必定有 $p \nmid i$（即 `i % p != 0`），内层循环绝不会提前 `break`；
  3. 因此，内层循环一定能顺利枚举到 $p_{\min}$，并精准执行 `is_comp[i * p_min] = true`，将合数 $M$ 筛除！

#### 3. 手动模拟推演（以 $i = 2 \sim 6$ 为例）

为了直观感受欧拉筛与埃氏筛的区别，我们追踪前几步的执行过程：

- **$i = 2$**：未标记 $\implies$ 质数表 `primes = [2]`。
  - $j = 1, p_1 = 2$：筛去 $2 \times 2 = 4$。此时 $2 \bmod 2 = 0 \implies$ **`break`**。
- **$i = 3$**：未标记 $\implies$ 质数表 `primes = [2, 3]`。
  - $j = 1, p_1 = 2$：筛去 $3 \times 2 = 6$（$6$ 的最小质因数是 $2$）。$3 \bmod 2 \ne 0$，继续；
  - $j = 2, p_2 = 3$：筛去 $3 \times 3 = 9$（$9$ 的最小质因数是 $3$）。此时 $3 \bmod 3 = 0 \implies$ **`break`**。
- **$i = 4$**：已在 $i=2$ 时被标记为合数，不入质数表，但仍进入内层循环：
  - $j = 1, p_1 = 2$：筛去 $4 \times 2 = 8$。此时 $4 \bmod 2 = 0 \implies$ **`break`**！
  - *注：正因为这里立刻 `break`，没有去算 $4 \times 3 = 12$，才把合数 $12$ 留给了稍后 $i = 6$ 时作为 $6 \times 2 = 12$（最小质因数为 $2$）唯一筛除！*
- **$i = 5$**：未标记 $\implies$ 质数表 `primes = [2, 3, 5]`。
  - 依次筛去 $5 \times 2 = 10$、$5 \times 3 = 15$、$5 \times 5 = 25$，随后 $5 \bmod 5 = 0 \implies$ **`break`**。
- **$i = 6$**：已被标记为合数，进入内层循环：
  - $j = 1, p_1 = 2$：筛去 $6 \times 2 = 12$。此时 $6 \bmod 2 = 0 \implies$ **`break`**（不再筛 $6 \times 3 = 18$，$18$ 将在 $i = 9$ 时作为 $9 \times 2$ 被筛除）。

可以看到，被筛除的合数序列依次是 $4, 6, 9, 8, 10, 15, 25, 12 \dots$，没有任何一个合数出现过两次！

#### 4. 完整参考代码 (C++11)

```cpp
/**
 * Problem: luogu-P3383 【模板】线性筛素数
 * Algorithm: 初等数论·欧拉线性筛法 (Euler's Linear Sieve)
 * Standard: C++11 (CCF GESP 五级 / CSP-J 官方规范)
 * Blog: https://www.coderli.com/gesp-5-luogu-p3383/
 * Author: OneCoder
 */

#include <iostream>

using namespace std;

// 查询范围最大为 10^8，10^8 以内共有 5,761,455 个质数
// 大规模数组必须声明在全局静态存储区（BSS 段），严禁放在 main 函数栈空间内以防爆栈（MLE/RE）
const int MAXN = 100000005;
const int MAXP = 6000005;

// is_comp[x] 为 true 表示 x 是合数（已被筛除），为 false 表示 x 是质数
bool is_comp[MAXN];

// primes[k] 按从小到大的顺序存储第 k 小的质数（下标从 1 开始）
int primes[MAXP];

// 已筛出的质数总个数
int cnt = 0;

/**
 * 欧拉线性筛（Euler's Sieve）预处理 [2, n] 范围内的所有质数
 * 核心性质：每个合数仅被其“最小质因数”唯一筛除一次，时间复杂度严格为 O(n)
 * @param n 筛法处理的正整数上限
 */
void euler_sieve(int n) {
    // 0 和 1 既不是质数也不是合数，预先标记为非质数
    is_comp[0] = true;
    is_comp[1] = true;

    for (int i = 2; i <= n; ++i) {
        // 如果 i 未被任何更小的数筛除，说明 i 必然是质数，收入质数表
        if (!is_comp[i]) {
            primes[++cnt] = i;
        }

        // 遍历当前已筛出的所有质数 primes[j]，用 i * primes[j] 筛除合数
        // 使用 1LL * i * primes[j] <= n 防止乘积超出 32 位有符号整型上限导致溢出
        for (int j = 1; j <= cnt && 1LL * i * primes[j] <= n; ++j) {
            // 将合数 i * primes[j] 标记为已筛除，此时 primes[j] 是它的最小质因数
            is_comp[i * primes[j]] = true;

            // 【欧拉筛灵魂剪枝】
            // 若 primes[j] 整除 i，说明 i 本身已经包含质因子 primes[j]（即 i 的最小质因数就是 primes[j]）。
            // 如果继续向后枚举更大的质数 primes[j+1]，那么合数 M = i * primes[j+1] 的最小质因数依然是 primes[j] 而非 primes[j+1]，
            // M 会在后续外层循环枚举到 i' = (i / primes[j]) * primes[j+1] 时被 primes[j] 正常筛除。
            // 因此必须立即 break 终止内层循环，确保每个合数绝不被重复标记！
            if (i % primes[j] == 0) {
                break;
            }
        }
    }
}

int main() {
    // 读取查询范围上限 n 和询问个数 q
    int n, q;
    cin >> n >> q;

    // 线性时间 O(n) 预处理 1 ~ n 范围内的全部质数
    euler_sieve(n);

    // 依次回答 q 次查询，每次 O(1) 查表输出第 k 小的质数
    for (int i = 0; i < q; ++i) {
        int k;
        cin >> k;
        cout << primes[k] << "\n";
    }

    return 0;
}
```

### 时空复杂度分析与常见避坑指南

#### 1. 时空复杂度评估
- **时间复杂度**：
  - **预处理阶段**：区间 $[2, n]$ 内的每个合数恰好被其最小质因数筛除一次，内层循环的赋值操作总执行次数严格等于 $[2, n]$ 内合数的个数（小于 $n$），因此预处理时间复杂度为严格的 $\mathcal{O}(n)$。
  - **查询阶段**：所有质数已按升序连续存放在 `primes[1..cnt]` 数组中，每次询问直接按数组下标访问 `primes[k]`，单次查询耗时 $\mathcal{O}(1)$，$q$ 次询问共耗时 $\mathcal{O}(q)$。
  - **总时间复杂度**：$\mathcal{O}(n + q)$，在 $n = 10^8, q = 10^6$ 规模下具有最优的渐近效率。
- **空间复杂度**：
  - 布尔标记数组 `bool is_comp[100000005]` 占用约 $100 \times 10^6 \text{ Bytes} \approx 95.4\text{ MB}$；
  - 质数表数组 `int primes[6000005]`（由素数定理 $\pi(n) \approx \frac{n}{\ln n}$，当 $n = 10^8$ 时实际共有 $5,761,455$ 个素数）占用约 $6 \times 10^6 \times 4 \text{ Bytes} \approx 22.9\text{ MB}$；
  - 总静态内存消耗约为 $118.3\text{ MB}$，空间复杂度为 $\mathcal{O}(n)$。若在内存受限更严苛（如 $64\text{ MB}$）的题目中，可将 `bool is_comp[MAXN]` 替换为 `<bitset>` 库中的 `bitset<MAXN> is_comp;`，将布尔标记空间压缩至 $\frac{1}{8}$（仅约 $12\text{ MB}$）。

#### 2. 考场高频失分点防范
1. **将亿级大数组声明在 `main()` 函数内部导致运行崩溃（RE）**：
   - 操作系统的函数调用栈（Stack）空间通常仅有 $2\text{ MB} \sim 8\text{ MB}$。如果把 `bool is_comp[100000005]` 写在 `main` 函数内部，程序一启动就会触发栈溢出（Stack Overflow / Segmentation Fault）。凡是规模超过 $10^5$ 的大数组，**必须声明为全局变量**，存放在全局静态存储区（BSS 段）。
2. **用 `int is_comp[MAXN]` 代替 `bool` 导致内存超限（MLE）**：
   - 一个 `int` 占 $4$ 字节，长度为 $10^8$ 的 `int` 数组会瞬间消耗近 $400\text{ MB}$ 内存；而 `bool` 类型每个元素仅占 $1$ 字节，务必使用 `bool` 或 `bitset` 标记合数。
3. **误用 `endl` 换行引发百万次缓冲区刷新超时（TLE）**：
   - 本题有高达 $q = 10^6$ 行输出。C++ 中的 `endl` 不仅输出换行符，还会强制调用 `flush` 刷新输出流缓冲区，执行一百万次系统级 I/O 刷新会白白浪费数秒时间。在海量输出场景下，务必使用转义字符 `"\n"` 替代 `endl`。
4. **把 `break` 写在筛除赋值语句之前**：
   - 在内层循环中，必须**先执行** `is_comp[i * primes[j]] = true;` 将合数 $i \times \text{primes}[j]$ 筛掉，**再判断** `if (i % primes[j] == 0) break;`。如果颠倒了这两行代码的顺序，所有形如 $p^2$（如 $4, 9, 25$）以及最小质因数幂次大于 $1$ 的合数（如 $8, 12, 18$）都会漏筛，被错误地当成素数！
