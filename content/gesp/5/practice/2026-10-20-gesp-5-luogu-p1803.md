在一条有限的时间轴上面对 $n$（$n \le 10^6$）场起止时间各异的比赛，要求从中选出互不重叠的最多场次，初学者最容易掉入两个直觉陷阱：要么优先挑选“开始时间最早”的比赛（却可能被一场从早持续到晚的马拉松赛事霸占整条时间轴），要么优先挑选“持续时间最短”的比赛（却可能因为一场短赛恰好横跨在两场长赛的交界处，导致以一换二得不偿失）。洛谷 P1803「凌乱的yyy / 线段覆盖」正是算法竞赛中最负盛名的**区间调度问题（Interval Scheduling / Activity Selection Problem）**标准模型，也是 CCF GESP 五级（贪心算法与最优子结构）及 CSP-J 普及组的核心必考母题。本题真正的破局之道在于转换视角——参加任何一场比赛的收益都是固定的 $+1$，而它对未来的唯一负面影响是**将时间轴封锁到了它的结束时刻 $b_i$**。因此，按照**结束时间（右端点 $b_i$）从小到大升序排序**，每次无脑选择当前不冲突且最早结束的比赛，就能为后续留出最充裕的剩余时间窗口，在 $\mathcal{O}(n \log n)$ 时间内一步锁定全局最优解。题目在洛谷的官方难度评级为`普及−`。

## luogu-P1803 凌乱的yyy / 线段覆盖

> 🔗 **洛谷原题传送门**：[luogu-P1803 凌乱的yyy / 线段覆盖](https://www.luogu.com.cn/problem/P1803)

### 题目背景

**Python 用户可以尝试使用 pypy3 提交试题。**

快 noip 了，yyy 很紧张！

### 题目描述

现在各大 oj 上有 $n$ 个比赛，每个比赛的开始、结束的时间点是知道的。

yyy 认为，参加越多的比赛，noip 就能考的越好（假的）。

所以，他想知道他最多能参加几个比赛。

由于 yyy 是蒟蒻，如果要参加一个比赛必须善始善终，而且不能同时参加 $2$ 个及以上的比赛。

### 输入格式

第一行是一个整数 $n$ ，接下来 $n$ 行每行是 $2$ 个整数 $a_{i},b_{i}$ ( $a_{i}<b_{i}$ )，表示比赛开始、结束的时间。

### 输出格式

一个整数最多参加的比赛数目。

### 输入输出样例

#### 样例输入 #1
```text
3
0 2
2 4
1 3
```

#### 样例输出 #1
```text
2
```

### 说明/提示

- 对于 $20\%$ 的数据， $n \le 10$。
- 对于 $50\%$ 的数据， $n \le 10^3$。
- 对于 $70\%$ 的数据， $n \le 10^{5}$。
- 对于 $100\%$ 的数据， $1\le n \le 10^{6}$ ， $0 \le a_{i} < b_{i} \le 10^6$。

### 题目深度剖析与核心解题模型

#### 1. 三种直觉贪心策略的真伪辨析（反例构造法）

面对“在数轴上选出最多条互不重叠线段”的问题，考场上常见三种贪心猜想。我们可以用极简的线段反例，一眼看穿前两种策略为何失效：

1. **错误猜想一：按开始时间（左端点 $a_i$）从小到大贪心？**
   - **反例**：设有三场比赛：`[0, 10]`、`[1, 3]`、`[3, 5]`。
   - 若按左端点优先，第一场就会选中跨度极长的 `[0, 10]`，导致后面两场 `[1, 3]` 和 `[3, 5]` 全部冲突作废，只能参加 $1$ 场；而最优解显然是放弃 `[0, 10]`，连打 `[1, 3]` 和 `[3, 5]` 共 $2$ 场。
   - **病根**：开始得早不代表结束得早，“早起的长尾巨无霸”会直接吞噬整条时间轴。

2. **错误猜想二：按持续时间（区间长度 $b_i - a_i$）从小到大贪心？**
   - **反例**：设有三场比赛：`[0, 5]`、`[4, 7]`、`[6, 11]`。
   - 其中 `[4, 7]` 长度仅为 $3$（最短），而 `[0, 5]` 和 `[6, 11]` 长度均为 $5$。
   - 若优先选择最短的 `[4, 7]`，它的左右两端恰好同时卡死了 `[0, 5]` 和 `[6, 11]`，最终只能参加 $1$ 场；而选择 `[0, 5]` 与 `[6, 11]` 则可以安稳参加 $2$ 场。
   - **病根**：哪怕区间再短，一旦骑在两个合法区间的衔接处，就会造成“一子坏满盘”的阻断效应。

3. **正确策略：按结束时间（右端点 $b_i$）从小到大贪心！**
   - **核心逻辑**：无论你选哪一场作为第一场比赛，你的比赛场数都是 $+1$。既然收益完全相同，我们唯一关心的就是：**打完这场比赛后，我还剩多少时间可以去打后面的比赛？**
   - 显然，第一场比赛结束得越早（$b_i$ 越小），留给后续比赛的可用时间区间 $[b_i, +\infty)$ 就越宽裕！

---

#### 2. 右端点贪心的交换论证（Exchange Argument）严格证明

为什么“每次选结束时间最早的合法区间”一定能推导出全局最优解？我们用数学归纳与交换论证法给出严格证明：

- 设我们将所有比赛按右端点升序排列后，贪心算法依次选出的比赛序列为 $G = \{g_1, g_2, \dots, g_k\}$，其结束时间满足 $b_{g_1} \le b_{g_2} \le \dots \le b_{g_k}$。
- 假设存在某一个全局最优方案 $O = \{o_1, o_2, \dots, o_m\}$（同样按时间先后排列，且 $m \ge k$）。
- **考察第一场比赛（$i = 1$）**：
  - 因为贪心策略总是选择全场最早结束的比赛作为 $g_1$，所以必然有：
    $$b_{g_1} \le b_{o_1}$$
  - 在最优方案 $O$ 中，第二场比赛 $o_2$ 的开始时间满足 $a_{o_2} \ge b_{o_1}$。结合上式可得：
    $$a_{o_2} \ge b_{o_1} \ge b_{g_1}$$
  - 这意味着：如果我们把最优方案 $O$ 中的第一场比赛 $o_1$ **直接替换为贪心选出的 $g_1$**，得到的新方案 $O' = \{g_1, o_2, o_3, \dots, o_m\}$ 依然 $100\%$ 互不冲突，且总场数依然是 $m$！
- **归纳递推（最优子结构）**：
  - 确定第一场选 $g_1$ 后，问题规约为在剩余时间区间 $[b_{g_1}, +\infty)$ 内的所有合法比赛中选出最多场次，这与原问题同构。
  - 依此类推，我们可以将最优解中的 $o_2, o_3, \dots, o_k$ 逐一等量替换为贪心解中的 $g_2, g_3, \dots, g_k$，且始终保持 $b_{g_i} \le b_{o_i}$。
  - 若 $m > k$，则最优解中还存在第 $k+1$ 场比赛 $o_{k+1}$，满足 $a_{o_{k+1}} \ge b_{o_k} \ge b_{g_k}$。但这说明在 $g_k$ 结束之后仍有合法的比赛可选，贪心算法绝不会在 $g_k$ 处停下，产生矛盾！因此必有 $k = m$，贪心解即为全局最优解。

---

#### 3. 端点重合判定与样例推演

1. **端点重合算不算冲突？**
   - 观察样例输入：`[0, 2]`、`[2, 4]`、`[1, 3]`，样例输出为 `2`。
   - 如果端点重合算冲突，那么 `[0, 2]` 与 `[2, 4]` 不能共存，最多只能选 $1$ 场；而样例输出 `2` 明确告诉我们：**上一场比赛在时刻 $2$ 结束，下一场比赛在时刻 $2$ 开始（即 $a_{\text{next}} \ge b_{\text{last}}$），是可以无缝衔接、连续参加的！**
2. **样例手动推演**：
   - 原始区间：`[0, 2]`、`[2, 4]`、`[1, 3]`。
   - 按右端点 $r$ 从小到大排序后得到：
     1. `[0, 2]`（$r = 2$）
     2. `[1, 3]`（$r = 3$）
     3. `[2, 4]`（$r = 4$）
   - 扫描过程（初始 `last_end = -1, ans = 0`）：
     - 考察 `[0, 2]`：开始时间 $0 \ge -1$，合法！选中该场，更新 `ans = 1, last_end = 2`；
     - 考察 `[1, 3]`：开始时间 $1 < 2$，与 `[0, 2]` 冲突，直接跳过；
     - 考察 `[2, 4]`：开始时间 $2 \ge 2$，合法！选中该场，更新 `ans = 2, last_end = 4`。
   - 最终输出 `2`。

### 完整参考代码 (C++11)

```cpp
/**
 * Problem: luogu-P1803 凌乱的yyy / 线段覆盖
 * Algorithm: 贪心算法·活动安排与右端点排序 (Activity Selection & Right-Endpoint Greedy)
 * Standard: C++11 (CCF GESP 五级 / CSP-J 官方规范)
 * Blog: https://www.coderli.com/gesp-5-luogu-p1803/
 * Author: OneCoder
 */

#include <iostream>
#include <algorithm>

using namespace std;

// 比赛总数 n 最大可达 10^6，大数组必须声明在全局静态存储区（BSS 段），避免 main 函数栈溢出
const int MAXN = 1000005;

// 定义结构体存储每场比赛的开始时间与结束时间
struct Contest {
    int l; // 比赛开始时间 a_i
    int r; // 比赛结束时间 b_i
};

Contest c[MAXN];

/**
 * 自定义比较函数：按比赛结束时间 r 从小到大升序排序
 * 若结束时间相同，则按开始时间 l 从小到大排序
 * 严格遵循 C++ STL 严格弱序 (Strict Weak Ordering) 规范，绝不使用 <=
 */
bool cmp(const Contest& x, const Contest& y) {
    if (x.r != y.r) {
        return x.r < y.r;
    }
    return x.l < y.l;
}

int main() {
    int n;
    // 读取比赛总数 n
    cin >> n;

    // 依次读取 n 场比赛的开始时间和结束时间（下标从 1 到 n）
    for (int i = 1; i <= n; ++i) {
        cin >> c[i].l >> c[i].r;
    }

    // 第一步：将所有比赛按照结束时间从早到晚升序排序
    sort(c + 1, c + n + 1, cmp);

    // 第二步：线性扫描，贪心选择每一个不冲突且最早结束的比赛
    int ans = 0;        // 统计最多能参加的比赛数目
    int last_end = -1;  // 记录上一场已选比赛的结束时间，因 0 <= a_i，初始设为 -1

    for (int i = 1; i <= n; ++i) {
        // 如果当前第 i 场比赛的开始时间不早于上一场已选比赛的结束时间（端点重合如 [0,2] 与 [2,4] 互不冲突）
        if (c[i].l >= last_end) {
            ans++;              // 决定参加这场最早结束的合法比赛
            last_end = c[i].r;  // 更新时间轴的占用右边界为当前比赛的结束时间
        }
    }

    // 输出最多能参加的比赛数目
    cout << ans << "\n";

    return 0;
}
```

### 复杂度分析与常见避坑指南

1. **时间与空间复杂度评估**：
   - **时间复杂度**：对 $n$ 个区间结构体调用 `std::sort` 耗时 $\mathcal{O}(n \log n)$，随后单次线性遍历耗时 $\mathcal{O}(n)$。总时间复杂度为 $\mathcal{O}(n \log n)$，在 $n = 10^6$ 且洛谷给定 $3.00\text{s}$ 宽裕时限下可稳健通过。
   - **空间复杂度**：全局结构体数组 `Contest c[1000005]` 占用约 $10^6 \times 8\text{ Bytes} \approx 7.63\text{ MB}$ 内存，空间复杂度为 $\mathcal{O}(n)$，远低于 $512.00\text{MB}$ 限制。
2. **避坑点 1：百万级结构体数组切勿定义在 `main` 函数内**：
   - 数据范围 $100\%$ 达到了 $n \le 10^6$。若在 `main()` 内部写 `Contest c[1000005];`，将申请约 $8\text{MB}$ 的局部栈空间，在部分评测机默认栈大小限制下极易引发栈溢出（RE / MLE）。务必将其声明为全局变量。
3. **避坑点 2：初始右边界 `last_end` 的取值与 $a_i = 0$ 边界**：
   - 题目说明中明确指出 $0 \le a_i < b_i \le 10^6$，即比赛最早可以从 **$0$ 时刻**开始！
   - 虽然由于 $a_i < b_i$ 恒成立，第一场比赛的开始时间 $a_i \ge 0$，将 `last_end` 初始化为 `0` 在本题中也能碰巧通过（因为 $0 \ge 0$ 成立），但在养成严谨工程习惯时，凡是左端点可能取到 $0$ 的区间问题，建议将初始哨兵设为 `-1`，杜绝在允许单点区间 $[0, 0]$ 的变式题中漏选第一个区间。
4. **避坑点 3：混淆 `c[i].l >= last_end` 与 `c[i].l > last_end`**：
   - 区间不相交的判定条件是 `c[i].l >= last_end`（允许首尾端点重合无缝衔接）。若误写为严格大于 `>`，样例就会错误输出 `1`。
