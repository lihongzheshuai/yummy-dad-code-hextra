在一个 $N \times M$（$N, M \le 5$）且散布着 $T$ 处障碍的网格迷宫中，统计从起点到终点且每个方格最多经过一次的不同路径总数，洛谷 P1605「迷宫」是引领信奥选手从基础枚举迈向**网格图深度优先搜索（DFS）与状态回溯（Backtracking）**的标志性启蒙题。与求“最短步数”通常依赖广度优先搜索（BFS）或计数型动态规划（仅允许向右、向下单向移动）不同，本题允许向**上、下、左、右四个方向自由折返**，这意味着状态之间不存在单向拓扑序，必须借助递归调用栈遍历整棵搜索树：每踏入一个合法相邻格 $(nx, ny)$ 时将其标记为已访问（`vis[nx][ny] = true`），当该分支探索完毕退回父节点时，再立即将其恢复为未访问状态（`vis[nx][ny] = false`），从而让后续其他平行分支能够重新借道该格。然而，考场上大量初学者在拿满样例分后却频频卡在 $70 \sim 80$ 分（WA），其根源几乎都出在两个极易被忽视的边界陷阱上：一是**出发前忘记预先锁定起点**（未设置 `vis[sx][sy] = true`），导致走出第一步后又折返回起点形成“假环路”，使合法路径被成倍重复统计；二是未考虑**障碍物恰好落在终点 $(FX, FY)$ 上**的极端测试点（题目仅保证起点无障碍，并未保证终点无障碍）。本题契合 CCF GESP 五级至六级过渡（递归回溯与深度优先搜索）及 CSP-J 普及组的考察要求，洛谷官方难度评级为`普及−`。

## luogu-P1605 迷宫

> 🔗 **洛谷原题传送门**：[luogu-P1605 迷宫](https://www.luogu.com.cn/problem/P1605)

### 题目描述

给定一个 $N \times M$ 方格的迷宫，迷宫里有 $T$ 处障碍，障碍处不可通过。

在迷宫中移动有上下左右四种方式，每次只能移动一个方格。数据保证起点上没有障碍。

给定起点坐标和终点坐标，每个方格最多经过一次，问有多少种从起点坐标到终点坐标的方案。

### 输入格式

第一行为三个正整数 $N,M,T$，分别表示迷宫的长宽和障碍总数。

第二行为四个正整数 $SX,SY,FX,FY$，$SX,SY$ 代表起点坐标，$FX,FY$ 代表终点坐标。

接下来 $T$ 行，每行两个正整数，表示障碍点的坐标。

### 输出格式

输出从起点坐标到终点坐标的方案总数。

### 输入输出样例

#### 样例输入 #1
```text
2 2 1
1 1 2 2
1 2
```

#### 样例输出 #1
```text
1
```

### 说明/提示

对于 $100\%$ 的数据，$1 \le N,M \le 5$，$1 \le T \le 10$，$1 \le SX,FX \le n$，$1 \le SY,FY \le m$。

### 题目深度剖析与核心解题模型

#### 1. 为什么本题不能用递推 DP（如过河卒），而必须用 DFS 回溯？

很多刚学完递推与简单网格问题的同学会问：*“求从起点到终点的方案数，能不能像『过河卒』那样写 `dp[i][j] = dp[i-1][j] + dp[i][j-1]`？”*

答案是：**绝对不能！**
1. **移动方向的本质区别**：
   - 在「过河卒」中，卒只能**向下或向右**走，坐标和 $(x + y)$ 严格单调递增，绝对不可能走回头路，因此它是一张有向无环图（DAG），满足动态规划的“无后效性”。
   - 而在本题「迷宫」中，允许**上、下、左、右四个方向移动**。一条合法路径完全可以先向下绕过障碍、再向上折返、最后向右抵达终点（呈“U 型”或“S 型”蜿蜒路线）。
2. **简单路径（每个方格最多经过一次）的历史依赖性**：
   - 能否踏入下一格 $(nx, ny)$，不仅取决于当前所在的坐标 $(x, y)$，还取决于**之前走过的整条历史轨迹**中是否已经包含 $(nx, ny)$。
   - 加上数据范围 $1 \le N, M \le 5$ 极小（整个棋盘最多只有 $25$ 个格子），这正是**深度优先搜索（DFS）配合回溯法**暴力枚举所有合法简单路径的标准舞台！

---

#### 2. 状态回溯（Backtracking）的核心三步曲：“标记 — 递归 — 撤销”

在网格图 DFS 中，我们使用二维布尔数组 `vis[x][y]` 记录当前正在探索的这条路径上哪些格子已经被踩过了。当站在 $(x, y)$ 准备迈向相邻的合法格子 $(nx, ny)$ 时，必须严格执行对称的回溯三步曲：

```text
vis[nx][ny] = true;   // 1. 做出选择：将 (nx, ny) 加入当前路径现场，防止后续绕圈重入
dfs(nx, ny);          // 2. 递归深入：基于当前选择，继续探索通往终点的所有可能
vis[nx][ny] = false;  // 3. 撤销选择（回溯）：从该分支退回时，擦除足迹，把格子归还给其他分支
```

- **为什么要执行 `vis[nx][ny] = false`（回溯）？**
  - 假如从 $(1, 1)$ 出发，先尝试向右走到 $(1, 2)$，标记了 `vis[1][2] = true` 并一路搜到底部返回了 $(1, 1)$。
  - 接下来，我们从 $(1, 1)$ 改走下方 $(2, 1) \to (2, 2) \to (1, 2)$。如果刚才从 $(1, 2)$ 退回时没有把 `vis[1][2]` 改回 `false`，那么这条新路径走到 $(2, 2)$ 时就会误以为 $(1, 2)$ 已经被占用了，从而漏掉大量合法方案！
  - **一句话总结**：“不撞南墙不回头，撞了南墙退一步；退回一步擦脚印，换个方向再探路。”

---

#### 3. 考场 70 分与 80 分的两大经典死穴剖析

在洛谷讨论区中，本题有两类高频丢分原因，几乎每位初学者都曾踩过其中之一：

1. **死穴一：70 分 WA —— 忘记在 `dfs(sx, sy)` 之前初始化 `vis[sx][sy] = true`**
   - **现象复盘**：如果在 `main()` 函数中直接调用 `dfs(sx, sy)`，而没有事先写 `vis[sx][sy] = true`，会发生什么？
   - **灾难推演**：以样例为例，起点是 $(1, 1)$，终点是 $(2, 2)$，障碍在 $(1, 2)$。
     - 从 $(1, 1)$ 向下走到 $(2, 1)$，此时 `vis[2][1] = true`；
     - 在 $(2, 1)$ 处，一种走法是直接向右到终点 $(2, 2)$（方案 $+1$）；
     - 但因为在 $(1, 1)$ 出发前没打标记（`vis[1][1]` 仍是 `false`），程序在 $(2, 1)$ 向上看时，发现起点 $(1, 1)$ 居然“没被访问过”！于是它会**从 $(2, 1)$ 重新走回起点 $(1, 1)$**，再从 $(1, 1)$ 寻找其他出路！
   - **后果**：所有从起点能迈出去再退回来的邻居格，都会把起点当成普通跳板再走一遍，导致答案比正确值大得多。**铁律：调用 `dfs(sx, sy)` 前，必须先写 `vis[sx][sy] = true;`！**

2. **死穴二：80/90 分 WA —— 障碍物直接生成在终点 $(FX, FY)$ 上**
   - 仔细审题：题干中只写了*“数据保证起点上没有障碍”*，**只字未提终点上没有障碍**！
   - 如果你在 `dfs(x, y)` 函数的第一行先判断 `if (x == fx && y == fy) { ans++; return; }`，而没有在迈向 $(nx, ny)$ 时拦截障碍物（或者虽然拦截了，但起点和终点重合且上面有障碍），就可能把落在障碍物上的终点误判为合法到达。
   - **防御方案**：一方面，在 `for` 循环扩展下一格 $(nx, ny)$ 时，严格先检查 `!obs[nx][ny]` 再递归进入 `dfs(nx, ny)`；另一方面，在 `main` 函数读完障碍后直接加一行 `if (obs[fx][fy]) { cout << 0 << "\n"; return 0; }`，双保险彻底封死终点障碍漏洞。

### 完整参考代码 (C++11)

```cpp
/**
 * Problem: luogu-P1605 迷宫
 * Algorithm: 深度优先搜索与状态回溯 (Depth-First Search & Backtracking on Grid)
 * Standard: C++11 (CCF GESP 五级 / CSP-J 官方规范)
 * Blog: https://www.coderli.com/gesp-5-luogu-p1605/
 * Author: OneCoder
 */

#include <iostream>

using namespace std;

// 迷宫长宽最大为 5，开到 10 预留充足边界
const int MAXN = 10;

int n, m, t;          // 迷宫的行数 n、列数 m、障碍总数 t
int sx, sy, fx, fy;   // 起点坐标 (sx, sy) 与终点坐标 (fx, fy)
int ans = 0;          // 统计从起点到终点的合法方案总数

bool obs[MAXN][MAXN]; // obs[x][y] = true 表示坐标 (x, y) 处有障碍物
bool vis[MAXN][MAXN]; // vis[x][y] = true 表示坐标 (x, y) 在当前路径中已被经过

// 方向偏移量数组：分别对应向上、向下、向左、向右移动一个方格
int dx[4] = {-1, 1, 0, 0};
int dy[4] = {0, 0, -1, 1};

/**
 * 深度优先搜索 (DFS) 枚举所有从当前位置 (x, y) 出发到达终点的简单路径
 * @param x 当前所在的行坐标
 * @param y 当前所在的列坐标
 */
void dfs(int x, int y) {
    // 递归终止条件：如果成功到达终点 (fx, fy)，说明找到了一条合法路径
    if (x == fx && y == fy) {
        ans++; // 方案总数加 1
        return;
    }

    // 尝试向上、下、左、右四个相邻方向移动
    for (int i = 0; i < 4; ++i) {
        int nx = x + dx[i];
        int ny = y + dy[i];

        // 1. 越界检查：新坐标必须在 [1, n] x [1, m] 的迷宫范围内
        if (nx < 1 || nx > n || ny < 1 || ny > m) {
            continue;
        }
        // 2. 合法性检查：新方格不能是障碍物，且在当前路径中未被经过
        if (obs[nx][ny] || vis[nx][ny]) {
            continue;
        }

        // 做出选择：标记新方格 (nx, ny) 为已访问
        vis[nx][ny] = true;

        // 递归深入：从 (nx, ny) 继续向下搜索
        dfs(nx, ny);

        // 状态回溯（撤销选择）：从 (nx, ny) 退回当前格时，恢复其未访问状态，
        // 以便后续其他分支路径可以重新经过该方格
        vis[nx][ny] = false;
    }
}

int main() {
    // 读取迷宫的长 n、宽 m 和障碍总数 t
    cin >> n >> m >> t;

    // 读取起点坐标 (sx, sy) 和终点坐标 (fx, fy)
    cin >> sx >> sy >> fx >> fy;

    // 读取 t 处障碍点的坐标并标记
    for (int i = 1; i <= t; ++i) {
        int ox, oy;
        cin >> ox >> oy;
        obs[ox][oy] = true;
    }

    // 边界防御：如果终点本身就有障碍物，则不可能到达，直接输出 0
    if (obs[fx][fy]) {
        cout << 0 << "\n";
        return 0;
    }

    // 核心初始化（极其重要）：出发前必须先将起点 (sx, sy) 标记为已访问！
    // 否则搜索过程中会走“回头路”再次回到起点，导致路径重复统计（考场常见 70 分陷阱）
    vis[sx][sy] = true;

    // 从起点 (sx, sy) 开始深度优先搜索
    dfs(sx, sy);

    // 输出从起点到终点的方案总数
    cout << ans << "\n";

    return 0;
}
```

### 复杂度分析与常见避坑指南

1. **时间与空间复杂度评估**：
   - **时间复杂度**：迷宫总格数为 $V = N \times M \le 5 \times 5 = 25$。由于每个格子最多经过一次，路径最大长度不超过 $25$，且除起点外每一步最多向 $3$ 个未访问方向扩展（不能走刚刚来的那一步）。在 $5 \times 5$ 的网格中，无障碍时从左上角到右下角的简单路径总数仅为 $8512$ 条，整个搜索树的总节点数在 $10^4 \sim 10^5$ 量级以内，运行耗时不足 $3\text{ms}$。
   - **空间复杂度**：递归调用栈的最大深度不超过总格数 $N \times M = 25$，配合两个 $10 \times 10$ 的布尔标记数组，空间复杂度为 $\mathcal{O}(N \times M)$，内存消耗可忽略不计。
2. **避坑点 1：到达终点后切勿在 `if (x == fx && y == fy)` 内部停止，忘了 `return`**：
   - 题目问的是“从起点到终点的方案数”，一旦到达终点 $(fx, fy)$，该条路径即告完成，必须立刻 `return` 退回上一格（并在上一格的 `for` 循环中触发 `vis[fx][fy] = false` 回溯），绝不能穿过终点继续往外走！
3. **避坑点 2：多个障碍物坐标可能重合**：
   - 测试数据中有可能在同一坐标给出多次障碍物。因此，记录障碍时应使用布尔赋值 `obs[ox][oy] = true;`（幂等操作），而不要写成 `obs[ox][oy] += 1;` 或翻转异或。
