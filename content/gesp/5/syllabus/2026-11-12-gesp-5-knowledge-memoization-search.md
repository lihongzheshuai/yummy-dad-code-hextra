为什么一段只有 5 行的斐波那契递归代码 `return fib(n - 1) + fib(n - 2);`，当输入 $n = 10$ 时瞬间出解，一旦输入 $n = 45$ 就会触发超过 **22 亿次**函数调用，把评测机死死卡在 **TLE（运行超时）**？更神奇的是，为什么在不改变递归主体结构的前提下，仅仅在函数里加上一个备忘录数组 `memo[]` 和**两行查表/存表代码**，原本需要跑好几分钟的程序就能在 **0.001 秒（仅 89 次调用）**内光速通关？在 GESP 五级认证与 CSP-J/S 初赛阅读程序、复赛搜索与动态规划过渡题中，**朴素递归指数级爆炸的元凶（重叠子问题）、备忘录数组 `memo[]` 的哨兵值设计、“以空间换时间”的剪枝思想，以及记忆化搜索通往动态规划（DP）的桥梁作用**，是每一位选手从“暴力枚举”迈向“高效算法设计”的分水岭。本文将带你彻底打通记忆化搜索的任督二脉。

## 🎯 考纲锚点与核心痛点

> 📍 **对应考点**：剖析朴素多分支递归产生指数级时间复杂度的根本原因（重叠子问题 Overlapping Subproblems）；掌握记忆化搜索（Memoization Search）的标准三步改造框架与“以空间换时间”思想；熟练计算记忆化后的状态数与时间复杂度，理解自顶向下记忆化搜索与自底向上动态规划（DP）的等价与互补关系。
> 🎯 **适用等级**：`GESP 五级考点 | CSP-J/S 初赛/复赛必考`

在考场做阅读程序题和编写复赛搜索/递推代码时，同学们最容易在以下三个痛点上丢分：
1. **“看不出递归树里的海量重复劳动，误判时间复杂度”**：看到递归代码只有几行，误以为复杂度是 $O(n)$；遇到初赛阅读程序题加入 `memo[]` 数组后，又算不清哪些分支被直接剪掉、函数到底被调用了多少次；
2. **“哨兵值初始化踩坑，导致记忆化彻底失效退化回 $O(2^n)$”**：习惯性直接用全局变量默认的 `0` 表示“未计算”，结果遇到合法答案恰好等于 `0`（如死胡同方案数为 `0`、最小代价为 `0`）的数据点时，`if (memo[x] != 0)` 永远拦不住，程序当场退化成裸递归超时；
3. **“遇到转移方向乱跳的题目，死磕 `for` 循环递推写不出拓扑序”**：比如在二维网格中可以向**上下左右四个方向**滑行，不知道该按什么顺序写嵌套 `for` 循环，却忘了直接用“自顶向下记忆化搜索”可以无视枚举顺序、十行代码轻松满分。

## 🧠 一、 核心原理深度拆解（有理论）

### 1. 朴素递归指数级爆炸的真凶：重叠子问题（Overlapping Subproblems）

以最经典的斐波那契数列 $f(n) = f(n - 1) + f(n - 2)$（边界 $f(0) = 0, f(1) = 1$）为例。如果我们不加任何记录，直接调用 `fib(5)`，计算机在底层展开的递归调用树如下左图所示：

```text
====================================================================================
【左图：朴素递归 fib(5)（共 15 次调用）】      【右图：记忆化搜索 fib(5)（仅 9 次调用）】

              fib(5)                                        fib(5)
            /        \                                    /        \
        fib(4)       fib(3) [重复整棵子树!]            fib(4)      [fib(3)] ⚡命中缓存!
        /    \        /    \                          /    \       (O(1)直接返回 memo[3])
    fib(3)  fib(2) fib(2) fib(1)                  fib(3)  [fib(2)] ⚡命中缓存!
    /   \    /  \   /  \                          /   \    (O(1)直接返回 memo[2])
 fib(2) f(1)f(1)f(0)f(1)f(0)                  fib(2) fib(1)
  /  \                                         /   \
f(1) f(0)                                   fib(1) fib(0)

 ★ 痛点诊断：                                  ★ 剪枝奇迹：
   fib(3) 被完整重算了 2 遍；                    沿着最左侧链一路算完并存入 memo[2..5] 后，
   fib(2) 被完整重算了 3 遍！                    所有右分支遇到已算状态全部 O(1) 瞬间返回，
   当 n=45 时，同类子问题被重算上亿遍 -> O(2^n)   整棵树被削成一条“左主干+右叶子” -> O(n)！
====================================================================================
```

所谓**重叠子问题**，是指在将大问题拆解为子问题的递归过程中，**相同的子问题（参数完全一致的函数调用）在不同的递归分支中被反复请求了成千上万次**。朴素递归就像一个“没有草稿本的健忘症患者”，刚在左子树千辛万苦算完 `fib(3) = 2`，转身进右子树遇到 `fib(3)` 又从头拆解再算一遍，导致节点总数呈 $O(2^n)$ 指数级爆炸。

### 2. “以空间换时间”：记忆化搜索的标准三步改造框架

既然慢在“健忘重算”，解决之道就非常直观——给递归函数配一本**全局草稿本（备忘录数组 `memo[]`）**，这就是算法竞赛中大名鼎鼎的**以空间换时间（Space-Time Tradeoff）**：多花费 $O(n)$ 的内存空间记录历史答案，换取时间复杂度从指数级 $O(2^n)$ 暴降到多项式级 $O(n)$！

任何满足**无后效性**（即函数的返回值**完全且唯一地由传入的形参决定**，不随调用路径或外部可变全局变量改变）的递归函数，都可以按以下**“三步走铁律”**无脑改造为记忆化搜索：

1. **【第 0 步：初始化哨兵】**：开设与状态维度一致的备忘录数组（一维 `memo[N]`、二维 `memo[N][M]`），并在主函数中将其全部初始化为一个**绝对不可能是合法答案的特殊哨兵值**（最常用 `memset(memo, -1, sizeof(memo));`）；
2. **【第 1 步：判边界后先查表（Lookup）】**：进入递归函数，先处理递归终止边界（防止非法下标越界），紧接着检查 `if (memo[state] != -1) return memo[state];`。一旦命中缓存（Cache Hit），直接 $O(1)$ 返回，斩断后续所有递归分支；
3. **【第 2 步：首次算出必存表（Store）】**：若缓存未命中（Cache Miss），正常递归求解子问题，但在 `return` 之前**必须将结果写入 `memo[state]`**，确保每个状态终生只被展开计算 **1 次**！

### 3. 记忆化搜索复杂度计算与“通往动态规划（DP）的桥梁”

在初赛和复赛分析复杂度时，记忆化搜索的时间复杂度不再看递归分支有多深，而是严格遵循以下通用公式：

$$\text{记忆化搜索总时间复杂度} = (\text{本质不同的状态总数}) \times (\text{单个状态内部的转移计算代价})$$

例如在 `fib(n)` 中，本质不同的状态只有 $0 \sim n$ 共 $O(n)$ 个，每个状态内部只做 1 次加法（代价 $O(1)$），因此总时间复杂度严格为 $O(n) \times O(1) = O(n)$！

从算法思想上看，**记忆化搜索本质上就是“自顶向下（Top-Down）实现的动态规划”**，它是连接搜索与动态规划最平滑的桥梁：

| 核心对比维度 | 记忆化搜索（Top-Down DP） | 递推动态规划（Bottom-Up DP） |
| :---: | :--- | :--- |
| **驱动方式** | **按需索取（递归驱动）**：从终态 `dfs(n)` 出发，需要哪个子状态就去递归算哪个，算完存进 `memo[]` | **全量推演（循环驱动）**：从初态 `dp[0]` 出发，按拓扑顺序写 `for` 循环把整张 `dp[]` 表填满 |
| **代码编写难度** | **极低、极自然**：完全顺着人类直觉写递归规则，**无需人工构造复杂的枚举拓扑顺序** | 需严格确定状态计算的先后依赖顺序（顺序写反直接算出错解） |
| **无效状态过滤** | **天然跳过不可达状态**：从起点根本走不到的冗余状态一次都不会算 | 循环通常会死板地把表里所有格子（包括不可达状态）全部扫一遍 |
| **运行常数与栈风险** | 有函数压栈开销；若递归链深度超过 $10^5$ 存在系统栈溢出（Stack Overflow）风险 | 纯数组寻址无函数调用开销，运行常数更小，且可用滚动数组压缩空间 |

> 💡 **考场黄金法则（背诵直接套用）**：
> 1. **【记忆化剪枝计数铁律】**：若每个非边界状态内部固定发起 $k$ 次子调用，且共有 $M$ 个本质不同的非边界状态被展开，则每个内部状态**有且仅有第 1 次访问会被展开**，整场运行的函数总调用次数必为 **$1 + k \times M$**（根节点初始调用 $1$ 次 $+$ $M$ 个内部节点各发起 $k$ 次子调用）！
> 2. **【记忆化 vs 循环 DP 选型铁律】**：线性、背包等拓扑顺序一目了然且深度可能达 $10^5$ 的题，优先写 **`for` 循环递推 DP**；四方向网格跳跃、树/有向无环图（DAG）路径、博弈必胜态等**转移方向纵横交错、循环顺序难以排定**的题，无脑首选**记忆化搜索**！

## 🔍 二、 具象代码与数据推演（有举例）

### 示例 1：一维记忆化搜索的内存填表与缓存命中全轨迹

请阅读以下标准 C++11 程序，观察 `fib(5)` 如何将 15 次调用压缩为 9 次，并注意 `memo[]` 数组的写入时机：

```cpp
#include <iostream>
#include <cstring>
using namespace std;

long long memo[55];
int call_cnt = 0;

long long fib(int n) {
    call_cnt++;
    if (n <= 1) {
        return n;
    }
    if (memo[n] != -1) {
        return memo[n]; // 命中缓存，O(1) 直接返回！
    }
    memo[n] = fib(n - 1) + fib(n - 2); // 首次计算，存表备查
    return memo[n];
}

int main() {
    memset(memo, -1, sizeof(memo));
    cout << fib(5) << " " << call_cnt << endl;
    return 0;
}
```

#### 分步调用与 `memo[2..5]` 内存状态推演表（初始均为 `-1`）

| 调用序号 | 当前进入函数 | 查表 / 边界判定结果 | `memo[2..5]` 状态变化 | 动作与返回结果 |
| :---: | :---: | :--- | :---: | :--- |
| **#1 ~ #4** | `fib(5)->(4)->(3)->(2)` | 全部 `memo[n] == -1`（未命中） | `[-1, -1, -1, -1]` | 沿左主干一路压栈深入，挂起等待子调用 |
| **#5, #6** | `fib(1)`, `fib(0)` | 触发边界 `n <= 1`，返回 `1` 和 `0` | **`[1, -1, -1, -1]`** | `fib(2)` 汇总得 `1+0=1`，**写入 `memo[2]=1`** 返回 |
| **#7** | `fib(1)`（来自 `fib(3)` 右支） | 触发边界 `n <= 1`，返回 `1` | **`[1, 2, -1, -1]`** | `fib(3)` 汇总得 `1+1=2`，**写入 `memo[3]=2`** 返回 |
| **#8** | `fib(2)`（来自 `fib(4)` 右支） | **⚡ 命中缓存 `memo[2] == 1`！** | **`[1, 2, 3, -1]`** | 不再向下递归！直接返回 `1`，`fib(4)` **写入 `memo[4]=3`** |
| **#9** | `fib(3)`（来自 `fib(5)` 右支） | **⚡ 命中缓存 `memo[3] == 2`！** | **`[1, 2, 3, 5]`** | 不再向下递归！直接返回 `2`，`fib(5)` **写入 `memo[5]=5`** |

* **推演验证**：内部非边界状态 `n = 2, 3, 4, 5` 共 $M = 4$ 个，每个展开 $k = 2$ 个分支，套用黄金法则公式得总调用次数 $= 1 + 2 \times 4 = 9$ 次。程序最终输出：`5 9`。

### 示例 2：二维状态记忆化搜索——网格路径计数的查表剪枝

当递归函数依赖**两个独立变量**（如坐标 `(x, y)`）时，备忘录也必须同步升维成**二维数组 `memo[x][y]`**：

```cpp
#include <iostream>
#include <cstring>
using namespace std;

int memo_grid[10][10];
int hit_cnt = 0;

int count_paths(int x, int y) {
    if (x == 1 || y == 1) {
        return 1; // 第一行或第一列只有 1 条直线路径
    }
    if (memo_grid[x][y] != -1) {
        hit_cnt++;
        return memo_grid[x][y];
    }
    memo_grid[x][y] = count_paths(x - 1, y) + count_paths(x, y - 1);
    return memo_grid[x][y];
}

int main() {
    memset(memo_grid, -1, sizeof(memo_grid));
    cout << count_paths(3, 3) << " " << hit_cnt << endl;
    return 0;
}
```

* **分步数据推演**：
  1. 求 `count_paths(3, 3)` 时，先走上分支 `count_paths(2, 3)`：
     * `count_paths(2, 3)` 拆解为 `count_paths(1, 3)`（返回 `1`）与 `count_paths(2, 2)`；
     * `count_paths(2, 2)` 拆解为 `count_paths(1, 2)`（返回 `1`）与 `count_paths(2, 1)`（返回 `1`），算出 **`memo_grid[2][2] = 2`**；
     * 进而算出 **`memo_grid[2][3] = 1 + 2 = 3`**。
  2. 随后回溯求左分支 `count_paths(3, 2)`：
     * 拆解请求 `count_paths(2, 2)` 时，发现 `memo_grid[2][2]` 已经等于 `2`（**触发 1 次缓存命中 `hit_cnt = 1`**），直接返回 `2`；
     * 加上边界 `count_paths(3, 1)` 返回的 `1`，得出 `memo_grid[3][2] = 3`。
  3. 最终汇总 `memo_grid[3][3] = 3 + 3 = 6`，程序输出：`6 1`。在 $N \times M$ 网格中，朴素递归复杂度高达 $O(\binom{N+M}{N})$，而二维记忆化搜索只需填满表格，时间复杂度稳稳降为 **$O(N \times M)$**！

## ⚡ 三、 考场高频避坑指南（正误辨析）

在 GESP 五级真题与 CSP-J 复赛中，记忆化搜索看似简单，但以下三个隐蔽陷阱每年都会坑掉大批考生：

### ❌ 易错点 1：用默认的 `0` 当“未计算标记”，撞上合法答案 `0` 导致缓存彻底失效！
* **错误写法**：
  ```cpp
  int memo[1005]; // 全局数组默认全为 0
  int dfs(int u) {
      if (u == target) return 1;
      if (memo[u] != 0) return memo[u]; // 致命漏洞！
      int ways = 0;
      // ... 若从 u 出发全是死胡同，算出来 ways 恰好等于 0！
      return memo[u] = ways;
  }
  ```
* **为什么错**：如果图中存在一大片无法到达终点的“死胡同子图”，这些节点的真实路径条数 `ways` 算出来**本来就是 `0`**！当你把 `0` 存入 `memo[u]` 后，下次别的分支再走到 `u` 时，`if (memo[u] != 0)` 判断为假，误以为 `u` 还没算过，于是又一头扎进死胡同重算几百万遍，**时间复杂度瞬间从 $O(N + M)$ 退化回指数级 $O(2^N)$ 惨遭 TLE**！
* **正确规范**：**一律将 `memo` 初始化为绝不可能出现的非法哨兵值**（例如求方案数/距离时 `memset(memo, -1, sizeof(memo));`，判 `if (memo[u] != -1)`）；如果答案连 `-1` 甚至任意整数都有可能取到，就老老实实多开一个布尔数组 **`bool vis[1005]`** 专门记录“是否算过”！

### ❌ 易错点 2：把查表语句写在越界/边界判断之前，触发负数下标越界 RE
* **错误写法**：
  ```cpp
  int solve(int x) {
      if (memo[x] != -1) return memo[x]; // 危险！若传入 x = -2 直接内存越界！
      if (x <= 0) return 0;
      return memo[x] = solve(x - 1) + solve(x - 3);
  }
  ```
* **为什么错**：当 `x = 1` 调用 `solve(1 - 3)` 即 `solve(-2)` 时，程序一进门还没来得及被 `if (x <= 0)` 拦住，就先访问了 `memo[-2]`，轻则读到栈/全局区相邻变量的垃圾值导致 **WA（答案错误）**，重则直接触发段错误 **RE**！
* **正确规范**：死记口诀——**“先判越界与边界，再查 `memo` 备忘录，最后转移写缓存”**。

### ❌ 易错点 3：在违反“无后效性”（含环或依赖历史路径 `used[]`）的回溯搜索中乱加一维记忆化
* **典型误区**：在“无向带环图求最长简单路径”或“迷宫不走回头路求方案数（带 `used[x][y] = true` 回溯）”中，直接加上 `if (memo[x][y] != -1) return memo[x][y];`。
* **为什么错**：在这些题目里，当你站在同一个格子 `(x, y)` 时，后续能怎么走**取决于你之前走过了哪些格子（即 `used` 数组的状态）**！第一次以路径 A 到达 `(x, y)` 算出的答案，与第二次以路径 B 到达 `(x, y)` 算出的可用答案根本不同。强行只按 `(x, y)` 缓存会把后续合法路线错误剪掉导致 **WA**。**只有当状态转移构成有向无环图（DAG，例如坐标单调递增、高度严格递减、剩余步数严格减少）时，才能直接按节点坐标记忆化！**

## 📝 四、 真题实战演练与精析（有例题：3 道）

### 【例题 1 · 单选题】（CSP-J 初赛阅读程序题：三分支记忆化搜索返回值与精确调用计数）

**题目**：阅读以下 C++11 程序，当主函数执行完毕后，屏幕输出的 `ans` 值与全局变量 `cnt`（即 `solve` 函数被调用的总次数）分别是（ ）。
```cpp
#include <iostream>
#include <cstring>
using namespace std;

int cnt = 0;
int f_memo[20];

int solve(int n) {
    cnt++;
    if (n <= 2) {
        return n;
    }
    if (f_memo[n] != -1) {
        return f_memo[n];
    }
    f_memo[n] = solve(n - 1) + solve(n - 2) - solve(n - 3);
    return f_memo[n];
}

int main() {
    memset(f_memo, -1, sizeof(f_memo));
    int ans = solve(6);
    cout << ans << " " << cnt << endl;
    return 0;
}
```
* **A.** `6 7`
* **B.** `6 13`
* **C.** `5 13`
* **D.** `6 25`

**🔍 答案与逐项排除解析**：
* **正确答案**：**B**
* **解析过程**：
  1. **第一步：自底向上秒推返回值 `ans`**：
     * 记忆化绝不改变函数本身的数学返回值，因此直接列表递推：
     * 边界：$n \le 2$ 时返回 $n$，即 `solve(0) = 0, solve(1) = 1, solve(2) = 2`；
     * `solve(3) = solve(2) + solve(1) - solve(0) = 2 + 1 - 0 = 3`；
     * `solve(4) = solve(3) + solve(2) - solve(1) = 3 + 2 - 1 = 4`；
     * `solve(5) = solve(4) + solve(3) - solve(2) = 4 + 3 - 2 = 5`；
     * `solve(6) = solve(5) + solve(4) - solve(3) = 5 + 4 - 3 = 6`。
     故 `ans = 6`（直接**排除 C**）。
  2. **第二步：套用“记忆化剪枝计数铁律”秒算 `cnt`**：
     * 注意 `cnt++` 写在函数第一行！无论是边界返回还是命中 `f_memo` 缓存返回，只要踏进 `solve()` 函数大门就会计 `1` 次调用（误选 **A** 的同学错把状态个数当成了调用次数，漏算了命中缓存的那几次入栈检查；误选 **D** 的同学则是按未加记忆化的裸递归算了 $25$ 次）。
     * 观察展开节点：从 `solve(6)` 出发，真正突破 `f_memo[n] != -1` 并执行最后一行三分支展开的非边界状态，只有 **`n = 6, 5, 4, 3` 这 $M = 4$ 个状态**（每个状态终生只展开 1 次）！
     * 每个展开节点固定发起 $k = 3$ 次子调用，再加上主函数最初发起的 $1$ 次根调用 `solve(6)`，总调用次数严格为：
       $$\text{cnt} = 1 + 3 \times 4 = 13$$
     故锁定 **B**！

### 【例题 2 · 判断题】（GESP 五级考纲概念辨析：哨兵值设计与复杂度退化）

**题目**：在编写求解非负整数答案（即合法结果可能为 $0, 1, 2, \dots$）的记忆化搜索程序时，如果使用全局整型数组 `int memo[1005];`（默认初值为 `0`），并通过 `if (memo[x] != 0) return memo[x];` 来判断是否命中缓存，既不会影响计算结果的正确性，也能保证每个状态最多只被展开计算一次。（ ）

**🔍 答案与反例证明**：
* **结论**：**错误（×）**
* **反例证明**：
  1. 虽然当真实答案为 `0` 时，重新计算一遍得到的依然是 `0`（表面上没有改变最终输出值），但它**彻底破坏了“每个状态最多只被展开一次”的时间复杂度保证**！
  2. **具体反例**：设递推式为 `f(n) = f(n - 1) * f(n - 2)`，且边界 `f(0) = 0, f(1) = 0`。此时对于任意 $n \ge 2$，`f(n)` 的合法计算结果恒为 `0`。每次算完 `memo[n] = 0` 后，由于 `memo[n] != 0` 恒为假，备忘录形同虚设，每次遇到 `f(n)` 都会重新展开左右两个分支，调用次数高达 $O(2^n)$ 指数级！只有将 `memo` 初始化为 `-1`（判 `memo[x] != -1`）或配合独立的 `bool vis[]` 标记数组，才能真正保证每个状态只展开一次。故原命题错误。

### 【例题 3 · 微代码实战】（二维记忆化搜索经典模型：网格严格下坡最长滑翔路线）

**题目描述**：给定一个 $R$ 行 $C$ 列的整数高度矩阵 $h$（$1 \le R, C \le 100$，$0 \le h_{i,j} \le 10000$）。一名滑翔翼选手可以从网格中的**任意一个格子**作为起点出发，每次只能向**上、下、左、右**四个相邻格子之一滑行，且目标格子的高度必须**严格小于**当前所在格子的高度（即 $h_{nx, ny} < h_{x, y}$）。请你求出该选手最多能连续经过多少个格子（包含起点和终点格子本身）。

**输入格式**：
第一行包含两个正整数 $R$ 和 $C$，分别表示矩阵的行数和列数。
接下来 $R$ 行，每行包含 $C$ 个非负整数，表示高度矩阵 $h$。

**输出格式**：
输出一行一个正整数，表示最长滑翔路径所经过的格子总数。

**💡 算法建模与为什么首选“记忆化搜索”**：
1. **为什么普通 `for` 循环 DP 很难写？** 因为选手可以向上下左右四个方向移动，`(i, j)` 可能依赖它下方 `(i + 1, j)` 或右方 `(i, j + 1)` 的结果，单纯按行号列号从小到大写双重 `for` 循环，依赖的状态还没算出来！
2. **为什么天然满足无后效性？** 因为题目规定每次移动必须满足高度**严格递减**（$h_{nx, ny} < h_{x, y}$），选手绝不可能绕一圈回到原来的格子（图中天然不存在环，是一个严格的有向无环图 DAG）！
3. **状态与复杂度分析**：设 `dfs(x, y)`（备忘录 `memo[x][y]`，初始化为 `-1`）表示从 `(x, y)` 出发最多能经过的格子数。若四周无更低格子，则至少包含自身 `1` 个格子；否则枚举四个方向取 `max(best, 1 + dfs(nx, ny))` 并写入 `memo[x][y]`。总共 $R \times C$ 个状态，每个状态枚举 4 个方向，总时间复杂度仅为 **$O(R \times C)$**（最多 $10^4 \times 4$ 次运算，毫秒级秒杀）！

```cpp
#include <iostream>
#include <cstring>
#include <algorithm>
using namespace std;

int r, c;
int h[105][105];
int memo[105][105];
int dx[4] = {-1, 1, 0, 0};
int dy[4] = {0, 0, -1, 1};

int dfs(int x, int y) {
    if (memo[x][y] != -1) {
        return memo[x][y];
    }
    int best = 1;
    for (int dir = 0; dir < 4; dir++) {
        int nx = x + dx[dir];
        int ny = y + dy[dir];
        if (nx >= 1 && nx <= r && ny >= 1 && ny <= c && h[nx][ny] < h[x][y]) {
            best = max(best, 1 + dfs(nx, ny));
        }
    }
    memo[x][y] = best;
    return best;
}

int main() {
    cin >> r >> c;
    for (int i = 1; i <= r; i++) {
        for (int j = 1; j <= c; j++) {
            cin >> h[i][j];
        }
    }
    memset(memo, -1, sizeof(memo));
    int ans = 0;
    for (int i = 1; i <= r; i++) {
        for (int j = 1; j <= c; j++) {
            ans = max(ans, dfs(i, j));
        }
    }
    cout << ans << endl;
    return 0;
}
```

* **输入样例 1**：
  ```text
  3 3
  9 8 7
  2 5 6
  3 4 1
  ```
* **输出样例 1**：
  ```text
  8
  ```
  *（样例 1 解释：从左上角 `9` 出发，沿螺旋下降路线 `9 -> 8 -> 7 -> 6 -> 5 -> 4 -> 3 -> 2` 滑行，共经过 8 个格子。）*
* **输入样例 2**：
  ```text
  2 4
  10 9 2 1
  5 8 7 6
  ```
* **输出样例 2**：
  ```text
  6
  ```
  *（样例 2 解释：最优路线为 `10 -> 9 -> 8 -> 7 -> 2 -> 1` 共 6 格。注意在高度 `7` 处若盲目贪心选次大的 `6` 只能走 5 格，而记忆化搜索枚举全部合法分支后能准确找到向上滑向 `2 -> 1` 的全局最优解！）*
