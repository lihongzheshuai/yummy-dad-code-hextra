当题目给出的数据规模从 $n = 1000$ 跃升到 $n = 10^5$ 时，无论是冒泡排序、直接插入排序，还是用双重 `for` 循环暴力枚举统计“逆序对”，运算次数都会瞬间飙升至 $\frac{n(n-1)}{2} \approx 5 \times 10^9$ 次，在 1 秒时限面前毫无悬念地触发 **TLE（运行超时）**！而许多同学熟悉的快速排序虽然也很快，却不仅会在特定极端数据下退化成 $O(n^2)$，还会因为跨距交换彻底打乱相等元素的相对顺序，无法直接用来统计逆序对。究竟有没有一种算法，无论面对有序、逆序还是全相等的毒瘤数据，都能像精密钟表一样雷打不动地保持 **$O(n \log n)$**，既严格保持排序**稳定性**，又能在合并有序数组的过程中仅凭一行 **`cnt += mid - i + 1`** 顺手把几十亿个逆序对一次性秒杀？在 GESP 五级认证以及 CSP-J/S 初赛与复赛中，**分治法（Divide and Conquer）三步曲、归并排序（Merge Sort）的底层机制与复杂度严格证明，以及基于归并排序的 $O(n \log n)$ 逆序对计数模型**，是跨越初级暴力迈向高效算法的核心里程碑。本文将带你把这套经典分治组合拳彻底吃透。

## 🎯 考纲锚点与核心痛点

> 📍 **对应考点**：深入理解分治算法的核心三步曲（分解 Divide、解决 Conquer、合并 Combine）；掌握二路归并排序的递归切分逻辑、双指针线性合并过程、恒定 $O(n \log n)$ 时间复杂度严格证明与 $O(n)$ 空间代价；熟练运用归并排序合并阶段计算全局逆序对总数。
> 🎯 **适用等级**：`GESP 五级考点 | CSP-J/S 初赛/复赛必考`

在考场解答初赛客观题、阅读程序题和编写复赛分治代码时，同学们最容易在以下三个痛点上栽跟头：
1. **“只背了 $O(n \log n)$ 结论，算不清双指针合并的比较次数边界”**：初赛单选题给出两个长度为 $m$ 的有序子数组，追问合并它们最少需要比较几次、最多需要比较几次，或者具体执行了几次 `if` 比较，很多同学直接拍脑袋填 $2m$ 次，忽略了“一侧耗尽即停”的提前结束特征；
2. **“逆序对公式死记硬背，写成 `mid - i` 或 `j - mid` 当场爆零”**：不理解为什么只有当右半元素 `a[j]` 严格小于左半元素 `a[i]` 时才累加逆序对，更想不通为什么加的是左半剩余元素个数 `mid - i + 1` 而不是 `1`；
3. **“合并条件漏写等号（把 `<=` 写成 `<`），一字之差引发连环惨案”**：遇到含重复数字的测试点时，不仅亲手毁掉了归并排序的稳定性，还把相等元素误判成逆序对，导致复赛大片测试点 WA！

## 🧠 一、 核心原理深度拆解（有理论）

### 1. 分治法（Divide and Conquer）的标准三步曲

所谓**分治（分而治之）**，就是面对一个规模庞大、直接求解代价极高的大问题时，将其层层对半切分为若干个**结构完全相同但规模减半的独立子问题**，逐一击破后再将子问题的解高效拼装成原问题的解。任何标准分治算法都严格遵循以下三步曲：

1. **分解（Divide）**：找到当前区间 `[l, r]` 的中点 `mid = l + (r - l) / 2`，将原数组一分为二，拆成左半子区间 `[l, mid]` 与右半子区间 `[mid + 1, r]`；
2. **解决（Conquer）**：分别对左、右两个子区间递归调用归并排序。当区间缩小到只剩 $1$ 个元素（即递归终止边界 **`l >= r`**）时，$1$ 个数天然就是有序的，直接返回；
3. **合并（Combine —— 算法的灵魂所在）**：此时左半 `[l, mid]` 和右半 `[mid + 1, r]` 都已经各自升序排好。只需派出两个指针 `i = l` 和 `j = mid + 1` 站在左右两个有序队列的队首，每次挑出较小者放入辅助数组 `tmp[k++]`，一趟线性扫描即可拼出完整的有序区间 `[l, r]`，最后拷回原数组 `a[l..r]`！

### 2. 归并排序为什么恒为 $O(n \log n)$？（分治递归树严格证明）

我们以数组 `[5, 2, 6, 1, 4, 3]` 为例，画出归并排序“自顶向下拆分、自底向上合并”的分治树与每层工作量账单：

```text
====================================================================================
【一、自顶向下递归拆分（Divide）】              【二、每层双指针合并代价统计（Combine）】

          [5, 2, 6, 1, 4, 3]                  第 0 层（规模 n）  <── 合并总扫描 = n 次
          /                \
     [5, 2, 6]          [1, 4, 3]             第 1 层（2 个 n/2）<── 合并总扫描 = n 次
      /     \            /     \
  [5, 2]    [6]      [1, 4]    [3]            第 2 层（4 个 n/4）<── 合并总扫描 = n 次
   /  \               /  \
 [5]  [2]           [1]  [4]                  第 3 层（单元素天然有序，直接触底返回）

                     │  触底反弹，开始自底向上双指针归并（Merge）
                     ▼
 [2, 5]     [6]      [1, 4]    [3]            合并小区间：[5]&[2]->[2,5]；[1]&[4]->[1,4]
      \     /            \     /
     [2, 5, 6]          [1, 3, 4]             合并中区间：[2,5]&[6]->[2,5,6]；[1,4]&[3]->[1,3,4]
          \                /
          [1, 2, 3, 4, 5, 6]                  合并总区间：[2,5,6] & [1,3,4] -> 全局有序！
====================================================================================
```

* **时间复杂度严格数学证明**：
  1. **纵向看层数（高度 $O(\log n)$）**：每次将长度为 $n$ 的区间严格对半切分：$n \to \frac{n}{2} \to \frac{n}{4} \to \dots \to 1$。设切分 $h$ 层后长度为 $1$，由 $\frac{n}{2^h} = 1$ 立得递归层数 $h = \lceil \log_2 n \rceil$；
  2. **横向看每层合并代价（每层恒为 $O(n)$）**：合并两个总长度为 $L$ 的有序子数组时，双指针 `i` 和 `j` 每比较一次就必定有 $1$ 个元素确定落入 `tmp[]` 且指针单向前进绝不回退，加上拷回原数组的开销，代价严格正比于 $L$。在第 $d$ 层，虽然有 $2^d$ 个子任务，但所有子任务的区间长度之和**恰好等于总元素个数 $n$**！
  3. **总复杂度相乘**：设总运行时间为 $T(n) = 2T\left(\frac{n}{2}\right) + O(n)$，共有 $\log_2 n$ 层合并，每层固定干 $O(n)$ 的活，因此总时间复杂度严格等于 **$O(n \log n)$**！
* **考场核心特性对比**：
  * **无惧任何极端数据**：无论输入原本是完全升序、完全降序还是全相等，归并排序永远雷打不动地对半切分、逐层归并，**最好、最坏、平均时间复杂度全都是 $O(n \log n)$**（彻底告别快速排序最坏退化到 $O(n^2)$ 的隐患）；
  * **合并比较次数的精确上下界**：合并两个长度分别为 $n_1$ 和 $n_2$ 的有序数组时：
    * **最少比较次数** $= \min(n_1, n_2)$（例如 `[1, 2, 3]` 与 `[4, 5, 6]`，左半 $3$ 个元素连赢 $3$ 次率先耗尽，右半直接整块搬运）；
    * **最多比较次数** $= n_1 + n_2 - 1$（例如 `[1, 3, 5]` 与 `[2, 4, 6]`，双方交替胜出，直到只剩最后 $1$ 个最大元素 `6` 无需比较直接搬运）。
  * **空间代价与稳定性**：因为合并过程必须开辟长度为 $n$ 的辅助数组 `tmp[]`（外加 $O(\log n)$ 层递归调用栈），其**额外空间复杂度为 $O(n)$**（非原地排序）；只要合并时坚持 `a[i] <= a[j]` 让左半相等元素优先出列，归并排序就是**严格稳定的排序算法**（C++ `std::stable_sort` 的底层主力正是归并排序）！

### 3. 神来之笔：如何用 `mid - i + 1` 顺手秒杀“逆序对”统计？

回顾**逆序对（Inversion Pair）**的定义：在数组 `a` 中，若下标满足 **$p < q$ 且 $a[p] > a[q]$**，则称 $(a[p], a[q])$ 为一个逆序对。

在分治视角下，区间 `[l, r]` 内的任何一个逆序对 $(p, q)$，按两个下标相对于中点 `mid` 的位置，必然**不重不漏**地归属于以下三类之一：
1. **左半内部逆序对**（$l \le p < q \le \text{mid}$）：在递归调用 `merge_sort(l, mid)` 时已统计完毕；
2. **右半内部逆序对**（$\text{mid} + 1 \le p < q \le r$）：在递归调用 `merge_sort(mid + 1, r)` 时已统计完毕；
3. **跨越中点的逆序对**（$l \le p \le \text{mid} < q \le r$）：左元素在左半区间、右元素在右半区间——**这正是双指针合并阶段 $O(1)$ 批量捕获的目标！**

⚠️ **一个初学者最爱问的灵魂疑问**：“把左右两个子区间各自排好序之后，元素位置都变了，不会把原本跨区间的逆序对搞乱吗？”
**绝对不会！** 因为对于跨区间点对而言，左半区间**任何一个数**在原数组中的下标本来就严格小于右半区间**任何一个数**（始终满足 $p \le \text{mid} < q$）。左半内部怎么交换顺序、右半内部怎么交换顺序，丝毫不会改变“左半元素在左、右半元素在右”的跨区先后关系！反而因为左右两半各自排成了**升序**，赋予了我们“一抓抓一串”的超能力：

```text
====================================================================================
【双指针合并抓捕“跨区间逆序对”微观定格图】
  左半有序区间 a[l..mid] = [ 2,  5,  6 ]      右半有序区间 a[mid+1..r] = [ 1,  3,  4 ]
  下标位置：               [0] [1] [2]                                   [3] [4] [5]
                                ▲                                             ▲
                                i = 1 (当前值 5)                              j = 4 (当前值 3)

  ★ 此时双指针正面对决：发现左半 a[i] = 5  >  右半 a[j] = 3 ！
    因为左半区间 [0..2] 已经严格按从小到大排好序：a[1] <= a[2]（即 5 <= 6），
    既然连左半当前最小的排头兵 a[i]=5 都严格大于 a[j]=3，
    那么从下标 i 到 mid 剩余的所有元素 [5, 6] 必然【全都严格大于 3】！

  ⚡ 批量结算：无需逐个枚举，关于右元素 a[j]=3 的跨区间逆序对个数直接等于：
     左半剩余元素个数 = mid - i + 1 = 2 - 1 + 1 = 2 个（即 (5,3) 与 (6,3)）！
     累加 cnt += (mid - i + 1) 后，把较小的 a[j]=3 放入 tmp 并令 j++，绝不重复统计！
====================================================================================
```

> 💡 **考场黄金法则（背诵直接套用）**：
> 1. **【归并复杂度与比较边界铁律】**：归并排序最好、最坏、平均时间复杂度恒为 **$O(n \log n)$**，额外空间复杂度为 **$O(n)$**，属于**稳定排序**；合并长度分别为 $n_1, n_2$ 的两个有序表，元素比较次数最少为 **$\min(n_1, n_2)$** 次，最多为 **$n_1 + n_2 - 1$** 次！
> 2. **【跨区间逆序对批量结算铁律】**：双指针升序归并时，分支条件必须写 **`if (a[i] <= a[j])`**；一旦走入 `else`（即 `a[i] > a[j]`），右半元素 `a[j]` 出列的同时，左半区间 `[i..mid]` 剩余的所有数均与 `a[j]` 构成逆序对，立即累加 **`cnt += mid - i + 1`**，且计数器必须开 **`long long`**！

## 🔍 二、 具象代码与数据推演（有举例）

### 示例：追踪序列 `[5, 2, 6, 1, 4, 3]` 的分治归并与逆序对捕获全过程

下面给出一段标准 C++11 演示程序，完整打印每一次合并区间时的跨区间逆序对增量 `cross_inv` 与排序进展：

```cpp
#include <iostream>
using namespace std;

int a[6] = {5, 2, 6, 1, 4, 3};
int tmp[6];
long long inv_cnt = 0;

void merge_sort(int l, int r) {
    if (l >= r) {
        return; // 单元素区间天然有序，0 个逆序对
    }
    int mid = l + (r - l) / 2;
    merge_sort(l, mid);       // 递归排左半并统计左半内部逆序对
    merge_sort(mid + 1, r);   // 递归排右半并统计右半内部逆序对

    int i = l, j = mid + 1, k = l;
    long long cross_inv = 0;
    while (i <= mid && j <= r) {
        if (a[i] <= a[j]) {
            tmp[k++] = a[i++];
        } else {
            tmp[k++] = a[j++];
            cross_inv += (mid - i + 1); // 批量累加左半剩余元素个数
        }
    }
    while (i <= mid) {
        tmp[k++] = a[i++];
    }
    while (j <= r) {
        tmp[k++] = a[j++];
    }
    for (int p = l; p <= r; p++) {
        a[p] = tmp[p];
    }
    inv_cnt += cross_inv;
    cout << "Merge [" << l << ".." << mid << "] & [" << (mid + 1) << ".." << r
         << "] -> cross=" << cross_inv << ", total=" << inv_cnt << endl;
}

int main() {
    merge_sort(0, 5);
    cout << "Sorted: ";
    for (int i = 0; i < 6; i++) {
        cout << a[i] << (i == 5 ? "\n" : " ");
    }
    return 0;
}
```

#### 逐次合并内存快照与 `mid - i + 1` 分步推演表

| 合并次序 | 左有序段 `a[l..mid]` | 右有序段 `a[mid+1..r]` | 触发 `a[i] > a[j]` 的具体时刻与批量累加明细 | 本轮新增 `cross` | 累计 `total` | 合并后 `a[l..r]` |
| :---: | :---: | :---: | :--- | :---: | :---: | :---: |
| **第 1 次** | `[0..0]: [5]` | `[1..1]: [2]` | `i=0(5) > j=1(2)` $\to +(0-0+1)=+1$ `[(5,2)]` | `1` | `1` | `[2, 5]` |
| **第 2 次** | `[0..1]: [2, 5]` | `[2..2]: [6]` | `2<=6, 5<=6` 左半耗尽，无跨区逆序对 | `0` | `1` | `[2, 5, 6]` |
| **第 3 次** | `[3..3]: [1]` | `[4..4]: [4]` | `1<=4` 左半耗尽，无跨区逆序对 | `0` | `1` | `[1, 4]` |
| **第 4 次** | `[3..4]: [1, 4]` | `[5..5]: [3]` | `1<=3` 后，`i=4(4) > j=5(3)` $\to +(4-4+1)=+1$ `[(4,3)]` | `1` | `2` | `[1, 3, 4]` |
| **第 5 次** | `[0..2]: [2, 5, 6]` | `[3..5]: [1, 3, 4]` | ① `i=0(2)>j=3(1)` $\to +(2-0+1)=+3$ `[(2,1),(5,1),(6,1)]`<br>② `i=0(2)<=j=4(3)` 左移 `i=1`<br>③ `i=1(5)>j=4(3)` $\to +(2-1+1)=+2$ `[(5,3),(6,3)]`<br>④ `i=1(5)>j=5(4)` $\to +(2-1+1)=+2$ `[(5,4),(6,4)]` | `7` | **`9`** | `[1, 2, 3, 4, 5, 6]` |

运行程序输出：
```text
Merge [0..0] & [1..1] -> cross=1, total=1
Merge [0..1] & [2..2] -> cross=0, total=1
Merge [3..3] & [4..4] -> cross=0, total=1
Merge [3..4] & [5..5] -> cross=1, total=2
Merge [0..2] & [3..5] -> cross=7, total=9
Sorted: 1 2 3 4 5 6
```
验算原数组 `[5, 2, 6, 1, 4, 3]` 逆序对：`5` 贡献 `4` 个 + `2` 贡献 `1` 个 + `6` 贡献 `3` 个 + `4` 贡献 `1` 个 $= 9$ 个，分毫不差！

## ⚡ 三、 考场高频避坑指南（正误辨析）

在 GESP 五级真题与 CSP-J 初赛阅读程序、复赛代码实现中，以下三大陷阱杀伤力极强：

### ❌ 易错点 1：把 `if (a[i] <= a[j])` 误写成 `if (a[i] < a[j])`！
* **错误写法**：
  ```cpp
  if (a[i] < a[j]) { // 漏写了等号！
      tmp[k++] = a[i++];
  } else {
      tmp[k++] = a[j++];
      cnt += (mid - i + 1);
  }
  ```
* **为什么错（一错双杀）**：当左右两半存在相等元素（例如数组 `[2, 2]`，`l=0, mid=0, r=1`）时，`2 < 2` 为假，程序误入 `else` 分支：
  1. **稳定性破产**：右半的后辈 `a[1]` 抢在左半的前辈 `a[0]` 之前被塞进 `tmp`，相等元素相对顺序颠倒；
  2. **逆序对凭空多算**：相等元素明明不满足严格大于（$a[p] > a[q]$），却错误触发了 `cnt += mid - i + 1`，把 `(2, 2)` 及左半后续元素全部错算进去，遇到含重复数字的数据点必全盘 WA！
* **正确规范**：合并条件铁打不动写 **`a[i] <= a[j]`**——相等时左半优先出列，既保住稳定性，又完美避开逆序对误判！

### ❌ 易错点 2：逆序对计数器写成 `int cnt = 0;`，大数据点全部溢出变负数！
* **典型惨案**：归并排序模板写得滴水不漏，唯独函数返回值和累加变量顺手写了 `int`。结果小样例全过，一提交大测试点只拿 30~50 分！
* **为什么错**：当 $n = 10^5$ 且原序列完全降序（如 `100000, 99999, ..., 1`）时，逆序对总数高达：
  $$\frac{n(n - 1)}{2} = \frac{100000 \times 99999}{2} = 4,999,950,000 \approx 5 \times 10^9$$
  而 32 位 `int` 的最大值仅为 $2,147,483,647 \approx 2.14 \times 10^9$，直接发生有符号整数溢出！
* **正确规范**：凡涉及区间对数统计（逆序对、满足条件的点对数），计数器与函数返回类型一律无脑使用 **`long long`**！

### ❌ 易错点 3：在递归函数内部开全长局部数组 `int tmp[100005]` 或全量拷贝！
* **错误写法**：每次进入 `merge_sort(int l, int r)` 都在函数体内定义 `int tmp[100005];`，甚至用 `memcpy(a, tmp, sizeof(a));` 拷贝整个数组。
* **为什么错**：递归深度可达 $\approx 17$ 层，每层在系统栈上分配 $400\text{ KB}$ 会极易引发栈溢出（RE）；更致命的是，如果在合并长度为 $2$ 的小区间时却去循环或拷贝全长 $n$ 个元素，每一层的代价就会从 $O(n)$ 暴涨到 $O(2^d \cdot n)$，整套算法当场退化为比冒泡还慢的 $O(n^2)$！
* **正确规范**：将辅助数组 `int tmp[MAXN];` 定义在**全局静态区**（全局共用同一块内存），且每次合并结束只精准拷贝当前区间：`for (int p = l; p <= r; p++) a[p] = tmp[p];`！

## 📝 四、 真题实战演练与精析（有例题：3 道）

### 【例题 1 · 单选题】（GESP 五级 / CSP-J 初赛阅读推演：含相等元素的二路归并细节）

**题目**：在二路归并排序的某次合并操作中，待合并的左半有序子区间为 `a[0..3] = {3, 6, 8, 10}`（`l = 0, mid = 3`），右半有序子区间为 `a[4..7] = {2, 6, 7, 12}`（`mid + 1 = 4, r = 7`）。若采用标准保稳归并逻辑（当 `a[i] <= a[j]` 时取左半元素，否则取右半元素并执行 `cnt += mid - i + 1`），则在主循环 `while (i <= mid && j <= r)` 运行期间，`a[i] <= a[j]` 共被执行了多少次比较？本轮合并累计捕获了多少个跨中点逆序对？

* **A.** 比较 7 次，跨区间逆序对 8 个
* **B.** 比较 7 次，跨区间逆序对 9 个
* **C.** 比较 8 次，跨区间逆序对 8 个
* **D.** 比较 6 次，跨区间逆序对 8 个

**🔍 答案与逐项排除解析**：
* **正确答案**：**A**
* **解析过程**：
  设初始双指针 `i = 0, j = 4`，我们一步步追踪每次 `a[i] <= a[j]` 的对决：
  1. **第 1 次比较**：`a[0]=3` vs `a[4]=2` $\implies$ `3 <= 2` 假，输出 `2`，`j = 5`，累加 `cnt += (3 - 0 + 1) = +4`（捕获 `(3,2),(6,2),(8,2),(10,2)`）；
  2. **第 2 次比较**：`a[0]=3` vs `a[5]=6` $\implies$ `3 <= 6` 真，输出 `3`，`i = 1`；
  3. **第 3 次比较（核心陷阱位！）**：`a[1]=6` vs `a[5]=6` $\implies$ **`6 <= 6` 真**！左半的 `6` 优先输出，`i = 2`，**不累加逆序对**（若误记成 `<` 则会多算 `(6,6)` 误选 **B**，排除 B）；
  4. **第 4 次比较**：`a[2]=8` vs `a[5]=6` $\implies$ `8 <= 6` 假，输出右半的 `6`，`j = 6`，累加 `cnt += (3 - 2 + 1) = +2`（捕获 `(8,6),(10,6)`）；
  5. **第 5 次比较**：`a[2]=8` vs `a[6]=7` $\implies$ `8 <= 7` 假，输出 `7`，`j = 7`，累加 `cnt += (3 - 2 + 1) = +2`（捕获 `(8,7),(10,7)`）；
  6. **第 6 次比较**：`a[2]=8` vs `a[7]=12` $\implies$ `8 <= 12` 真，输出 `8`，`i = 3`；
  7. **第 7 次比较**：`a[3]=10` vs `a[7]=12` $\implies$ `10 <= 12` 真，输出 `10`，`i = 4`（此时 `i > mid`，主循环立即终止，排除 **D**）。
  * 最后右半仅剩的 `a[7]=12` 由后续扫尾循环 `while (j <= r)` 直接拷入，**无需再与任何元素比较**（排除误以为 8 个元素必比较 8 次的 **C**）。综上，共比较 **7 次**，捕获跨区间逆序对 $4 + 2 + 2 = 8$ 个，锁定 **A**。

### 【例题 2 · 判断题】（GESP 五级考纲概念辨析：复杂度与空间特性）

**题目**：对于包含 $n$ 个元素的任意整型数组，二路归并排序在最好、最坏和平均情况下的时间复杂度均为 $O(n \log n)$，且与直接插入排序一样，它是一种稳定的、额外空间复杂度为 $O(1)$ 的原地排序算法。（ ）

**🔍 答案与反例证明**：
* **结论**：**错误（×）**
* **辨析证明**：
  1. 命题前半部分正确：二路归并排序不受输入数据初始分布影响，始终精确对半拆分 $\lceil \log_2 n \rceil$ 层、每层线性合并 $O(n)$，因此最好、最坏、平均时间复杂度恒为 **$O(n \log n)$**，且通过 `a[i] <= a[j]` 保证了排序的**稳定性**；
  2. 但命题最后关于**空间复杂度**的论断错误！标准二路归并排序在线性时间合并两个相邻有序子数组时，必须依赖一个长度为 $n$ 的额外辅助数组 `tmp[]` 来暂存归并序列（同时递归调用还占用 $O(\log n)$ 的栈帧空间），因此其**额外空间复杂度为 $O(n)$**，绝非 $O(1)$ 原地排序（In-place Sort）。故原命题错误。

### 【例题 3 · 微代码实战】（GESP 五级 / CSP-J 复赛高频模板：队列最少相邻交换次数）

**题目描述**：运动会入场式上，$n$ 名运动员站成一排（$1 \le n \le 10^5$），第 $i$ 名运动员的身高为正整数 $a_i$（$1 \le a_i \le 10^9$，可能存在身高相同的运动员）。体育老师每次只能发令让**相邻的两名运动员**交换位置，目标是将整支队伍调整为按身高**从小到大（非递减）**排列。请你利用分治与归并排序思想编写程序，计算最少需要执行多少次相邻交换，并输出最终排好序的队伍身高序列。

**输入格式**：
第一行包含一个正整数 $n$，表示运动员人数。
第二行包含 $n$ 个正整数 $a_1, a_2, \dots, a_n$，表示初始队伍中每名运动员的身高。

**输出格式**：
第一行输出一个整数，表示将队伍排成非递减有序所需的最少相邻交换次数。
第二行输出 $n$ 个整数，以单个空格分隔，表示最终排好序后的身高序列。

**💡 算法建模与避坑要点**：
1. **数学等价转化**：“仅允许交换相邻元素将其排成非递减序列的最少交换次数”——每次交换一对相邻逆序元素 $(x, y)$（$x > y$）最多消去 $1$ 个逆序对，而只要序列中还存在逆序对就必然存在相邻逆序对可消去，因此**最少相邻交换次数严格等于原序列的逆序对总数**！
2. **复杂度把控**：由于 $n \le 10^5$，$O(n^2)$ 模拟冒泡必超时，直接套用二路归并排序分治模板，在 $O(n \log n)$ 时间内同步完成逆序对统计与数组排序；注意身高相等无需交换，合并条件写 `a[i] <= a[j]`，答案用 `long long` 存储。

```cpp
#include <iostream>
using namespace std;

const int MAXN = 100005;
int a[MAXN];
int tmp[MAXN];

long long merge_count(int l, int r) {
    if (l >= r) {
        return 0;
    }
    int mid = l + (r - l) / 2;
    long long cnt = merge_count(l, mid) + merge_count(mid + 1, r);

    int i = l, j = mid + 1, k = l;
    while (i <= mid && j <= r) {
        // 相等元素左半优先出列：既保证归并稳定，又不把相等身高判作逆序对
        if (a[i] <= a[j]) {
            tmp[k++] = a[i++];
        } else {
            tmp[k++] = a[j++];
            cnt += (mid - i + 1);
        }
    }
    while (i <= mid) {
        tmp[k++] = a[i++];
    }
    while (j <= r) {
        tmp[k++] = a[j++];
    }
    for (int p = l; p <= r; p++) {
        a[p] = tmp[p];
    }
    return cnt;
}

int main() {
    int n;
    cin >> n;
    for (int i = 0; i < n; i++) {
        cin >> a[i];
    }

    long long ans = merge_count(0, n - 1);
    cout << ans << endl;
    for (int i = 0; i < n; i++) {
        if (i > 0) {
            cout << " ";
        }
        cout << a[i];
    }
    cout << endl;
    return 0;
}
```

* **输入样例 1**：
  ```text
  6
  5 4 2 6 3 1
  ```
* **输出样例 1**：
  ```text
  11
  1 2 3 4 5 6
  ```
  *（样例 1 解释：序列 `[5, 4, 2, 6, 3, 1]` 中各元素与右侧构成的逆序对数依次为 `4 + 3 + 1 + 2 + 1 + 0 = 11` 个，故最少需要交换相邻运动员 11 次。）*
* **输入样例 2**：
  ```text
  5
  3 1 3 1 2
  ```
* **输出样例 2**：
  ```text
  5
  1 1 2 3 3
  ```
  *（样例 2 解释：含重复身高序列 `[3, 1, 3, 1, 2]` 中，第一个 `3` 与右侧构成 `(3,1),(3,1),(3,2)` 共 3 个逆序对，第二个 `3` 与右侧构成 `(3,1),(3,2)` 共 2 个逆序对，相同身高 `(3,3)` 与 `(1,1)` 因 `<=` 稳定出列不计入，总计最少交换 `5` 次。）*
