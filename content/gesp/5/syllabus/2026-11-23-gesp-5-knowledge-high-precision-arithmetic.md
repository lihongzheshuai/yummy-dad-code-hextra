在信息学竞赛中，一旦题目要求计算 `100!` 的精确值，或者求两个长达 `500` 位的超级大整数之和、之差、之积与商，C++ 内置的 `int`（上限约 $2.14 \times 10^9$）和 `long long`（上限约 $9.22 \times 10^{18}$）甚至 `unsigned long long`（上限约 $1.84 \times 10^{19}$）都会瞬间溢出报废。为了突破硬件字长枷锁，我们必须用数组逐位模拟小学竖式计算——这就是**高精度运算（High-Precision Arithmetic）**。但许多同学在初学高精度时，总是对一连串“反直觉”的写法满头雾水：明明数字是从左往右读入的字符串，为什么加、减、乘偏偏要把每一位**倒序**塞进数组，唯独除法却要从高位向低位顺着算？高精度减法为什么不能直接写 `if (s1 < s2)` 比大小？高精度乘法那句神秘的 `c[i + j] += a[i] * b[j]` 究竟是怎么推导出来的？更让人崩溃的是，代码在普通样例上全对，一遇到 `999 + 1`、`12345 - 12345`、`99999 * 0` 这类边界数据，要么丢掉最高位进位，要么把唯一的 `0` 删得一干二净直接输出空行！在 GESP 五级认证以及 CSP-J 初复赛中，**高精度加减乘除的底层存储规律、进位借位状态机与去前导零边界控制**是必须烂熟于心的硬核模块。本文将从内存对齐与位权本质出发，把高精度四大运算的底层状态机彻底讲透。

## 🎯 考纲锚点与核心痛点

> 📍 **对应考点**：掌握字符串转倒序整型数组的对齐优势，熟练编写高精度加法（进位 `t /= 10`）、高精度减法（先比大小后借位）、高精度乘法（`c[i + j] += a[i] * b[j]`）及高精度除以低精度代码，严防前导零删除过度与余数溢出。
> 🎯 **适用等级**：`GESP 五级考点 | CSP-J 初赛/复赛必考`

在历年 GESP 五级与 CSP-J 考场上，考生最常在以下三大痛点上丢分：
1. **“死背倒序转换却不解其意，下标对齐频频写反”**：读入字符串后不知道哪一端是个位、哪一端是最高位，导致输出时忘记逆序打印，或在乘法 `c[i + j]` 与除法从高位试商之间张冠李戴；
2. **“忽视边界特例，栽在进位、借位与零结果上”**：加法循环结束忘了补最后一位进位（`999 + 1` 错算成 `0`）；减法直接拿 `string` 字典序比大小（把 `"100"` 判成小于 `"20"`）；去前导零漏写 `len > 1` 守卫（把 `0` 删空）；
3. **“高精除低精的余数错用 `int`，大除数直接溢出”**：看到除数 `b` 在 $10^9$ 以内便用 `int` 存余数 `rem`，殊不知下一位拉下来执行 `rem = rem * 10 + digit` 时数值可达 $10^{10}$，瞬间撑爆 32 位 `int`！

## 🧠 一、 核心原理深度拆解（有理论）

### 1. 灵魂拷问：为什么加、减、乘必须把字符串“倒序”存进数组？

读入两个大整数字符串 `s1 = "1234"` 和 `s2 = "56"` 时，如果直接**正序**存进数组，`s1[0]` 存的是千位 `'1'`，而 `s2[0]` 存的是十位 `'5'`——**相同下标对应的位权根本不对齐**！更致命的是，如果相加后最高位产生了进位（例如 `999 + 1 = 1000`），正序存储必须在数组下标 `0` 之前插入新元素，迫使整个数组所有元素整体右移一位（$O(n)$ 搬迁成本）。

把字符串**倒序**转存为整型数组后（即 `a[i] = s[n - 1 - i] - '0'`，**下标 `0` 永远存个位、下标 `1` 存十位、下标 `i` 严格对应位权 $10^i$**），三大工程难题迎刃而解：

```text
========================================================================
【正序存储 vs 倒序存储（以 1234 + 56 与 999 + 1 为例）】

❌ 正序存储（灾难）：
  下标:    [0]  [1]  [2]  [3]
  s1 =      1    2    3    4     <-- s1[0] 是千位，s2[0] 是十位，错位！
  s2 =      5    6               <-- 最高位进位还得全数组右移！

✅ 倒序存储（完美对齐，下标 i 严格绑定 10^i）：
  下标:    [0]  [1]  [2]  [3]  [4]
  位权:   10^0 10^1 10^2 10^3 10^4
  a  =      4    3    2    1         (表示 1234)
  b  =      6    5    0    0         (表示 56，高位天然补 0)
  ─────────────────────────────────────────────────────────────
  ▶ 优势 1（低位天然对齐）：a[i] 与 b[i] 永远是同一位权，直接相加减！
  ▶ 优势 2（进位 O(1) 扩容）：999 + 1 产生新最高位时，直接在尾部 push_back(1)！
  ▶ 优势 3（乘法位权自洽）：a[i]·10^i × b[j]·10^j = (a[i]*b[j])·10^(i+j)！
========================================================================
```

### 2. 高精度加法与减法状态机：进位 `t /= 10` 与比大小、借位

在倒序数组表示下，任意非负整数 $A$ 可写作多项式 $A = \sum_{i=0}^{n-1} a_i \cdot 10^i$。加减法本质上是一个**从低位下标 `0` 向高位推进的线性状态机**：

#### （1）高精度加法状态机（状态变量：进位 `t`）
设当前累积值 `t` 初始为 `0`。对每一位 `i = 0, 1, ..., max(n, m) - 1`：
1. **状态转移**：把当前两数该位数值累加到上一位传来的进位上：`t += a[i] + b[i]`（越界的高位视作 `0`）；
2. **输出当前位**：`c[i] = t % 10`；
3. **更新进位**：`t /= 10`（十进制下两数相加加上进位最大为 `9 + 9 + 1 = 19`，因此进位非 `0` 即 `1`）；
4. **收尾溢出位**：循环结束后，若 **`t > 0`**，必须在最高位追加 `c[len++] = t`（如 `999 + 1`）。

#### （2）高精度减法状态机（前置比大小 + 状态变量：借位 `borrow`）
竖式减法必须在**“大数减小数”**的前提下进行，否则最高位借位无处可借、会算出补码式的错误数字。因此高精度减法分两步：
1. **严格数值比大小**：先比较有效长度（位数多的一定更大）；仅当**位数相等**时，从最高位向低位逐位比较（或直接比较无前导零的原字符串字典序）。若 $A < B$，先输出负号 `-`，再交换计算 $B - A$；
2. **逐位借位推进**：保证 $A \ge B$ 后，维护借位 `borrow = 0`。对 `i = 0 .. lenA - 1`：
   * 计算 `t = a[i] - b[i] - borrow`；
   * 若 `t < 0`，说明不够减，必须向高位借 `1` 当 `10`：`t += 10; borrow = 1;`；
   * 否则无需借位：`borrow = 0;`；
   * 当前结果位 `c[i] = t`（也可以用一行无分支写法 `c[i] = (t + 10) % 10; borrow = (t < 0 ? 1 : 0);`）。
3. **清除高位前导零**：例如 `1000 - 999` 算完得到倒序数组 `[1, 0, 0, 0]`，必须把末尾多余的 `0` 弹掉。

### 3. 高精度乘法状态机：为什么下标一定是 `c[i + j] += a[i] * b[j]`？

很多同学把高精度乘法的核心语句 `c[i + j] += a[i] * b[j]` 当作神秘口诀死记硬背。其实只需把两个大整数写成多项式相乘，一秒就能看透其数学本质：

$$A \times B = \left(\sum_{i=0}^{n-1} a_i \cdot 10^i\right) \times \left(\sum_{j=0}^{m-1} b_j \cdot 10^j\right) = \sum_{i=0}^{n-1} \sum_{j=0}^{m-1} (a_i \cdot b_j) \cdot 10^{i+j}$$

* `a[i]` 的位权是 $10^i$，`b[j]` 的位权是 $10^j$；
* 二者相乘得到的贡献 `a[i] * b[j]`，其位权必然是 $10^i \times 10^j = 10^{i+j}$——这恰好精准落在结果数组的 **`c[i + j]`** 格子里！
* **最大位数上界**：$n$ 位数（$< 10^n$）与 $m$ 位数（$< 10^m$）相乘，结果严格小于 $10^{n+m}$，因此结果数组长度**至多为 `n + m`**（下标 `0` 到 `n + m - 1`）。

更妙的是，我们可以把乘法拆成极其清爽的**“两阶段流水线”**：
1. **阶段一（只乘累加，暂不进位）**：双重循环执行 `c[i + j] += a[i] * b[j]`。每一格最多累加 $\min(n, m)$ 个不超过 `81`（$9 \times 9$）的乘积，在万位级高精度下远不会爆 `int`；
2. **阶段二（统一向高位滚雪球进位）**：从 `k = 0` 到 `n + m - 2` 线性扫描一遍：
   ```cpp
   c[k + 1] += c[k] / 10;
   c[k] %= 10;
   ```
3. **阶段三（去前导零）**：当乘数为 `0` 或最高位未进位（如 `12 × 13 = 156`，`n + m = 4` 但实际只有 `3` 位）时，弹掉高位多余的 `0`。

### 4. 高精度除法（高精 ÷ 低精）状态机：为何唯独它是“从高位到低位”？

在 GESP 五级与 CSP-J 中，最常考的高精度除法模型是**高精度除以低精度**（被除数 $A$ 长达数百上千位，除数 $b$ 是 $1 \le b \le 10^9$ 的普通整数）。

回忆小学竖式除法 `1025 ÷ 13`：我们**绝不会**从个位 `'5'` 开始除，而是必须**从最高位往低位**逐位拉下来试商！因此除法的状态转移方向与加、减、乘完全相反：
* 维护状态变量**当前余数 `rem`**（必须开 **`long long`**，初始为 `0`）；
* 从最高位到最低位顺次扫描原字符串 `s[0 .. n - 1]`（若使用倒序数组，则下标从 `n - 1` 递减到 `0`）：
  1. **拉下一位拼接**：`rem = rem * 10 + (s[i] - '0')`；
  2. **求当前商位**：`q[i] = rem / b`；
  3. **更新剩余余数**：`rem %= b`；
* 扫描完毕后，`rem` 即为最终余数；而商 `q` 的前面可能出现一串前导零（如 `"0078"`），同样需要去除前导零并保留单个 `0`！

---

### 5. 统一收尾守门员：去除前导零并保留单个 `0`

无论是减法、乘法还是除法，运算结束后最高位都可能残存多余的 `0`。去除前导零的标准写法必须带有一个雷打不动的**长度保底条件**：
* **倒序数组 / `vector` 版**：`while (C.size() > 1 && C.back() == 0) C.pop_back();`（定长数组为 `while (len > 1 && c[len - 1] == 0) len--;`）；
* **正序字符串版（除法商）**：`int pos = 0; while (pos + 1 < (int)q.size() && q[pos] == '0') pos++;`。

这里的 **`size() > 1`（或 `len > 1`）** 就像守门员：只要有效位数降到 `1` 位，哪怕这最后一位就是 `0`，也立刻停手！从而保证结果为零时精准保留一个 `"0"`。

#### 高精度四大运算底层状态机全景对照表

| 运算类型 | 推荐存储与扫描方向 | 核心状态转移公式 | 结果最大位数 | 是否需去前导零 | 时间复杂度 |
| :---: | :---: | :--- | :---: | :---: | :---: |
| **高精 + 高精** | 倒序存，低位 $\to$ 高位 | `t += a[i] + b[i]; c[i] = t % 10; t /= 10;` | $\max(n, m) + 1$ | 否（无前导零输入时） | $O(\max(n, m))$ |
| **高精 - 高精** | 先比大小；倒序存，低位 $\to$ 高位 | `t = a[i] - b[i] - borrow;` 负则 `+10` 借 `1` | $\max(n, m)$ | **必须**（保留单个 `0`） | $O(\max(n, m))$ |
| **高精 × 高精** | 倒序存，双循环乘后再低位 $\to$ 高位进位 | `c[i + j] += a[i] * b[j];` 再统一进位 | $n + m$ | **必须**（乘 `0` 或未进位） | $O(n \cdot m)$ |
| **高精 ÷ 低精** | **正序存，高位 $\to$ 低位** | `rem = rem * 10 + d; q = rem / b; rem %= b;` | $n$ | **必须**（商首位常为 `0`） | $O(n)$ |

> 💡 **考场黄金法则**：
> 1. **【加减乘倒序对齐，除法正序高位试商】**：倒序让下标 `i` 锁定位权 $10^i$（进位直接追加尾部、乘法直落 `c[i + j]`）；除法从高位拉位算 `rem = rem * 10 + d`，且 `rem` 一律开 `long long`。
> 2. **【减法先比长度，去零必保 `len > 1`】**：比大小严禁直接拿 `string` 做字典序比较；去前导零务必写 `while (len > 1 && c[len - 1] == 0) len--;`，守住零结果底线！

## 🔍 二、 具象代码与数据推演（有举例）

### 示例 1：高精度乘法两阶段状态机追踪（`99 × 98 = 9702`）

下面这段 24 行的标准 C++11 程序先完整演示“只乘累加”得到的未进位中间数组，再执行线性进位与逆序输出：

```cpp
#include <iostream>
#include <string>
using namespace std;

int main() {
    string s1 = "99", s2 = "98";
    int a[10] = {0}, b[10] = {0}, c[20] = {0};
    int n = s1.size(), m = s2.size();
    for (int i = 0; i < n; i++) a[i] = s1[n - 1 - i] - '0';
    for (int j = 0; j < m; j++) b[j] = s2[m - 1 - j] - '0';
    for (int i = 0; i < n; i++)
        for (int j = 0; j < m; j++)
            c[i + j] += a[i] * b[j];
    cout << "Before carry: ";
    for (int k = 0; k < n + m; k++) cout << c[k] << " ";
    cout << endl;
    int len = n + m;
    for (int k = 0; k < len - 1; k++) {
        c[k + 1] += c[k] / 10;
        c[k] %= 10;
    }
    while (len > 1 && c[len - 1] == 0) len--;
    cout << "After carry:  ";
    for (int k = len - 1; k >= 0; k--) cout << c[k];
    cout << endl;
    return 0;
}
```

#### 分步内存数组推演（`a = [9, 9]`，`b = [8, 9]`）

* **阶段一（双重循环累加 `c[i + j] += a[i] * b[j]`）**：
  * `i = 0, j = 0`：`c[0] += 9 * 8 = 72`
  * `i = 0, j = 1`：`c[1] += 9 * 9 = 81`
  * `i = 1, j = 0`：`c[1] += 9 * 8 = 72`（此时 `c[1] = 81 + 72 = 153`）
  * `i = 1, j = 1`：`c[2] += 9 * 9 = 81`
  * 阶段一结束，未进位数组为 **`c = [72, 153, 81, 0]`**（验算：$72 + 1530 + 8100 = 9702$！）。

* **阶段二（低位到高位滚雪球进位）**：

| 扫描下标 `k` | 进位前数组 `c[0..3]` | 向高位进位值 `c[k] / 10` | 保留本位 `c[k] % 10` | 进位后数组 `c[0..3]` |
| :---: | :---: | :---: | :---: | :---: |
| **`k = 0`** | `[72, 153, 81, 0]` | `72 / 10 = 7` 加至 `c[1]` | `72 % 10 = 2` | `[2, 160, 81, 0]` |
| **`k = 1`** | `[2, 160, 81, 0]` | `160 / 10 = 16` 加至 `c[2]` | `160 % 10 = 0` | `[2, 0, 97, 0]` |
| **`k = 2`** | `[2, 0, 97, 0]` | `97 / 10 = 9` 加至 `c[3]` | `97 % 10 = 7` | **`[2, 0, 7, 9]`** |

检查最高位 `c[3] = 9 != 0`，无需去零，从 `k = 3` 倒序打印 `9702`！程序经 `g++ -O2 -std=c++11` 编译运行实际输出：

```text
Before carry: 72 153 81 0 
After carry:  9702
```

### 示例 2：高精度除以低精度状态机追踪（`1025 ÷ 13 = 78 ... 11`）

下面这段 18 行的标准 C++11 程序展示了从高位到低位逐位试商、更新 `rem` 并裁掉商的前导零的完整过程：

```cpp
#include <iostream>
#include <string>
using namespace std;

int main() {
    string s = "1025";
    long long b = 13, rem = 0;
    string q = "";
    for (int i = 0; i < (int)s.size(); i++) {
        rem = rem * 10 + (s[i] - '0');
        q += char('0' + rem / b);
        rem %= b;
        cout << "i=" << i << " digit=" << s[i]
             << " -> q=\"" << q << "\", rem=" << rem << endl;
    }
    int pos = 0;
    while (pos + 1 < (int)q.size() && q[pos] == '0') pos++;
    cout << "Quotient=" << q.substr(pos) << ", Remainder=" << rem << endl;
    return 0;
}
```

#### 分步状态机推演表

| 循环下标 `i` | 拉下数字 `s[i]` | 拼接被除值 `rem * 10 + d` | 产生商位 `rem / 13` | 更新余数 `rem % 13` | 当前商串 `q` |
| :---: | :---: | :---: | :---: | :---: | :---: |
| **`i = 0`** | `'1'` | `0 * 10 + 1 = 1` | `1 / 13 = 0` | `1 % 13 = 1` | `"0"` |
| **`i = 1`** | `'0'` | `1 * 10 + 0 = 10` | `10 / 13 = 0` | `10 % 13 = 10` | `"00"` |
| **`i = 2`** | `'2'` | `10 * 10 + 2 = 102` | `102 / 13 = 7` | `102 % 13 = 11` | `"007"` |
| **`i = 3`** | `'5'` | `11 * 10 + 5 = 115` | `115 / 13 = 8` | `115 % 13 = 11` | `"0078"` |

收尾 `while` 跳过前两个 `'0'`，定位到 `pos = 2`，截取 `q.substr(2)` 得到商 `78`、余数 `11`（验算：$78 \times 13 + 11 = 1025$）。程序经 `g++ -O2 -std=c++11` 编译运行实际输出：

```text
i=0 digit=1 -> q="0", rem=1
i=1 digit=0 -> q="00", rem=10
i=2 digit=2 -> q="007", rem=11
i=3 digit=5 -> q="0078", rem=11
Quotient=78, Remainder=11
```

## ⚡ 三、 考场高频避坑指南（正误辨析）

在 GESP 五级判断题与 CSP-J 考场上，以下三个边界陷阱最容易让人痛失满分：

### ❌ 易错点 1：去前导零漏写 `len > 1`（或 `C.size() > 1`），结果为 `0` 时直接空输出甚至越界！
* **错误代码**：
  ```cpp
  while (c[len - 1] == 0) len--;        // 定长数组版：致命错误！
  // 或 vector 版：while (C.back() == 0) C.pop_back();
  ```
* **为什么错**：当运算结果恰好为 `0`（例如 `12345 - 12345`、`987654321 * 0`、`5 / 13`）时，数组中所有位全是 `0`。缺少 `len > 1` 守卫后，`len` 一路减到 `0`，不仅什么都不输出导致 **WA**，下一轮判断 `c[-1] == 0` 或对空 `vector` 调用 `back()` 还会直接触发数组负下标越界 / **RE（Runtime Error）**！
* **正确规范**：务必加上长度守卫并把长度检查写在 `&&` 左侧（利用短路求值防越界）：
  ```cpp
  while (len > 1 && c[len - 1] == 0) len--;
  // 或 vector 版：while (C.size() > 1 && C.back() == 0) C.pop_back();
  ```

### ❌ 易错点 2：高精度减法直接写 `if (s1 < s2)` 比大小，落入字符串字典序陷阱！
* **错误代码**：
  ```cpp
  if (s1 < s2) {
      swap(s1, s2);
      cout << "-";
  }
  ```
* **为什么错**：C++ 中 `std::string` 的 `<` 运算符比较的是**字典序**（从左到右逐字符对比 ASCII 码），而不是数值大小！拿 `s1 = "100"` 和 `s2 = "20"` 一试：首字符 `'1' < '2'`，于是 `"100" < "20"` 竟然返回 **`true`**！程序不仅白白输出一个负号 `-`，还把小数字 `"20"` 放到上面去减大数字 `"100"`，导致最高位借位无法消化、输出一堆乱码数字！
* **正确规范**：无前导零的非负大整数比较大小，必须**先比长度，同长再比字典序（或从高位往低位逐位比）**：
  ```cpp
  bool lessThan(const string &a, const string &b) {
      if (a.size() != b.size()) return a.size() < b.size();
      return a < b;
  }
  ```

### ❌ 易错点 3：加法漏补最高位进位 `if (t > 0)`，或高精除低精余数 `rem` 错用 `int` 导致溢出！
* **错误写法**：
  1. 高精度加法只循环 `i = 0 .. max(n, m) - 1`，忘记在循环后补 `if (t > 0) c[len++] = t;`；
  2. 高精除以低精时，见题目说除数 $b \le 10^9$ 在 `int` 范围内，便声明 `int b, rem = 0;`，然后直接算 `rem = rem * 10 + (s[i] - '0')`。
* **为什么错**：
  1. 计算 `999 + 1` 或 `500 + 500` 时，两数均为 `3` 位但和为 `4` 位；循环结束时进位 `t = 1` 还捏在手里，不补位就会把最高位的 `1` 直接丢弃，错算出 `0`！
  2. 除数 $b = 999999999$ 时，上一步余数 `rem` 最大可达 `999999998`。下一步拉下一位数字计算 `rem * 10 + 9` 时，结果高达 **`9999999989`**（约 $10^{10}$），直接冲破 32 位 `int` 上限 `2147483647` 变成负数，后续商和余数全盘崩坏！
* **正确规范**：高精度加法循环后条件反射写 **`if (t > 0) C.push_back(t);`**；高精度除以低精度中，余数 **`rem` 一律使用 `long long`** 存储。

### 【例题 1 · 单选题】（GESP 五级 / CSP-J 初赛高频阅读程序考点：高精度乘法未进位中间状态推演）

**题目**：用倒序整型数组实现两个非负大整数 `"256"` 与 `"34"` 的高精度乘法，先将它们倒序存入 `a[0..2]` 和 `b[0..1]`（即 `a = {6, 5, 2}`，`b = {4, 3}`），数组 `c` 初始全为 `0`。执行以下核心循环后，**在尚未执行进位处理循环之前**，`c[0], c[1], c[2], c[3]` 的值依次为（ ）。

```cpp
for (int i = 0; i < 3; i++)
    for (int j = 0; j < 2; j++)
        c[i + j] += a[i] * b[j];
```

* **A.** `6, 23, 38, 24`
* **B.** `24, 38, 23, 6`
* **C.** `4, 0, 7, 8`
* **D.** `24, 20, 15, 6`

**🔍 答案与逐项排除解析**：
* **正确答案**：**B**
* **解析过程**：
  1. **逐项追踪 `c[k]` 的所有 `(i, j)` 贡献**（`a[0]=6, a[1]=5, a[2]=2`；`b[0]=4, b[1]=3`）：
     * `i + j = 0`：`c[0] = a[0] * b[0] = 6 * 4 = 24`；
     * `i + j = 1`：`c[1] = a[0] * b[1] + a[1] * b[0] = 6 * 3 + 5 * 4 = 18 + 20 = 38`；
     * `i + j = 2`：`c[2] = a[1] * b[1] + a[2] * b[0] = 5 * 3 + 2 * 4 = 15 + 8 = 23`；
     * `i + j = 3`：`c[3] = a[2] * b[1] = 2 * 3 = 6`。
     验算位权和：$24 \times 1 + 38 \times 10 + 23 \times 100 + 6 \times 1000 = 8704 = 256 \times 34$，完全吻合！
  2. **逐项排除干扰项**：
     * **排除 A**：把高低位顺序完全写反了（误把最高位放在下标 `0`）；
     * **排除 C**：`4, 0, 7, 8` 是 `8704` **进位处理之后**的倒序数组，题目明确问的是“**尚未执行进位处理循环之前**”，属于审题陷阱；
     * **排除 D**：漏算了同一位权 `i + j` 的交叉累加项（只算了部分乘积而没有把 `+=` 全部汇集到 `c[1]` 和 `c[2]`）。
  3. 综合确认选 **B**。

### 【例题 2 · 判断题】（GESP 五级边界辨析考点：高精度减法的 `string` 比较陷阱）

**题目**：在编写计算非负大整数 $A - B$ 的高精度减法程序时，因为 C++ 的 `std::string` 类型已经重载了 `<` 运算符，所以读入无前导零的大整数字符串 `s1`、`s2` 后，只需判断 `if (s1 < s2)`，若条件成立则交换 `s1` 与 `s2` 并先输出负号 `-`，即可确保后续始终执行大数减小数、避免最高位借位错误。（ ）

**🔍 答案与反例证明**：
* **结论**：**错误（×）**
* **辨析证明**：
  1. **混淆字典序与数值大小**：`std::string` 的 `<` 运算符执行的是**按字符 ASCII 码从左到右逐位比较的字典序**，只在两个字符串**长度相同**且无前导零时才与数值大小一致；当两个大整数位数不同时，字典序完全不能代表数值大小！
  2. **极简反例**：取 `s1 = "100"`，`s2 = "20"`。数值上显然 $100 > 20$，正确结果应为正数 `80`；但比较首字符时 `'1'`（ASCII `49`）`< '2'`（ASCII `50`），因此 `s1 < s2` 返回 **`true`**！程序会错误地输出负号 `-` 并交换两数，接着拿较小的 `"20"` 去减较大的 `"100"`，最终导致最高位借位无法消除、结果彻底错误。
  3. **正确判据**：必须先比较 `s1.size() != s2.size()`（长度短的数一定更小），仅当长度相等时再用 `s1 < s2`。故原命题错误。

### 【例题 3 · 微代码实战】（GESP 五级 / CSP-J 复赛高频模板题：大整数四则运算统一引擎）

**题目描述**：给定 `T`（$1 \le T \le 20$）组测试数据，每组输入格式为 `A op B`，其中 `A` 和 `B` 是不含多余前导零的非负整数（位数不超过 `500`），`op` 为 `+`、`-`、`*`、`/` 四种运算符之一（当 `op` 为 `/` 时，保证 `B` 是不超过 $10^9$ 的正整数）。请对每组数据输出精确运算结果：
* `op == '+'`：输出 $A + B$；
* `op == '-'`：输出 $A - B$（若 $A < B$ 则带负号 `-`）；
* `op == '*'`：输出 $A \times B$；
* `op == '/'`：输出 $A \div B$ 的整数商与余数，中间用一个空格隔开。

**输入格式**：
第一行输入一个正整数 `T`。
接下来 `T` 行，每行依次包含字符串 `A`、字符 `op` 与字符串 `B`（以空格分隔）。

**输出格式**：
对于每组数据输出一行对应的精确运算结果。

**💡 算法建模与关键细节**：
1. **统一转换与打印**：封装 `toVec` 将字符串倒序存入 `vector<int>`（顺带防脏前导零），封装 `printVec` 逆序打印；
2. **加、减、乘模块化**：
   * `addBig`：单层循环逐位累加并维护进位 `t /= 10`，收尾补 `if (t > 0) C.push_back(t)`；
   * `geq` + `subBig`：先比 `size()` 再从高位逐位比较，保证大减小，算完必去前导零；
   * `mulBig`：开长度为 `A.size() + B.size()` 的全 `0` 数组，先双层循环 `C[i + j] += A[i] * B[j]`，再线性扫进位，最后去前导零；
3. **高精除低精防溢出**：`divBig` 直接从高位向低位扫描原字符串 `sa`，用 `long long rem` 承接 `rem * 10 + digit`，最后用 `pos + 1 < (int)q.size()` 保留单个 `0`。

```cpp
#include <iostream>
#include <string>
#include <vector>
#include <algorithm>
using namespace std;

vector<int> toVec(const string &s) {
    vector<int> v;
    for (int i = (int)s.size() - 1; i >= 0; i--) {
        v.push_back(s[i] - '0');
    }
    while (v.size() > 1 && v.back() == 0) v.pop_back();
    return v;
}

void printVec(const vector<int> &v) {
    for (int i = (int)v.size() - 1; i >= 0; i--) cout << v[i];
}

// 判断大整数 |A| >= |B|
bool geq(const vector<int> &A, const vector<int> &B) {
    if (A.size() != B.size()) return A.size() > B.size();
    for (int i = (int)A.size() - 1; i >= 0; i--) {
        if (A[i] != B[i]) return A[i] > B[i];
    }
    return true;
}

vector<int> addBig(const vector<int> &A, const vector<int> &B) {
    vector<int> C;
    int t = 0;
    int n = max(A.size(), B.size());
    for (int i = 0; i < n; i++) {
        if (i < (int)A.size()) t += A[i];
        if (i < (int)B.size()) t += B[i];
        C.push_back(t % 10);
        t /= 10;
    }
    if (t > 0) C.push_back(t);
    return C;
}

// 调用前保证 A >= B
vector<int> subBig(const vector<int> &A, const vector<int> &B) {
    vector<int> C;
    int borrow = 0;
    for (int i = 0; i < (int)A.size(); i++) {
        int t = A[i] - borrow;
        if (i < (int)B.size()) t -= B[i];
        if (t < 0) {
            t += 10;
            borrow = 1;
        } else {
            borrow = 0;
        }
        C.push_back(t);
    }
    while (C.size() > 1 && C.back() == 0) C.pop_back();
    return C;
}

vector<int> mulBig(const vector<int> &A, const vector<int> &B) {
    vector<int> C(A.size() + B.size(), 0);
    for (int i = 0; i < (int)A.size(); i++) {
        for (int j = 0; j < (int)B.size(); j++) {
            C[i + j] += A[i] * B[j];
        }
    }
    for (int k = 0; k + 1 < (int)C.size(); k++) {
        C[k + 1] += C[k] / 10;
        C[k] %= 10;
    }
    while (C.size() > 1 && C.back() == 0) C.pop_back();
    return C;
}

pair<string, long long> divBig(const string &sa, long long b) {
    string q = "";
    long long rem = 0;
    for (int i = 0; i < (int)sa.size(); i++) {
        rem = rem * 10 + (sa[i] - '0');
        q += char('0' + rem / b);
        rem %= b;
    }
    int pos = 0;
    while (pos + 1 < (int)q.size() && q[pos] == '0') pos++;
    return make_pair(q.substr(pos), rem);
}

int main() {
    int T;
    cin >> T;
    for (int tc = 0; tc < T; tc++) {
        string sa, sb;
        char op;
        cin >> sa >> op >> sb;
        if (op == '+') {
            printVec(addBig(toVec(sa), toVec(sb)));
            cout << "\n";
        } else if (op == '-') {
            vector<int> A = toVec(sa), B = toVec(sb);
            if (geq(A, B)) {
                printVec(subBig(A, B));
            } else {
                cout << "-";
                printVec(subBig(B, A));
            }
            cout << "\n";
        } else if (op == '*') {
            printVec(mulBig(toVec(sa), toVec(sb)));
            cout << "\n";
        } else if (op == '/') {
            long long b = 0;
            for (int i = 0; i < (int)sb.size(); i++) b = b * 10 + (sb[i] - '0');
            pair<string, long long> res = divBig(sa, b);
            cout << res.first << " " << res.second << "\n";
        }
    }
    return 0;
}
```

* **输入样例**：
  ```text
  7
  999 + 1
  12345 - 12345
  20 - 100
  98765432109876543210 * 0
  12345678901234567890 * 9876543210
  5 / 13
  100000000000000000000 / 999999999
  ```
* **输出样例**：
  ```text
  1000
  0
  -80
  0
  121932631124828532111263526900
  0 5
  100000000100 100
  ```
  *（样例解释：第 `1` 组验证加法最高位进位 `if (t > 0)`；第 `2`、`4`、`6` 组集中检验减法归零、乘以 `0`、商为 `0` 时“去前导零且保留单个 `0`”的底线；第 `3` 组用 `"20" - "100"` 精准击破字典序比大小陷阱；第 `5` 组产出远超 `unsigned long long` 上限的 `30` 位大数乘积；第 `7` 组用接近 $10^9$ 的除数 `999999999` 检验了 `long long rem` 在 `rem * 10` 超过 `int` 上限时的完全防溢出表现。）*
