写数组时只要记住下标，几乎很少遇到“写反两行赋值就让整个数据瞬间人间蒸发”的惨案；可一旦进入链表世界，这种惊魂时刻就会频频上演。GESP 五级选择题和 CSP-J 初赛最爱考这样一道“看似送分、实则杀人诛心”的代码题：要在单链表节点 `p` 后面插入新节点 `s`，把 `s->next = p->next;` 和 `p->next = s;` 稍微调换一下顺序，结果不仅 `p` 后面的整条链表瞬间丢失变成内存泄漏，连新节点 `s` 自己都变成了 `s->next == s` 的无限死循环自环！到了双向链表，一次插入要连改 `4` 条指针，究竟哪几行可以互换顺序、哪一行绝对必须压轴执行？到了 CSP-J 复赛现场，为什么高分选手几乎不用 `new`/`delete` 写动态指针链表，反而清一色改用**数组模拟静态链表**？本文从底层指针覆盖机制切入，彻底讲透单链表、双向链表、循环链表的操作顺序铁律与竞赛级静态链表模板。

## 🎯 考纲锚点与核心痛点

> 📍 **对应考点**：掌握单链表、双向链表与循环链表的节点内存结构；精通单链表插入删除的“先连后断”铁律与双向链表 `4` 条指针修改的数据依赖顺序；掌握竞赛常用的数组模拟静态双向链表与哨兵节点写法。
> 🎯 **适用等级**：`GESP 五级/六级考点 | CSP-J 初赛/复赛必考`

在历年 GESP 五级认证与 CSP-J 初复赛中，考生在链表专题上失分高度集中在三大痛点：
1. **只背代码不画指针图，顺序一变就懵圈**：死记某一种固定 4 行模板，遇到初赛选项把 4 条赋值语句打乱重排、甚至把 `p->next->prev = s` 改写成 `s->next->prev = s` 时，无法用“谁覆盖了 `p->next`”判断对错；
2. **首尾空指针边界漏判，频发段错误（RE）**：在链表尾节点后插入或删除头节点时，忘记检查 `p->next != nullptr` 或忘记更新 `head`，导致空指针解引用崩溃；
3. **复赛硬写动态指针链表，调试极慢且易超时/泄漏**：不熟悉数组模拟静态链表，在 $n = 10^5$ 的插队/删人题中要么用 `vector::insert` 退化到 $O(n^2)$ 超时（TLE），要么用 `new`/`delete` 写出野指针和重复删除悬空指针 Bug。

## 🧠 一、 核心原理深度拆解（有理论）

### 1. 数组 vs 链表，以及三大链表家族的节点结构

**数组（顺序表）**像一排紧挨着编号的连排储物柜，内存地址连续，因此凭下标 `a[i]` 可以 $O(1)$ 随机直达；但要在中间硬塞或抽走一个元素，后面所有元素都必须整排搬家，耗时 $O(n)$。

**链表（Linked List）**则像一场**寻宝接力游戏**：每个节点散落在内存的任意角落，不要求物理地址连续，而是通过节点内部存放的**指针域**（即下一个/上一个节点的内存地址）把整条链串起来。因此，一旦定位到操作位置，插入和删除只需改写局部的几条“寻宝线索”，耗时严格 $O(1)$；代价是无法按序号直接跳达，找第 `k` 个元素必须顺着线索从头走 $O(n)$ 步。

按指针域的数量与首尾连接方式，考纲要求掌握**三大链表家族**：

```text
========================================================================
【三大链表家族节点拓扑图】

1) 单链表（Singly Linked List）—— 只能单向往右走，尾节点指向 nullptr
   head ──> [ 10 | next ] ──> [ 20 | next ] ──> [ 30 | nullptr ]

2) 双向链表（Doubly Linked List）—— 同时保存 prev 与 next，进退自如
            nullptr ◄── [ prev | 10 | next ] ◄──► [ prev | 20 | next ] ──> nullptr

3) 循环链表（Circular Linked List）—— 尾节点指回头节点，表内没有 nullptr！
   head ──> [ 10 | next ] ──> [ 20 | next ] ──> [ 30 | next ]
              ▲                                       │
              └───────────────────────────────────────┘
========================================================================
```

**顺序表（数组）与三类链表核心特性对照表**：

| 数据结构 | 随机访问第 `k` 项 | 已知前驱 `p` 插入/删除 | 已知节点 `q` 本身删除 | 额外指针开销 | 适用典型场景 |
| :---: | :---: | :---: | :---: | :---: | :--- |
| **一维数组** | $O(1)$ | $O(n)$（需搬移元素） | $O(n)$ | 无 | 频繁下标查询、二分查找 |
| **单链表** | $O(n)$ | $O(1)$（改 `2`/`1` 条链） | $O(n)$（尾节点无法 $O(1)$ 找前驱） | 每节点 `1` 个指针 | 头插法建图（邻接表）、仅正向扫描 |
| **双向链表** | $O(n)$ | $O(1)$（改 `4`/`2` 条链） | **$O(1)$**（直接用 `q->prev`） | 每节点 `2` 个指针 | 任意节点左右插队、任意编号 $O(1)$ 删除 |
| **循环链表** | $O(n)$ | $O(1)$ | 单向 $O(n)$ / 双向 $O(1)$ | `1` 或 `2` 个指针 | 约瑟夫环、轮转调度 |

### 2. 单链表核心铁律：为什么插入必须“先连后断”？

假设单链表当前为 `p(20) -> q(30)`（即 `p->next` 存着节点 `q` 的地址），现在要把新节点 `s(25)` 插入到 `p` 的**后面**。

关键问题在于：**此时全宇宙只有 `p->next` 这唯一一根绳子抓着后半截链表 `q(30)`！**

```text
========================================================================
【单链表在 p 后插入 s：正确“先连后断” vs 致命“先断后连”】

初始状态：   p(20) ───────────► q(30) ──► ...     独立新节点：s(25)

✅ 正确顺序（先连后断）：
   第①步 s->next = p->next;   // 先让 s 稳稳抓住 q(30)！
          p(20) ───────────► q(30)
                               ▲
                     s(25) ────┘
   第②步 p->next = s;         // 确认后方已安全接管，再断开旧链、p 指向 s！
          p(20) ──► s(25) ──► q(30) ──► ...   （完好无损 ✅）

❌ 致命错误（颠倒两行，先断后连）：
   第①步 p->next = s;         // 灾难！唯一指向 q 的地址被覆盖，q 及其后整条链永久丢失！
          p(20) ──► s(25)       [q(30) ──► ... 断链失踪，内存泄漏！]
   第②步 s->next = p->next;   // 此时 p->next 已经是 s 自己，等价于 s->next = s！
          p(20) ──► s(25) ──┐
                      ▲     │ （s 指向自己，遍历时原地无限死循环 TLE！❌）
                      └─────┘
========================================================================
```

**单链表删除节点 `p` 的直接后继 `q`**：
同样必须先用临时指针记下待删节点，再“跨桥绕过”，最后才能释放内存：
```cpp
Node *q = p->next;   // ① 先用 q 暂存待删节点地址（否则绕过后找不到它，无法 delete）
p->next = q->next;   // ② 绕过 q，让 p 直接连向 q 的后继（也可写 p->next = p->next->next）
delete q;            // ③ 确认链路完整脱离后，最后再释放 q 所占堆内存
```
如果把第 ② 步和第 ③ 步颠倒（先 `delete q` 再读 `q->next`），就会访问已释放的非法内存（**悬空指针 / Use-After-Free**），触发未定义行为！

### 3. 双向链表插入删除：用“数据依赖图”秒杀一切 4 行排序题

在双向链表中，设 `p` 的后继为 `q`（`q = p->next`，假设非空），现在要在 `p` 和 `q` 之间插入新节点 `s`。我们需要修改整整 **`4` 条指针**：

```text
========================================================================
【双向链表在 p(20) 与 q(30) 之间插入 s(25)：4 条指针全景】

初始：  p(20) ══════════════► q(30)
        p(20) ◄══════════════ q(30)

目标：  p(20) ──④──► s(25) ──①──► q(30)
        p(20) ◄──②── s(25) ◄──③── q(30)

标准无错四步（记住口诀：先连新节点两翼，再改旧后继回指，最后断 p->next）：
  ① s->next = p->next;          // 新节点右翼牵住 q        [读 p->next]
  ② s->prev = p;                // 新节点左翼牵住 p        [无依赖]
  ③ if (p->next != nullptr)
        p->next->prev = s;      // 原后继 q 回指 s         [读 p->next]
  ④ p->next = s;                // 最后才改写 p->next！    [写 p->next]
========================================================================
```

**初赛选择题核心破局点（依赖本质）**：
很多同学死背“只能按 ①②③④ 写”，结果考场遇到顺序微调的正确选项反倒选错！其实只要盯住**唯一被覆写的共享变量 `p->next`**，一眼就能判断任意排列是否合法：
* 只要语句中用到了**旧的 `p->next`**（也就是 `s->next = p->next` 和 `p->next->prev = s`），它们就**必须排在 `p->next = s` 之前**！
* 一旦提前执行了 `p->next = s`，后续再写 `p->next->prev = s` 实际改的就不再是 `q->prev`，而是 `s->prev = s`，彻底漏掉了 `q->prev` 的更新！
* **高阶变式**：如果有人把第 ③ 步改写成 **`s->next->prev = s`**，那它读取的是已经存好 `q` 地址的 `s->next` 而不再依赖 `p->next`！此时只要保证 `s->next = p->next` 在 `s->next->prev = s` 和 `p->next = s` 之前，哪怕把 `p->next = s` 放到第 3 行也**依然完全正确**！

**双向链表删除已知节点 `p`（借助哨兵节点零特判）**：
当已知待删节点 `p`（且确保 `p` 左右均存在邻居或哨兵）时，只需 `2` 行：
```cpp
p->prev->next = p->next;   // 左邻居的右指针跨过 p，直连右邻居
p->next->prev = p->prev;   // 右邻居的左指针跨过 p，直连左邻居
delete p;                  // 最后释放 p
```
注意：因为这两行读写的是 `p` 的左右两个不同邻居，并没有改写 `p->prev` 和 `p->next` 本身，所以这两行**互换顺序完全等价**！但 `delete p` 依然必须放在最后！

### 4. 竞赛王牌武器：数组模拟静态双向链表 + 虚拟头尾哨兵

在 GESP 五级/六级和 CSP-J 复赛中，动态 `new Node` 有三大硬伤：申请堆内存慢、代码易出空指针段错误、无法通过元素编号 $O(1)$ 找到节点地址。竞赛真正统治考场的写法是**数组模拟静态双向链表（Static Doubly Linked List）**：

* 用数组下标 `1 .. n` 代替内存地址，作为每个节点的唯一“指针”；
* `val[i]` 存节点 `i` 的数据（若节点编号本身就是值，连 `val[]` 都可以省掉！）；
* `prv[i]`（或 `L[i]`）存节点 `i` 的前驱下标，`nxt[i]`（或 `R[i]`）存节点 `i` 的后继下标；
* **终极降维打击——虚拟哨兵头尾（`HEAD = 0`, `TAIL = n + 1`）**：在链表最左端和最右端各放一个永不删除的“空壳保安”，初始让 `nxt[HEAD] = TAIL, prv[TAIL] = HEAD`。从此无论在表头插入、表尾插入、删头还是删尾，每一个真实节点左右两侧**永远都有合法下标**，**所有 `if (p->next != nullptr)` 和 `if (p == head)` 边界特判全部清零**！

> 💡 **考场黄金法则**：
> 1. **【先读后写，先连后断】**：单链表插 `s` 到 `p` 后死守 `s->next = p->next; p->next = s;`；双向链表凡读取旧 `p->next` 的语句一律排在 `p->next = s` 之前；删除严格“先暂存、再绕过、最后释放”。
> 2. **【复赛首选静态链表 + 双哨兵】**：用 `L[]`、`R[]` 替代指针，配 `HEAD = 0`、`TAIL = n + 1` 双哨兵，零空指针 RE 且支持按编号 $O(1)$ 定位插删。

## 🔍 二、 具象代码与数据推演（有举例）

### 示例 1：动态单链表的“先连后断”插入与安全删除（24 行标准 C++11 程序）

下面这段 C++11 程序构造单链表 `10 -> 20 -> 30 -> NULL`，演示在 `p(20)` 后正确插入 `s(25)`，再安全删除 `s` 的后继节点 `30`：

```cpp
#include <iostream>
using namespace std;

struct Node { int val; Node *next; };

void show(Node *head) {
    for (Node *cur = head; cur != nullptr; cur = cur->next)
        cout << cur->val << " -> ";
    cout << "NULL\n";
}

int main() {
    Node *a = new Node{10, nullptr}, *b = new Node{20, nullptr}, *c = new Node{30, nullptr};
    a->next = b; b->next = c;
    show(a);                          // 初始：10 -> 20 -> 30 -> NULL
    Node *p = b, *s = new Node{25, nullptr};
    s->next = p->next;                // ① 先连：s 接住原后继 c(30)
    p->next = s;                      // ② 后断：p 改指向 s(25)
    show(a);                          // 插入：10 -> 20 -> 25 -> 30 -> NULL
    Node *q = s->next;                // 暂存待删节点 c(30)
    s->next = q->next;                // 绕过 c(30)，s 直接接 NULL
    delete q;                         // 释放 c(30) 内存
    show(a);                          // 删除：10 -> 20 -> 25 -> NULL
    delete s; delete b; delete a;
    return 0;
}
```

#### 分步内存指针变化推演表

| 执行步骤 | `a(10)->next` | `b(20)->next` | `s(25)->next` | `c(30)->next` | 链表当前逻辑序列 |
| :---: | :---: | :---: | :---: | :---: | :--- |
| 建链完成 | `b(20)` | `c(30)` | 未创建 | `NULL` | `10 -> 20 -> 30 -> NULL` |
| `s->next = p->next;` | `b(20)` | `c(30)` | **`c(30)`** | `NULL` | `b` 与 `s` 同时指向 `c`（后半链已安全接管） |
| `p->next = s;` | `b(20)` | **`s(25)`** | `c(30)` | `NULL` | `10 -> 20 -> 25 -> 30 -> NULL` |
| `q = s->next; s->next = q->next;` | `b(20)` | `s(25)` | **`NULL`** | `NULL`（待删） | `10 -> 20 -> 25 -> NULL`（`c` 已脱离链） |
| `delete q;` | `b(20)` | `s(25)` | `NULL` | 已释放 | `10 -> 20 -> 25 -> NULL`（无内存泄漏） |

程序经 `g++ -O2 -std=c++11` 编译运行实际输出：

```text
10 -> 20 -> 30 -> NULL
10 -> 20 -> 25 -> 30 -> NULL
10 -> 20 -> 25 -> NULL
```

### 示例 2：双哨兵数组模拟静态双向链表（24 行标准 C++11 程序）

下面这段静态双向链表程序以 `H = 0` 为左哨兵、`T = 9` 为右哨兵，初始串起 `10(下标1) <-> 20(下标2) <-> 30(下标3)`，演示在下标 `2` 后插入下标 `4(val=25)`，随后 $O(1)$ 删除下标 `2`：

```cpp
#include <iostream>
using namespace std;

int val[10], prv[10], nxt[10];

void show(int H, int T) {
    for (int u = nxt[H]; u != T; u = nxt[u])
        cout << val[u] << (nxt[u] != T ? " <-> " : "\n");
}

int main() {
    int H = 0, T = 9;                 // 哨兵头 0、哨兵尾 9
    val[1] = 10; val[2] = 20; val[3] = 30;
    nxt[H] = 1; prv[1] = H; nxt[1] = 2; prv[2] = 1;
    nxt[2] = 3; prv[3] = 2; nxt[3] = T; prv[T] = 3;
    int p = 2, s = 4; val[s] = 25;    // 在节点 2(20) 后插入节点 4(25)
    nxt[s] = nxt[p];                  // ① 新节点右连 3
    prv[s] = p;                       // ② 新节点左连 2
    prv[nxt[p]] = s;                  // ③ 原后继 3 左连 s（必须在 nxt[p] 被覆盖前）
    nxt[p] = s;                       // ④ 最后才改写 nxt[p] 断开旧桥
    show(H, T);                       // 10 <-> 20 <-> 25 <-> 30
    nxt[prv[p]] = nxt[p];             // 删除节点 2(20)：左邻 1 右连 4
    prv[nxt[p]] = prv[p];             // 右邻 4 左连 1
    show(H, T);                       // 10 <-> 25 <-> 30
    return 0;
}
```

#### 分步静态数组下标状态推演表

| 阶段 | 节点 `1(10)` `(prv, nxt)` | 节点 `2(20)` `(prv, nxt)` | 节点 `4(25)` `(prv, nxt)` | 节点 `3(30)` `(prv, nxt)` | 正向遍历输出 |
| :---: | :---: | :---: | :---: | :---: | :--- |
| **初始态** | `(0, 2)` | `(1, 3)` | 未使用 | `(2, 9)` | `10 <-> 20 <-> 30` |
| **在 `2` 后插入 `4`** | `(0, 2)` | `(1, 4)` | **`(2, 3)`** | **`(4, 9)`** | `10 <-> 20 <-> 25 <-> 30` |
| **删除节点 `2`** | **`(0, 4)`** | 逻辑脱离（残值 `(1, 4)`） | **`(1, 3)`** | `(4, 9)` | `10 <-> 25 <-> 30` |

程序经 `g++ -O2 -std=c++11` 编译运行实际输出：

```text
10 <-> 20 <-> 25 <-> 30
10 <-> 25 <-> 30
```

## ⚡ 三、 考场高频避坑指南（正误辨析）

在 GESP 五级/六级判断题与 CSP-J 复赛考场上，以下三个陷阱是链表题丢分的重灾区：

### ❌ 易错点 1：双向链表表尾插入忘记判空 `p->next != nullptr`，直接解引用触发 RE！
* **错误代码**：
  ```cpp
  // 当 p 是无哨兵双向链表的尾节点时，p->next == nullptr！
  s->next = p->next;
  s->prev = p;
  p->next->prev = s;  // 致命崩盘！对空指针执行 ->prev 立即触发段错误 RE！
  p->next = s;
  ```
* **为什么错**：若没有右哨兵节点，当 `p` 恰好是最后一个节点时，`p->next` 是 `nullptr`，强行访问 `p->next->prev` 属于非法访问 `0x0` 地址，Linux 评测机瞬间判 **Runtime Error（SIGSEGV）**。
* **正确规范**：动态指针写法必须加判空 `if (p->next != nullptr) p->next->prev = s;`；复赛实战则推荐直接建立虚拟头尾哨兵 `HEAD`、`TAIL`，让所有真实节点的 `nxt[p]` 永远有效！

### ❌ 易错点 2：静态链表对同一节点重复删除（或误删未入表编号），把现存链表撕裂成死循环！
* **错误代码**：
  ```cpp
  void removeNode(int x) {
      R[L[x]] = R[x];
      L[R[x]] = L[x];  // 坑：若 x 早已被删过一次，再次删除会把已更新的邻居指针强行覆盖回旧残值！
  }
  ```
* **为什么错**：静态链表删除只是“绕过 `x`”，并不会清空 `L[x]` 和 `R[x]` 里残留的旧邻居下标。如果后来那些旧邻居的左右关系又发生了变化，或者 `x` 从未加入过链表（`L[x] == 0, R[x] == 0`），第二次调用 `removeNode(x)` 甚至会把 `R[0]` 改写成 `0`，造成 `HEAD` 指向自己的**原地死循环**！
* **正确规范**：必须配套一个布尔数组 `bool removed[MAXN]`，删除前严格检查 `if (x < 1 || x > n || removed[x]) return;`，删除后立刻置位 `removed[x] = true;`！

### ❌ 易错点 3：遍历循环链表套用 `while (cur != nullptr)` 导致无限死循环！
* **错误代码**：
  ```cpp
  // 非空单向循环链表中，尾节点指向 head，整条链根本不存在 nullptr！
  Node *cur = head;
  while (cur != nullptr) {   // 永远为真！程序卡死 TLE！
      cout << cur->val << " ";
      cur = cur->next;
  }
  ```
* **为什么错**：普通单链表以 `nullptr` 作为终点，而循环链表将尾节点的 `next` 接回了 `head`（或哨兵节点），表内不存在任何空指针！
* **正确规范**：不带哨兵的非空循环链表遍历应先判空再用 `do ... while (cur != head)`；带虚拟哨兵头节点 `head` 的循环链表，则从 `cur = head->next` 出发，条件写为 `while (cur != head)`！

## 📝 四、 真题实战演练与精析（有例题：3 道）

### 【例题 1 · 单选题】（GESP 五级 / CSP-J 初赛高频真题模型：双向链表 4 条指针顺序依赖判定）

**题目**：在一个带头尾哨兵节点的双向链表中，节点结构体包含前驱指针 `prev` 与后继指针 `next`。已知指针 `p` 指向链表中的某个有效节点（保证 `p->next != nullptr`），现要将独立的新节点 `s` 插入到节点 `p` 的**正后方**（即 `p` 与原后继节点 `q = p->next` 之间）。下列四段代码序列中，**不能正确完成双向插入、会导致反向链路断裂**的是（ ）。

* **A.**
  ```cpp
  s->next = p->next;
  s->prev = p;
  p->next->prev = s;
  p->next = s;
  ```
* **B.**
  ```cpp
  s->prev = p;
  s->next = p->next;
  p->next = s;
  s->next->prev = s;
  ```
* **C.**
  ```cpp
  p->next->prev = s;
  s->next = p->next;
  p->next = s;
  s->prev = p;
  ```
* **D.**
  ```cpp
  s->next = p->next;
  p->next = s;
  p->next->prev = s;
  s->prev = p;
  ```

**🔍 答案与逐项排除解析**：
* **正确答案**：**D**
* **解析过程（盯紧共享变量 `p->next` 何时被覆写）**：
  设插入前 `p` 的后继节点为 `q`（即初始 `p->next == q`、`q->prev == p`），正确插入后的 4 条目标指针必须是：`p->next == s`、`s->prev == p`、`s->next == q`、`q->prev == s`。
  1. **锁定 D（错误选项）**：
     * 第 1 行：`s->next = q`（正确）；
     * 第 2 行：`p->next = s`（**提前覆写了 `p->next`！此时 `p->next` 已变成 `s`，不再是 `q`！**）；
     * 第 3 行：`p->next->prev = s` 实际执行的变成了 **`s->prev = s`**，而原后继 `q` 的 `q->prev` 根本没被改到，依然死指着 `p`；
     * 第 4 行：`s->prev = p` 把第 3 行写坏的 `s->prev` 改回了 `p`，最终留下隐蔽的**反向断链 Bug**（正向 `p -> s -> q` 看似正常，反向从 `q->prev` 往回走却直接跳过 `s` 跳回了 `p`！）。故 **D 必然错误**；
  2. **排除 A**：标准教科书顺序。第 1 行与第 3 行都在 `p->next` 被改写之前读取 `q`，第 4 行压轴执行 `p->next = s`，4 条指针全对；
  3. **排除 B**：经典初赛变式陷阱！虽然第 3 行提前执行了 `p->next = s`，但注意第 4 行写的是 **`s->next->prev = s`**——它通过第 2 行早已保存好 `q` 的 `s->next` 找到 `q`，完全不依赖被覆盖的 `p->next`，因此 4 条指针全部正确；
  4. **排除 C**：第 1 行先改 `q->prev = s`，第 2 行再让 `s->next = q`，确认所有依赖旧 `p->next` 的操作都完成后，第 3 行才覆盖 `p->next = s`，第 4 行补上独立的 `s->prev = p`，4 条指针全部正确。
  5. 综合确认选 **D**。

### 【例题 2 · 判断题】（GESP 五级核心概念辨析：单链表仅知待删节点指针能否恒 $O(1)$ 删除）

**题目**：在单链表中，只要已知指向任意待删节点 `q` 的指针（包括 `q` 可能是链表尾节点的情况），就能在不遍历链表的前提下，以 $O(1)$ 时间复杂度修改其前驱节点的 `next` 指针并将 `q` 从链表中彻底删除。（ ）

**🔍 答案与反例证明**：
* **结论**：**错误（×）**
* **反例与原理证明**：
  1. **单链表缺乏反向指针**：单链表的每个节点只存储指向后继的 `next` 指针，不存储前驱指针 `prev`，因此仅凭待删节点 `q` 的地址无法在 $O(1)$ 时间内直接回溯找到它的前驱节点；
  2. **“偷天换日复制后继法”在尾节点处彻底失效**：若 `q` 不是尾节点，确实有一个冷门技巧——把 `q->next->val` 复制到 `q->val`，再绕过并删除 `q->next` 来变相实现 $O(1)$ 删除；但一旦 `q` 恰好是**链表尾节点**（`q->next == nullptr`），`q` 后面根本没有后继节点可供复制！为了把前驱节点的 `next` 置为 `nullptr`，此时**唯一可行的方法是从 `head` 开始逐个遍历找到 `q` 的前驱**，最坏时间复杂度必然退化为 $O(n)$；
  3. 只有**双向链表**（因为节点内部直接持有 `q->prev`）才能对包含尾节点在内的任意已知节点保证严格 $O(1)$ 删除。故原命题错误。

### 【例题 3 · 微代码实战】（GESP 五级 / CSP-J 复赛静态双向链表经典模型：实验室排队调度）

**题目描述**：某实验队列初始时仅有编号为 `1` 的 `1` 名队员。接下来依次将编号为 `2` 到 `n`（$2 \le n \le 10^5$）的队员按指令插入队列：第 `i` 名队员给出两个整数 `k` 和 `d`（保证此时编号 `k` 已在队列中），若 `d == 0` 表示将 `i` 插入到 `k` 的**左侧（紧邻前面）**；若 `d == 1` 表示将 `i` 插入到 `k` 的**右侧（紧邻后面）**。
全部 `n` 名队员入队完成后，再执行 `m`（$0 \le m \le 10^5$）次离队指令：每次给出一个整数编号 `x`（$1 \le x \le n$），若 `x` 当前仍在队列中，将其移出队列；若 `x` 已被移出，则忽略该指令。
请你从左到右输出最终仍留在队列中的所有队员编号（保证最终至少剩余 `1` 名队员）。

**输入格式**：
第一行输入一个正整数 `n`。
接下来 `n - 1` 行，第 `i - 1` 行（对应编号 `i = 2 .. n`）输入两个整数 `k` 和 `d`（`d` 为 `0` 或 `1`）。
下一行输入一个非负整数 `m`。
接下来 `m` 行，每行输入一个整数 `x`，表示要移出队列的队员编号。

**输出格式**：
一行输出若干个用单个空格隔开的整数，表示最终队列从左到右的队员编号。

**💡 算法建模与关键细节**：
1. **为什么不用 `vector` 而必须用静态双向链表**：$n, m \le 10^5$，在 `vector` 中间插入/删除会搬移大量元素导致 $O(n^2)$ 超时；而每个队员编号 `1 .. n` 唯一且互不重复，恰好可以直接当作静态双向链表的**节点下标**，定位编号 `k` 或 `x` 只需 $O(1)$！
2. **双哨兵统一左右插入**：设虚拟左哨兵 `HEAD = 0`、虚拟右哨兵 `TAIL = n + 1`，初始链为 `HEAD <-> 1 <-> TAIL`。只需写一个 `insertAfter(p, s)` 函数：
   * 插到 `k` 右侧（`d == 1`）：直接调用 `insertAfter(k, i)`；
   * 插到 `k` 左侧（`d == 0`）：等价于插到 `k` 的左邻居 `L[k]` 的右侧，直接调用 **`insertAfter(L[k], i)`**！得益于哨兵 `HEAD = 0`，即使 `k` 位于队首，`L[k]` 也是合法的 `0`，彻底免去头节点特判！
3. **重复删除防护**：用 `removed[x]` 标记已离队人员，防止同一编号被删两次破坏现存左右邻居指针。总时间复杂度严格 $O(n + m)$，空间复杂度 $O(n)$。

```cpp
#include <iostream>
using namespace std;

const int MAXN = 100005;
int L[MAXN], R[MAXN];
bool removed[MAXN];
int n;

void insertAfter(int p, int s) {
    R[s] = R[p];
    L[s] = p;
    L[R[p]] = s;
    R[p] = s;
}

void removeNode(int x) {
    if (x < 1 || x > n || removed[x]) return;
    R[L[x]] = R[x];
    L[R[x]] = L[x];
    removed[x] = true;
}

int main() {
    cin >> n;
    int HEAD = 0, TAIL = n + 1;
    R[HEAD] = 1; L[1] = HEAD;
    R[1] = TAIL; L[TAIL] = 1;

    for (int i = 2; i <= n; i++) {
        int k, d;
        cin >> k >> d;
        if (d == 1) {
            insertAfter(k, i);
        } else {
            insertAfter(L[k], i);
        }
    }

    int m;
    cin >> m;
    for (int i = 0; i < m; i++) {
        int x;
        cin >> x;
        removeNode(x);
    }

    bool first = true;
    for (int cur = R[HEAD]; cur != TAIL; cur = R[cur]) {
        if (!first) cout << " ";
        cout << cur;
        first = false;
    }
    cout << "\n";
    return 0;
}
```

* **输入样例**：
  ```text
  5
  1 0
  2 1
  1 1
  3 0
  2
  3
  3
  ```
* **输出样例**：
  ```text
  2 5 1 4
  ```
  *（样例解释：初始队列 `[1]`；`2` 插到 `1` 左侧得 `[2, 1]`；`3` 插到 `2` 右侧得 `[2, 3, 1]`；`4` 插到 `1` 右侧得 `[2, 3, 1, 4]`；`5` 插到 `3` 左侧（即 `L[3] = 2` 右侧）得 `[2, 5, 3, 1, 4]`。随后第 1 次删 `3` 令 `5` 与 `1` 直连并置 `removed[3] = true`，得 `[2, 5, 1, 4]`；第 2 次再删 `3` 被 `removed[3]` 安全拦截，最终顺着 `R[0]` 遍历至 `TAIL = 6` 输出 `2 5 1 4`。）*
