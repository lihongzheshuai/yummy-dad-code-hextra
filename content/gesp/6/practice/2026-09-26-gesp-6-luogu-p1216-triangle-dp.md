洛谷经典算法题 P1216「[USACO1.5] 数字三角形 Number Triangles」（同时也是 IOI 1994 第一天第一题），是算法竞赛与等级考试中**动态规划（Dynamic Programming）**无可争议的启蒙之作与奠基经典。本题标准收录于 CCF GESP 六级考纲（基础动态规划核心考点）以及 CSP-J 普及组核心基础题单。题目要求从数字金字塔的最高点出发，每一步只能走到左下方的点或右下方的点，寻找一条直通底部的路径，使经过的数字之和最大。本题完美展现了“最优子结构”与“无后效性”的动态规划核心特质。相较于自顶向下的正向递推，采用**自底向上的逆推 DP**，不仅能天然规避金字塔边缘边界判定的繁琐细节，还能省去在底层逐一遍历查找最大值的步骤，最终一步锁定金字塔顶部的最优全局解。题目难度⭐⭐★☆☆，洛谷官方难度评级为`普及−`。

## luogu-P1216 [USACO1.5] 数字三角形

> 🔗 **洛谷原题传送门**：[luogu-P1216 [USACO1.5] 数字三角形](https://www.luogu.com.cn/problem/P1216)

### 题目描述

观察下面的数字金字塔。

写一个程序来查找从最高点到底部任意处结束的路径，使路径经过数字的和最大。每一步可以走到左下方的点也可以到达右下方的点。

![](https://cdn.luogu.com.cn/upload/image_hosting/95pzs0ne.png)

在上面的样例中，从 $7 \to 3 \to 8 \to 7 \to 5$ 的路径产生了最大权值。

### 输入格式

第一个行一个正整数 $r$，表示行的数目。

后面每行为这个数字金字塔特定行包含的整数。

### 输出格式

单独的一行，包含那个可能得到的最大的和。

### 输入输出样例

#### 输入 #1

```text
5
7
3 8
8 1 0
2 7 4 4
4 5 2 6 5
```

#### 输出 #1

```text
30
```

### 说明/提示

【数据范围】  
对于 $100\%$ 的数据，$1 \le r \le 1000$，所有输入在 $[0, 100]$ 范围内。

### 题目深度剖析

#### 1. 为什么贪心算法在此题失效？

初学者在接触本题时，往往容易产生一种直觉解法——**贪心策略（Greedy Approach）**：从金字塔顶点出发，每一步都观察左下方和右下方两个数字，哪一个数值大就往哪边走。

然而，局部最优绝不等于全局最优。我们可以构造一个极简的反例：
```text
        1
      2   10
    100 1   1 1
```
- 若使用贪心算法：从顶点 $1$ 出发，左边是 $2$，右边是 $10$。贪心策略会选择走 $10$；接下来在第 $3$ 行只能选择走 $1$，最终得到的路径总和为 $1 + 10 + 1 = 12$。
- 但全局最优路径显而易见是往左走：$1 \to 2 \to 100$，路径总和高达 $1 + 2 + 100 = 103$。

贪心算法的致命缺陷在于**目光短浅**：只顾眼前一步的收益，而无法感知后续可能蕴藏的巨大权值。因此，必须使用能够通盘衡量所有路径组合的算法——**动态规划**。

#### 2. 暴力搜索与重叠子问题

如果使用纯深度优先搜索（DFS）来穷举所有路径，从第 $1$ 层走到第 $r$ 层，每一层都有 $2$ 种走向选择（左下或右下）。总路径数为：
$$2^{r-1}$$
当 $r = 1000$ 时，$2^{999}$ 是一个天文数字，计算机完全无法在有效时间内完成。

暴搜之所以如此低效，是因为存在大量的**重叠子问题（Overlapping Subproblems）**。例如，从顶点走两条不同路径：
- 路径 A：$7 \to 3 \to 8$
- 路径 B：$7 \to 8 \to 8$

这两条路径汇合到了第 $3$ 行第 $2$ 列的数字 $8$。无论之前走的是路径 A 还是路径 B，从这个位置向下到达底部的最优走法是完全相同且互相独立的（满足**无后效性**）。如果反复对该位置的后续路径进行重复搜索，就会造成海量的算力浪费。

#### 3. 动态规划设计：正推 vs 逆推

动态规划的核心思想是将子问题的最优解存储起来，自底向上或自顶向下递推求解。

##### （1）正推法（自顶向下递推）的局限
若设 $dp[i][j]$ 表示从顶点 $(1, 1)$ 出发走到位置 $(i, j)$ 的最大路径和：
- 状态转移需要考虑上方来源：位置 $(i, j)$ 只能由正上方偏左的点 $(i-1, j-1)$ 或正上方偏右的点 $(i-1, j)$ 走过来；
- **边界痛点**：每一行的第 $1$ 列只能从上一行的第 $1$ 列转移过来（没有左上方来源）；每一行的最后一列只能从上一行的最后一列转移过来（没有右上方来源）。编写代码时需要大量处理 `j == 1` 和 `j == i` 的边界特殊情况；
- **结果汇总**：递推到最底层第 $r$ 行后，顶点到任意底部的最大值可能落在第 $r$ 行的任意一列，因此还必须在 $dp[r][1 \dots r]$ 中再次遍历扫描一遍求最大值。

##### （2）逆推法（自底向上递推）的极简优雅
如果我们颠倒思维方向，**自底向上逆推**：
- **状态定义**：设 $dp[i][j]$ 表示**从网格位置 $(i, j)$ 出发走到金字塔底部的最大路径和**。
- **基础状态（边界）**：
  金字塔最底层第 $r$ 行的点本身就是终点，其向下的最大路径和就是它自身的数值：
  $$dp[r][j] = a[r][j] \quad (1 \le j \le r)$$
- **状态转移方程**：
  从倒数第二行 $i = r - 1$ 开始向上逆推至第 $1$ 行。对于位置 $(i, j)$，下一步只能走到 $(i+1, j)$ 或 $(i+1, j+1)$：
  $$dp[i][j] = a[i][j] + \max(dp[i+1][j], dp[i+1][j+1])$$
- **完美优势**：
  1. **零边界特判**：无论 $j$ 是多少，下方两个点 $(i+1, j)$ 和 $(i+1, j+1)$ 永远客观存在且合法，完全不需要任何针对行首、行尾的条件分支判断！
  2. **一步出解**：递推回金字塔顶点后，$dp[1][1]$ 就是从最高点到底部的全局最优路径总和，无需在底层做任何额外的 $\max$ 查找。

#### 4. 空间优化：滚动数组思想

在逆推状态转移方程中，计算第 $i$ 行的 $dp[i][j]$ 时，**仅仅依赖于第 $i+1$ 行的计算结果**，更早的第 $i+2 \dots r$ 行的数据已经完成历史使命，无需长期驻留内存。

因此，完全可以将二维数组压缩为一维滚动数组 $dp[j]$：
$$dp[j] = a[i][j] + \max(dp[j], dp[j+1])$$
当内层循环 $j$ 从 $1$ 升序遍历到 $i$ 时，$dp[j]$ 和 $dp[j+1]$ 存储的恰好是上一轮（第 $i+1$ 行）的结果，空间复杂度直接从 $\mathcal{O}(r^2)$ 降低到 $\mathcal{O}(r)$。

不过由于本题 $r \le 1000$，二维数组占用的内存仅为 $1005 \times 1005 \times 4\text{ 字节} \approx 4\text{MB}$，远低于题目限制的 $125.00\text{MB}$。为了保持教学展示的直观性与逻辑完整性，标准解法采用二维状态数组编写。

#### 5. 易错点与边界防坑指南

1. **数组大小与下标安全**：
   - 题目给定 $r \le 1000$。为避免数组越界，全局数组必须定义在 `1005` 以上（如 `const int MAXN = 1005;`）。
   - 下标统一采用竞赛惯用的 $1$-based 索引（行 $1 \dots r$，列 $1 \dots i$），与题面自然对应。
2. **数据范围与整型溢出验证**：
   - 输入每项数值在 $[0, 100]$ 范围内，最大行数 $r = 1000$。
   - 最大路径总和的理论上限为 $1000 \times 100 = 10^5$。
   - 32 位带符号整型 `int` 的上限约为 $2.14 \times 10^9$，远大于 $10^5$，因此使用普通 `int` 即可安全存储，无需引入 `long long`。
3. **逆推循环边界**：
   - 外层循环初始为底部的上一行：`i = r - 1`，终止条件为 `i >= 1`，自减步进 `--i`。
   - 内层循环遍历当前行的每个元素：`j = 1` 到 `j <= i`。

#### 6. 复杂度深度剖析

- **时间复杂度**：
  金字塔第 $i$ 行包含 $i$ 个数字，总元素个数为：
  $$\sum_{i=1}^r i = \frac{r(r + 1)}{2}$$
  逆推过程中，每个格点的状态转移仅包含一次加法和一次二元求最大值操作，单次转移开销严格为 $\mathcal{O}(1)$。
  因此整体时间复杂度严格为：
  $$\mathcal{O}(r^2)$$
  在 $r = 1000$ 的极端情况下，总计算次数约为 $5 \times 10^5$ 次，现代 CPU 可以在 $5\text{ms}$ 内瞬间执行完毕，毫无超时风险。
- **空间复杂度**：
  二维数据矩阵 `a[MAXN][MAXN]` 与状态矩阵 `dp[MAXN][MAXN]` 的空间开销为：
  $$\mathcal{O}(r^2)$$
  占用内存约 $2 \times 1005 \times 1005 \times 4\text{ 字节} \approx 8\text{MB}$，远在 $125.00\text{MB}$ 的限制之内。

### 完整参考代码 (C++11)

```cpp
/**
 * Problem: luogu-P1216 [USACO1.5] 数字三角形
 * Algorithm: 基础动态规划 (坐标型逆推 / 自底向上 DP)
 * Standard: C++11 (CCF GESP 官方大纲规范)
 * Author: OneCoder
 */

#include <iostream>
#include <algorithm>

using namespace std;

// 最大行数 1000，预留边界安全裕量
const int MAXN = 1005;

// a[i][j] 存储原始数字金字塔的数值
int a[MAXN][MAXN];

// dp[i][j] 表示从坐标 (i, j) 出发走到金字塔底部的最大路径权值和
int dp[MAXN][MAXN];

int main() {
    // 读入数字金字塔的行数 r
    int r;
    cin >> r;

    // 读入金字塔的每一行数值
    // 第 i 行共有 i 个数字
    for (int i = 1; i <= r; ++i) {
        for (int j = 1; j <= i; ++j) {
            cin >> a[i][j];
        }
    }

    // 边界初始状态：金字塔最底层 (第 r 行) 向下走的最大和即为自身数值
    for (int j = 1; j <= r; ++j) {
        dp[r][j] = a[r][j];
    }

    // 自底向上逆推：从倒数第二行 (r - 1) 逐步递推至金字塔顶部 (第 1 行)
    for (int i = r - 1; i >= 1; --i) {
        for (int j = 1; j <= i; ++j) {
            // 状态转移方程：
            // 当前格子的最大路径和 = 自身数值 + 下方左、右两个可选路径的最大值
            dp[i][j] = a[i][j] + max(dp[i + 1][j], dp[i + 1][j + 1]);
        }
    }

    // 最终顶点 dp[1][1] 即为从最高点到底部任意处结束的最大路径权值和
    cout << dp[1][1] << "\n";

    return 0;
}
```
