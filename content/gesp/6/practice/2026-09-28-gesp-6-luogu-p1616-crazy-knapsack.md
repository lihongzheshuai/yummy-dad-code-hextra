洛谷经典算法题 P1616「疯狂的采药」是算法竞赛与等级考试中**经典动态规划·完全背包问题（Unbounded Knapsack Problem）**的代表性试题。本题标准收录于 CCF GESP 六级考纲（基础动态规划模型核心考点）以及 CSP-J 普及组核心考点题单。本题是经典 0/1 背包题 P1048「采药」的进阶强化版：辰辰的同门 LiYuxiang 同样需要在有限的总时间 $t$ 内采摘草药，山洞中有 $m$ 种草药，每种草药不仅采摘耗时与蕴含价值不同，更关键的是**每种草药都可以无限制地疯狂重复采摘多次**！题目要求在给定的总时间内使得采摘草药的总价值最大化。本题的核心考点在于深入理解完全背包的状态转移方程、洞悉**一维滚动数组正序遍历**的数学机理，以及防范**数值溢出（必须使用 64 位整数 `long long`）**的高频陷阱。题目难度⭐⭐★☆☆，洛谷官方难度评级为`普及−`。

## luogu-P1616 疯狂的采药

> 🔗 **洛谷原题传送门**：[luogu-P1616 疯狂的采药](https://www.luogu.com.cn/problem/P1616)

### 题目描述

LiYuxiang 是个天资聪颖的孩子，他的梦想是成为世界上最伟大的医师。为此，他想拜附近最有威望的医师为师。医师为了判断他的资质，给他出了一个难题。医师把他带到一个到处都是草药的山洞里对他说：“孩子，这个山洞里有一些不同种类的草药，采每一种都需要一些时间，每一种也有它自身的价值。我会给你一段时间，在这段时间里，你可以采到一些草药。如果你是一个聪明的孩子，你应该可以让采到的草药的总价值最大。”

如果你是 LiYuxiang，你能完成这个任务吗？

此题和原题的不同点：

$1$. 每种草药可以无限制地疯狂采摘。

$2$. 药的种类眼花缭乱，采药时间好长好长啊！师傅等得菊花都谢了！

### 输入格式

输入第一行有两个整数，分别代表总共能够用来采药的时间 $t$ 和代表山洞里的草药的数目 $m$。

第 $2$ 到第 $(m + 1)$ 行，每行两个整数，第 $(i + 1)$ 行的整数 $a_i, b_i$ 分别表示采摘第 $i$ 种草药的时间和该草药的价值。

### 输出格式

输出一行，这一行只包含一个整数，表示在规定的时间内，可以采到的草药的最大总价值。

### 输入输出样例

#### 样例输入 #1

```text
70 3
71 100
69 1
1 2
```

#### 样例输出 #1

```text
140
```

### 说明/提示

#### 数据规模与约定

- 对于 $30\%$ 的数据，保证 $m \le 10^3$ 。
- 对于 $100\%$ 的数据，保证 $1 \leq m \le 10^4$，$1 \leq t \leq 10^7$，且 $1 \leq m \times t \leq 10^7$，$1 \leq a_i, b_i \leq 10^4$。

### 题目深度剖析

#### 1. 完全背包模型的抽象与核心本质

本题将现实中的时间分配问题抽象为经典算法模型——**完全背包问题（Unbounded Knapsack Problem）**。

与我们在 P1048 中学习的 **0/1 背包**相比，二者的本质区别在于物品的**可用数量约束**：
- **0/1 背包**：每种物品仅有一件，只有“选 1 次”或“选 0 次”两种对立状态；
- **完全背包**：每种物品拥有**无限件**（数量不设上限），在容量允许的前提下，同一种物品可以被重复选取任意非负整数次（$0, 1, 2, \dots$ 次）。

对应到本题的具体情境：
- **背包总容量**：对应可用的总采药时间 $t$（$1 \le t \le 10^7$）；
- **物品种类数**：对应山洞里的草药种类 $m$（$1 \le m \le 10^4$）；
- **物品占用体积（Cost）**：第 $i$ 种草药的采摘耗时 $a_i$；
- **物品蕴含价值（Value）**：第 $i$ 种草药自身的收益价值 $b_i$；
- **决策目标**：在总耗时不超过 $t$ 的约束下，合理规划每种草药的采摘频次，使得总价值最大化。

#### 2. 二维动态规划：状态设计与转移推导

##### （1）状态定义
设二维状态数组 $dp[i][j]$ 表示：
> **只考虑前 $i$ 种草药，在采药总时间上限不超过 $j$ 的情况下，所能获取的最大总价值。**
其中 $0 \le i \le m$，$0 \le j \le t$。

##### （2）朴素转移与三重循环
按照最直观的决策思考，对于第 $i$ 种草药，设我们采摘了 $k$ 株（$k \ge 0$ 且 $k \times a_i \le j$），则状态转移为：
$$dp[i][j] = \max_{k \ge 0} \big(dp[i - 1][j - k \times a_i] + k \times b_i\big)$$
这种朴素递推需要三重循环（枚举种类 $i$、枚举容量 $j$、枚举件数 $k$），时间复杂度为 $\mathcal{O}(m \times t \times \frac{t}{a_i})$，在 $t \le 10^7$ 的极限规模下必然严重超时（TLE）。

##### （3）完全背包的精妙二维转移优化
我们对比展开 $dp[i][j]$ 与 $dp[i][j - a_i]$ 的表达式：
- $dp[i][j] = \max\Big(dp[i-1][j], \; \max_{k \ge 1}(dp[i-1][j - k \cdot a_i] + k \cdot b_i)\Big)$
- 将 $k \ge 1$ 设为 $k' + 1$（其中 $k' \ge 0$），则后半部分变为：
  $$\max_{k' \ge 0}\big(dp[i-1][(j - a_i) - k' \cdot a_i] + k' \cdot b_i\big) + b_i = dp[i][j - a_i] + b_i$$

因此，我们得到了完全背包最经典的**二维无需枚举 $k$ 的状态转移方程**：
$$dp[i][j] = \begin{cases} dp[i - 1][j], & j < a_i \\ \max\big(dp[i - 1][j], \; dp[i][j - a_i] + b_i\big), & j \ge a_i \end{cases}$$

**核心玄机对比**：
- **0/1 背包**选物品时的转移来源是：$dp[\mathbf{i - 1}][j - w_i] + v_i$（来自上一行，表示该物品只能选一次）；
- **完全背包**选物品时的转移来源是：$dp[\mathbf{i}][j - a_i] + b_i$（来自**本行**当前物品，表示已经选过当前物品后，依然可以继续选当前物品）！

#### 3. 空间极致优化：一维滚动数组与“正序遍历”之谜

##### （1）由二维到一维的降维投影
观察上述完全背包转移方程：
$$dp[i][j] = \max\big(dp[i - 1][j], \; dp[i][j - a_i] + b_i\big)$$
计算当前第 $i$ 轮时，要么继承同一列前一轮的值 $dp[i-1][j]$，要么借助**本轮左侧**已计算好的新状态 $dp[i][j - a_i]$。

因此，完全可以省去物品种类维度 $i$，将空间压缩为一维数组 `dp[j]`，表示总时间容量为 $j$ 时的全局最大价值。

##### （2）为什么完全背包必须“正向顺序遍历”？
这是背包动态规划教学中最为关键的对比点：

- **在 0/1 背包中**：
  我们需要保证每件物品只被使用一次。
  为了防止计算 `dp[j]` 时引用的 `dp[j - w]` 被当前物品提前污染，内层循环必须**倒序遍历**（从大到小 $t \to w$），利用旧一轮的历史数据进行转移。

- **在完全背包中**：
  我们**恰恰需要允许**同一种物品被多次使用！
  当我们采用**正序遍历**（从小到大 $a_i \to t$）：
  ```text
  for (int j = a_i; j <= t; ++j) {
      dp[j] = max(dp[j], dp[j - a_i] + b_i);
  }
  ```
  在计算较大的时间容量 $j$ 时，其所引用的较小容量状态 `dp[j - a_i]` 已经在前面的步数中被第 $i$ 种草药更新过了。
  换言之，`dp[j - a_i]` 中可能已经包含了 $1$ 株、$2$ 株乃至多株第 $i$ 种草药的收益；此时再加上一个 $b_i$，完美模拟了“在已经采摘了若干株第 $i$ 种草药的基础上，再多采一株”的连续累加过程！

这种**正序遍历天然支持无限复选**的特性，使得完全背包的一维代码不仅极其简洁，甚至比 0/1 背包在循环结构上还要更直观。

#### 4. 易错点与边界防坑指南（高频踩坑点深度剖析）

在洛谷提交这道题目时，有超过 $60\%$ 的初学者第一次提交会遭遇全红 WA 或 RE，其核心原因集中在以下四个致命坑点：

1. **致命坑点一：数据溢出！必须使用 `long long` 保存价值**
   - 题目中给出的数据范围：$t \le 10^7$，$a_i \ge 1$，$b_i \le 10^4$；
   - 考虑极限测试数据：总时间 $t = 10^7$，某种草药耗时 $a_i = 1$，价值 $b_i = 10^4$。此时可以疯狂采摘 $10^7$ 次，最终收获的总价值高达：
     $$10^7 \times 10^4 = 10^{11}$$
   - 常见的 32 位带符号整型 `int` 的最大上限约为 $2.14 \times 10^9$；
   - $10^{11}$ 远远超出 `int` 的表达极限，如果使用 `int` 存储 `dp` 数组，会发生严重整型有符号溢出（变为巨大的负数），导致输出结果全为负数或错误答案而 0 分。
   - **防坑准则**：`dp` 数组必须声明为 `long long` 类型！

2. **致命坑点二：数组超大，严禁定义在局部栈内存**
   - 本题时间上限 $t \le 10^7$，一维数组长度需达到 $10000005$；
   - 一个长度为 $10^7$ 的 `long long` 数组占用的内存空间为：
     $$10^7 \times 8 \text{ Bytes} \approx 80 \times 10^6 \text{ Bytes} \approx 76.3 \text{ MB}$$
   - 在 Linux/Windows 评测环境下，函数内部的栈内存（Stack）通常默认限制为 $8\text{MB}$ 甚至更小；若将 `long long dp[MAXT]` 写在 `main()` 函数内部，程序一运行就会直接触发**栈溢出段错误（Segmentation Fault / RE）**；
   - **防坑准则**：必须将大数组开在全局变量区（BSS 静态存储区），全局区直接受评测机 $128\text{MB}$ 的堆空间约束，完全在安全范围内。

3. **致命坑点三：输入顺序别看错！先时间 $t$ 后种类 $m$**
   - 第一行输入的是两个整数 $t$ 和 $m$，其中 $t$ 是总时间，$m$ 是草药种类；
   - 在 P1048 中也是类似的变量名，但切勿因为粗心将 $t$ 与 $m$ 颠倒读入。

4. **致命坑点四：循环边界与时间复杂度安全性**
   - 题面特别给出了核心约束保证：$1 \le m \times t \le 10^7$；
   - 正是因为有 $m \times t \le 10^7$ 这一关键上界，两层循环的实际总执行步数 $\sum (t - a_i + 1) \le m \times t \le 10^7$，在现代 CPU（约 $10^8$ 次运算/秒）下耗时仅需 $0.03 \sim 0.05$ 秒，完全不需要常数优化也能瞬间通过。

#### 5. 复杂度深度分析

- **时间复杂度**：
  外层循环遍历 $m$ 种草药，内层循环正序遍历时间容量，步数不超过 $t$。
  总操作次数为：
  $$\mathcal{O}(m \times t)$$
  结合题目限定的 $m \times t \le 10^7$，在 $1.00\text{s}$ 的时间限制下余裕极大，执行极其飞速。
- **空间复杂度**：
  采用一维滚动数组后，空间复杂度为：
  $$\mathcal{O}(t)$$
  占用内存约为 $76.3\text{MB}$，完全满足题目给定的空间要求（小于通常的 $128\text{MB}$）。

### 完整参考代码 (C++11)

```cpp
/**
 * Problem: luogu-P1616 疯狂的采药
 * Algorithm: 基础动态规划 (完全背包问题 · 一维滚动数组正序优化)
 * Standard: C++11 (CCF GESP / CSP-J 官方规范)
 * Author: OneCoder
 */

#include <iostream>
#include <algorithm>

using namespace std;

// 最大时间上限 t <= 10^7，全局开辟数组预留安全裕量
const int MAXT = 10000005;

// 一维滚动数组：dp[j] 表示在总耗时不超过 j 的情况下，能采得的草药最大总价值
// 易错提示：极限情况下总价值可达 10^7 * 10^4 = 10^11，超出 32 位 int 范围，必须使用 long long
long long dp[MAXT];

int main() {
    int t, m;
    // 读入能够用来采药的总时间 t 和山洞里的草药种类数 m
    cin >> t >> m;

    // 逐一处理每种草药（外层循环遍历物品种类）
    for (int i = 1; i <= m; ++i) {
        int cost, val;
        // 读入当前草药采摘耗时 cost 和其蕴含价值 val
        cin >> cost >> val;

        // 完全背包核心：正序遍历时间容量 j（从当前耗时 cost 到总时间 t）
        // 正序遍历能让较小容量的状态在当前这轮中先被更新
        // 当更新到较大容量时，所引用的 dp[j - cost] 已经包含了选取当前物品的收益
        // 这天然实现了同一种草药可以无限制地疯狂重复采摘
        for (int j = cost; j <= t; ++j) {
            dp[j] = max(dp[j], dp[j - cost] + val);
        }
    }

    // 最终 dp[t] 即为在规定的总时间 t 内能够采得的最大草药总价值
    cout << dp[t] << "\n";

    return 0;
}
```
