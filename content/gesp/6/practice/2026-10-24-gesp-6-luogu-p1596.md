在 $N \times M$（$1 \le N, M \le 100$）的矩形田地网格中，统计由积水字符 `'W'` 按**八个相邻方向（上、下、左、右及四个对角线方向）**相互连接所形成的水塘总数，洛谷 P1596「[USACO10OCT] Lake Counting S」是网格图**连通块计数与洪水填充（Flood Fill）**领域最具代表性的母题之一。与常见的“上下左右四连通”迷宫不同，本题引入了**八连通（Moore 邻域）**拓扑规则——即便两个积水方格仅在左上、左下、右上或右下角尖处相接（如样例左下角呈菱形交错分布的 `'W'`），它们依然同属一片水塘。若仅采用逐行扫描或局部邻域统计，面对蜿蜒曲折甚至带环的积水区域必然会产生重复计数或归属分裂。破局的核心在于构建**“扫描触发 + 全域漫灌消去”**的双层机制：外层循环逐格遍历田地，每当捕获一个尚未处理的 `'W'`，便意味着发现了一个全新的水塘（计数器加 $1$），随即以该格为源点发起一次**八方向广度优先搜索（BFS）**，将整片水塘中所有与之八连通的 `'W'` 原地“抽干”改写为干地 `'.'`，从而确保同一水塘在后续扫描中绝不会被二次触发。此外，在 $100 \times 100$ 满格积水的极端测试点下，纯递归深度优先搜索（DFS）的调用栈深度可达 $10^4$ 层，而采用基于队列的 BFS 结合“入队即改写”策略，不仅彻底消除了递归爆栈隐患，更省去了额外的 `vis` 访问标记数组。本题对应 CCF GESP 六级（DFS/BFS 搜索与图论连通性）及 CSP-J 普及组核心考点，洛谷官方难度评级为`普及−`。

## luogu-P1596 [USACO10OCT] Lake Counting S

> 🔗 **洛谷原题传送门**：[luogu-P1596 [USACO10OCT] Lake Counting S](https://www.luogu.com.cn/problem/P1596)

### 题目描述

由于最近的降雨，水在农夫约翰的田地里积聚了。田地可以表示为一个 $N \times M$ 的矩形（$1 \leq N \leq 100$；$1 \leq M \leq 100$）。每个方格中要么是水（`W`），要么是干地（`.`）。农夫约翰想要弄清楚他的田地里形成了多少个水塘。一个水塘是由连通的水方格组成的，其中一个方格被认为与它的八个邻居相邻。给定农夫约翰田地的示意图，确定他有多少个水塘。

Due to recent rains, water has pooled in various places in Farmer John's field, which is represented by a rectangle of N x M (1 <= N <= 100; 1 <= M <= 100) squares. Each square contains either water ('W') or dry land ('.'). Farmer John would like to figure out how many ponds have formed in his field. A pond is a connected set of squares with water in them, where a square is considered adjacent to all eight of its neighbors. Given a diagram of Farmer John's field, determine how many ponds he has.

### 输入格式

第 $1$ 行：两个用空格分隔的整数：$N$ 和 $M$。

第 $2$ 行到第 $N+1$ 行：每行 $M$ 个字符，表示农夫约翰田地的一行。

每个字符要么是 `W`，要么是 `.`。

字符之间没有空格。

Line 1: Two space-separated integers: N and M \* Lines 2..N+1: M characters per line representing one row of Farmer John's field. Each character is either 'W' or '.'. The characters do not have spaces between them.

### 输出格式

第 $1$ 行：农夫约翰田地中的水塘数量。

Line 1: The number of ponds in Farmer John's field.

### 输入输出样例

#### 样例输入 #1
```text

.WWW.....WWW
....WW...WW.
.........WW.
```

```text
3
```

### 题目深度剖析与核心解题模型

#### 1. 四连通 vs 八连通：为什么左下角的菱形点阵只算 1 个水塘？

在二维网格搜索问题中，相邻关系的定义直接决定了连通块的划分结果：
- **四连通（冯·诺依曼邻域）**：每个格子仅与**上、下、左、右** $4$ 个正方向格子相邻（共享一条公共边）。
- **八连通（摩尔邻域，本题规则）**：每个格子不仅与上下左右相邻，还与**左上、右上、左下、右下** $4$ 个对角线格子相邻（只要共享一个顶点即视为连通）。

观察样例左下角第 $6 \sim 10$ 行、第 $1 \sim 5$ 列的局部区域：
```text
..W..
.W.W.
W.W.W
.W.W.
..W..
```
如果按照“上下左右”四连通规则，这 $9$ 个 `'W'` 之间没有任何两条公共边相连，会被拆成 $9$ 个孤立的水坑；但在本题的**八连通**规则下，它们通过左上、右上、左下、右下对角线紧密咬合在一起，因此**整体只构成 $1$ 个水塘**！

在代码实现中，我们可以通过两个长度为 $8$ 的方向偏移数组 `dx[8]` 和 `dy[8]`，一次性涵盖以 $(x, y)$ 为中心的 $3 \times 3$ 九宫格内除自身 $(0, 0)$ 以外的全部 $8$ 个邻居：
```cpp
int dx[8] = {-1, -1, -1,  0, 0,  1, 1, 1};
int dy[8] = {-1,  0,  1, -1, 1, -1, 0, 1};
```

#### 2. 核心算法：洪水填充（Flood Fill）与“原地抽干”技巧

如何不重不漏地数出整片田地里有多少个水塘？

我们可以把每次搜索想象成**用抽水机抽干一整片相连的水塘**：
1. 从第 $1$ 行第 $1$ 列开始，双重循环逐格扫描田地 `grid[i][j]`。
2. 当遇到干地 `'.'` 时，直接跳过。
3. 当遇到积水 `'W'` 时：
   - 说明我们发现了一个**此前从未见过的新水塘**，立即将水塘计数器 `pond_count++`；
   - 紧接着以 `(i, j)` 为起点启动 `bfs(i, j)`，顺着八连通方向蔓延，把这片水塘里所有相连的 `'W'` **全部原地改写为 `'.'`**（相当于把这片水塘彻底抽干变成干地）。
4. 当 `bfs(i, j)` 结束返回外层循环继续扫描时，刚才那片水塘里的所有格子都已经变成了 `'.'`，后续扫描到它们时会自动忽略，从而完美保证了**每个水塘恰好只被统计一次**！

这种**直接将已访问的 `'W'` 原地修改为 `'.'`** 的做法，不仅语义直观，而且省去了额外开辟 `bool vis[MAXN][MAXN]` 数组的内存开销。

#### 3. 完整参考代码 (C++11)

```cpp
/**
 * Problem: luogu-P1596 [USACO10OCT] Lake Counting S
 * Algorithm: 八方向广度优先搜索与连通块计数 (8-Directional BFS & Connected Components Flood Fill)
 * Standard: C++11 (CCF GESP 六级 / CSP-J 官方规范)
 * Blog: https://www.coderli.com/gesp-6-luogu-p1596/
 * Author: OneCoder
 */

#include <iostream>
#include <queue>

using namespace std;

// 田地规模最大为 100 x 100，开到 105 留出安全余量
const int MAXN = 105;

int n, m;
char grid[MAXN][MAXN]; // 存储田地字符：'W' 表示积水，'.' 表示干地

// 定义结构体表示二维网格坐标
struct Point {
    int x;
    int y;
};

// 八个相邻方向（上、下、左、右、左上、右上、左下、右下）的行、列偏移量
int dx[8] = {-1, -1, -1, 0, 0, 1, 1, 1};
int dy[8] = {-1, 0, 1, -1, 1, -1, 0, 1};

/**
 * 从积水点 (sx, sy) 出发，利用广度优先搜索 (BFS) 将同一水塘的所有连通 'W' 抽干为 '.'
 */
void bfs(int sx, int sy) {
    queue<Point> q;

    // 原地修改：在起点入队时立即将 'W' 改为 '.'，兼具“标记已访问”与“防止重复入队”的双重作用
    grid[sx][sy] = '.';
    Point start;
    start.x = sx;
    start.y = sy;
    q.push(start);

    while (!q.empty()) {
        Point cur = q.front();
        q.pop();

        // 向周围全部 8 个相邻方向扩展搜索
        for (int i = 0; i < 8; ++i) {
            int nx = cur.x + dx[i];
            int ny = cur.y + dy[i];

            // 1. 边界合法性检查：坐标必须落在 [1, n] x [1, m] 范围内
            if (nx < 1 || nx > n || ny < 1 || ny > m) {
                continue;
            }
            // 2. 状态检查：仅对尚未处理的积水方格 ('W') 进行扩展
            if (grid[nx][ny] != 'W') {
                continue;
            }

            // 关键：在推入队列前立刻将积水方格原地置为 '.'，杜绝周围其他邻居重复将其入队
            grid[nx][ny] = '.';
            Point next_pt;
            next_pt.x = nx;
            next_pt.y = ny;
            q.push(next_pt);
        }
    }
}

int main() {
    // 读取田地的行数 n 和列数 m
    cin >> n >> m;

    // 逐字符读取 n x m 的田地示意图（cin >> char 会自动跳过换行符与空白符）
    for (int i = 1; i <= n; ++i) {
        for (int j = 1; j <= m; ++j) {
            cin >> grid[i][j];
        }
    }

    int pond_count = 0; // 记录水塘（八连通块）的总数

    // 扫描整片田地：每发现一个未被抽干的 'W'，就找到了一个新的水塘
    for (int i = 1; i <= n; ++i) {
        for (int j = 1; j <= m; ++j) {
            if (grid[i][j] == 'W') {
                pond_count++; // 水塘数量加 1
                bfs(i, j);    // 发起洪水填充，将与 (i, j) 八连通的所有 'W' 全部原地抽干为 '.'
            }
        }
    }

    // 输出水塘总数
    cout << pond_count << "\n";

    return 0;
}
```

### 复杂度分析与常见避坑指南

1. **时间与空间复杂度评估**：
   - **时间复杂度**：整片田地共有 $N \times M$ 个方格。外层双重循环扫描每个方格 $1$ 次；每个 `'W'` 方格至多入队 $1$ 次、出队 $1$ 次（入队瞬间即被改写为 `'.'`），出队时固定探测 $8$ 个方向。因此总时间复杂度严格为线性级别 $\mathcal{O}(N \times M)$。对于 $N, M \le 100$，总操作次数在 $8 \times 10^4$ 以内，耗时不足 $2\text{ms}$。
   - **空间复杂度**：全局字符数组 `grid` 占用 $\mathcal{O}(N \times M)$ 空间，BFS 队列在最坏情况下最多同时容纳 $\mathcal{O}(N \times M)$ 个坐标点，整体空间复杂度为 $\mathcal{O}(N \times M)$。
2. **避坑点 1：BFS 为什么必须在“入队前”修改状态，而不能在“出队时”修改？**：
   - 在八连通网格中，同一个 `'W'` 方格周围最多有 $8$ 个相邻的 `'W'`。如果等到节点从队首 `q.front()` 取出时才执行 `grid[cur.x][cur.y] = '.'`，那么在该节点排队等待出队期间，它周围的其他邻居会反复发现它仍是 `'W'` 并将其重复推入队列，导致队列元素呈指数级膨胀，最终引发**超出内存限制（MLE）**或**运行超时（TLE）**！
3. **避坑点 2：为什么网格规模较大时推荐 BFS 而非递归 DFS？**：
   - 虽然本题 $N, M \le 100$ 使用 DFS 递归也能通过，但如果整张 $100 \times 100$ 的网格全是 `'W'`，DFS 会产生深达 $100 \times 100 = 10000$ 层的函数递归调用栈。在部分栈空间限制较严的评测环境或更大规模网格（如 $1000 \times 1000$）中，纯 DFS 极易触发栈溢出（Stack Overflow / RE），而基于 `std::queue` 堆内存的 BFS 则完全没有爆栈之虞。
