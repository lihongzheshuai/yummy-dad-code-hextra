在 GESP 六级与 CSP-J/S 初赛考场上，有三大“几乎年年露面、看似送分却总有人阴沟翻船”的线性结构经典题型：**合法出栈序列判定**、**循环队列指针与容量计算**、**前/中/后缀表达式转换与求值**。很多同学碰到出栈序列题，只能拿草稿纸对 4 个选项逐一硬画入栈出栈过程，既耗时又容易漏看一步；碰到循环队列回绕（`rear < front`），直接套 `(rear - front) % M` 算出了负数，或忘记“牺牲 1 格判满”把容量多算了 1；碰到中缀转前缀、后缀，一遇到 `-`、`/` 同级运算或嵌套括号就乱了顺序，甚至写后缀求值代码时把先弹出的右操作数当成左操作数，把 `8 - 3` 算成了 `-5`。本文直接从**栈（LIFO）**与**队列（FIFO）**的底层操作约束切入，打通“3-1-2 禁令”秒判法则、循环队列取模公式、手算加括号转换大法，以及标准 C++11 栈求值代码实现。

## 🎯 考纲锚点与核心痛点

> 📍 **对应考点**：掌握栈（LIFO）与队列（FIFO）的逻辑特性与操作约束，精通合法出栈序列的“大数后小数必逆序”秒判法则与卡特兰数计数、循环队列判空/判满/求长度取模公式、中缀表达式转前缀（波兰式）与后缀（逆波兰式）的手算加括号法及栈求值模拟。
> 🎯 **适用等级**：`GESP 六级考点 | CSP-J/S 初赛/复赛必考`

在历年 GESP 六级认证与 CSP-J/S 初复赛中，考生在这一专题上丢分高度集中在三大痛点：
1. **出栈序列靠死模拟耗尽时间**：对 5~6 个元素的 4 个选项逐个手画栈变化，不仅拖慢节奏，还极易在草稿涂改中把合法项看错；
2. **循环队列的“少存 1 格”与“回绕求长”频频踩雷**：分不清 `front`（队首）与 `rear`（队尾后一空位）的指向约定，误以为长度为 `M` 的数组能装满 `M` 个元素，算长度时漏写 `+ M` 导致 C++ 负数取模出错；
3. **表达式转换忽略结合性、代码求值写反操作数**：手算 `a - b - c` 转后缀时把左结合错当右结合；写后缀求值栈代码时忘记“后入先出”，直接拿首次 `top()` 减第二次 `top()`，造成减法和除法全盘反转。

## 🧠 一、 核心原理深度拆解（有理论）

### 1. 栈（LIFO）与合法出栈序列的秒判定理（“3-1-2 禁令”）

**栈（Stack）**是一种只允许在同一端（称为**栈顶 `top`**）进行插入（`push`）和删除（`pop`）的受限线性表，遵循严格的后进先出（**LIFO**, Last-In First-Out）原则；**队列（Queue）**则是只允许在一端（**队尾 `rear`**）插入、在另一端（**队首 `front`**）删除的线性表，遵循严格的先进先出（**FIFO**, First-In First-Out）原则。两者所有核心操作（入、出、查端元素）的时间复杂度均为 $O(1)$。

```text
========================================================================
【栈（LIFO：后进先出） vs 队列（FIFO：先进先出）结构对照】

  栈（如步枪弹夹 / 叠盘子）            队列（如食堂排队打饭）
       push ↓   ↑ pop
         +-------+                  出队 pop                  入队 push
         |   3   | ← top (栈顶)       ◄───  [ 1 | 2 | 3 |   ]  ◄───
         +-------+                            ↑           ↑
         |   2   |                          front        rear
         +-------+                          (队首)    (队尾后一空位)
         |   1   | ← bottom (栈底)
         +-------+
  压入顺序：1 → 2 → 3                入队顺序：1 → 2 → 3
  弹出顺序：3 → 2 → 1（反序）        出队顺序：1 → 2 → 3（保序）
========================================================================
```

**核心定理（不合法出栈序列秒判法则）**：
假设元素按 `1, 2, ..., n` 的递增顺序依次入栈，且入栈过程中任意时刻只要栈非空都允许出栈。考察任意一个已经出栈的元素 `x`：
1. 在 `x` 能够出栈的那一瞬间，所有比 `x` 小的元素（`1, 2, ..., x - 1`）**必然都已经入过栈**；
2. 其中一部分可能早在 `x` 之前就已经出栈了；而**剩下的尚未出栈的小元素**，此刻全部老老实实地压在 `x` 下方的栈里，且**自栈底向栈顶严格递增**；
3. 根据栈“后进先出”的物理铁律，这批压在下面的小元素将来弹出时，**必须按照自顶向下的顺序（严格递减）依次出栈**！

由此推导出考场最强推论——**“3-1-2 禁令”**：
在合法出栈序列中，**绝对不可能**存在三个位置满足“左 → 中 → 右”排列的元素 `a ... b ... c`，使得 `a > c > b`（即大数 `a` 出栈之后，两个比 `a` 小的数 `b`、`c` 却按**从小到大**的顺序先后出栈）。

> 💡 **考场黄金法则 1（出栈序列 3 秒秒杀术）**：按 `1 ~ n` 顺序入栈时，盯住出栈序列中的每一个数 `x`，它右边所有比 `x` 小的数**必须严格递减**！只要扫到一组“大 → 小 → 中”（如 `4 ... 1 ... 2`），立刻判定该序列**不合法**！

**附：CSP 初赛高频计数结论（卡特兰数 Catalan Number）**：
当 `n` 个不同元素按固定顺序入栈时，所有**合法出栈序列的总方案数**恰好等于第 $n$ 项卡特兰数：

$$C_n = \frac{1}{n + 1}\binom{2n}{n}$$

考场直接背诵前 5 项即可秒杀计数选择题：
* $n = 1 \Rightarrow C_1 = 1$
* $n = 2 \Rightarrow C_2 = 2$
* $n = 3 \Rightarrow C_3 = 5$（`1,2,3` 的 6 种全排列中唯独 `3,1,2` 不合法，故 $6 - 1 = 5$）
* $n = 4 \Rightarrow C_4 = 14$
* $n = 5 \Rightarrow C_5 = 42$

### 2. 队列（FIFO）与循环队列的取模闭环公式

用普通一维数组 `q[0..M-1]` 模拟队列时，每次入队执行 `rear++`，每次出队执行 `front++`。随着不断出队入队，`front` 和 `rear` 一路向右移动，很快就会出现 `rear == M` 无法再入队、但数组前端 `0 .. front - 1` 明明空着一大片的尴尬现象——这就是考纲高频概念**“假溢出”（False Overflow）**。

解决假溢出的标准方案是将数组首尾相接，利用取模运算 `% M` 构成**循环队列（Circular Queue）**。在 GESP 六级与 CSP 初赛中，最通用的指针约定为：
* `front` 指向当前**队首元素**的下标；
* `rear` 指向当前**队尾元素的下一个空位**下标（左闭右开区间 `[front, rear)`）；
* 初始状态：`front = 0, rear = 0`。

**为什么要故意空出 1 个存储单元不放数据？**
如果允许把 `M` 个格子全部填满，那么当最后一个元素入队、`rear = (rear + 1) % M` 追上 `front` 时，同样会出现 `front == rear`——此时仅凭 `front` 和 `rear` 根本分不清队列是**全空**还是**全满**！因此，经典循环队列规定**牺牲 1 个单元作为哨兵位**（最大有效容量为 `M - 1`），彻底消除二义性：

```text
========================================================================
【循环队列环形内存图（数组长度 M = 6，最多存 M - 1 = 5 个元素）】

               idx 0       idx 1       idx 2
             +-------+   +-------+   +-------+
             |  50   | → |  60   | → | (空)  | ← rear = 2 (下一个写入位)
             +-------+   +-------+   +-------+
                 ↑                       ↓
             +-------+   +-------+   +-------+
             |  40   | ← |  30   | ← | (哨兵)|   idx 3 若也填入，rear 变 3，
             +-------+   +-------+   +-------+   再填 idx 3 则 (3+1)%6 == 4 判满！
               idx 5       idx 4       idx 3
                             ↑
                         front = 4 (当前队首)

  当前元素：q[4]=30, q[5]=40, q[0]=50, q[1]=60（共 4 个）
  长度公式：(rear - front + M) % M = (2 - 4 + 6) % 6 = 4 ✅
========================================================================
```

**循环队列五大核心公式（数组容量 `M`，牺牲 1 格约定）**：
* **最大可存元素数**：`M - 1`
* **队空判定**：`front == rear`
* **队满判定**：`(rear + 1) % M == front`
* **入队 / 出队推进**：入队 `q[rear] = x; rear = (rear + 1) % M;`；出队 `front = (front + 1) % M;`
* **当前元素个数**：`len = (rear - front + M) % M`（回绕时 `rear < front`，加 `M` 保证非负）

### 3. 前缀（波兰式）、中缀与后缀（逆波兰式）表达式——手算“加括号大法”

人类习惯书写**中缀表达式**（运算符夹在两个操作数中间，如 `(a + b) * c - d / e`），但它极度依赖括号与运算符优先级规则；而计算机编译器更喜欢**前缀表达式（波兰式，Prefix）**与**后缀表达式（逆波兰式，Postfix）**——它们**完全不需要任何括号**，运算顺序天然唯一确定！

从数据结构本质看，任意算术表达式都可以画成一棵**表达式二叉树**（叶子节点是操作数，内部节点是运算符）：
* **前缀表达式（波兰式）** = 表达式树的**前序遍历**（根 → 左 → 右）；
* **中缀表达式** = 表达式树的**中序遍历**（左 → 根 → 右，需按优先级加括号）；
* **后缀表达式（逆波兰式）** = 表达式树的**后序遍历**（左 → 右 → 根）。

在初赛草稿纸上，不需要死背繁琐的栈转换表，直接用零失误的**“完全加括号大法”**三步即可 100% 拿满分：
1. **第一步（补全所有括号）**：严格遵守“先括号内、次 `* /`、后 `+ -`、同级从左到右”的顺序，把**每一次二元运算**都用一对独立括号 `(...)` 严严实实包起来；
2. **第二步（移动运算符）**：
   * 转**前缀**：把每一对括号里的运算符移到它所属的**左括号 `(` 外侧**；
   * 转**后缀**：把每一对括号里的运算符移到它所属的**右括号 `)` 外侧**；
3. **第三步（拆掉全部括号）**：把所有 `(` 和 `)` 全部删干净，剩下的字符序列就是最终答案！

以中缀表达式 `(a + b) * c - d / e` 为例，对照表达式二叉树与加括号大法：

```text
========================================================================
【表达式二叉树 vs 完全加括号大法演示：(a + b) * c - d / e】

        (-)               第一步·补全括号：
       /   \              ( ( (a + b) * c ) - (d / e) )
     (*)   (/)
    /   \  /  \           第二步·转前缀（运算符移到对应左括号外）：
  (+)   c d    e          - ( * ( + (a b) c ) / (d e) )
  / \                     第三步·去括号得前缀：- * + a b c / d e
 a   b
                          第二步·转后缀（运算符移到对应右括号外）：
                          ( ( (a b) + c ) * (d e) / ) -
                          第三步·去括号得后缀：a b + c * d e / -
========================================================================
```

注意观察一个关键规律：无论前缀、中缀还是后缀，**所有操作数的相对先后顺序（`a b c d e`）永远保持不变**，变化的仅仅是运算符的出场位置！

> 💡 **考场黄金法则 2（表达式转换与后缀栈求值口诀）**：手算中缀转前/后缀紧扣“**补全括号 → 前移左/后移右 → 拆括号**”；用栈计算后缀表达式时从左往右扫描，**遇数入栈、遇符弹俩**，务必牢记**先弹出的是右操作数 `b`，后弹出的是左操作数 `a`**，计算 `a op b` 后压回栈顶！

## 🔍 二、 具象代码与数据推演（有举例）

### 实例 1：栈模拟判定出栈序列合法性（19 行核心 C++11 程序）

给定入栈序列 `1, 2, ..., n` 以及长度为 `n` 的目标序列 `b[0..n-1]`，利用 `std::stack<int>` 贪心匹配：每压入一个新数 `x`，就尽可能连续弹出所有与当前目标 `b[pos]` 相等的栈顶元素。循环结束后，若栈为空则说明全部成功匹配（合法），否则不合法。

```cpp
#include <iostream>
#include <stack>
using namespace std;

int main() {
    int n, b[105];
    cin >> n;
    for (int i = 0; i < n; i++) cin >> b[i];
    stack<int> st;
    int pos = 0;
    for (int x = 1; x <= n; x++) {
        st.push(x);
        while (pos < n && !st.empty() && st.top() == b[pos]) {
            st.pop();
            pos++;
        }
    }
    cout << (st.empty() ? "Yes" : "No") << "\n";
    return 0;
}
```

**分步内存状态推演（`n = 4`）**：

* **场景 A：输入目标序列 `b = [2, 4, 3, 1]`（合法）**
  * `x = 1` 入栈：栈 `[1]`，栈顶 `1 != b[0](2)` → 停，此时 `pos = 0`；
  * `x = 2` 入栈：栈 `[1, 2]`，栈顶 `2 == b[0](2)` → 弹出 `2`，`pos = 1`；栈顶 `1 != b[1](4)` → 停，栈 `[1]`；
  * `x = 3` 入栈：栈 `[1, 3]`，栈顶 `3 != b[1](4)` → 停，此时 `pos = 1`；
  * `x = 4` 入栈：栈 `[1, 3, 4]` → 连续命中 `b[1]=4`、`b[2]=3`、`b[3]=1`，全部弹出，`pos = 4`；
  * 循环结束，`st.empty()` 为真 → 输出 **`Yes`**。

* **场景 B：输入目标序列 `b = [3, 1, 2, 4]`（触犯“3-1-2 禁令”，非法）**
  * `x = 1, 2` 入栈：栈 `[1, 2]`，均不等于 `b[0](3)`；
  * `x = 3` 入栈：栈 `[1, 2, 3]`，命中 `b[0]=3` → 弹出 `3`，`pos = 1`；此时目标变成 `b[1] = 1`，但栈顶是 `2`（`1` 被死死压在 `2` 下面！），`while` 被迫中止；
  * `x = 4` 入栈：栈 `[1, 2, 4]`，栈顶 `4 != b[1](1)`；
  * 循环结束，栈内残余 `[1, 2, 4]` 非空 → 输出 **`No`**。

### 实例 2：循环队列手动数组回绕推演（23 行 C++11 程序）

下面这段数组模拟循环队列的程序（数组大小 `M = 5`，最大有效容量 `4`）完整演示了 `rear` 跨越数组末尾回绕到下标 `0` 和 `1` 的真实内存演变：

```cpp
#include <iostream>
using namespace std;

const int M = 5;
int q[M], front = 0, rear = 0;

void pushVal(int x) {
    if ((rear + 1) % M == front) return;
    q[rear] = x;
    rear = (rear + 1) % M;
}
void popVal() {
    if (front == rear) return;
    front = (front + 1) % M;
}

int main() {
    pushVal(10); pushVal(20); pushVal(30); pushVal(40);
    popVal(); popVal();
    pushVal(50); pushVal(60);
    int len = (rear - front + M) % M;
    cout << "front=" << front << " rear=" << rear << " len=" << len << "\n";
    cout << "full=" << ((rear + 1) % M == front) << " head=" << q[front] << "\n";
    return 0;
}
```

**分步数组与指针变化推演**：
1. 连续入队 `10, 20, 30, 40` 后：`q = [10, 20, 30, 40, _]`，`front = 0, rear = 4`。此时 `(4 + 1) % 5 == 0 == front`，队列已满（存了 `4` 个元素，下标 `4` 为哨兵空位）；
2. 连续出队 2 次（弹出 `10, 20`）：`front` 从 `0` 推进到 `2`，此时队中有效元素为 `q[2]=30`、`q[3]=40`（`rear = 4` 不变）；
3. 入队 `50`：写入 `q[4] = 50`，`rear = (4 + 1) % 5 = 0`（**发生首次回绕**！）；
4. 入队 `60`：写入 `q[0] = 60`，`rear = (0 + 1) % 5 = 1`。此时 `q = [60, _, 30, 40, 50]`，有效区间跨越数组边界：`q[2] → q[3] → q[4] → q[0]`；
5. 计算当前状态：`len = (1 - 2 + 5) % 5 = 4`，`(1 + 1) % 5 == 2 == front`（`full = 1`），队首 `q[2] = 30`。

**程序实际运行输出**：
```text
front=2 rear=1 len=4
full=1 head=30
```

## ⚡ 三、 考场高频避坑指南（正误辨析）

### ❌ 易错点 1：STL `stack` / `queue` 漏判空直接 `top()` / `pop()`，或把 `pop()` 当返回值用
* **错误代码**：
  ```cpp
  int x = st.pop();                 // 坑 1：编译错误 CE！STL 的 pop() 返回类型是 void
  while (st.top() == b[pos]) {      // 坑 2：栈空时调用 st.top() 直接段错误 RE！
      st.pop();
  }
  ```
* **为什么错**：
  1. C++ STL 中 `stack::pop()` 和 `queue::pop()` 只负责删除元素，**不返回任何值（`void`）**；
  2. 对空栈调用 `top()` / `pop()` 或对空队列调用 `front()` / `pop()` 属于未定义行为（UB），在 Linux 评测机上会瞬间触发段错误（Runtime Error）；
  3. 即使写了判空，也必须把 `!st.empty()` 写在 `&&` **左侧**利用逻辑短路保护右侧的 `st.top()`。
* **正确规范**：取值与弹栈严格分两步，且永远先判 `!empty()`：
  ```cpp
  while (!st.empty() && st.top() == b[pos]) {
      int x = st.top();
      st.pop();
      pos++;
  }
  ```

### ❌ 易错点 2：循环队列算长度漏加 `M` 变成负数，或误以为数组长度 `M` 能存 `M` 个元素
* **错误代码**：
  ```cpp
  int len = (rear - front) % M; // 当 M=5, front=2, rear=1 时，C++ 算出 (-1) % 5 == -1！
  ```
* **为什么错**：
  1. 在 C++ 中，负数取模的结果保留被除数的负号（`-1 % 5 == -1`），一旦循环队列发生回绕（`rear < front`），漏写 `+ M` 会直接算出负长度；
  2. 在常见的“无额外计数变量、用 `(rear + 1) % M == front` 判满”实现中，长度为 `M` 的数组**最多只能存放 `M - 1` 个元素**（只有当题目明确额外维护了元素计数器 `size` 或读写标记 `tag` 时，才能存满 `M` 个）。
* **正确规范**：求长度一律写成 **`(rear - front + M) % M`**；做初赛选择题时，先看清题目是否额外定义了 `count` 变量，若仅靠 `front` 和 `rear` 判满，最大容量必为 `M - 1`。

### ❌ 易错点 3：后缀求值写反左右操作数顺序，或中缀转后缀把 `>=` 错写成 `>`
* **错误代码**：
  ```cpp
  // 坑 1：后缀求值写反操作数（遇到 "8 3 -" 时，先弹 3 后弹 8，却算成了 3 - 8 = -5！）
  long long a = vals.top(); vals.pop();
  long long b = vals.top(); vals.pop();
  if (op == '-') vals.push(a - b);

  // 坑 2：中缀转后缀写成严格大于 >，导致 "10 - 3 - 2" 变成 "10 3 2 - -"（算成了 10-(3-2)=9！）
  while (!ops.empty() && ops.top() != '(' && prec(ops.top()) > prec(c)) ...
  ```
* **为什么错**：
  1. 后缀表达式中左操作数先入栈（压在下面）、右操作数后入栈（浮在栈顶），因此**第一次 `top()` 拿到的是右操作数 `b`，第二次 `top()` 才是左操作数 `a`**，减法与除法绝不满足交换律，顺序一反答案全错；
  2. 加减乘除均为**左结合运算符**（`10 - 3 - 2` 必须先算 `10 - 3`）。用调度场算法（Shunting-Yard）转后缀时，当栈顶运算符优先级**大于或等于（`>=`）**当前扫描到的运算符 `c` 时，说明栈顶符号在左边且不比 `c` 弱，必须先弹出输出！
* **正确规范**：后缀求值严格按“**先弹 `b`、后弹 `a`、算 `a op b`**”；左结合运算符中缀转后缀循环条件严格写 **`prec(ops.top()) >= prec(c)`**。

### 【例题 1 · 单选题】（GESP 六级 / CSP-J 初赛高频考点：合法出栈序列秒判）

**题目**：一个初始为空的栈，若将 5 个元素按 `1, 2, 3, 4, 5` 的顺序依次入栈，且在入栈过程中任意时刻均允许出栈，则下列四个序列中，**不可能**作为出栈序列的是（ ）。

* **A.** `2, 4, 3, 5, 1`
* **B.** `3, 2, 5, 4, 1`
* **C.** `4, 3, 5, 1, 2`
* **D.** `1, 4, 3, 2, 5`

**🔍 答案与逐项排除解析**：
* **正确答案**：**C**
* **解析过程（先用“3-1-2 禁令”3 秒秒杀，再用进出栈验证）**：
  1. **锁定 C（`4, 3, 5, 1, 2`）**：盯住已经出栈的 `4`，排在它右边且比 `4` 小的元素依次是 `3, 1, 2`——其中 `1` 排在 `2` 前面（递增！构成 `4 ... 1 ... 2` 的“大 → 小 → 中”违规三元组）。从物理栈状态看：`4` 出栈时，`1, 2, 3` 早已按自底向顶 `[1, 2, 3]` 压在栈内，`3` 弹出后栈中 `2` 死死压在 `1` 上方，绝对不可能让 `1` 先于 `2` 出栈！故 **C 不可能**；
  2. **排除 A（`2, 4, 3, 5, 1`）**：每个数右侧比它小的子序列均严格递减（`2` 后只有 `1`；`4` 后有 `3, 1`；`5` 后只有 `1`）。合法操作：`push 1, push 2, pop 2, push 3, push 4, pop 4, pop 3, push 5, pop 5, pop 1`；
  3. **排除 B（`3, 2, 5, 4, 1`）**：`3` 后较小元素为 `2, 1`（递减），`5` 后较小元素为 `4, 1`（递减）。合法操作：`push 1,2,3, pop 3, pop 2, push 4,5, pop 5, pop 4, pop 1`；
  4. **排除 D（`1, 4, 3, 2, 5`）**：`4` 后较小元素为 `3, 2`（递减）。合法操作：`push 1, pop 1, push 2,3,4, pop 4,3,2, push 5, pop 5`。
  5. 综合确认选 **C**。

### 【例题 2 · 判断题】（GESP 六级核心概念辨析：循环队列回绕元素计数与剩余容量）

**题目**：在一个用长度为 `8` 的一维数组 `q[0..7]` 实现的循环队列中，约定 `front` 指向队首元素、`rear` 指向队尾元素的下一个空位，以 `front == rear` 判空、`(rear + 1) % 8 == front` 判满。若初始时 `front = 0, rear = 0`，经过若干次合法入队与出队操作后，当前观测到 `front = 5, rear = 2`，则此时队列中共有 `3` 个元素，且最多还能再入队 `4` 个元素。（ ）

**🔍 答案与反例证明**：
* **结论**：**错误（×）**
* **严谨计算与逐格定位证明**：
  1. 本题数组长度 `M = 8`，采用牺牲 1 格哨兵位判满策略，因此队列最大有效容量为 `M - 1 = 7` 个元素；
  2. 当前 `front = 5, rear = 2`（已发生跨边界回绕），代入标准长度公式：
     $$\text{len} = (\text{rear} - \text{front} + M) \bmod M = (2 - 5 + 8) \bmod 8 = 5$$
     逐一核对有效下标：`q[5]`、`q[6]`、`q[7]`、`q[0]`、`q[1]`，共 **`5` 个元素**（题目中的 `3` 是错用 `|2 - 5| = 3` 算出的典型干扰坑）；
  3. 队列最多还能再入队 `7 - 5 = 2` 个元素：分别写入 `q[2]` 与 `q[3]` 后，`rear` 推进到 `4`，此时 `(4 + 1) % 8 == 5 == front` 触发队满，`q[4]` 作为哨兵空位不可再写入。因此当前应为 `5` 个元素、最多再入队 `2` 个，原命题两处数值均错误。

### 【例题 3 · 微代码实战】（GESP 六级 / CSP-J 复赛经典模板：中缀表达式转后缀并求值）

**题目描述**：输入一个不含空格的合法中缀算术表达式字符串 `s`（长度不超过 `1000`），表达式中只包含非负整数、四则运算符 `+`、`-`、`*`、`/` 以及圆括号 `(`、`)`，除法按 C++ 整数除法向零取整（保证除数不为 `0` 且所有中间计算结果均在 64 位有符号整数范围内）。请编写程序：
1. 第一行输出该表达式对应的**后缀表达式（逆波兰式）**，相邻的数字或运算符之间用单个空格隔开；
2. 第二行输出该表达式的最终计算结果。

**输入格式**：
一行一个不含空格的中缀表达式字符串 `s`。

**输出格式**：
第一行输出空格分隔的后缀表达式。
第二行输出一个整数，表示表达式的最终运算值。

**💡 算法建模与关键细节**：
1. **多位数解析**：扫描数字字符 `'0' ~ '9'` 时用 `while` 连续拼出完整数字串，再一并加入 `postfix` 向量（注意内层循环结束后 `i--` 防止外层 `for` 多跳一位）；
2. **运算符栈调度（Shunting-Yard）**：
   * 遇 `(` 直接入栈 `ops`；
   * 遇 `)` 不断把 `ops` 栈顶运算符弹出并输出到 `postfix`，直到遇到 `(` 并将其弹出丢弃；
   * 遇 `+ - * /` 时，只要栈非空、栈顶不是 `(` 且 **`prec(ops.top()) >= prec(c)`**（确保同级左结合），就先弹出栈顶输出，最后将当前 `c` 入栈；
   * 扫描完整个字符串后，将 `ops` 中剩余运算符依次弹出到 `postfix`；
3. **后缀表达式双弹求值**：遍历 `postfix`，遇到数字压入 `stack<long long> vals`，遇到运算符严格先弹右操作数 `b`、再弹左操作数 `a`，将 `calc(a, b, op)` 压回栈中。

```cpp
#include <iostream>
#include <string>
#include <vector>
#include <stack>
using namespace std;

int prec(char op) {
    if (op == '+' || op == '-') return 1;
    if (op == '*' || op == '/') return 2;
    return 0;
}

long long calc(long long a, long long b, char op) {
    if (op == '+') return a + b;
    if (op == '-') return a - b;
    if (op == '*') return a * b;
    return a / b;
}

int main() {
    string s;
    cin >> s;

    vector<string> postfix;
    stack<char> ops;
    int len = (int)s.size();
    for (int i = 0; i < len; i++) {
        char c = s[i];
        if (c >= '0' && c <= '9') {
            string num = "";
            while (i < len && s[i] >= '0' && s[i] <= '9') {
                num += s[i];
                i++;
            }
            i--;
            postfix.push_back(num);
        } else if (c == '(') {
            ops.push(c);
        } else if (c == ')') {
            while (!ops.empty() && ops.top() != '(') {
                postfix.push_back(string(1, ops.top()));
                ops.pop();
            }
            if (!ops.empty()) ops.pop();
        } else {
            while (!ops.empty() && ops.top() != '(' && prec(ops.top()) >= prec(c)) {
                postfix.push_back(string(1, ops.top()));
                ops.pop();
            }
            ops.push(c);
        }
    }
    while (!ops.empty()) {
        postfix.push_back(string(1, ops.top()));
        ops.pop();
    }

    stack<long long> vals;
    for (int i = 0; i < (int)postfix.size(); i++) {
        string tok = postfix[i];
        if (tok[0] >= '0' && tok[0] <= '9') {
            long long num = 0;
            for (int j = 0; j < (int)tok.size(); j++) {
                num = num * 10 + (tok[j] - '0');
            }
            vals.push(num);
        } else {
            long long b = vals.top(); vals.pop();
            long long a = vals.top(); vals.pop();
            vals.push(calc(a, b, tok[0]));
        }
    }

    for (int i = 0; i < (int)postfix.size(); i++) {
        if (i > 0) cout << " ";
        cout << postfix[i];
    }
    cout << "\n" << vals.top() << "\n";
    return 0;
}
```

* **输入样例**：
  ```text
  (12+8)*3-18/6
  ```
* **输出样例**：
  ```text
  12 8 + 3 * 18 6 / -
  57
  ```
  *（样例解释：第一步转后缀：`12`、`8` 输出，遇 `)` 弹出 `+` 得 `12 8 +`；乘以 `3` 后遇 `-`（优先级低于 `*`），先弹出 `*` 得 `12 8 + 3 *`，再将 `-` 入栈；接着 `/` 优先级高于 `-` 直接入栈，扫完 `6` 后依次清空栈中 `/` 与 `-`，得到完整后缀 `12 8 + 3 * 18 6 / -`。第二步栈求值：`12, 8` 入栈遇 `+` 算 `12 + 8 = 20`；`3` 入栈遇 `*` 算 `20 * 3 = 60`；`18, 6` 入栈遇 `/` 严格先弹右操作数 `6`、后弹左操作数 `18` 算 `18 / 6 = 3`；最后遇 `-` 先弹 `3`、后弹 `60` 算 `60 - 3 = 57`，与原式 `(12 + 8) * 3 - 18 / 6 = 20 * 3 - 3 = 57` 完全吻合。）*
