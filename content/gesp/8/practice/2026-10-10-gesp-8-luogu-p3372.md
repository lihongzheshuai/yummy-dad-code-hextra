在序列维护与动态区间统计问题中，同时支持「区间批量增量修改」与「区间任意求和查询」是高阶算法竞赛的核心分水岭：朴素静态数组在进行区间 $[x, y]$ 逐项累加时单次开销高达 $O(n)$，多次操作会导致严重超时；静态前缀和数组虽能以 $O(1)$ 实现区间求和，但在区间修改后需重构整个前缀和序列，单次更新同样退化为 $O(n)$；而单点树状数组虽然擅长单点改与区间查，但若要同时维护区间加与区间求和，必须引入双树状数组与较繁琐的高阶代数推导。洛谷 P3372「【模板】线段树 1」作为 CCF GESP 八级与 CSP-S 组别中最基础且最重要的进阶数据结构模板题，确立了**线段树（Segment Tree）结合延迟标记（Lazy Tag / 懒标记）**这一解决区间修改与统计问题的工业级标准方案。线段树依托完备的二叉树分治结构，将长度为 $n$ 的连续序列划分为若干对数级别的子区间，利用延迟标记将区间修改的均摊复杂度压制在严格的 $O(\log n)$，并在区间查询时以同样的 $O(\log n)$ 精确汇总答案。题目洛谷官方难度评级为`普及+/提高-`。

## luogu-P3372 【模板】线段树 1

> 🔗 **洛谷原题传送门**：[luogu-P3372 【模板】线段树 1](https://www.luogu.com.cn/problem/P3372)

### 题目描述

如题，已知一个数列，你需要进行下面两种操作：

1. 将某区间每一个数加上 $k$。
2. 求出某区间每一个数的和。


## 输入格式

第一行包含两个整数 $n, m$，分别表示该数列数字的个数和操作的总个数。

第二行包含 $n$ 个用空格分隔的整数，其中第 $i$ 个数字表示数列第 $i$ 项的初始值。

接下来 $m$ 行每行包含 $3$ 或 $4$ 个整数，表示一个操作，具体如下：

1. `1 x y k`：将区间 $[x, y]$ 内每个数加上 $k$。
2. `2 x y`：输出区间 $[x, y]$ 内每个数的和。

## 输出格式

输出包含若干行整数，即为所有操作 2 的结果。

## 样例 #1

### 样例输入 #1
```
5 5
1 5 4 2 3
2 2 4
1 2 3 2
2 3 4
1 1 5 1
2 1 4
```

### 样例输出 #1

```
11
8
20
```

对于 $30\%$ 的数据：$n \le 8$，$m \le 10$。  
对于 $70\%$ 的数据：$n \le {10}^3$，$m \le {10}^4$。  
对于 $100\%$ 的数据：$1 \le n, m \le {10}^5$。

保证任意时刻数列中所有元素的绝对值之和 $\le {10}^{18}$。

### 题目深度剖析

#### 1. 操作矛盾与设计动机：从线性扫描到对数分治

在面对序列上的混合操作时，不同基础数据结构的性能权衡如下：
- **朴素数组方案**：单点查询 $O(1)$、区间修改 $O(n)$、区间求和 $O(n)$。当操作指令达到 $m = 10^5$ 规模时，总运算步数高达 $10^{10}$ 次，发生致命超时（TLE）；
- **静态前缀和方案**：无修改下区间求和 $O(1)$，但一旦发生区间修改，后续所有前缀和必须重构，单次修改耗时 $O(n)$；
- **标准单点树状数组**：单点加与区间查均为 $O(\log n)$，但无法直接应对区间加；若用差分树状数组，则支持区间加与单点查，却丢失了高效区间求和能力。

为了同时实现「区间修改」与「区间查询」的高效平衡，我们需要一种天然支持**区间二分剖分**的树状层次结构——线段树。线段树将任意一个区间 $[x, y]$ 拆分为至多 $2 \lceil \log_2 n \rceil$ 个完全包含在树节点中的子区间，从而将所有区间操作从线性扫描优化至对数级别。

#### 2. 线段树的形态特征与 $4N$ 存储空间原理解析

线段树是一棵基于数组下标划分的完全/满二叉树衍生结构：
1. **树节点定义**：树中每个节点编号为 $p$，维护原序列一段闭区间 $[l, r]$ 的统计信息（在本题中为区间元素之和 $\sum_{i=l}^r a[i]$）；
2. **左右子节点划分**：令中点 $\text{mid} = \lfloor (l + r) / 2 \rfloor$。节点的左子节点编号为 $2p$（位运算简写为 `p << 1`），管辖区间为 $[l, \text{mid}]$；右子节点编号为 $2p + 1$（位运算简写为 `(p << 1) | 1`），管辖区间为 $[\text{mid} + 1, r]$；
3. **空间开辟上限（$4N$ 证明）**：
   - 当区间长度 $n$ 恰好为 $2$ 的幂次时，线段树为满二叉树，节点总数为 $2n - 1 < 2n$；
   - 当 $n$ 不是 $2$ 的幂次时，树的最后一层叶子节点可能偏置延伸至更深一层，最后一层的最大节点编号可能接近最底层虚构满二叉树的末尾。数学上可以严格证明，在采用静态一维数组存储完全二叉树编号时，节点最大下标严格不超过 $4n$。因此，所有数组必须开辟至原数组大小的 $4$ 倍以防止越界段错误（RE）。

#### 3. 核心突破口：延迟标记（Lazy Tag）的精髓与时间复杂度守护

如果进行区间修改时，递归访问并逐个更新叶子节点中的所有元素，单次区间修改的时间复杂度将退化为 $O(n)$，线段树的分治优势将荡然无存。此时必须引入线段树最核心的优化机制——**延迟标记（Lazy Tag / 懒标记）**：

- **核心思想（推迟更新，按需分发）**：当修改区间 $[ql, qr]$ 完全覆盖当前线段树节点管辖区间 $[l, r]$ 时，该节点所管辖的所有子节点都必然会增加相同的增量 $val$。此时，无需继续向下递归修改子节点，而是：
  1. 直接更新当前节点的区间总和：$\text{tree}[p] \mathrel{+}= val \times (r - l + 1)$；
  2. 在当前节点打上延迟累加标记：$\text{lazy}[p] \mathrel{+}= val$；
  3. 立即返回，终止向下递归。
- **标记的下传（Push Down）**：延迟标记本质上是一笔「尚未兑现给子节点的增量账单」。当且仅当后续的查询或修改操作需要深入访问该节点的左子树或右子树时，才顺带将当前节点的标记下传给直接左右孩子，并相应更新左右孩子的区间和，随后将当前节点的延迟标记清零。
- **复杂度保障**：通过延迟标记，任何一次区间修改或区间查询在树上访问的节点数量被严格限制在 $O(\log n)$ 级别。

#### 4. 关键下传与上传策略：`push_up` 与 `push_down` 的协同

1. **`push_up(p)`（子节点向父节点汇总）**：
   - 依赖关系：$\text{tree}[p] = \text{tree}[2p] + \text{tree}[2p + 1]$；
   - 触发时机：在建树过程完成左右子树递归之后，或者区间修改中对子区间完成修改返回后，父节点必须调用 `push_up` 重新校准自身区间和。
2. **`push_down(p, l, r)`（父节点向子节点分发）**：
   - 触发时机：在区间修改或区间查询过程中，若当前节点区间未被目标区间完全覆盖，需要递归进入子节点之前，必须先行下传标记，确保子节点维护的数据绝对真实有效。

#### 5. 易错点与工程防御

1. **数值范围与 64 位整型**：题目明确说明数列所有元素的绝对值之和可达 $10^{18}$，且增量修改多次累加后会远超 32 位整型极限（$2^{31} - 1 \approx 2.14 \times 10^9$）。因此，原数组、线段树维护的区间和数组、延迟标记数组以及累加统计变量均必须使用 `long long`；
2. **位运算优先级**：在计算左右子节点下标时，加减运算符的优先级高于位移运算符。表达式 `l + ((r - l) >> 1)` 必须显式添加括号防止优先级错位；
3. **输入输出流规范**：严格遵循竞赛规范，使用纯正 C++11 标准，避免在输入流中添加多余的判断分支。

### 详尽注释源码（C++11 标准）

```cpp
/**
 * 题目: 【GESP/CSP练习】GESP八级 / CSP-S 题解：luogu-P3372 【模板】线段树 1
 * 题号: P3372
 * 归属: GESP八级 / CSP-S / 高级数据结构·线段树区间加与Lazy标记维护
 * 博客: https://www.coderli.com/gesp-8-luogu-p3372/
 * 标准: C++11 (严格遵循 CCF GESP 官方规范)
 */

#include <iostream>

using namespace std;

// 最大序列长度
const int MAXN = 100005;

// 数列长度 n 与操作次数 m
int n, m;

// 原始数列数组
long long a[MAXN];

// 线段树节点维护的区间和数组，空间需开辟原数组的 4 倍
long long tree[MAXN << 2];

// 延迟标记（Lazy Tag）数组，记录子树区间尚未下传的区间增量累加值
long long lazy[MAXN << 2];

/**
 * 向上更新节点区间和信息 (Push Up)
 * 父节点的区间和等于左子节点与右子节点的区间和之和
 * @param p 当前线段树节点编号
 */
void push_up(int p) {
    tree[p] = tree[p << 1] + tree[(p << 1) | 1];
}

/**
 * 向下传递延迟标记 (Push Down)
 * 当需要访问或修改子节点时，将当前节点的延迟增量分配给左右子树
 * 并更新左右子树维护的区间和数值，随后清空当前节点的延迟标记
 * @param p 当前线段树节点编号
 * @param l 当前节点管辖区间的左端点
 * @param r 当前节点管辖区间的右端点
 */
void push_down(int p, int l, int r) {
    if (lazy[p] != 0) {
        int mid = l + ((r - l) >> 1);
        int left_child = p << 1;
        int right_child = (p << 1) | 1;

        // 下传增量给左子节点，左子区间长度为 (mid - l + 1)
        lazy[left_child] += lazy[p];
        tree[left_child] += lazy[p] * (mid - l + 1);

        // 下传增量给右子节点，右子区间长度为 (r - mid)
        lazy[right_child] += lazy[p];
        tree[right_child] += lazy[p] * (r - mid);

        // 当前节点的延迟标记已成功分发，归零重置
        lazy[p] = 0;
    }
}

/**
 * 递归构建线段树 (Build)
 * 自底向上初始化线段树各节点的管辖区间和
 * @param p 当前线段树节点编号
 * @param l 当前节点管辖区间的左端点
 * @param r 当前节点管辖区间的右端点
 */
void build(int p, int l, int r) {
    lazy[p] = 0;
    if (l == r) {
        // 叶子节点，直接赋值为原数组第 l 个元素
        tree[p] = a[l];
        return;
    }
    int mid = l + ((r - l) >> 1);
    build(p << 1, l, mid);
    build((p << 1) | 1, mid + 1, r);
    push_up(p);
}

/**
 * 区间增量修改操作 (Range Update)
 * 将区间 [ql, qr] 内每一个元素均加上增量 val
 * @param p 当前线段树节点编号
 * @param l 当前节点管辖区间的左端点
 * @param r 当前节点管辖区间的右端点
 * @param ql 目标修改区间的左端点
 * @param qr 目标修改区间的右端点
 * @param val 增加的增量数值
 */
void update_range(int p, int l, int r, int ql, int qr, long long val) {
    // 当前节点区间被目标修改区间完全覆盖
    if (ql <= l && r <= qr) {
        tree[p] += val * (r - l + 1);
        lazy[p] += val;
        return;
    }
    // 尚未完全覆盖，需要访问子区间，先下传延迟标记
    push_down(p, l, r);
    int mid = l + ((r - l) >> 1);
    if (ql <= mid) {
        update_range(p << 1, l, mid, ql, qr, val);
    }
    if (qr > mid) {
        update_range((p << 1) | 1, mid + 1, r, ql, qr, val);
    }
    // 子区间更新后，重新汇总当前节点的区间和
    push_up(p);
}

/**
 * 区间求和查询操作 (Range Query)
 * 查询目标区间 [ql, qr] 内所有元素的累加和
 * @param p 当前线段树节点编号
 * @param l 当前节点管辖区间的左端点
 * @param r 当前节点管辖区间的右端点
 * @param ql 目标查询区间的左端点
 * @param qr 目标查询区间的右端点
 * @return 目标区间的元素累加和
 */
long long query_range(int p, int l, int r, int ql, int qr) {
    // 当前节点区间被目标查询区间完全覆盖，直接返回该节点的区间和
    if (ql <= l && r <= qr) {
        return tree[p];
    }
    // 尚未完全覆盖，先下传延迟标记
    push_down(p, l, r);
    int mid = l + ((r - l) >> 1);
    long long total = 0;
    if (ql <= mid) {
        total += query_range(p << 1, l, mid, ql, qr);
    }
    if (qr > mid) {
        total += query_range((p << 1) | 1, mid + 1, r, ql, qr);
    }
    return total;
}

int main() {
    cin >> n >> m;

    for (int i = 1; i <= n; ++i) {
        cin >> a[i];
    }

    build(1, 1, n);

    for (int i = 0; i < m; ++i) {
        int opt;
        cin >> opt;
        if (opt == 1) {
            int x, y;
            long long k;
            cin >> x >> y >> k;
            update_range(1, 1, n, x, y, k);
        } else if (opt == 2) {
            int x, y;
            cin >> x >> y;
            cout << query_range(1, 1, n, x, y) << "\n";
        }
    }

    return 0;
}
```

### 算法复杂度全面分析

1. **时间复杂度分析**：
   - **建树操作 `build`**：线段树共有至多 $4n$ 个节点，每个节点仅被常数次访问与合并计算，建树整体时间复杂度为严格的 $O(n)$；
   - **区间修改 `update_range`**：在递归修改过程中，任何一个查询区间在同一深度至多访问 $4$ 个节点。在树高 $\lceil \log_2 n \rceil$ 的二叉树中，单次区间修改访问的节点总数不超过 $4 \log_2 n$，因此单次区间修改的时间复杂度严格为 $O(\log n)$；
   - **区间求和 `query_range`**：同理，查询操作在每一层至多访问 $4$ 个节点，单次区间求和的时间复杂度严格为 $O(\log n)$；
   - **整体时间复杂度**：处理 $m$ 次混合操作与 $n$ 个初始元素，整体运行时间复杂度为 $O(n + m \log n)$。代入题目数据规模 $n, m = 10^5$，$\log_2(10^5) \approx 17$，总运算步数约为 $1.7 \times 10^6$ 次，远低于 1.0 秒时限承受的 $10^8$ 次运算阈值，可极速通过全部测试点。

2. **空间复杂度分析**：
   - **状态存储数组**：原序列数组 `a` 占用 $O(n)$ 空间；线段树区间和数组 `tree` 与延迟标记数组 `lazy` 大小为 $4n$；
   - **内存实际占用**：`tree` 数组占用 $400000 \times 8 \text{ 字节} \approx 3.2 \text{ MB}$，`lazy` 数组占用约 $3.2 \text{ MB}$，原序列数组占用约 $0.8 \text{ MB}$，整体静态内存开销约为 $7.2 \text{ MB}$；
   - **整体空间复杂度**：严格为 $O(n)$ 线性空间，远低于题目给定的 125.00 MB 空间限制，空间效率极为安全可靠。
