在单模式串匹配（Single String Pattern Matching）问题中，判断一个长度为 $m$ 的目标模式串 $s_2$ 是否在长度为 $n$ 的主串 $s_1$ 中出现并找出所有匹配位置，是计算机科学与算法竞赛中最基础且核心的课题之一。朴素的暴力匹配（Brute-force）算法通过逐位对齐并向后比对，一旦在某一位置发生失配，主串指针必须大幅回退至起始比对位置的下一个字符重新开始，最坏情况下时间复杂度高达 $O(n \times m)$。当 $n, m$ 均达到 $10^6$ 级别（如主串为全 `A` 串、模式串为前 $m-1$ 个 `A` 加末尾一个 `B`）时，暴力比对的运算量将飙升至 $10^{12}$ 次，面临无法逾越的超时（TLE）壁垒。洛谷 P3375「【模板】KMP」作为 CCF GESP 八级与 CSP-S 组别中字符串领域最具代表性的基石模板题，确立了由 Knuth、Morris 和 Pratt 共同提出的 **KMP 经典线性字符串匹配算法**。KMP 算法的革命性突破在于彻底摒弃了主串指针的回溯：通过对模式串进行静态结构剖析，挖掘前缀子串内部的「最长真前后缀（border）」自相似性，在失配发生时利用预处理的 `next` 数组（前缀函数 $\pi$）直接将模式串平移滑动到下一个可能匹配的最长公共重叠位置，从而将单模式匹配的全流程时间复杂度严格压缩至 $O(n + m)$ 的线性极限。题目洛谷官方难度评级为`普及+/提高`。

## luogu-P3375 【模板】KMP

> 🔗 **洛谷原题传送门**：[luogu-P3375 【模板】KMP](https://www.luogu.com.cn/problem/P3375)

### 题目描述

给出两个字符串 $s_1$ 和 $s_2$，若 $s_1$ 的区间 $[l, r]$ 子串与 $s_2$ 完全相同，则称 $s_2$ 在 $s_1$ 中出现了，其出现位置为 $l$。  
现在请你求出 $s_2$ 在 $s_1$ 中所有出现的位置。

定义一个字符串 $s$ 的 border 为 $s$ 的一个**非 $s$ 本身**的子串 $t$，满足 $t$ 既是 $s$ 的前缀，又是 $s$ 的后缀。  
对于 $s_2$，你还需要求出对于其每个前缀 $s'$ 的最长 border $t'$ 的长度。

## 输入格式

第一行为一个字符串，即为 $s_1$。  
第二行为一个字符串，即为 $s_2$。\n\n
## 输出格式

首先输出若干行，每行一个整数，**按从小到大的顺序**输出 $s_2$ 在 $s_1$ 中出现的位置。  
最后一行输出 $|s_2|$ 个整数，第 $i$ 个整数表示 $s_2$ 的长度为 $i$ 的前缀的最长 border 长度。

## 样例 #1

### 样例输入 #1
```
ABABABC
ABA
```

### 样例输出 #1

```
1
3
0 0 1
```

## 提示

### 样例 1 解释

 ![](https://cdn.luogu.com.cn/upload/pic/2257.png)。
 
对于 $s_2$ 长度为 $3$ 的前缀 `ABA`，字符串 `A` 既是其后缀也是其前缀，且是最长的，因此最长 border 长度为 $1$。


### 数据规模与约定

**本题采用多测试点捆绑测试，共有 3 个子任务**。

- Subtask 1（30 points）：$|s_1| \leq 15$，$|s_2| \leq 5$。
- Subtask 2（40 points）：$|s_1| \leq 10^4$，$|s_2| \leq 10^2$。
- Subtask 3（30 points）：无特殊约定。

对于全部的测试点，保证 $1 \leq |s_1|,|s_2| \leq 10^6$，$s_1, s_2$ 中均只含大写英文字母。

### 题目深度剖析

#### 1. 暴力比对的瓶颈与 KMP 的核心设计动机
在朴素匹配算法中，假设主串指针为 $i$，模式串指针为 $j$。当 $s_1[i] \neq s_2[j]$ 发生失配时，算法将模式串右移 $1$ 位，主串指针回溯至 $i - j + 1$ 重置比对。这种机制的根本缺陷在于**丢弃了前面 $j$ 个字符已经匹配成功所蕴含的全部已知信息**。
事实上，如果已经得知 $s_1[i-j \dots i-1] = s_2[0 \dots j-1]$，若想在不回溯主串指针 $i$ 的前提下继续比对，只需寻找模式串前缀 $s_2[0 \dots j-1]$ 的一个最长固有结构：它既是已经匹配成功的该子串的后缀（以继续与主串当前字符前面的内容保持对齐），又是模式串自身的前缀（以从模式串头部无缝衔接比对）。这个结构在代数上就是著名的 **Border（相等真前后缀）**。

#### 2. 字符串 Border 的严格数学定义与传递性
设字符串 $s$ 的长度为 $|s|$。若存在非空子串 $t$（$|t| < |s|$），满足：
1. $t$ 是 $s$ 的前缀（Prefix）；
2. $t$ 是 $s$ 的后缀（Suffix）。
则称 $t$ 为 $s$ 的一个 Border。
- **自包含与链式传递定理**：若 $t$ 是 $s$ 的 Border，且 $t'$ 是 $t$ 的 Border，则 $t'$ 必然也是 $s$ 的 Border。
- **前缀函数（Prefix Function / $\pi$ 数组）**：对于模式串的每个前缀子串 $s[0 \dots i]$，定义 $\pi[i]$ 为该前缀子串的**最长 Border 长度**。由传递定理可知，子串 $s[0 \dots i]$ 的所有可能 Border 长度构成的集合，恰好为降序链：
  $$ \mathcal{B}(s[0 \dots i]) = \{ \pi[i], \pi[\pi[i]-1], \pi[\pi[\pi[i]-1]-1], \dots \} $$
当字符尝试扩展失配时，沿此链依次回退即可穷尽所有合法的候选前后缀，绝无遗漏。

#### 3. 前缀函数（`next` 数组）的增量递推构建
计算模式串自身的 $\pi$ 数组（通常记为 `next` 数组）本身也是一个模式匹配过程：
- **基础状态**：长度为 $1$ 的前缀 $s_2[0]$，其真前后缀长度严格小于 $1$，故 $\pi[0] = 0$。
- **状态转移**：假设已知前缀 $s_2[0 \dots i-1]$ 的最长 border 长度为 $j = \pi[i-1]$：
  1. 若当前字符 $s_2[i] == s_2[j]$，则直接在上一级最长 border 的基础上扩展 $1$ 位，即 $\pi[i] = j + 1$；
  2. 若 $s_2[i] \neq s_2[j]$，说明长度为 $j+1$ 的扩展失败，此时必须回退到次长 border 继续尝试：令 $j = \pi[j-1]$，重复比对直到找到字符相等的断点或 $j = 0$；
  3. 若最终回退至 $j = 0$ 且仍有 $s_2[i] \neq s_2[0]$，则当前前缀的最长 border 长度为 $0$。

#### 4. KMP 检索主循环与模式串重叠命中处理
在主串 $s_1$ 与模式串 $s_2$ 的匹配流程中：
- 维护主串指针 $i \in [0, n-1]$ 与模式串当前已匹配长度 $j$；
- 循环单向推进 $i$，失配时回退 $j = \pi[j-1]$ 直至字符匹配或 $j = 0$；
- 若匹配成功则 `++j`；
- 当 $j == m$ 时，说明在区间 $[i - m + 1, i]$ 完整命中了模式串 $s_2$。此时题目要求输出 1-based 起始下标，即 $(i - m + 1) + 1 = i - m + 2$；
- 命中后，视同在模式串末尾发生了虚拟失配，令 $j = \pi[j-1]$，继续向后扫描，从而天然且正确地支持模式串的重叠出现（如在 `AAAA` 中查找 `AA`）。

#### 5. 易错点与工程防御
1. **下标体系对应**：洛谷题目要求输出 1-based 下标，而 C++ 中 `std::string` 默认为 0-based。起始位置公式应为 `(i - m + 2)`。
2. **回退越界防御**：回退条件必须严格判断 `while (j > 0 && ...)`，防止 `j - 1` 索引变成负数造成非法内存访问。
3. **大数据输入吞吐**：数据规模达到 $10^6$，必须注意 I/O 开销。在遵循标准 CCF 规范不使用加速语句的前提下，单次 `cin >> s1 >> s2;` 仅进行两次字符串整体读取，开销极小。输出换行统一采用 `'\n'` 而非 `std::endl`，避免频繁刷新缓冲区。

### 详尽注释源码（C++11 标准）

```cpp
/**
 * 题目: 【GESP/CSP练习】GESP八级 / CSP-S 题解：luogu-P3375 【模板】KMP
 * 题号: P3375
 * 归属: GESP八级 / CSP-S / 字符串算法·KMP单模式匹配与next数组
 * 博客: https://www.coderli.com/gesp-8-luogu-p3375/
 * 标准: C++11 (严格遵循 CCF GESP 官方规范)
 */

#include <iostream>
#include <string>
#include <vector>

using namespace std;

// 最大字符串长度常量定义
const int MAXN = 1000005;

// nxt[i] 存储模式串 s2 前缀子串 s2[0...i] 的最长相等真前后缀长度 (即最长 border 长度)
int nxt[MAXN];

/**
 * 预处理模式串 s2 的最长 border 数组（即 KMP 的 next / 前缀函数数组）
 * 利用已匹配的前缀自相似性，递推计算每个前缀子串的最长 border 长度
 * 
 * @param s 待预处理的模式串 (采用 0-indexed 标准)
 * @param m 模式串长度
 */
void build_next(const string& s, int m) {
    // 长度为 1 的前缀不存在非自身的真前后缀，border 长度定义为 0
    nxt[0] = 0;
    
    // j 维护当前所能匹配的最长 border 候选长度
    int j = 0;
    for (int i = 1; i < m; ++i) {
        // 当下一个字符不匹配且 j > 0 时，沿 border 链回退到次长 border 继续尝试扩展
        while (j > 0 && s[i] != s[j]) {
            j = nxt[j - 1];
        }
        // 如果当前字符匹配成功，最长 border 长度增加 1
        if (s[i] == s[j]) {
            ++j;
        }
        // 记录长度为 i + 1 的前缀的最长 border 长度
        nxt[i] = j;
    }
}

/**
 * KMP 模式匹配主算法
 * 在主串 s1 中高效检索模式串 s2 的所有出现位置
 * 利用 border 性质避免主串指针回溯，使匹配过程保持线性推进
 * 
 * @param s1 文本主串
 * @param s2 目标模式串
 */
void kmp_search(const string& s1, const string& s2) {
    int n = s1.size();
    int m = s2.size();
    
    // 模式串当前匹配到的字符数 (对应前缀 s2[0...j-1])
    int j = 0;
    for (int i = 0; i < n; ++i) {
        // 字符失配时，主串指针 i 不回退，模式串指针 j 沿 next 数组向左回退
        while (j > 0 && s1[i] != s2[j]) {
            j = nxt[j - 1];
        }
        // 当前字符匹配成功，匹配长度递增
        if (s1[i] == s2[j]) {
            ++j;
        }
        // 完整匹配到了模式串 s2
        if (j == m) {
            // 按照题目要求输出 1-based 起始下标: (i - m + 1) + 1 = i - m + 2
            cout << (i - m + 2) << "\n";
            // 模式串完整匹配后，视作在最后一个位置发生失配，回退至次长 border 寻找重叠出现
            j = nxt[j - 1];
        }
    }
}

int main() {
    // 主串 s1 与模式串 s2
    string s1, s2;
    cin >> s1 >> s2;

    int m = s2.size();

    // 1. 预处理模式串 s2 的前缀函数 (border 数组)
    build_next(s2, m);

    // 2. 在主串 s1 中匹配模式串 s2 并输出所有出现位置
    kmp_search(s1, s2);

    // 3. 按照格式输出 s2 每个前缀的最长 border 长度
    for (int i = 0; i < m; ++i) {
        cout << nxt[i] << (i + 1 == m ? "\n" : " ");
    }

    return 0;
}
```

### 算法复杂度全面分析

1. **时间复杂度分析**：
   - **预处理阶段**：构建模式串 $s_2$ 的前缀函数 $\pi$ 数组时，外层循环推进 $i$ 共 $m-1$ 次，变量 $j$ 每次循环至多增加 $1$（总增量上限为 $m-1$）。内层 `while` 循环每次执行必然使 $j$ 严格减少至少 $1$。由于 $j \ge 0$，因此 `while` 循环的总回退次数必然不超过 $j$ 的总增量，即内层回退总次数严格受限于 $m$。因此预处理时间复杂度严格为 $O(m)$；
   - **主串匹配阶段**：同理，主串指针 $i$ 线性递增 $n$ 次，匹配长度变量 $j$ 每次循环至多增加 $1$（总增量上限为 $n$）。内层失配回退循环使 $j$ 减小，总回退次数严格受限于总增量 $n$。因此主串匹配时间复杂度严格为 $O(n)$；
   - **整体时间复杂度**：全流程总运行时间复杂度为严格的 $O(n + m)$。代入题目数据上限 $n, m = 10^6$，总运算步数严格在 $2 \times 10^6$ 次左右，运行耗时约 $0.1$ 秒，以绝对优势轻松通过 1.0 秒时限。

2. **空间复杂度分析**：
   - **状态存储数组**：全局 `nxt` 数组大小为 $MAXN = 1000005$，占用静态内存约 $4 \times 10^6 \text{ 字节} \approx 3.8 \text{ MB}$；
   - **字符串存储**：两个 `std::string` 对象存储长度为 $10^6$ 的字符，动态内存开销约 $2 \text{ MB}$；
   - **整体空间复杂度**：严格为 $O(n + m)$ 线性空间，程序峰值内存占用小于 $10 \text{ MB}$，远低于题目规定的 512.00 MB 空间限制，运行极其轻量且安全。
