将 $n$ 个正整数首尾相接拼成一个尽可能大的整数，表面上看似乎只需将数字“从大到小”排列，实则暗藏两重极易踩中的经典陷阱：第一，多达 $20$ 个不超过 $10^9$ 的正整数拼接后总位数最高可达 $200$ 位，远超 64 位整型 `unsigned long long` 的表示极限，因此必须将每个数直接作为**字符串（`string`）**读入与处理；第二，无论是按数值大小排序（认为 $312 > 13$，实则 $13$ 与 $312$ 之外如 $4$ 与 $246$ 按数值排会错把 $246$ 放前面），还是按普通字符串字典序降序排列（当两串存在公共前缀时，字典序规则判定较长的 `"321" > "32"`，拼出 $32132$，而反过来 `"32" + "321"` 拼出的 $32321$ 明显更大），都会在前缀重叠的测试点上全盘皆输。洛谷 P1012「[NOIP 1998 提高组] 拼数」的破局关键，正是**邻项交换贪心（微扰法）与自定义拼接比较规则**：对于任意两个数字字符串 $a$ 和 $b$，直接比较两种拼接结果 `a + b` 与 `b + a` 的字典序大小——由于 `a + b` 与 `b + a` 的总长度完全相等，其字符串字典序与十进制数值大小 $100\%$ 等价，且满足严格的传递性。本题完美契合 CCF GESP 四级（自定义排序规则、字符串处理）与 CSP-J 普及组的核心考点，洛谷官方难度评级为`普及+/提高−`。

## luogu-P1012 [NOIP 1998 提高组] 拼数

> 🔗 **洛谷原题传送门**：[luogu-P1012 [NOIP 1998 提高组] 拼数](https://www.luogu.com.cn/problem/P1012)

### 题目描述

设有 $n$ 个正整数 $a_1 \dots a_n$，请将它们联接成一排，相邻数字首尾相接，组成一个最大的整数。

### 输入格式

第一行有一个整数，表示数字个数 $n$。

第二行有 $n$ 个整数，表示给出的 $n$ 个整数 $a_i$。

### 输出格式

一个正整数，表示最大的整数。

### 输入输出样例

#### 样例输入 #1
```text
3
13 312 343
```

#### 样例输出 #1
```text
34331213
```

#### 样例输入 #2
```text
4
7 13 4 246
```

#### 样例输出 #2
```text
7424613
```

### 说明/提示

对于全部的测试点，保证 $1 \leq n \leq 20$，$1 \leq a_i \leq 10^9$。

NOIP1998 提高组 第二题

### 题目深度剖析与核心解题模型

#### 1. 为什么常规的“数值排序”和“直接字典序排序”都会出错？

在分析正确解法之前，我们先通过两组反例看清直觉解法的漏洞：

1. **反例一：按整数数值从大到小排序（错误）**
   - 观察样例 2：`7 13 4 246`。
   - 如果按整数大小排序，顺序是 $246 > 13 > 7 > 4$，拼出来的数字是 $2461374$（首位是 $2$）。
   - 而把一位数 $7$ 放在最前面，拼出的 $7424613$ 首位是 $7$，远远大于 $2461374$！显然，决定拼接后数字大小的首先看**最高位（最左侧字符）**，而不是单个整数本身的位数。

2. **反例二：直接按字符串字典序 `a > b` 降序排序（错误！）**
   - 既然要先比最高位，很多同学会直接写 `string` 的默认字典序比较：`return a > b;`。
   - 这在两个字符串没有前缀包含关系时（如 `"7" > "246"`，因为 `'7' > '2'`）是正确的；但一旦**一个字符串是另一个字符串的前缀**，默认字典序就会给出错误结果！
   - **经典反例**：考虑 `a = "32"`，`b = "321"`。
     - C++ 默认的 `string` 字典序比较规则是：前两位 `'3'` 和 `'2'` 相同，谁更长谁就更大，因此判定 `"321" > "32"`。
     - 按此顺序拼接得到 `"321" + "32" = "32132"`。
     - 但如果反过来把 `"32"` 放在前面，拼接得到 `"32" + "321" = "32321"`。
     - 对比两个五位数：$32321 > 32132$！默认字典序在这里彻底翻车。

---

#### 2. 破局核心：邻项交换贪心与 `a + b > b + a`

既然“长度不同”导致了前缀比较的歧义，那怎样才能彻底消除长度差异？

答案极其巧妙：**直接把两个字符串按两种先后顺序拼起来再比！**
- 方案一：$a$ 在前、$b$ 在后，得到拼接串 `a + b`；
- 方案二：$b$ 在前、$a$ 在后，得到拼接串 `b + a`。

请注意一个关键事实：无论字符串 $a$ 和 $b$ 各自有多长，**`a + b` 和 `b + a` 的总长度一定完全相等**（都等于 $\text{len}(a) + \text{len}(b)$）！
- 当两个数字字符串的长度完全相等时，按字典序从左到右逐位比较字符大小（`a + b > b + a`），与比较它们代表的十进制大整数的数值大小是 **$100\%$ 等价**的！
- 回到刚才的反例 `a = "32"`，`b = "321"`：
  - `a + b = "32321"`
  - `b + a = "32132"`
  - 因为 `"32321" > "32132"`，所以 `a` 必须排在 `b` 前面，一行代码 `return a + b > b + a;` 瞬间解决所有前缀长短不一的边界情况。

---

#### 3. 数学证明：为什么该比较规则满足传递性（严格弱序）？

使用 `std::sort` 自定义比较函数时，必须保证比较关系具有**传递性**（即若 $a \succ b$ 且 $b \succ c$，则必有 $a \succ c$）。我们可以用简单的数学变换证明这一点：

设正整数字符串 $a$ 的长度为 $|a|$，其数值为 $V(a)$；字符串 $b$ 的长度为 $|b|$，其数值为 $V(b)$。
- 拼接串 `a + b` 代表的十进制数值为：$V(a) \times 10^{|b|} + V(b)$；
- 拼接串 `b + a` 代表的十进制数值为：$V(b) \times 10^{|a|} + V(a)$。

不等式 `a + b > b + a` 在数值上等价于：
$$V(a) \times 10^{|b|} + V(b) > V(b) \times 10^{|a|} + V(a)$$

将含 $V(a)$ 的项移到左边，含 $V(b)$ 的项移到右边：
$$V(a) \times \left(10^{|b|} - 1\right) > V(b) \times \left(10^{|a|} - 1\right)$$

因为 $|a| \ge 1, |b| \ge 1$，所以 $10^{|a|} - 1 > 0$ 且 $10^{|b|} - 1 > 0$。两边同时除以 $\left(10^{|a|} - 1\right)\left(10^{|b|} - 1\right)$，得到：
$$\frac{V(a)}{10^{|a|} - 1} > \frac{V(b)}{10^{|b|} - 1}$$

这个分式的几何意义非常直观：分母 $10^{|a|} - 1$ 就是由 $|a|$ 个 $9$ 组成的数（如 $9, 99, 999$），而 $\frac{V(a)}{10^{|a|} - 1}$ 恰好是将数字 $a$ 无限循环展开成的纯循环小数 $0.\dot{a}\dot{a}\dot{a}\dots$（例如 `"32"` 对应 $0.323232\dots$，`"321"` 对应 $0.321321\dots$）。
既然比较 `a + b > b + a` 等价于比较每个数对应的实数特征值 $f(x) = \frac{V(x)}{10^{|x|} - 1}$ 的大小，而实数的大于关系天然具有严格的传递性，因此用 `std::sort` 排序后得到的序列必然是全局唯一的最优最大解！

### 完整参考代码 (C++11)

```cpp
/**
 * Problem: luogu-P1012 [NOIP 1998 提高组] 拼数
 * Algorithm: 邻项交换贪心与自定义字符串拼接排序 (Adjacent-Swap Greedy & Custom String Sorting)
 * Standard: C++11 (CCF GESP 四级 / CSP-J 官方规范)
 * Author: OneCoder
 */

#include <iostream>
#include <string>
#include <algorithm>

using namespace std;

int n;
string s[25]; // 将每个正整数直接作为字符串读入和存储

/**
 * 自定义排序比较函数（邻项交换法）
 * @param a 第一个待比较的数字字符串
 * @param b 第二个待比较的数字字符串
 * @return 若 a 排在 b 前面拼出的数字更大，则返回 true
 */
bool cmp(const string& a, const string& b) {
    // 比较两种拼接顺序：a 在前 (a + b) 与 b 在前 (b + a)
    // 因为 a + b 和 b + a 的字符串长度完全相同，字典序大小完全等价于数值大小
    return a + b > b + a;
}

int main() {
    // 读取正整数的个数 n
    cin >> n;

    // 直接以字符串形式读取 n 个正整数
    for (int i = 1; i <= n; ++i) {
        cin >> s[i];
    }

    // 使用自定义比较函数 cmp 对字符串数组 s[1..n] 进行排序
    sort(s + 1, s + n + 1, cmp);

    // 按排序后的最优顺序依次拼接输出，组成最大的整数
    for (int i = 1; i <= n; ++i) {
        cout << s[i];
    }
    cout << "\n";

    return 0;
}
```

### 复杂度分析与避坑指南

1. **时间与空间复杂度**：
   - 共有 $n$（$n \le 20$）个字符串，每个字符串长度不超过 $10$。
   - `std::sort` 进行 $\mathcal{O}(n \log n)$ 次比较，每次比较拼接两个长度不超过 $10$ 的字符串耗时 $\mathcal{O}(L)$（$L \le 20$）。总运算次数不足 $2000$ 次操作，运行耗时仅为 $1\text{ms} \sim 3\text{ms}$，空间复杂度 $\mathcal{O}(n \cdot L)$。
2. **自定义 `cmp` 函数严禁使用 `>=`**：
   - 在编写 `std::sort` 的比较函数时，**必须严格使用 `<` 或 `>`**（即 `return a + b > b + a;`），绝对不能写成 `return a + b >= b + a;`。
   - 当数组中存在两个相等的字符串（或拼接效果相同的串，如 `"12"` 和 `"1212"`）时，`>=` 会违反 C++ 标准库要求的**严格弱序（Strict Weak Ordering）**规则（即 `cmp(x, x)` 必须为 `false`），在数据量较大时会导致 `std::sort` 指针越界触发段错误（RE）。
3. **进阶思考：如果题目允许输入包含 $0$ 怎么办？**
   - 本题数据范围明确保证 $a_i$ 是**正整数**（$1 \le a_i \le 10^9$），因此最高位绝不会是 `'0'`，直接输出即可。
   - 若遇到同类变式题（如 LeetCode 179 最大数）允许输入非负整数 $0$，当所有输入数字全为 $0$（例如输入 `0 0`）时，拼接结果会变成 `"00"`。此时只需在排序后检查首元素 `if (s[1] == "0")`，若是则直接输出单个 `"0"` 即可避免前导零。
