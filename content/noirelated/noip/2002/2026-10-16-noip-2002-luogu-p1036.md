在给定 $n$ 个正整数中任选 $k$ 个数求和并统计其中素数的个数，这一经典问题将**“动态层数的组合枚举”**与**“单点素数判定”**两大基础算法无缝融合。与直接枚举 $1 \sim n$ 自然数（如 P1157 组合的输出）不同，洛谷 P1036「[NOIP2002 普及组] 选数」中的待选元素存储在数组 $x[1 \dots n]$ 中，且不同下标的元素数值可能相同、但作为不同位置的独立个体参与组合。本题的破局核心在于两点：一是利用递归函数按**数组下标严格递增**（`i + 1`）的顺序推进搜索，在传入累加和 `sum + x[i]` 的同时结合“剩余元素不少于待选个数”的可行性剪枝，遍历全部 $\binom{n}{k}$ 种下标组合而无需 `visited` 标记数组；二是针对最大可达 $20 \times 5 \times 10^6 = 10^8$ 的累加和，放弃占用超大空间的线性筛，直接采用时间复杂度为 $\mathcal{O}(\sqrt{S})$ 的**试除法**完成高效判定。本题完美契合 CCF GESP 四级（递归函数设计与时间复杂度优化）及 CSP-J 普及组的核心考点，洛谷官方难度评级为`普及−`。

## luogu-P1036 [NOIP2002 普及组] 选数

> 🔗 **洛谷原题传送门**：[luogu-P1036 [NOIP2002 普及组] 选数](https://www.luogu.com.cn/problem/P1036)

### 题目描述

已知 $n$ 个整数 $x_1,x_2,\cdots,x_n$，以及 $1$ 个整数 $k$（$k<n$）。从 $n$ 个整数中任选 $k$ 个整数相加，可分别得到一系列的和。例如当 $n=4$，$k=3$，$4$ 个整数分别为 $3,7,12,19$ 时，可得全部的组合与它们的和为：

$3+7+12=22$

$3+7+19=29$

$7+12+19=38$

$3+12+19=34$

现在，要求你计算出和为素数共有多少种。

例如上例，只有一种的和为素数：$3+7+19=29$。

### 输入格式

第一行两个空格隔开的整数 $n,k$（$1 \le n \le 20$，$k<n$）。

第二行 $n$ 个整数，分别为 $x_1,x_2,\cdots,x_n$（$1 \le x_i \le 5\times 10^6$）。

### 输出格式

输出一个整数，表示种类数。

### 输入输出样例

#### 样例输入 #1
```text
4 3
3 7 12 19
```

#### 样例输出 #1
```text
1
```

### 题目深度剖析与核心解题模型

#### 1. 核心思路一：下标递增的组合递归枚举

很多同学刚拿到这道题时，容易陷入两个误区：
- **误区 1：按全排列去搜**。使用 `vis[i]` 数组标记每个数是否用过，每次循环都从 $1$ 到 $n$。这样会把 $(x_1, x_2, x_3)$ 和 $(x_2, x_1, x_3)$ 当作不同方案重复计算 $k!$ 次，不仅导致答案放大 $k!$ 倍，而且当 $k=10$ 时 $10! = 3628800$，会直接超时（TLE）。
- **误区 2：对数值去重**。注意题目描述的是“从 $n$ 个整数中任选 $k$ 个整数”，指的是**按位置（下标）选出 $k$ 个不同位置的数**。即使数组中有两个相同数值（例如 $x_1 = 1, x_2 = 1$），选 $x_1$ 和选 $x_2$ 属于不同的组合位置，不能把输入数组去重。

正确的组合搜索模型非常简单：我们不枚举数值本身，而是**严格按数组下标从小到大枚举**。设递归函数为 `dfs(int step, int start, int sum)`：
- `step`：当前正在挑选第几个数（从 $1$ 到 $k$）；
- `start`：当前这一步允许从数组 $x$ 的哪个下标开始往后挑（初始为 $1$）；
- `sum`：当前已经选出的 `step - 1` 个数的累加和。

当我们在第 `step` 步选中了下标为 $i$（$i \ge \text{start}$）的元素 $x[i]$ 后，下一步直接递归调用 `dfs(step + 1, i + 1, sum + x[i])`。因为下一层的起始下标强制变成了 $i + 1$，选出的下标序列必然满足 $1 \le i_1 < i_2 < \dots < i_k \le n$，天然做到**不重不漏**！

---

#### 2. 可行性剪枝（Pruning）

在循环枚举当前位置的下标 $i$ 时，$i$ 的上界是多少？
- 选定当前第 `step` 个数后，后续还需要继续选出 $k - \text{step}$ 个数；
- 如果当前选了下标 $i$，那么下标区间 $[i + 1, n]$ 中还剩下 $n - i$ 个元素可供选择；
- 为了保证剩下的元素足够凑齐 $k$ 个数，必须满足：
  $$n - i \ge k - \text{step} \implies i \le n - (k - \text{step})$$
- 将循环条件写为 `for (int i = start; i <= n - (k - step); ++i)`，即可提前剪掉所有“剩余元素不够凑满 $k$ 个”的死胡同分支。

---

#### 3. 核心思路二：为什么用 $\mathcal{O}(\sqrt{S})$ 试除法而不是素数筛？

当递归抵达边界（`step > k`）时，我们需要判断累加和 `sum` 是否为质数（素数）。这里通过数据范围对比两种素数判定方案：

1. **最大累加和估算**：
   - 已知 $n \le 20$，单个元素 $x_i \le 5 \times 10^6$；
   - 选出 $k$ 个数的最大可能和为 $S_{\max} \approx 20 \times 5 \times 10^6 = 10^8$（一亿），在 32 位有符号整型 `int`（上限约 $2.14 \times 10^9$）的安全范围内，不会溢出。
2. **方案对比**：
   - 若使用埃氏筛或欧拉筛预处理到 $10^8$，布尔标记数组需要消耗约 $100\text{MB}$ 内存，逼近甚至超出 $128\text{MB}$ 的内存限制，且预处理 $10^8$ 次循环耗时较长；
   - 反观组合总数：当 $n = 20$ 时，组合数最多为 $\binom{20}{10} = 184756$ 种。
   - 若对每个组合和直接采用**试除法**判断质数，单次判断只需枚举 $2 \sim \lfloor\sqrt{\text{sum}}\rfloor$，最多循环 $\sqrt{10^8} = 10^4$ 次（且绝大多数合数会在除以 $2, 3, 5$ 时瞬间退出）。
3. **总时间复杂度**：
   - 最坏总运算量远小于 $\binom{20}{10} \times \sqrt{S_{\max}}$，在 C++11 下实际运行耗时不足 $15\text{ms}$，空间复杂度仅为 $\mathcal{O}(n)$，堪称空间与时间的双重最优解。

### 完整参考代码 (C++11)

```cpp
/**
 * Problem: luogu-P1036 [NOIP2002 普及组] 选数
 * Algorithm: 递归枚举组合与试除法质数判定 (Recursive Combination Enumeration & Primality Test)
 * Standard: C++11 (CCF GESP 四级 / CSP-J 官方规范)
 * Author: OneCoder
 */

#include <iostream>

using namespace std;

int n, k;
int x[25];    // 存储读入的 n 个整数
int ans = 0;  // 统计和为质数的组合方案总数

/**
 * 试除法判断正整数 num 是否为质数（素数）
 * @param num 待判断的整数
 * @return 若为质数返回 true，否则返回 false
 */
bool is_prime(int num) {
    // 小于 2 的整数均不是质数
    if (num < 2) {
        return false;
    }
    // 枚举从 2 到 sqrt(num) 的所有整数测试能否整除
    // 使用 i * i <= num 避免调用浮点函数 sqrt() 带来的精度问题
    for (int i = 2; i * i <= num; ++i) {
        if (num % i == 0) {
            return false; // 存在除了 1 和自身以外的约数，是合数
        }
    }
    return true;
}

/**
 * 递归枚举从 n 个数中选出 k 个数的所有组合
 * @param step  当前正在选择第几个数（从 1 到 k）
 * @param start 当前允许从数组 x 的哪个下标开始往后选择（保证下标严格递增，不重复选）
 * @param sum   当前已经选出的数字累加和
 */
void dfs(int step, int start, int sum) {
    // 递归边界：当 step > k 时，说明已经选满了 k 个数字
    if (step > k) {
        // 检查这 k 个数字的累加和是否为质数
        if (is_prime(sum)) {
            ans++;
        }
        return;
    }

    // 枚举当前第 step 个位置选择的数组下标 i
    // 可行性剪枝：剩余可选元素的数量 (n - i) 必须不少于还需选择的个数 (k - step)
    // 即 n - i >= k - step，移项可得 i <= n - (k - step)
    for (int i = start; i <= n - (k - step); ++i) {
        // 选中 x[i]，继续递归选择第 step + 1 个数，下一层起始下标为 i + 1，累加和加上 x[i]
        dfs(step + 1, i + 1, sum + x[i]);
    }
}

int main() {
    // 读取整数总数 n 和需要选取的个数 k
    cin >> n >> k;

    // 读取 n 个整数（下标从 1 到 n 存储）
    for (int i = 1; i <= n; ++i) {
        cin >> x[i];
    }

    // 从第 1 个选位、数组起始下标 1、初始累加和 0 开始深度优先搜索
    dfs(1, 1, 0);

    // 输出和为素数的种类总数
    cout << ans << "\n";

    return 0;
}
```

### 常见失分点与避坑指南

1. **在回溯时忘了恢复全局变量 `sum`**：
   - 如果把 `sum` 定义为全局变量，在递归调用前写 `sum += x[i]; dfs(step + 1, i + 1);`，那么递归返回后**必须**紧跟一句 `sum -= x[i];`（恢复现场）。
   - 更稳妥、不易出错的写法是像参考代码一样，把 `sum` 作为函数参数传递：`dfs(step + 1, i + 1, sum + x[i])`。这样每一层栈帧拥有独立的 `sum` 副本，返回时自动还原，无需手动写回溯扣减。
2. **质数判断漏掉 `num < 2` 的边界**：
   - 虽然本题中 $x_i \ge 1$ 且 $k \ge 1$，但当 $k=1, x_1=1$ 时，累加和可能为 $1$。记住 **$1$ 既不是质数也不是合数**，最小的质数是 $2$，因此 `is_prime` 函数开头必须加上 `if (num < 2) return false;`。
3. **试除法循环条件误写为 `i <= num / 2`**：
   - 若将试除上界写成 `num / 2`，当 `num` 接近 $10^8$ 且为质数时，单次判断需要循环 $5 \times 10^7$ 次，必然导致评测超时（TLE）。务必使用 `i * i <= num`（或 `i <= num / i`）将单次检测控制在 $\mathcal{O}(\sqrt{\text{num}})$ 以内。
