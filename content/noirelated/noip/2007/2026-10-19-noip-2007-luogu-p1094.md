在容量上限固定为 $w$ 的礼袋中装载 $n$（$n \le 3 \times 10^4$）件纪念品，若仅限制总价值不超过 $w$ 而对件数无要求，这便是一个 NP-Hard 的经典装箱问题（Bin Packing Problem）；然而，洛谷 P1094「[NOIP2007 普及组] 纪念品分组」给出了一个极具辨识度的关键约束——**“每组最多只能包括两件纪念品”**。正是这一最多两件的限制，彻底改变了问题的决策结构，使其无需复杂的动态规划或回溯搜索，而能直接通过**排序 + 首尾相向双指针贪心**在 $\mathcal{O}(n \log n)$ 时间内一步到位求得全局最优解。本题的破局核心在于思考当前最昂贵的那件纪念品 $P_{\max}$ 的归宿：如果连当前全场最便宜的纪念品 $P_{\min}$ 与它相加都超出了上限 $w$（即 $P_{\min} + P_{\max} > w$），那么没有任何其他纪念品能与 $P_{\max}$ 同组，它只能独占一组；反之，若 $P_{\min} + P_{\max} \le w$，将最便宜的 $P_{\min}$ 直接配给最贵的 $P_{\max}$ 必然是最优决策，因为把宝贵的“小体积”名额留给价格更低的物品并不会创造更多的合装组数，反而可能浪费大件物品的剩余容量。本题完美契合 CCF GESP 五级（贪心算法与双指针思想）及 CSP-J 普及组的核心考点，洛谷官方难度评级为`普及−`。

## luogu-P1094 [NOIP2007 普及组] 纪念品分组

> 🔗 **洛谷原题传送门**：[luogu-P1094 [NOIP2007 普及组] 纪念品分组](https://www.luogu.com.cn/problem/P1094)

### 题目描述

元旦快到了，校学生会让乐乐负责新年晚会的纪念品发放工作。为使得参加晚会的同学所获得 的纪念品价值相对均衡，他要把购来的纪念品根据价格进行分组，但每组最多只能包括两件纪念品， 并且每组纪念品的价格之和不能超过一个给定的整数。为了保证在尽量短的时间内发完所有纪念品，乐乐希望分组的数目最少。

你的任务是写一个程序，找出所有分组方案中分组数最少的一种，输出最少的分组数目。

### 输入格式

共 $n+2$ 行：

第一行包括一个整数 $w$，为每组纪念品价格之和的上限。
第二行为一个整数 $n$，表示购来的纪念品的总件数 $G$。

第 $3\sim n+2$ 行每行包含一个正整数 $P_i$ 表示所对应纪念品的价格。

### 输出格式

一个整数，即最少的分组数目。

### 输入输出样例

#### 样例输入 #1
```text
100 
9 
90 
20 
20 
30 
50 
60 
70 
80 
90
```

#### 样例输出 #1
```text
6
```

### 说明/提示

$50\%$ 的数据满足：$1\le n\le15$。

$100\%$ 的数据满足：$1\le n\le3\times10^4$，$80\le w\le200$，$5 \le  P_i  \le  w$。

---

### 题目深度剖析与核心解题模型

#### 1. 问题转化：最多两件约束下的最大配对数

已知共有 $n$ 件纪念品，每组只能放 $1$ 件或 $2$ 件。假设最终我们成功将 $k$ 对纪念品两两合装（共消耗 $k$ 个分组，装走 $2k$ 件纪念品），那么剩下的 $n - 2k$ 件纪念品就只能各自单独成组（消耗 $n - 2k$ 个分组）。
此时，总分组数为：
$$\text{Total} = k + (n - 2k) = n - k$$
由于总件数 $n$ 是固定常数，**要使总分组数 $\text{Total}$ 最少，完全等价于使成功两两配对的组数 $k$ 最多**！

---

#### 2. 贪心策略推导与交换论证（Exchange Argument）证明

为了方便地找到最便宜和最昂贵的纪念品，我们先将所有纪念品的价格按从小到大升序排序：
$$P_1 \le P_2 \le \dots \le P_{l} \le \dots \le P_{r} \le \dots \le P_n$$

在任意时刻，用左指针 $l$ 指向当前尚未分组的**最便宜纪念品** $P_l$，用右指针 $r$ 指向当前尚未分组的**最昂贵纪念品** $P_r$。我们站在最昂贵的 $P_r$ 的视角进行分类讨论：

1. **情况一：$P_l + P_r > w$（连最便宜的都塞不下）**
   - 因为数组已经升序排列，对于当前剩余的任何一件其他纪念品 $P_i$（$l \le i < r$），都有 $P_i \ge P_l$，从而必然有：
     $$P_i + P_r \ge P_l + P_r > w$$
   - 这说明 **$P_r$ 不可能与剩下的任何一件纪念品合装**！它唯一的出路就是自己单独占一组。
   - **操作**：分组数 `ans++`，右指针左移 `r--`（将 $P_r$ 单独打包移出待选区间），左指针 $l$ 保持不变，留给后续相对便宜的大件尝试配对。

2. **情况二：$P_l + P_r \le w$（最便宜的能与最贵的合装）**
   - 此时直觉告诉我们：直接把 $P_l$ 和 $P_r$ 配成一组是最划算的。
   - **严谨性反证（交换论证法）**：
     - 有人可能会担心：如果我不拿 $P_l$ 去配 $P_r$，而是拿一个稍微贵一点的 $P_k$（$l < k < r$，且满足 $P_k + P_r \le w$）去配 $P_r$，把最便宜的 $P_l$ 留给别人，会不会更优？
     - 假设在某个最优方案中，$P_r$ 与 $P_k$ 配成了一组，而最便宜的 $P_l$ 与某件纪念品 $P_m$（$m < r$）配成了一组，即满足：
       $$P_k + P_r \le w \quad \text{且} \quad P_l + P_m \le w$$
     - 由于 $P_l \le P_k$ 且 $P_m \le P_r$，如果我们交换它们的搭档，让 **$(P_l, P_r)$ 配对**、让 **$(P_k, P_m)$ 配对**，则有：
       $$P_l + P_r \le P_k + P_r \le w$$
       $$P_k + P_m \le P_k + P_r \le w$$
     - 可以看到，交换后**两组依然完全合法，且成功配对的总组数丝毫没有减少**！而如果原本 $P_l$ 是单独成组的，让 $P_l$ 替换 $P_k$ 去配 $P_r$，反而解放出了价格更高的 $P_k$ 去单独成组，结果同样不会变差。
   - 因此，**一旦 $P_l + P_r \le w$，立即将 $P_l$ 与 $P_r$ 配成一组必能通向全局最优解**！
   - **操作**：分组数 `ans++`，左指针右移 `l++`，右指针左移 `r--`（两件纪念品同时打包移出待选区间）。

---

#### 3. 样例手动推演（双指针移动全过程）

以题目样例为例：上限 $w = 100$，共 $n = 9$ 件纪念品。
将原价格序列 `[90, 20, 20, 30, 50, 60, 70, 80, 90]` 从小到大排序后得到：
`p[1..9] = [20, 20, 30, 50, 60, 70, 80, 90, 90]`

追踪左右指针 $(l, r)$ 的每一步决策：
- **第 1 步**（$l = 1, r = 9$）：`p[1] + p[9] = 20 + 90 = 110 > 100`。超重！`p[9](90)` 单独成组 $\implies l = 1, r = 8, \text{ans} = 1$；
- **第 2 步**（$l = 1, r = 8$）：`p[1] + p[8] = 20 + 90 = 110 > 100`。超重！`p[8](90)` 单独成组 $\implies l = 1, r = 7, \text{ans} = 2$；
- **第 3 步**（$l = 1, r = 7$）：`p[1] + p[7] = 20 + 80 = 100 <= 100`。成功配对！`{p[1](20), p[7](80)}` 合装一组 $\implies l = 2, r = 6, \text{ans} = 3$；
- **第 4 步**（$l = 2, r = 6$）：`p[2] + p[6] = 20 + 70 = 90 <= 100`。成功配对！`{p[2](20), p[6](70)}` 合装一组 $\implies l = 3, r = 5, \text{ans} = 4$；
- **第 5 步**（$l = 3, r = 5$）：`p[3] + p[5] = 30 + 60 = 90 <= 100`。成功配对！`{p[3](30), p[5](60)}` 合装一组 $\implies l = 4, r = 4, \text{ans} = 5$；
- **第 6 步**（$l = 4, r = 4$）：此时 $l == r$，只剩下最后一件 `p[4](50)`，单独成组，循环结束 $\implies \text{ans} = 6$。

最终输出最少分组数 `6`，与样例输出完全吻合。

### 完整参考代码 (C++11)

```cpp
/**
 * Problem: luogu-P1094 [NOIP2007 普及组] 纪念品分组
 * Algorithm: 贪心算法与双指针首尾配对 (Greedy Algorithm & Two-Pointer Pairing)
 * Standard: C++11 (CCF GESP 五级 / CSP-J 官方规范)
 * Blog: https://www.coderli.com/noip-2007-luogu-p1094/
 * Author: OneCoder
 */

#include <iostream>
#include <algorithm>

using namespace std;

// 纪念品总件数 n 最大为 3 * 10^4，声明在全局静态存储区
const int MAXN = 30005;
int p[MAXN];

int main() {
    int w, n;
    // 读取每组纪念品价格之和的上限 w 与纪念品总件数 n
    cin >> w >> n;

    // 依次读取每件纪念品的价格（下标从 1 到 n）
    for (int i = 1; i <= n; ++i) {
        cin >> p[i];
    }

    // 第一步：将所有纪念品按价格从小到大升序排序
    sort(p + 1, p + n + 1);

    // 第二步：利用相向双指针 l 和 r 进行首尾贪心配对
    int l = 1;      // 左指针，指向当前剩余最便宜的纪念品
    int r = n;      // 右指针，指向当前剩余最昂贵的纪念品
    int ans = 0;    // 统计最终的最少分组数目

    while (l <= r) {
        // 如果当前最贵的 p[r] 能与当前最便宜的 p[l] 合装在一组（价格之和不超过 w）
        // 注意：当 l == r（仅剩最后一件纪念品）时，即便触发 l++ 和 r-- 也会立刻满足 l > r 退出循环，ans 同样只加 1
        if (p[l] + p[r] <= w) {
            l++;    // 最便宜的这一件成功搭车，左指针右移
            r--;    // 最贵的这一件完成分组，右指针左移
        } else {
            // 如果连最便宜的 p[l] 都无法与 p[r] 合装，说明 p[r] 无法与任何剩余物品配对
            r--;    // 最贵的这一件只能单独成组，右指针左移
        }
        ans++;      // 无论合装还是单独成组，都消耗了 1 个分组
    }

    // 输出最少的分组数目
    cout << ans << "\n";

    return 0;
}
```

### 复杂度分析与常见避坑指南

1. **时间与空间复杂度**：
   - **排序阶段**：对 $n$ 个元素调用 `std::sort` 耗时 $\mathcal{O}(n \log n)$；
   - **双指针扫描阶段**：每轮循环中，右指针 $r$ 必然减 $1$（或者左右指针同时向中间收缩），最多执行 $n$ 轮循环即可处理完所有纪念品，耗时严格为 $\mathcal{O}(n)$；
   - **总体复杂度**：总时间复杂度为 $\mathcal{O}(n \log n)$（在 $n = 3 \times 10^4$ 下运算量仅约 $4.5 \times 10^5$ 次，运行耗时不足 $5\text{ms}$），空间复杂度为 $\mathcal{O}(n)$。
2. **避坑点 1：误将相邻两个元素配对（`p[i] + p[i+1] <= w`）**：
   - 初学者常见的一个错误贪心是：排序后让相邻的两件纪念品配对，或者让最大的两个配对。
   - **反例**：设 $w = 100$，价格为 `[20, 30, 70, 80]`。如果按相邻配对，`20 + 30 = 50` 占了一组，剩下的 `70` 和 `80` 加起来 $150 > 100$ 只能拆成两组，总共需要 $3$ 组；而用首尾配对 `(20, 80)` 和 `(30, 70)`，总共只需要 $2$ 组！“用最小的去迁就最大的”才不会浪费小件物品的配对潜力。
3. **避坑点 2：当只剩最后一件物品（`l == r`）时的边界处理**：
   - 在 `while (l <= r)` 循环中，当 `l == r` 时，说明场上只剩最后一件落单的纪念品。
   - 此时在 `if (p[l] + p[r] <= w)` 判断中，虽然计算了 `2 * p[l] <= w`（相当于自己和自己加了一次），但无论进入 `if` 分支（执行 `l++; r--;`）还是进入 `else` 分支（执行 `r--;`），都会使得 $l > r$ 从而立即结束 `while` 循环，并且 `ans++` 都只会被执行一次！因此代码在 `l == r` 边界处是 $100\%$ 自洽且安全的。
4. **进阶思考：由于 $w \le 200$，能否优化到 $\mathcal{O}(n + w)$？**
   - 观察数据范围可以发现：纪念品的价格 $P_i \le w \le 200$，数值范围极小！
   - 如果使用 GESP 四级学过的**计数排序（桶排序）**，开一个大小为 $205$ 的桶数组 `cnt[x]` 统计每种价格出现的次数，再用双指针在 $[5, w]$ 的价格桶上相向配对，即可省去 $\mathcal{O}(n \log n)$ 的快速排序，将时间复杂度进一步压缩至极致的线性 $\mathcal{O}(n + w)$。不过在 $n = 3 \times 10^4$ 的规模下，`std::sort` 已经足够在几毫秒内轻松 AC。
