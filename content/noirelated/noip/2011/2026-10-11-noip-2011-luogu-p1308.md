洛谷经典真题 P1308「[NOIP2011 普及组] 统计单词数」，是全国青少年信息学奥林匹克联赛中极具代表性的字符串处理经典范例，同时也是 CCF GESP 三级（字符串基础操作与字符数组）和 CSP-J 普及组初学阶段必刷的算法基石。题目的核心诉求是模拟现代文本编辑器的“整词查找与计数”功能，其本质挑战集中在两个层面上：一是**大小写不敏感（Case-insensitive）**的等价匹配；二是**独立单词（Whole Word）**的精准界定，即目标单词若作为其他复合单词的局部子串（例如样例 2 中在 `Ottoman` 中寻找 `to`）则绝对不能视为有效命中。初学者如果盲目手写遍历逐字比对，往往会在行首、行尾以及连续空格等边缘细节上深陷特判泥潭。而若采用巧妙的**“双端空格哨兵垫底法（Space Sentinel Padding）”**，在目标词与文章首尾均补充空格并完成全小写归一化，便能将复杂的单词边界问题转化为标准的子串检索，不仅代码极为纯粹，还天然保证了首字母索引与原文本严格对齐。题目难度评级为洛谷`普及−`。

## luogu-P1308 [NOIP2011 普及组] 统计单词数

> 🔗 **洛谷原题传送门**：[luogu-P1308 [NOIP2011 普及组] 统计单词数](https://www.luogu.com.cn/problem/P1308)

### 题目描述

一般的文本编辑器都有查找单词的功能，该功能可以快速定位特定单词在文章中的位置，有的还能统计出特定单词在文章中出现的次数。

现在，请你编程实现这一功能，具体要求是：给定一个单词，请你输出它在给定的文章中出现的次数和第一次出现的位置。注意：匹配单词时，不区分大小写，但要求完全匹配，即给定单词必须与文章中的某一独立单词在不区分大小写的情况下完全相同（参见样例 1），如果给定单词仅是文章中某一单词的一部分则不算匹配（参见样例 2）。

### 输入格式

共 $2$ 行。

第 $1$ 行为一个字符串，其中只含字母，表示给定单词；  
第 $2$ 行为一个字符串，其中只可能包含字母和空格，表示给定的文章。

### 输出格式

一行，如果在文章中找到给定单词则输出两个整数，两个整数之间用一个空格隔开，分别是单词在文章中出现的次数和第一次出现的位置（即在文章中第一次出现时，单词首字母在文章中的位置，位置从 $0$ 开始）；如果单词在文章中没有出现，则直接输出一个整数 $-1$。

注意：空格占一个字母位。

### 输入输出样例

#### 输入 #1
```text
To
to be or not to be is a question
```

#### 输出 #1
```text
2 0
```

#### 输入 #2
```text
to
Did the Ottoman Empire lose its power at that time
```

#### 输出 #2
```text
-1
```

### 说明/提示

【数据范围】  
- 第一行单词长度 $\le 10$。  
- 文章长度 $\le 10^6$。  
- NOIP2011 普及组第 2 题。

### 题目深度剖析与核心解题模型

#### 1. 核心矛盾：独立单词与子串匹配的区别

在初学 C++ `string::find()` 成员函数时，我们知道 `s.find(sub)` 检索的是**任意子串（Substring）**。  
例如在样例 2 中：
- 给定目标单词：`to`
- 文章内容：`Did the Ottoman Empire lose its power at that time`

如果直接在全小写的文章 `did the ottoman...` 中查找 `to`，系统会在单词 `ottoman` 的中间（第 10 位）匹配成功！然而题目明确要求：**必须是独立的整词，作为其他词的一部分不算匹配**。

如何判定一个子串是“独立的单词”？在英语排版中，一个合法的独立单词必须满足：
1. **左边界**：前面要么是空格，要么是整篇文章的开头；
2. **右边界**：后面要么是空格，要么是整篇文章的结尾。

#### 2. 神级技巧：双端添加空格“哨兵垫底法”

如果分别写逻辑去特判“文章开头”、“文章结尾”以及“中间由空格隔开”，代码将充斥大量的分支条件（`if-else`），稍有不慎就会发生数组越界。

针对这种**边缘条件不对称**的字符串匹配，竞赛中最经典的高效处理技巧即为**“前后补齐空格哨兵”**：
1. 首先将输入的单词 `word` 和文章 `article` 全部转为小写字母；
2. 在目标单词的前后各加上一个空格：
   $$\text{search\_word} = \text{" "} + \text{word} + \text{" "}$$
3. 同样在整篇文章的前后也各加上一个空格：
   $$\text{search\_art} = \text{" "} + \text{article} + \text{" "}$$

##### 补齐空格后的神奇效应：
- 如果目标单词是 `to`，被包装后变为 `" to "`；
- 无论目标单词原本位于文章的**最开头**、**最末尾**还是**正中间**，在包装后的 `search_art` 中，它都必然**严格被两个空格左右包夹**！
- 此时，普通的子串查找 `search_art.find(search_word)` 就能**百分之百等价于独立整词查找**，彻底杜绝了将 `ottoman` 中的 `to` 误判为匹配的风险！

#### 3. 首次出现位置的数学恒等对齐

题目要求输出首次匹配时单词首字母在原文章中的索引（从 $0$ 开始计数）。

我们在 `article` 的最开头补了一个空格，使得：
- 原文章下标 $0$ 的字符，移到了 `search_art` 的下标 $1$；
- 原文章下标 $i$ 的字符，移到了 `search_art` 的下标 $i + 1$。

现在我们在 `search_art` 中查找的是 `" " + word + " "`：
- 当匹配成功时，`search_art.find(search_word)` 返回的是**匹配子串第一个字符（即左侧空格）在 `search_art` 中的下标**，记为 `pos`；
- 因为左侧空格的下一个字符就是目标单词的首字母，所以目标单词首字母在 `search_art` 中的下标为 `pos + 1`；
- 将其还原到原文章中，对应原文章中的索引为：
  $$(pos + 1) - 1 = pos$$
- **结论：`search_art.find()` 返回的左侧空格下标 `pos`，在数值上恰好严格等于目标单词在原文章中的起始索引！** 完全无需任何偏移换算！

#### 4. 输入处理与边界防坑提示

1. **整行带空格读取**：
   - 目标单词本身不含空格，可直接用 `getline(cin, word)`；
   - 文章包含大量空格，必须使用 `getline(cin, article)` 完整读取一整行。
2. **大小写统一归一化**：
   - 使用 C++ 标准库中的 `tolower()` 函数遍历字符，将所有大写字符转为小写。
3. **循环查找与位置步进**：
   - 找到一次匹配后，后续继续查找的起始搜索位置应为 `pos + 1`，避免陷入死循环。

#### 5. 复杂度分析

- **时间复杂度**：
  设文章长度为 $N \le 10^6$，单词长度为 $M \le 10$。
  将字符串转小写耗时 $\mathcal{O}(N + M)$；
  字符串查找总开销在线性时间内完成，在 $N = 10^6$ 时总计算耗时约 $0.02\text{s}$，远低于 $1.00\text{s}$ 的限时。
- **空间复杂度**：
  存储原字符串与填充空格后的字符串，占用内存约 $2 \sim 3\text{MB}$，远小于 $125.00\text{MB}$ 的限制。

### 完整参考代码 (C++11)

```cpp
/**
 * Problem: luogu-P1308 [NOIP2011 普及组] 统计单词数
 * Algorithm: 字符串检索 · 双端空格哨兵法 (Space Sentinel Padding)
 * Standard: C++11 (CCF GESP / CSP-J 官方规范)
 * Author: OneCoder
 */

#include <iostream>
#include <string>
#include <cctype>

using namespace std;

int main() {
    string word, article;

    // 读入目标单词与整篇待检索文章
    getline(cin, word);
    getline(cin, article);

    // 步骤一：全量转为小写字母，实现大小写不敏感匹配
    for (char &c : word) {
        c = tolower(c);
    }
    for (char &c : article) {
        c = tolower(c);
    }

    // 步骤二：核心哨兵法——两端各补一个空格
    // 强制将"独立单词"界定转化为"两端均为空格的子串检索"，天然消除行首行尾边界特判
    string search_word = " " + word + " ";
    string search_art = " " + article + " ";

    int cnt = 0;           // 记录匹配出现的总次数
    int first_pos = -1;    // 记录在原文章中第一次出现的起始下标
    size_t pos = search_art.find(search_word);

    // 步骤三：循环检索所有匹配出现的独立单词
    while (pos != string::npos) {
        if (cnt == 0) {
            // search_art 中左侧空格的索引 pos，恰好精确等于原文章中的首字母索引
            first_pos = pos;
        }
        cnt++;
        // 推进到下一个位置继续检索
        pos = search_art.find(search_word, pos + 1);
    }

    // 步骤四：输出结果
    if (cnt == 0) {
        cout << -1 << "\n";
    } else {
        cout << cnt << " " << first_pos << "\n";
    }

    return 0;
}
```
